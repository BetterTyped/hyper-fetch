## Socket Inspector

HyperFlow showed requests but not the realtime side of an app, so a chat that stopped updating meant digging through
`console.log`. Pass your sockets to the devtools plugin:

```ts title="client.ts"
const socket = new Socket({ url: "ws://localhost:3000" });

const client = createClient({ url: "http://localhost:3000" }).addPlugin(
  DevtoolsPlugin({
    appName: "My App",
    // highlight-next-line
    sockets: [socket],
  }),
);
```

The new **Sockets** page lists each socket with its URL, adapter and status, and counts messages, bytes, errors, failed
sends and reconnection attempts. A log below shows received and sent messages, connection events and errors, with
search, a direction filter and per-socket selection.

- It works with the WebSocket and Server-Sent Events adapters.
- When HyperFlow restarts, the plugin reports the sockets and their state again.
- Events waiting for HyperFlow are capped at the newest 1000, so an app running without HyperFlow open does not keep
  every event in memory.

## Devtools on the server

The devtools plugin uses the runtime's global `WebSocket` when there is no `window`, so it reports from Node.js 22+, Deno
and Bun with no extra setup. `environment` tells the backend apart from the frontend in HyperFlow:

```ts
const client = createClient({ url: "http://localhost:3000" }).addPlugin(
  // highlight-next-line
  DevtoolsPlugin({ appName: "My API", environment: "backend" }),
);
```

On Node.js 18 and 20, install `ws` and pass its class in the `WebSocket` option.

Invalidating a cache entry from HyperFlow now marks the data stale in your app, the same as `cache.invalidate()`. It used
to only notify listeners, and the data stayed fresh.

## Real observer counts

HyperFlow mirrors your app's cache with its own client, which has no subscriptions, so the observers column always
showed 0. The plugin now reports how many subscriptions your app has per cache key and query key, on every change and
each time HyperFlow connects. You can see which data is still on screen and which is safe to drop.

## A tested compatibility table

Every HyperFlow flow now runs end to end against each adapter: fetch, axios, GraphQL, tRPC, oRPC, Firebase, Firebase
Admin and a custom one. A real client reports through the devtools plugin to a real HyperFlow, and every mark on the
[compatibility page](/docs/hyper-flow/compatibility) is a test that runs on each change.

Writing those tests found bugs that are now fixed:

- The server survives crashes, invalid ports, restarts and reopened windows.
- Canceled requests are counted, and paused requests get their own icon.
- Plain string, number and boolean values can be edited in the cache view.
- Dialogs, crash badges and queue actions reset to the real state of your app.
- Charts label their legends and draw every particle, even when one leaves the canvas.

The [download page](/docs/hyper-flow/download) finds the newest release with HyperFlow installers and offers the one for
your system.

## Oxlint plugin

The lint rules catch what TypeScript lets through: every generic key on `createClient` and `createRequest` is optional,
so a typo like `rsponse` types your data as `unknown`. **`oxlint-plugin-hyper-fetch`** brings both rules to
[Oxlint](https://oxc.rs) with the same rule ids.

```bash npm2yarn2pnpm
npm install -D oxlint oxlint-plugin-hyper-fetch
```

```json title=".oxlintrc.json" {2}
{
  "jsPlugins": ["oxlint-plugin-hyper-fetch"],
  "rules": {
    "hyper-fetch/client-generic-types": "error",
    "hyper-fetch/request-generic-types": "error"
  }
}
```

The rules skip files that cannot contain a HyperFetch client or request before Oxlint builds their AST. On the 4960
files of the HyperFetch repository it lints in 1.09s, against 17.8s for ESLint, with the same findings. Moving from
ESLint only changes how the plugin is registered.

## ESLint plugin fixes

`eslint-plugin-hyper-fetch` read generics from `typeParameters`, which typescript-eslint 8 removed in favor of
`typeArguments`, so on current parsers the rules reported nothing. They now read `typeArguments` and fall back for older
parsers.

`configs.recommended` is now a flat config object, the format of ESLint 9 and the only one ESLint 10 reads:

```js title="eslint.config.mjs"
export default [
  {
    files: ["**/*.{ts,tsx,mts,cts}"],
    languageOptions: { parser: tseslint.parser },
  },
  // highlight-next-line
  hyperFetch.configs.recommended,
];
```

On ESLint 8 with `.eslintrc`, switch to the preset that moved:

## 88 runnable examples

The [examples catalog](/examples) has 88 standalone apps in ten groups: getting started, data fetching, caching,
mutations, request control, offline, realtime, integrations, frameworks and complete apps.

- Each example has a page with its real source files and a click-to-run preview.
- Each one opens in StackBlitz or CodeSandbox straight from GitHub.
- CI type-checks and builds every example against the current source, so the code works with the latest release.

```bash
npx tiged BetterTyped/hyper-fetch/examples/offline/offline-first my-app
```

The [offline-first](/examples/offline/offline-first) app persists both the cache and the request queue, so a whole
offline session survives a reload.

## Agent skills

Coding agents write data-fetching code from what they remember about a library. Every HyperFetch package now has a
public [agent skill](/docs/getting-started/ai) with setup, golden rules, patterns, pitfalls and type safety, each checked
against the package source.

```bash
npx skills add BetterTyped/hyper-fetch/skills

# or only the packages you use
npx skills add BetterTyped/hyper-fetch/skills \
  --skill hyper-fetch-core --skill hyper-fetch-react
```

There are fifteen skills: core, React, sockets, axios, GraphQL, tRPC, oRPC, Firebase, Firebase Admin, Hono, Elysia, the
CLI, devtools, ESLint and Oxlint.

## CLI fixes

- Generated SDKs call the real paths of the schema. The generator turns path segments into camelCase keys, so
  `sdk.pet.findByStatus.$get` used to call `/pet/find-by-status`. The generated file now passes
  [`pathSegments`](/blog/hyper-fetch-10-core-react#url-segments-for-sdk-keys) for every key the conversion would get
  wrong.
- `init` writes aliases that point to the directories it creates, and `generate` creates a missing output directory.
  A project without tsconfig `paths` used to fail its first `generate` with `ENOENT`.
