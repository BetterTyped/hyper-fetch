A typo in a Firestore field name returns an empty list, not an error. In HyperFetch 10, `@hyper-fetch/firebase` and
`@hyper-fetch/firebase-admin` build constraints in a typed callback, so the typo fails to compile. Writes and listeners
got a round of fixes, and nothing breaks on upgrade.

## Typed constraints

Type `queryParams` with `FirestoreQueryParams<Doc>`, and the callback checks every field name and value against the
document. `$where("yaer", ">=", "2020")` used to compile, run and match nothing.

```ts title="teas.ts"
type Tea = {
  name: string;
  type: "Green" | "Black";
  year: number;
  origin: { country: string };
};

const getTeas = client.createRequest<{
  response: (Tea & { __key: string })[];
  // highlight-next-line
  queryParams?: FirestoreQueryParams<Tea>;
}>()({ endpoint: "teas", method: "getDocs" });

getTeas.setQueryParams((c) => c.where("year", ">=", 2020)); // ✓
// ✗ unknown field, and year is a number
// highlight-next-line
getTeas.setQueryParams((c) => c.where("yaer", ">=", "2020"));
// ✓ nested fields use dots
getTeas.setQueryParams((c) => c.where("origin.country", "==", "Japan"));
```

The types follow Firebase's own rules:

- `where` checks the value against the field, so `"in"` takes an array and `"array-contains"` takes one element.
- Firestore cursors take one value per `orderBy`, in order. `orderBy("year").orderBy("name").startAfter(2023, "Sencha")`
  compiles, and a third value does not.
- A Realtime Database query allows one `orderBy*`, and its cursors and `equalTo` are typed by the ordered value.

```ts title="messages.ts"
const getMessages = client.createRequest<{
  response: (Message & { __key: string })[];
  // highlight-next-line
  queryParams?: RealtimeDBQueryParams<Message>;
}>()({ endpoint: "rooms/general/messages", method: "get" });

const { data } = await getMessages.send({
  queryParams: (c) => c.orderByChild("sentAt").limitToLast(50),
});
```

The callback runs the moment you set it, and the request stores the constraints it returns. Cache keys, query keys and
`toJSON()` only see plain data, so each combination of filters gets its own cache entry. Rules the types cannot see,
such as a missing composite index, come back in `response.error`.

Custom adapters can accept their own query params callbacks through the same two hooks:
`setQueryParamsResolver()` on the core `Adapter` and `setListenerQueryParamsResolver()` on the `SocketAdapter`.

## Constraints as an array

Queries built from filters a user toggles on screen are easier to write as an array, and `queryParams` now takes one
directly.

```ts
const constraints: FirestoreConstraint[] = [];
if (onlyGreen) constraints.push($where("type", "==", "Green"));
constraints.push($orderBy("year", "desc"));

// highlight-next-line
getTeas.setQueryParams(constraints);
```

- The array is what the callback resolves to, so both forms share the cache.
- Constraints apply in order.
- `RealtimeDBConstraint` types the Realtime Database helpers, such as `$orderByChild` and `$limitToLast`, and mixing the
  two databases' helpers is a type error.

## Listeners use the same query params

Listeners took their constraints in `options`. They now use the same `setQueryParams` as requests.

```ts
const socket = new Socket({
  url: "",
  adapter: FirebaseSocketsAdapter(getFirestore(app)),
});

const onGreenTeas = socket
  .createListener<(Tea & { __key: string })[]>()({
    topic: "teas",
    options: { groupByChangeType: true },
  })
  // highlight-start
  .setQueryParams((c) =>
    c.where("type", "==", "Green").orderBy("year", "desc").limit(20),
  );
// highlight-end

onGreenTeas.listen(({ data, extra }) => {
  render(data); // the full current result, every time
  extra.status; // "success" or "emptyResource", now typed
});
```

`options` keeps what is not part of the query: `groupByChangeType` for Firestore and `onlyOnce` for Realtime Database.
`useListener` from `@hyper-fetch/react` takes the listener as it is.

## Upgrading

Nothing breaks. The `{ constraints }` object on requests and `options.constraints` on listeners still work and are
marked `@deprecated`, so your editor points at every place to update.

<Tabs>
<TabItem value="before" label="Before">

```ts
await getTeas.send({
  queryParams: {
    constraints: [$where("type", "==", "Green"), $orderBy("year"), $limit(20)],
  },
});

socket.createListener<Tea[]>()({
  topic: "teas",
  options: { constraints: [$where("type", "==", "Green")] },
});
```

</TabItem>
<TabItem value="after" label="After">

```ts
await getTeas.send({
  // highlight-next-line
  queryParams: (c) => c.where("type", "==", "Green").orderBy("year").limit(20),
});

socket
  .createListener<Tea[]>()({ topic: "teas" })
  // highlight-next-line
  .setQueryParams((c) => c.where("type", "==", "Green"));
```

</TabItem>
</Tabs>

To keep the `$`-helpers, pass the array itself: `queryParams: [$where("type", "==", "Green"), $limit(20)]`. Only the
callback on a request typed with `FirestoreQueryParams<Doc>` or `RealtimeDBQueryParams<Doc>` checks field names.

## Reliability fixes

The emulator suites of both packages had been left out of CI and had drifted. Each fix below came with a spec that failed
first, and both suites now run on every change, with the release waiting for them.

### Writes

- `setDoc`, `addDoc`, `updateDoc`, `set`, `push` and `update` sent `undefined` since v7. They send the payload again, in
  `@hyper-fetch/firebase` and `@hyper-fetch/firebase-admin`.
- Realtime Database requests default to `get`. A request without a `method` used to fail, and a method the database
  does not have now resolves with `status: "error"`.

### Listeners

- Socket listeners deliver each snapshot once instead of twice.
- In `@hyper-fetch/firebase-admin`, unsubscribing a Realtime Database listener no longer removes every `value` listener
  on the same path.
- Document listeners with `groupByChangeType` deliver again, with `extra.groupedResult` set to `null`. Collection
  listeners keep the `added`, `modified` and `removed` groups.
- `extra.status` is typed on Firestore and Realtime Database listeners.

### Queries and types

- Firestore cursors with several values match again, and Realtime Database cursors keep the optional key. `$equalTo`
  takes the optional key too.
- The published declarations import types from `firebase`, not the internal `@firebase/*` packages, so projects that
  install only `firebase` typecheck.

The docs were rewritten alongside the fixes, with every example checked against the emulator or the type checker.
