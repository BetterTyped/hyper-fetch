## About HyperFetch

**HyperFetch** is a data-exchange framework that puts HTTP, GraphQL, Firebase, RPC and realtime sources like WebSockets
and Server-Sent Events behind one type-safe API. Caching, queueing, retries, offline support and devtools work the same
for every transport, in React, React Native and Node.js.

## Hardened everywhere

Before this release we audited every package and wrote a failing test for each problem before fixing it. Among the
fixes:

- Out-of-order responses no longer overwrite newer data.
- Falsy payloads and response data are kept.
- Removed requests stop retrying.
- A failing response mapper resolves `send()` with a failed response instead of rejecting.
- Scopes stay isolated in hooks and Suspense.
- SSE sockets no longer reconnect after a manual disconnect.

Flaky specs were fixed at the cause instead of retried: timing-dependent tests run on fake clocks or hold requests in
flight until they assert. Each area post lists the fixes for its package.

## Upgrading to 10

Core, React, Firebase and the HTTP adapters upgrade without code changes. The breaking changes are in
`@hyper-fetch/sockets` and `@hyper-fetch/graphql`:

| Change                                                                          | What to do                                                             |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Sockets connect wherever a global `WebSocket` exists, Node.js included          | Set `adapterOptions: { autoConnect: typeof window !== "undefined" }`   |
| `connectionTimeout` (5s) limits an attempt, `reconnectTime` is the minimum delay (1s) | Set `connectionTimeout` if you relied on `reconnectTime` for it  |
| `onMessage` interceptors receive `{ event, topic, extra }`                      | Nothing, unless you need the topic or the adapter extra               |
| Listener generics make room for subscription payloads                           | Update hand-written `Listener`, `ListenType` or `ListenerOfAdapter` types |
| `graphql` and `@hyper-fetch/sockets` are peer dependencies of `@hyper-fetch/graphql` | Install both                                                     |
| GraphQL cache keys changed                                                      | Nothing: data persisted by earlier versions is fetched again once     |

The [sockets post](/blog/hyper-fetch-10-sockets#upgrading) and the [GraphQL post](/blog/hyper-fetch-10-graphql#upgrading)
have the exact before and after for each change. The v9 docs stay available under
[v9.0.0](/docs/v9.0.0/getting-started).
