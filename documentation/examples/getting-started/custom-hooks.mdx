A list of posts with a details panel where you can rename a post. The components never touch a request, a query param or
the cache. They call three hooks from `hooks.ts`: `usePosts()`, `usePost(id)` and `useRenamePost(id)`.

:::tip What it shows

1. **Custom hooks** wrap `useFetch` and `useSubmit`, so components ask for data in the words of the app.
2. **Shared options** live in one object next to the hooks, not in every component.
3. **Inferred types**: the hooks return the typed `useFetch` result, so `data.posts` is typed with no type in the
   component.
4. **Side effects in one place**: `useRenamePost` updates both cached copies of a post after a successful save.

:::

## How it works

1. `api.ts` defines the client and three plain requests. It has no React code.
2. `hooks.ts` fixes the details a component should not repeat. `usePosts()` always reads the same list, so the query
   params are set once:

   ```ts
   const postsListRequest = getPostsRequest.setQueryParams({ limit: 5, select: "title,body,userId" });
   // highlight-next-line
   export const usePosts = () => useFetch(postsListRequest, sharedOptions);
   ```

   Every component that calls `usePosts()` uses the same cache key, so they share one response.

3. `usePost(postId)` sets the endpoint param. The hook returns the `useFetch` result as it is, so `data`, `error`,
   `loading` and the callbacks keep their types.
4. `useRenamePost(postId)` returns `{ renamePost, submitting, error }`. `renamePost(title)` builds the payload and
   resolves with the response, so the form can check `success`. In `onSubmitSuccess` the hook writes the new title into
   the cached post and the cached list with `client.cache.update()`, and both panels update.
5. `App.tsx` imports only from `hooks.ts`. To change the page size, the options or the endpoint, you edit one file.

dummyjson does not store changes, so the new title lives only in the cache. With a real API you could call
`client.cache.invalidate()` in the hook instead and let the hooks refetch.

:::note When to use it

- A request used in more than one component.
- A mutation that has to update or invalidate other data after it succeeds.
- Keep a plain `useFetch` call for a one-off request on a single screen.

:::
