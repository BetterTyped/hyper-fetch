# NestJS

`@nestjs/swagger` describes your NestJS controllers and DTOs as an OpenAPI document, and the
[HyperFetch CLI](/docs/cli/overview) turns that document into a typed SDK. The frontend then calls every route with the
response, payload, params and query types of your DTOs. There is no NestJS package to install.

:::tip Purpose

1. **No glue package**: `@nestjs/swagger` and the CLI are all you need.
2. **Types from your DTOs**: responses, bodies, path params and query params come from the DTOs you already have.
3. **One command to resync**: change a controller, regenerate, and the compiler shows every call to fix.

:::

---

## Install

On the server, install the Swagger module. In the frontend, install HyperFetch and the CLI:

```bash title="server"
npm install @nestjs/swagger
```

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
npm install -D @hyper-fetch/cli
```

---

## 1. Serve the OpenAPI document

Build the document in `main.ts` and mount it with `SwaggerModule.setup()`:

```ts title="server/src/main.ts"
import { NestFactory } from "@nestjs/core";
import { DocumentBuilder, SwaggerModule } from "@nestjs/swagger";

import { AppModule } from "./app.module";

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  const config = new DocumentBuilder()
    .setTitle("Shop API")
    .setVersion("1.0")
    .build();

  // highlight-start
  SwaggerModule.setup("docs", app, () =>
    SwaggerModule.createDocument(app, config),
  );
  // highlight-end

  await app.listen(3000);
}
bootstrap();
```

The Swagger UI is on `http://localhost:3000/docs` and the JSON document on `http://localhost:3000/docs-json`. The CLI
reads the JSON one.

---

## 2. Generate the SDK

Run the CLI in the frontend project while the NestJS app is running:

```bash title="frontend"
npx hyper-fetch generate --template openapi --fileName nest.sdk.ts \
  --overwrite --url http://localhost:3000/docs-json
```

It writes `src/api/nest.sdk.ts`. The folder comes from `api.json`, which the first run creates. Every path becomes
nested keys and every method a `$` key, so `GET /users/{id}` is `sdk.users.$id.$get`.

---

## 3. Call your API

```ts title="frontend/src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

import { createSdk } from "./nest.sdk";

export const client = createClient({ url: "http://localhost:3000" });
export const sdk = createSdk(client);
```

```ts title="frontend/src/users.ts"
import { sdk } from "./api/client";

// data is typed from the response DTO of GET /users/{id}
const { data, error } = await sdk.users.$id.$get.setParams({ id: "42" }).send();

// payload is typed from the body DTO of POST /users
await sdk.users.$post.send({
  payload: { name: "Ada", email: "ada@example.com" },
});
```

Every entry is a regular [Request](/docs/core/request), so it also works with `useFetch` and `useSubmit` from
[`@hyper-fetch/react`](/docs/react/overview).

## Framework quirks

- **DTO properties**: `@nestjs/swagger` only sees the properties it is told about. Decorate them with
  `@ApiProperty()`, or add the Swagger CLI plugin to `nest-cli.json` so it reads them from your TypeScript types:

```json title="server/nest-cli.json"
{
  "compilerOptions": { "plugins": ["@nestjs/swagger"] }
}
```

- **No running server**: write the document to a file in `main.ts` (`writeFileSync("openapi.json",
  JSON.stringify(document))`) and pass that path to `--url`. A local path is resolved from the frontend project.

---

## Keep the SDK in sync

Add a script so regenerating is one command locally and in CI. `-o` overwrites the old file without asking:

```json title="frontend/package.json"
{
  "scripts": {
    "api:generate": "hyper-fetch generate -t openapi -u http://localhost:3000/docs-json -f nest.sdk.ts -o"
  }
}
```

---

:::secondary Summary

- `@nestjs/swagger` serves your controllers and DTOs as an OpenAPI document at `/docs-json`.
- `hyper-fetch generate` turns that document into a typed SDK.
- `createSdk(client)` gives you typed requests for `send()`, `useFetch` and `useSubmit`.

:::
