# Firebase React hooks for Firestore and Realtime Database

`@hyper-fetch/firebase` runs Firestore and Realtime Database operations of the Firebase web SDK as HyperFetch requests.
You send them with `send()` or [`useFetch`](/docs/react/hooks/use-fetch) and get typed responses, caching and loading
state, while live data comes through [listeners](/docs/sockets/listener) and `useListener`. Server code with the Admin
SDK uses [`@hyper-fetch/firebase-admin`](/docs/integrations/adapter-firebase-admin/overview) instead.

:::tip Purpose

1. **One request API for Firebase**: Firestore and Realtime Database operations are regular requests.
2. **Typed queries**: `queryParams: (c) => c.where(...)` checks fields and values and is part of the cache key.
3. **Live data**: `FirebaseSocketsAdapter` turns `onSnapshot` and `onValue` into socket listeners.
4. **No rejected promises**: Firebase errors come back in `response.error`.

:::

---

## Install

`firebase` is a peer dependency. Add `@hyper-fetch/sockets` for live listeners and `@hyper-fetch/react` for hooks.

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/firebase firebase
```

## Setup

1. Pass an initialized database to `FirebaseAdapter`. The instance decides which methods the client accepts.

```ts title="api/firebase.ts"
import { createClient } from "@hyper-fetch/core";
import { FirebaseAdapter } from "@hyper-fetch/firebase";
import { initializeApp } from "firebase/app";
import { getFirestore } from "firebase/firestore";

const app = initializeApp({ projectId: "my-project" });
export const db = getFirestore(app);

export const client = createClient({ url: "" }).setAdapter(FirebaseAdapter(db));
```

2. Create a request. The `endpoint` is the Firebase path and the `method` the SDK operation.

```ts title="api/teas.ts"
import type { FirestoreQueryParams } from "@hyper-fetch/firebase";

import { client } from "./firebase";

export type Tea = { name: string; type: "Green" | "Black"; year: number };

export const getTeas = client.createRequest<{
  response: (Tea & { __key: string })[];
  queryParams?: FirestoreQueryParams<Tea>;
}>()({
  endpoint: "teas",
  method: "getDocs",
});
```

3. Send it, or read it in a component.

```tsx title="GreenTeas.tsx"
import { useFetch } from "@hyper-fetch/react";

import { getTeas } from "./api/teas";

export const GreenTeas = () => {
  const { data, loading, error } = useFetch(
    getTeas.setQueryParams((c) => c.where("type", "==", "Green")),
  );

  if (loading) return <p>Loading...</p>;
  if (error) return <p>{error.message}</p>;

  return data?.map((tea) => <p key={tea.__key}>{tea.name}</p>);
};
```

| Database instance | Methods                                                           | Default method |
| ----------------- | ----------------------------------------------------------------- | -------------- |
| `getFirestore()`  | `getDoc`, `getDocs`, `addDoc`, `setDoc`, `updateDoc`, `deleteDoc` | `getDoc`       |
| `getDatabase()`   | `get`, `set`, `push`, `update`, `remove`                          | `get`          |

## How it maps

| Firebase                                              | HyperFetch                                                                |
| ----------------------------------------------------- | ------------------------------------------------------------------------- |
| Database instance                                     | `FirebaseAdapter(db)` on the client                                       |
| Path (`doc(db, "teas/1")`, `ref(db, "rooms")`)        | `client.url + endpoint`, with `:params`                                   |
| SDK function (`getDocs`, `setDoc`, `push`, ...)       | request `method`                                                          |
| Data you write                                        | `payload`                                                                 |
| `setDoc(ref, data, { merge: true })`                  | request `options: { merge: true }`                                        |
| Query constraints (`where`, `orderBy`, `limit`, ...)  | `queryParams` callback or `$`-helper array, part of the cache key         |
| Document data and id                                  | `data`, with the id as `__key`                                            |
| Missing document, empty collection                    | `status: "emptyResource"`, `data` `null` or `[]`                          |
| Thrown `FirebaseError`                                | `error`, with `status: "error"`                                           |
| References and snapshots                              | `extra.ref`, `extra.snapshot`                                             |
| `onSnapshot`, `onValue`                               | a `Listener` on a `Socket` with `FirebaseSocketsAdapter`, path in `topic` |

---

## Paths

The adapter reads the path as `client.url + endpoint`, so `url: "teas/"` with `endpoint: ":teaId"` targets `teas/1`.

- An **odd** number of segments (`teas`, `teas/1/reviews`) is a collection or list.
- An **even** number of segments (`teas/1`) is a single document or value.
- Mind the slash when you split a path: `url: "teas"` with `endpoint: ":teaId"` gives `teas1`.

---

## Responses

`send()` resolves with the standard [response](/docs/core/request) and never rejects.

| Field     | Content                                                                                            |
| --------- | -------------------------------------------------------------------------------------------------- |
| `data`    | The document or list. Firestore documents and the items of every list get a `__key` with their id. |
| `status`  | `"success"`, `"emptyResource"` when nothing was found, or `"error"`.                               |
| `success` | `true` for `"success"` and `"emptyResource"`, `false` for `"error"`.                               |
| `error`   | The Firebase error (permission denied, missing index, updating a missing document) or `null`.     |
| `extra`   | `ref`, plus `snapshot` for reads. `{}` when the request failed.                                     |

## Querying

Pass `queryParams` a callback. It receives a constraints chain, and the constraints it collected apply in order and are
part of the cache key, so two queries never share a cached response.

```ts title="api/teas.ts"
const { data } = await getTeas.send({
  queryParams: (c) =>
    c.where("type", "==", "Green").orderBy("year", "desc").limit(20),
});
```

| Database          | Chain methods                                                                                               |
| ----------------- | ----------------------------------------------------------------------------------------------------------- |
| Firestore         | `where`, `orderBy`, `limit`, and the cursors `startAt`, `startAfter`, `endAt`, `endBefore`                  |
| Realtime Database | `orderByChild`, `orderByKey`, `orderByValue`, `limitToFirst`, `limitToLast`, then `equalTo` and the cursors |

With the document type in `FirestoreQueryParams<Tea>` or `RealtimeDBQueryParams<Message>`, field names and values are
checked. `queryParams` also takes the array the callback resolves to, built with `$where`, `$limit` and the other
`$`-helpers. Rules the types cannot see, such as Firestore composite indexes, come back in `response.error`.

## Live data

Requests read once. For updates as they happen, create a listener on a socket with `FirebaseSocketsAdapter`, described
in [realtime listening](/docs/integrations/adapter-firebase/realtime-queries).

```ts title="api/live.ts"
import { Socket } from "@hyper-fetch/sockets";
import { FirebaseSocketsAdapter } from "@hyper-fetch/firebase";

import { db } from "./firebase";
import type { Tea } from "./teas";

export const socket = new Socket({
  url: "",
  adapter: FirebaseSocketsAdapter(db),
});

export const onTeas =
  socket.createListener<
    (Tea & { __key: string })[]
  >()({
    topic: "teas",
  });
// const stop = onTeas.listen(({ data })
// => render(data));
```

For Firestore data that several views read and that must stay live, `firestoreCollection` from
`@hyper-fetch/firebase/db` declares a [`@hyper-fetch/db`](/docs/db/overview) collection, see
[DB with Firestore](/docs/db/firestore).

## Web and admin differences

The two packages share methods, paths, responses and constraints. These are the differences:

| Topic                                        | `@hyper-fetch/firebase` (web)                | `@hyper-fetch/firebase-admin` (server)         |
| -------------------------------------------- | -------------------------------------------- | ---------------------------------------------- |
| Runs                                         | in browsers and React Native, as the user    | on servers, with a service account             |
| Request adapter                              | `FirebaseAdapter`                            | `FirebaseAdminAdapter`                         |
| Socket adapter                               | `FirebaseSocketsAdapter`                     | `FirebaseSocketsAdminAdapter`                  |
| Security rules                               | enforced for the signed-in user              | bypassed                                       |
| Firestore `setDoc` `data`                    | the payload                                  | the Admin SDK `WriteResult`                    |
| Firestore socket `connect()`, `disconnect()` | toggle the network of the instance           | throw, stop listeners with their stop function |
| Realtime document listener `data`            | the value                                    | the value plus `__key`                         |
| Firestore listener `extra`                   | `ref`, `snapshot`, `status`, `groupedResult` | the same, plus `unsubscribe`                   |
| Documents in `groupedResult`                 | with `__key`                                 | without `__key`                                |
| `@hyper-fetch/db` collections                | `firestoreCollection`                        | not available                                  |

---

:::secondary Summary

- Pass `getFirestore()` or `getDatabase()` to `FirebaseAdapter`. The instance decides the methods.
- `client.url + endpoint` is the Firebase path, and its segment count decides document or collection.
- Queries are a `queryParams` callback, applied in order and part of the cache key.
- Errors resolve with `status: "error"`, missing data with `status: "emptyResource"`.

:::
