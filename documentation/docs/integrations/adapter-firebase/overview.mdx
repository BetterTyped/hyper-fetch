# Firebase React hooks for Firestore and Realtime Database

[Read the API Reference »](/api/adapter-firebase/Functions/FirebaseAdapter.mdx)

The Firebase JavaScript SDK has no React bindings, so firebase react hooks are something you write yourself or get from
a library. `@hyper-fetch/firebase` is one way to get them. It runs Firestore and Realtime Database operations through
HyperFetch requests: you create requests with `createRequest`, send them with `send()` or `useFetch`, and get the same
typed responses, caching, deduplication and loading state you use for HTTP. Live data comes through
`@hyper-fetch/sockets` listeners and the `useListener` hook.

---

:::tip Purpose

1.  **One request API for Firebase**: Firestore and Realtime Database operations are regular HyperFetch requests.
2.  **Typed results**: `data`, `payload`, `params` and the raw Firebase `extra` are typed per request.
3.  **Typed queries**: `queryParams: (c) => c.where(...)` checks fields and values, and is part of the cache key.
4.  **Live data**: `FirebaseSocketsAdapter` turns `onSnapshot` and `onValue` into socket listeners.
5.  **No rejected promises**: Firebase errors come back in `response.error`, never as a thrown exception.

:::

## Firebase in React without a library

Without a helper, reading Firestore in a component looks like this:

```tsx
import { collection, onSnapshot, query, where } from "firebase/firestore";
import { useEffect, useState } from "react";

function GreenTeas() {
  const [teas, setTeas] = useState<Tea[]>([]);
  const [error, setError] = useState<Error | null>(null);

  useEffect(() => {
    const q = query(collection(db, "teas"), where("type", "==", "Green"));
    const unsubscribe = onSnapshot(
      q,
      (snapshot) => setTeas(snapshot.docs.map((doc) => ({ __key: doc.id, ...doc.data() }) as Tea)),
      setError,
    );
    return unsubscribe;
  }, []);

  // ...
}
```

It works, and for one screen it is fine. The cost shows up when it repeats: every component writes its own loading and error
state, one-off reads with `getDocs` have no cache between pages, and the data is only typed if you cast it or add a
converter. The [React](#react) section below is the same component with this package.

## Installation

```bash
npm install @hyper-fetch/core @hyper-fetch/firebase firebase
```

Add `@hyper-fetch/sockets` for live listeners and `@hyper-fetch/react` for hooks. Server code that uses the Admin SDK
needs [`@hyper-fetch/firebase-admin`](/docs/integrations/adapter-firebase-admin/overview) instead.

## Setup

Pass an initialized database to `FirebaseAdapter`. The instance decides which methods the client accepts.

```tsx
import { Client } from "@hyper-fetch/core";
import { FirebaseAdapter } from "@hyper-fetch/firebase";
import { initializeApp } from "firebase/app";
import { getFirestore } from "firebase/firestore";

const app = initializeApp({ projectId: "my-project" });

export const client = new Client({ url: "" }).setAdapter(FirebaseAdapter(getFirestore(app)));

type Tea = { __key: string; name: string; type: "Green" | "Black"; year: number };

const getTeas = client.createRequest<{ response: Tea[] }>()({
  endpoint: "teas",
  method: "getDocs",
});

const { data, status, error, extra } = await getTeas.send();
```

| Database instance | Methods                                                           | Default method |
| ----------------- | ----------------------------------------------------------------- | -------------- |
| `getFirestore()`  | `getDoc`, `getDocs`, `addDoc`, `setDoc`, `updateDoc`, `deleteDoc` | `getDoc`       |
| `getDatabase()`   | `get`, `set`, `push`, `update`, `remove`                          | `get`          |

A method that the database does not have, such as `getDocs` on a Realtime Database client, resolves with
`status: "error"`.

## Paths

The adapter reads the path as `client.url + endpoint`, so `url: "teas/"` with `endpoint: ":teaId"` targets `teas/1`.

:::caution Document or collection is decided by the path

1.  A path with an **odd** number of segments (`teas`, `teas/1/reviews`) is a collection or list.
2.  A path with an **even** number of segments (`teas/1`) is a single document or value.
3.  Mind the slash when you split a path between `url` and `endpoint`: `url: "teas"` with `endpoint: ":teaId"` gives
    `teas1`. Use `url: "teas/"` or a leading slash in the endpoint.

:::

## Responses

Every request resolves with the standard HyperFetch response.

| Field     | Content                                                                                            |
| --------- | -------------------------------------------------------------------------------------------------- |
| `data`    | The document or list. Firestore documents and the items of every list get a `__key` with their id. |
| `status`  | `"success"`, `"emptyResource"` when nothing was found, or `"error"`.                               |
| `success` | `true` for `"success"` and `"emptyResource"`, `false` for `"error"`.                               |
| `error`   | The Firebase error (permission denied, missing index, updating a missing document...) or `null`.   |
| `extra`   | Raw Firebase objects: `ref`, and `snapshot` for reads. `{}` when the request failed.               |

`emptyResource` comes with `data: null` for a missing document and `data: []` for an empty Firestore collection.

```tsx
const { data, status, error } = await getTea.setParams({ teaId: "missing" }).send();

if (error) showError(error.message);
else if (status === "emptyResource") showNotFound();
else render(data);
```

## Querying data

Pass `queryParams` a callback. It receives a constraints chain, and the adapter stores the constraints it collected, so
they apply in order and are part of the cache key: two requests with different constraints never share a cached
response.

```tsx
const { data } = await getTeas.send({
  queryParams: (c) => c.where("type", "==", "Green").orderBy("year", "desc").limit(20),
});
```

Type the request's query params with the document type, and field names and values are checked:

```tsx
import type { FirestoreQueryParams } from "@hyper-fetch/firebase";

const getTeas = client.createRequest<{ response: Tea[]; queryParams?: FirestoreQueryParams<Tea> }>()({
  endpoint: "teas",
  method: "getDocs",
});

getTeas.setQueryParams((c) => c.where("year", ">=", 2020)); // ✓
getTeas.setQueryParams((c) => c.where("yaer", ">=", "2020")); // ✗ unknown field, and year is a number
```

| Database          | Chain methods                                                                                                  |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| Firestore         | `where`, `orderBy`, `limit`, and the cursors `startAt`, `startAfter`, `endAt`, `endBefore`                     |
| Realtime Database | `orderByChild`, `orderByKey`, `orderByValue`, `limitToFirst`, `limitToLast`, then `equalTo` and the cursors    |

The chain follows Firebase's rules in its types: Firestore cursors take one value per `orderBy`, and a Realtime Database
query has one `orderBy*`. Rules the types cannot see, such as Firestore composite indexes, come back in
`response.error`.

:::info Constraints as data

`queryParams` also takes the constraints array the callback resolves to, built with the `$`-helpers
(`[$where("type", "==", "Green"), $limit(20)]`). The `{ constraints: [...] }` object of earlier versions still works and
is deprecated.

:::

## Live data

Requests read once. For updates as they happen, create a listener on a socket with `FirebaseSocketsAdapter`, described
in [Realtime listening](/docs/integrations/adapter-firebase/realtime-queries).

```tsx
import { Socket } from "@hyper-fetch/sockets";
import { FirebaseSocketsAdapter } from "@hyper-fetch/firebase";

const socket = new Socket({ url: "", adapter: FirebaseSocketsAdapter(getFirestore(app)) });

const onTeas = socket.createListener<Tea[]>()({ topic: "teas" });
const stop = onTeas.listen(({ data }) => render(data));
```

## Collections

For Firestore data that several views read and that has to stay live, `firestoreCollection` declares a
[`@hyper-fetch/db`](/docs/db/overview) collection in one call. Queries become Firestore constraints and snapshots keep
them current, as described in [DB with Firestore](/docs/db/firestore).

```tsx
import { firestoreCollection } from "@hyper-fetch/firebase";

const Tea = firestoreCollection(TeaSchema, { client, socket, path: "teas", key: "id" });
```

## React

Firebase requests and listeners work with the regular hooks.

```tsx
import { useFetch, useListener } from "@hyper-fetch/react";

function GreenTeas() {
  const { data, loading, error } = useFetch(getTeas.setQueryParams((c) => c.where("type", "==", "Green")));
  const live = useListener(onTeas);

  // ...
}
```

:::note When to use it

- Your app already reads and writes Firebase and you want caching, deduplication and loading state without wiring them
  by hand.
- You want Firebase calls and HTTP calls to look and behave the same in your codebase.
- You want typed `data` and `payload` on every Firebase operation and errors handled through the response.

:::

1.  Pass `getFirestore()` or `getDatabase()` to `FirebaseAdapter`; the instance decides the available methods.

3.  Queries are a `queryParams` callback, `(c) => c.where(...)`, applied in order and part of the cache key.
4.  Errors resolve the request with `status: "error"`; missing data is `status: "emptyResource"`.
5.  Live data goes through `FirebaseSocketsAdapter` listeners.
