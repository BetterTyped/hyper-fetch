Firestore `onSnapshot` and Realtime Database `onValue` run through `@hyper-fetch/sockets`. You create a socket with
`FirebaseSocketsAdapter`, create a listener for a path, and receive the full current result every time it changes.

---

:::tip Purpose

1.  **Listen** to Firestore documents and queries, or Realtime Database paths, with typed data.
2.  **Filter** live queries with the same constraints as requests.
3.  **React** to changes with `useListener`, or group Firestore changes into added, modified and removed.

:::

---

## Setup

```bash
npm install @hyper-fetch/sockets
```

```tsx
import { Socket } from "@hyper-fetch/sockets";
import { FirebaseSocketsAdapter } from "@hyper-fetch/firebase";
import { getFirestore } from "firebase/firestore";
import { getDatabase } from "firebase/database";

export const firestoreSocket = new Socket({ url: "", adapter: FirebaseSocketsAdapter(getFirestore(app)) });
export const realtimeSocket = new Socket({ url: "", adapter: FirebaseSocketsAdapter(getDatabase(app)) });
```

:::danger One adapter per socket

1.  Call `FirebaseSocketsAdapter(db)` inside each `new Socket(...)`. An adapter binds to the socket it was created for,
    so sharing one adapter between two sockets sends every listener to the last socket's `url`.

:::

## Listening

The listener path is `socket.url + topic`. `listen` returns a function that stops the Firebase subscription.

```tsx
type TeaDoc = { __key: string; name: string; type: "Green" | "Black"; year: number };

const onTeas = firestoreSocket.createListener<TeaDoc[]>()({ topic: "teas" });

const stop = onTeas.listen(({ data, extra }) => {
  render(data); // the whole current result, every time
});

stop();
```

Topic params work like endpoint params:

```tsx
const onTea = firestoreSocket.createListener<TeaDoc | null>()({ topic: "teas/:teaId" });

onTea.setParams({ teaId: "sencha" }).listen(({ data }) => render(data));
```

Every snapshot is delivered once, as the full current document or list. Replace your state with it; do not append.

| Field                 | Firestore                                   | Realtime Database                     |
| --------------------- | ------------------------------------------- | ------------------------------------- |
| `data`                | document with `__key`, or list of documents | value, or list as described for `get` |
| `extra.status`        | `"success"` or `"emptyResource"`            | `"success"` or `"emptyResource"`      |
| `extra.ref`           | DocumentReference or Query                  | DatabaseReference                     |
| `extra.snapshot`      | DocumentSnapshot or QuerySnapshot           | DataSnapshot                          |
| `extra.groupedResult` | with `groupByChangeType`, see below         | -                                     |

## Options

| Option              | Database          | Effect                                                                                                                                   |
| ------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `constraints`       | both              | Constraints for the live query, the same `$`-helpers as `queryParams` in requests.                                                       |
| `groupByChangeType` | Firestore         | On collection listeners, adds `extra.groupedResult` with the `added`, `modified` and `removed` documents. Document listeners get `null`. |
| `onlyOnce`          | Realtime Database | Receives the first value and stops.                                                                                                      |

### Filtering

```tsx
import { $limit, $orderBy, $where } from "@hyper-fetch/firebase";

const onGreenTeas = firestoreSocket.createListener<TeaDoc[]>()({
  topic: "teas",
  options: { constraints: [$where("type", "==", "Green"), $orderBy("year", "desc"), $limit(20)] },
});
```

### Grouping changes

```tsx
const onTeas = firestoreSocket.createListener<TeaDoc[]>()({
  topic: "teas",
  options: { groupByChangeType: true },
});

onTeas.listen(({ data, extra }) => {
  render(data);

  // null when the snapshot has no document changes
  if (extra.groupedResult) {
    const { added, modified, removed } = extra.groupedResult;
    notify(`${added.length} new teas`);
  }
});
```

The documents in `groupedResult` are the raw document data, without `__key`.

### Reading once

```tsx
const onConfig = realtimeSocket.createListener<Config | null>()({
  topic: "config",
  options: { onlyOnce: true },
});
```

## React

```tsx
import { useListener } from "@hyper-fetch/react";

function GreenTeas() {
  const { data } = useListener(onGreenTeas);

  return data?.map((tea) => <p key={tea.__key}>{tea.name}</p>);
}
```

---

:::caution Things to know

1.  **One listener per topic on a socket.** Listeners on the same socket and topic also receive each other's snapshots,
    so two listeners on `teas` with different constraints would mix results. Give them different sockets.
2.  **`socket.disconnect()` takes the whole Firebase instance offline**: `disableNetwork` for Firestore, `goOffline` for
    Realtime Database. Your `FirebaseAdapter` requests go offline too. To stop one listener, call its `stop` function.
3.  **Sockets cannot emit.** Firebase sockets only receive; write with requests.

:::

---

:::secondary Summary

1.  Create each socket with its own `FirebaseSocketsAdapter(db)`.
2.  The listener path is `socket.url + topic`, and every snapshot arrives once as the full current result.
3.  Filter with `options.constraints`; group Firestore changes with `groupByChangeType`; read once with `onlyOnce`.
4.  Keep one listener per topic on a socket, and stop listeners with the function `listen` returns.

:::
