# React Native Firebase with HyperFetch

`@hyper-fetch/firebase` runs in React Native and Expo on top of the Firebase JavaScript SDK (`firebase` on npm), not on
React Native Firebase (`@react-native-firebase/*`), which wraps the native Android and iOS SDKs. This page compares the
two and sets up Firestore requests and listeners in a React Native app.

:::tip Purpose

1.  **Pick the right SDK**: know what the Firebase JS SDK supports in React Native and when you need native modules.
2.  **Run HyperFetch on the JS SDK**: Firestore and Realtime Database requests with `useFetch`, `useSubmit` and
    `useListener`.
3.  **Detect the network on a device**: connect `NetInfo` so offline handling works without browser events.

:::

---

## Firebase JS SDK vs React Native Firebase

| Question                       | Firebase JS SDK (`firebase`)                                   | React Native Firebase (`@react-native-firebase/*`)     |
| ------------------------------ | -------------------------------------------------------------- | ------------------------------------------------------ |
| What it is                     | The web SDK, pure JavaScript                                   | A wrapper around the native Android and iOS SDKs       |
| Works in Expo Go               | Yes                                                            | No, needs a development build                          |
| Native code                    | None                                                           | Yes, configured with Expo config plugins or by hand    |
| Analytics, Messaging, Crashlytics | Not supported in React Native                               | Yes                                                    |
| Works with `@hyper-fetch/firebase` | Yes                                                        | No                                                     |

Sources: Firebase's [supported environments page](https://firebase.google.com/docs/web/environments-js-sdk) (Firestore
without persistence, Realtime Database, Authentication without phone auth and popup or redirect OAuth),
[rnfirebase.io](https://rnfirebase.io/) and [Expo's Firebase guide](https://docs.expo.dev/guides/using-firebase/).

If your app reads and writes Firestore or the Realtime Database and signs users in with email or a token, the JS SDK
covers it and you skip native setup. Push notifications, Crashlytics and Analytics need React Native Firebase.

---

## Why the adapter needs the JS SDK

`FirebaseAdapter` and `FirebaseSocketsAdapter` call the modular JS SDK (`firebase/firestore`, `firebase/database`) and
tell Firestore from the Realtime Database with `instanceof` checks against its classes. An instance from
`@react-native-firebase/firestore` is not one of those classes, so the adapter can't run on it, and
`FirebaseSocketsAdapter` throws `Unknown database type`.

:::caution One SDK per job

If you add React Native Firebase for messaging or crash reports, keep reading and writing data through the JS SDK.
Each SDK initializes its own app instance and keeps its own signed-in user, so sign users in with the JS SDK's
`firebase/auth` when HyperFetch requests depend on security rules.

:::

## Installation

```bash
npx expo install firebase @react-native-community/netinfo
npm install @hyper-fetch/core @hyper-fetch/firebase @hyper-fetch/sockets \
  @hyper-fetch/react
```

Outside Expo, install `firebase` and `@react-native-community/netinfo` with npm as usual. `@hyper-fetch/sockets` is
only needed for live listeners.

## Setup

The default `AppManager` listens to browser online and offline events, which React Native doesn't have. Give the client
and the socket an `AppManager` driven by `NetInfo`, the same way the
[React Native environment guide](/docs/react/environments/react-native) does for HTTP:

```ts title="api/firebase.ts"
import { initializeApp } from "firebase/app";
import { getFirestore } from "firebase/firestore";
import NetInfo from "@react-native-community/netinfo";
import { AppManager, Client } from "@hyper-fetch/core";
import { Socket } from "@hyper-fetch/sockets";
import { FirebaseAdapter, FirebaseSocketsAdapter } from "@hyper-fetch/firebase";

const app = initializeApp({
  apiKey: process.env.EXPO_PUBLIC_FIREBASE_API_KEY,
  projectId: "my-project",
  appId: process.env.EXPO_PUBLIC_FIREBASE_APP_ID,
});
const db = getFirestore(app);

// highlight-start
const createAppManager = () =>
  new AppManager({
    initiallyOnline: () => NetInfo.fetch().then((state) => !!state.isConnected),
    onlineEvent: (setOnline) =>
      NetInfo.addEventListener((state) => setOnline(!!state.isConnected)),
  });
// highlight-end

export const client = new Client({
  url: "",
  appManager: createAppManager,
}).setAdapter(FirebaseAdapter(db));

export const socket = new Socket({
  url: "",
  appManager: createAppManager,
  adapter: FirebaseSocketsAdapter(db),
});
```

With this in place, requests sent while the device is offline wait and go out when `NetInfo` reports a connection
again. That is HyperFetch's default `offline: true` behaviour, described in [offline](/docs/guides/core/advanced/offline).

For Realtime Database, pass `getDatabase(app)` from `firebase/database` instead. The rest of this page works the same.

## Reading and writing in components

Requests are the same as on the web. See [Firestore](/docs/integrations/adapter-firebase/firestore) for every method.

```ts title="api/tasks.ts"
import type { FirestoreQueryParams } from "@hyper-fetch/firebase";
import { client } from "./firebase";

export type Task = { title: string; done: boolean; createdAt: number };

export const getTasks = client.createRequest<{
  response: (Task & { __key: string })[];
  queryParams?: FirestoreQueryParams<Task>;
}>()({
  endpoint: "tasks",
  method: "getDocs",
});

export const addTask = client.createRequest<{ response: Task; payload: Task }>()({
  endpoint: "tasks",
  method: "addDoc",
});
```

```tsx title="screens/tasks.tsx"
import { FlatList, Pressable, Text, View } from "react-native";
import { useFetch, useSubmit } from "@hyper-fetch/react";
import { client } from "../api/firebase";
import { addTask, getTasks } from "../api/tasks";

const openTasks = getTasks.setQueryParams((c) =>
  c.where("done", "==", false).orderBy("createdAt", "desc"),
);

export function TasksScreen() {
  const { data, loading, error } = useFetch(openTasks);
  const { submit, submitting, onSubmitSuccess } = useSubmit(addTask);

  onSubmitSuccess(() => client.cache.invalidate(openTasks));

  if (loading) return <Text>Loading...</Text>;
  if (error) return <Text>{error.message}</Text>;

  return (
    <View>
      <FlatList
        data={data ?? []}
        keyExtractor={(task) => task.__key}
        renderItem={({ item }) => <Text>{item.title}</Text>}
      />
      <Pressable
        disabled={submitting}
        onPress={() =>
          submit({
            payload: { title: "New task", done: false, createdAt: Date.now() },
          })
        }
      >
        <Text>Add task</Text>
      </Pressable>
    </View>
  );
}
```

Firebase errors such as a denied permission or a missing index come back in `error` with `status: "error"`. `send()`
and the hooks never throw them, so there's no `try/catch` to write.

## Live data

For updates as they happen, use a listener on the socket from the setup. It runs Firestore's `onSnapshot` under the
hood. More in [realtime listening](/docs/integrations/adapter-firebase/realtime-queries).

```tsx title="screens/live-task-count.tsx"
import { Text } from "react-native";
import { useListener } from "@hyper-fetch/react";
import { socket } from "../api/firebase";
import type { Task } from "../api/tasks";

const onTasks = socket.createListener<Task[]>()({ topic: "tasks" });

export function LiveTaskCount() {
  const { data } = useListener(onTasks);
  return <Text>{data?.length ?? 0} tasks</Text>;
}
```

Calling `socket.disconnect()` and `socket.connect()` turns the network of the whole Firestore instance off and on, not
only this listener.

## Limits

- **No Firestore offline persistence.** The JS SDK does not support it in React Native, so cached Firestore data does
  not survive an app restart. HyperFetch's cache lives in memory too. To keep queued writes across restarts, give the
  dispatcher persistent storage, as shown in [persistence](/docs/guides/core/advanced/persistence) and the React
  Native environment guide.
- **Auth.** Phone sign-in and popup or redirect OAuth flows are not supported by the JS SDK in React Native.
- **Admin SDK is for servers.** `@hyper-fetch/firebase-admin` uses `firebase-admin` and belongs in your backend, never
  in an app bundle. See the [Firebase Admin adapter](/docs/integrations/adapter-firebase-admin/overview).

---

:::secondary Summary

- `@hyper-fetch/firebase` works with the Firebase JS SDK only, which runs in React Native and Expo Go.
- Give the client and the socket a `NetInfo`-based `AppManager` so offline handling works on a device.
- Requests, `useFetch`, `useSubmit` and `useListener` work as on the web.
- Use React Native Firebase alongside for Messaging, Crashlytics or Analytics, and keep data on the JS SDK.

:::
