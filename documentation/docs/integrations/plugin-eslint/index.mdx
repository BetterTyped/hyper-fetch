# ESLint plugin for typed data fetching requests

`eslint-plugin-hyper-fetch` catches typos, unknown keys, empty generics and non-object generics in the types you pass to
`createClient` and `createRequest`. TypeScript accepts those mistakes without a word, and they cost you the types of
the response.

:::tip Purpose

1. **Catch generic typos**: `rsponse` instead of `response` is reported where you wrote it.
2. **Flag unknown keys**: anything outside `response`, `payload`, `error`, `queryParams`, `endpoint` and `params` on a
   request, or `error` on a client.
3. **No type-aware setup**: the rules read syntax only, so `parserOptions.project` is not needed.

:::

---

## Install

The rules read TypeScript generics, so files must be parsed by [typescript-eslint](https://typescript-eslint.io). The
plugin works with ESLint 8.57 and newer, including ESLint 10.

```bash npm2yarn2pnpm
npm install -D eslint eslint-plugin-hyper-fetch typescript-eslint
```

---

## Recommended config

Add the recommended preset to your flat config. It registers the plugin and turns on every rule as `"error"`:

```js title="eslint.config.mjs"
import hyperFetch from "eslint-plugin-hyper-fetch";
import tseslint from "typescript-eslint";

export default [
  {
    files: ["**/*.{ts,tsx,mts,cts}"],
    languageOptions: { parser: tseslint.parser },
  },
  hyperFetch.configs.recommended,
];
```

To pick severities yourself, scope the preset or use `.eslintrc`, see [Configuration](/docs/integrations/plugin-eslint/configuration).

## Why typed requests need linting

A typed request describes its data with a generic object. Every key in it is optional, because a request without a
payload or query params is valid. TypeScript rejects a generic with no known key at all, but once one key is right, a
typo next to it is legal:

```ts title="api/users.ts"
// No TypeScript error: `payload` is valid, so `rsponse` is an extra key and
// `data` gets the default type
const updateUser = client.createRequest<{
  rsponse: User;
  payload: UserInput;
}>()({
  endpoint: "/users/:id",
  method: "PATCH",
});
```

Nothing fails until someone reads `data` and finds it has no fields. The lint rule reports `rsponse` in the editor,
before the code runs.
