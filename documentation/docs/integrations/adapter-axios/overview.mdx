# Axios Adapter for HyperFetch

`@hyper-fetch/axios` makes [Axios](https://axios-http.com) the transport under a HyperFetch [Client](/docs/core/client).
Axios still sends every request with its own options and error objects, while HyperFetch adds the cache, retries,
deduplication, offline queues and typed requests.

:::tip Purpose

1. **Keep axios**: axios options, defaults and interceptors still apply.
2. **Real upload progress**: every axios `onUploadProgress` event reaches `send()` and the React hooks.
3. **Add what axios lacks**: [cache](/docs/core/cache), [retries](/docs/guides/core/basics/retries),
   [deduplication](/docs/guides/core/advanced/deduplication) and [offline](/docs/guides/core/advanced/offline) queues.

:::

---

## Install

`axios` and `@hyper-fetch/core` are peer dependencies.

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/axios axios
```

---

## Setup

1. Set the adapter on your client. `AxiosAdapter` is an instance, so pass it without calling it.

(@import adapter-axios AxiosAdapter type=import)

```ts title="client.ts"
import { createClient } from "@hyper-fetch/core";
import { AxiosAdapter } from "@hyper-fetch/axios";

export const client = createClient({
  url: "https://api.example.com",
}).setAdapter(AxiosAdapter);
```

2. Create a request. Its `options` are now typed as the axios request config.

```ts title="api/users.ts"
import { client } from "./client";

type User = { id: number; name: string };

export const getUser = client.createRequest<{ response: User }>()({
  endpoint: "/users/:userId",
  options: { timeout: 5000, withCredentials: true },
});
```

3. Send it, or pass it to a hook such as [`useFetch`](/docs/react/hooks/use-fetch).

```ts title="send.ts"
import { isAxiosError } from "axios";

import { getUser } from "./api/users";

const { data, error, status, extra } = await getUser
  .setParams({ userId: 1 })
  .send();

if (isAxiosError<{ message: string }>(error)) {
  console.log(status, error.response?.data?.message);
}
// extra.headers holds the axios response headers
```

## How it maps

| Axios                                  | HyperFetch                                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| `url` (with `baseURL`)                 | client `url` + request `endpoint` + encoded `queryParams`                           |
| `method`                               | request `method`, typed as the axios `Method`, default `"GET"`                      |
| `params`                               | `queryParams` (do not use axios `params`, the query string would be added twice)    |
| `data`                                 | `payload`. Plain objects are JSON-stringified by core, `FormData` and `Blob` are not |
| `headers`                              | request `headers` and `setHeaders`                                                  |
| `signal`                               | `request.abort()` and the request's `abortKey`                                      |
| `onUploadProgress`, `onDownloadProgress` | the `send()` progress callbacks, `onSubmitUploadProgress` in `useSubmit`          |
| `response.data`, `response.status`     | `data`, `status`                                                                    |
| `response.headers`                     | `extra.headers`                                                                     |
| rejected `AxiosError`                  | `error` (with `response.data` holding the server body), `status` `0` when there is no response |
| any other config field                 | request `options` and `setOptions`                                                  |

`send()` resolves with the [Response](/docs/core/request) object and never rejects. An aborted request resolves with a
HyperFetch abort error, not an `AxiosError`, so narrow with `isAxiosError` before reading `error.response`.

## Adapter options

Request `options` accept the axios request config except `url`, `baseURL`, `method`, `data`, `onUploadProgress` and
`onDownloadProgress`. `headers` and `signal` still type-check, but the adapter overwrites them. See the
[axios request config](https://axios-http.com/docs/req_config) for every field.

```ts title="api/reports.ts"
export const downloadReport = client.createRequest<{ response: Blob }>()({
  endpoint: "/reports/:reportId",
  options: { responseType: "blob", timeout: 30000 },
});

// setOptions replaces the whole options object on the returned clone
const slowReport = downloadReport.setOptions({
  responseType: "blob",
  timeout: 120000,
});
```

Set options for every request with `setAdapterDefaults`. Request `options` win over them.

```ts title="client.ts"
export const client = createClient({ url: "https://api.example.com" }).setAdapter(
  AxiosAdapter.setAdapterDefaults(() => ({ timeout: 5000 })),
);
```

Axios's own `adapter` option (`"xhr"`, `"http"` or `"fetch"`) is a regular config field, so you can still pick how axios
sends requests underneath the HyperFetch adapter.

## Differences from the HTTP adapter

| Behavior               | Default HTTP adapter                    | `AxiosAdapter`                                           |
| ---------------------- | --------------------------------------- | -------------------------------------------------------- |
| Timeout                | default 5000 ms, change it with `timeout` | none, set `options.timeout` or `setAdapterDefaults`    |
| GET deduplication      | on by default                           | off, set `deduplicate: true` on the request              |
| Upload progress        | one event when the body is handed off   | every axios `onUploadProgress` event (XHR in browsers)   |
| Errors                 | the response body                       | the `AxiosError`, body in `error.response.data`          |
| Interceptors           | HyperFetch only                         | HyperFetch, plus interceptors on the default `axios` export |

Limits:

- The adapter always calls the default `axios` export. Instances from `axios.create()` are not used, so register
  interceptors on `axios` itself or use HyperFetch [interceptors](/docs/guides/core/advanced/intercepting).
- `AxiosAdapter` is one shared object. `setAdapterDefaults` and the other setters change it for every client that uses it.
- Keep the default `validateStatus`. The adapter treats a resolved axios call as success, so `validateStatus: () => true`
  turns 404 and 500 responses into successes.

---

:::secondary Summary

- `setAdapter(AxiosAdapter)` routes every request through axios. Requests, cache and hooks stay the same.
- Axios config goes in request `options`. URL, method, payload, headers and abort stay HyperFetch's.
- Set a `timeout` yourself and narrow errors with `isAxiosError`.

:::
