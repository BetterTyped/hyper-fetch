# Oxlint plugin for typed data fetching requests

`oxlint-plugin-hyper-fetch` catches typos, unknown keys and malformed generics in `createClient` and `createRequest`
when you lint with [Oxlint](https://oxc.rs/docs/guide/usage/linter). Rule ids match the
[ESLint plugin](/docs/integrations/plugin-eslint), so you can switch linters without touching your rule config.

:::tip Purpose

1. **Catch generic typos**: `rsponse` instead of `response` silently drops the type of your data, the plugin flags it.
2. **Skip files cheaply**: files that cannot contain a mistake never have their AST built for the plugin.
3. **Migrate in one step**: the rules are named the same as in `eslint-plugin-hyper-fetch`.

:::

---

## Install

The plugin needs Oxlint 1.62.0 or newer.

```bash npm2yarn2pnpm
npm install -D oxlint oxlint-plugin-hyper-fetch
```

---

## Config

The plugin has no preset. Add it to `jsPlugins` in `.oxlintrc.json` and turn the rules on:

```json title=".oxlintrc.json"
{
  "jsPlugins": ["oxlint-plugin-hyper-fetch"],
  "rules": {
    "hyper-fetch/client-generic-types": "error",
    "hyper-fetch/request-generic-types": "error"
  }
}
```

With a TypeScript config, the same goes into `defineConfig`:

```ts title="oxlint.config.ts"
import { defineConfig } from "oxlint";

export default defineConfig({
  jsPlugins: ["oxlint-plugin-hyper-fetch"],
  rules: {
    "hyper-fetch/client-generic-types": "error",
    "hyper-fetch/request-generic-types": "error",
  },
});
```

Each rule accepts `"off"`, `"warn"` or `"error"`.

## Rules

| Rule                                                                                  | Description                                                    | Recommended   | Fixable |
| ------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------- | ------- |
| [`client-generic-types`](/docs/integrations/plugin-oxlint/rules#client-generic-types)   | Checks the generic of `createClient` from `@hyper-fetch/core` | No preset     | No      |
| [`request-generic-types`](/docs/integrations/plugin-oxlint/rules#request-generic-types) | Checks the generic of every `.createRequest<...>()` call      | No preset     | No      |

## Migrate from ESLint

Rule ids are the same, so only the plugin registration changes:

```json title=".oxlintrc.json"
{
  // diff-remove-next-line
  "plugins": ["hyper-fetch"],
  // diff-add-next-line
  "jsPlugins": ["oxlint-plugin-hyper-fetch"],
  "rules": {
    "hyper-fetch/client-generic-types": "error",
    "hyper-fetch/request-generic-types": "error"
  }
}
```

Oxlint parses every file in Rust, and handing the AST to a JS plugin is the expensive part. So
`request-generic-types` only runs where the source has `createRequest<`, and `client-generic-types` only where it
mentions both `@hyper-fetch/core` and `createClient`.
