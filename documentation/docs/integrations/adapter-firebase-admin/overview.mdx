# Firebase Admin SDK for Node.js with typed requests

[Read the API Reference »](/api/adapter-firebase-admin/Functions/FirebaseAdminAdapter.mdx)

`@hyper-fetch/firebase-admin` wraps the firebase admin sdk node package (`firebase-admin`) so Firestore and Realtime
Database operations from server code are HyperFetch requests. Route handlers, workers and scripts get typed responses,
retries and queues with the same request API as the browser package.

---

:::tip Purpose

1.  **Server-side Firebase as requests**: Admin SDK reads and writes are regular HyperFetch requests.
2.  **Same API as the web package**: methods, constraints and responses match `@hyper-fetch/firebase`, apart from the
    differences listed below.
3.  **Retries and queues for backend work**: HyperFetch retry, deduplication and queueing on top of the Admin SDK.
4.  **Live data on the server**: `FirebaseSocketsAdminAdapter` listens to Firestore and Realtime Database changes.
5.  **No rejected promises**: Firebase errors come back in `response.error`.

:::

---

## What the Firebase Admin SDK is for

Firebase has two JavaScript SDKs. The web SDK (`firebase`) runs in the browser as the signed-in user, and security
rules decide what that user may read and write. The Admin SDK (`firebase-admin`) runs on a server you control, such as
Node.js, Cloud Functions or a container. It authenticates with a service account or the default credentials of the
environment, and it has full access to the project.

Use the Admin SDK for work that should not depend on a user's rules: webhooks that update orders, scheduled cleanups,
data migrations, or an API route that checks permissions in your own code first. Never ship it, or its credentials, to
a browser.

---

## Installation

```bash
npm install @hyper-fetch/core @hyper-fetch/firebase-admin firebase-admin
```

Add `@hyper-fetch/sockets` for live listeners.

## Setup

```ts
import { Client } from "@hyper-fetch/core";
import { FirebaseAdminAdapter } from "@hyper-fetch/firebase-admin";
import { cert, initializeApp } from "firebase-admin/app";
import { getFirestore } from "firebase-admin/firestore";

initializeApp({ credential: cert(JSON.parse(process.env.FIREBASE_SERVICE_ACCOUNT!)) });

export const client = new Client({ url: "" }).setAdapter(FirebaseAdminAdapter(getFirestore()));

type Order = { __key: string; status: "open" | "paid"; total: number };

const getOrders = client.createRequest<{ response: Order[] }>()({
  endpoint: "orders",
  method: "getDocs",
});

const { data, error } = await getOrders.send();
```

Use `getDatabase()` from `firebase-admin/database` for Realtime Database; `initializeApp` then needs a `databaseURL`.

| Database instance | Methods                                                           | Default method |
| ----------------- | ----------------------------------------------------------------- | -------------- |
| `getFirestore()`  | `getDoc`, `getDocs`, `addDoc`, `setDoc`, `updateDoc`, `deleteDoc` | `getDoc`       |
| `getDatabase()`   | `get`, `set`, `push`, `update`, `remove`                          | `get`          |

:::danger Admin access bypasses security rules

1.  The Admin SDK reads and writes everything, whatever your security rules say. Check who may do what in your own code
    before you send a request.
2.  Keep service account credentials on the server. Browser code uses
    [`@hyper-fetch/firebase`](/docs/integrations/adapter-firebase/overview).

:::

## Paths and responses

Paths, responses and querying work like the web package, apart from the
[differences](#differences-from-hyper-fetchfirebase) below:

- The Firebase path is `client.url + endpoint`. An odd number of segments is a collection or list, an even number a
  document or value.
- Responses are `{ data, error, status, success, extra }`, with `status` `"success"`, `"emptyResource"` or `"error"`.
- Documents and list items carry `__key`, their id.
- Queries are a `queryParams` callback, checked against the document type when the request declares it:

```ts
const { data } = await getOrders.send({
  queryParams: (c) => c.where("status", "==", "open").orderBy("total", "desc").limit(50),
});
```

See the [Firebase adapter overview](/docs/integrations/adapter-firebase/overview) for the full rules.

## Differences from `@hyper-fetch/firebase`

| Topic                                     | `@hyper-fetch/firebase` (web)                | `@hyper-fetch/firebase-admin` (server)         |
| ----------------------------------------- | -------------------------------------------- | ---------------------------------------------- |
| Request adapter                           | `FirebaseAdapter`                            | `FirebaseAdminAdapter`                         |
| Socket adapter                            | `FirebaseSocketsAdapter`                     | `FirebaseSocketsAdminAdapter`                  |
| Security rules                            | enforced for the signed-in user              | bypassed                                       |
| Firestore `setDoc` `data`                 | the payload                                  | the Admin SDK `WriteResult`                    |
| Firestore socket `connect` / `disconnect` | toggle the network of the instance           | throw; stop listeners with their stop function |
| Realtime document listener `data`         | the value                                    | the value plus `__key`                         |
| Firestore listener `extra`                | `ref`, `snapshot`, `status`, `groupedResult` | the same, plus `unsubscribe`                   |

:::note When to use it

- API routes and server actions that read or write Firebase on behalf of a user you already authorized.
- Background jobs and scripts where retries, queues and typed responses save you wiring.
- Code shared between server and browser that should look the same on both sides.

:::

---

:::secondary Summary

1.  Pass `getFirestore()` or `getDatabase()` from `firebase-admin` to `FirebaseAdminAdapter`.
2.  Paths, responses, `__key` and `queryParams` callbacks match the web package.
3.  Admin access bypasses security rules, so authorize in your own code.
4.  `setDoc` returns the `WriteResult`, and the Firestore socket cannot connect or disconnect.

:::
