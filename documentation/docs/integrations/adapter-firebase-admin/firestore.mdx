# Firestore with the Firebase Admin SDK in Node.js

Each Firestore operation from Node.js is a request with a Firestore `method`, run by the Admin SDK. Methods, data and
queries match the [web Firestore page](/docs/integrations/adapter-firebase/firestore), so this page shows the server
setup and the differences.

:::tip Purpose

1. **Read** documents and collections with `getDoc` and `getDocs`.
2. **Write** with `addDoc`, `setDoc`, `updateDoc` and `deleteDoc`, with the payload typed per request.
3. **Query** collections with typed constraints and page through them with cursors.

:::

---

## Setup

Pass the Admin SDK Firestore instance to `FirebaseAdminAdapter`. With `url: ""` every endpoint is the full Firestore
path.

```ts title="server/firebase.ts"
import { createClient } from "@hyper-fetch/core";
import { FirebaseAdminAdapter } from "@hyper-fetch/firebase-admin";
import { initializeApp } from "firebase-admin/app";
import { getFirestore } from "firebase-admin/firestore";

initializeApp();

export const client = createClient({ url: "" }).setAdapter(
  FirebaseAdminAdapter(getFirestore()),
);

export type Order = {
  status: "open" | "paid";
  total: number;
  createdAt: number;
};
// __key is the document id, added by the adapter
export type OrderDoc = Order & { __key: string };
```

---

## Methods

The same six methods as the [web package](/docs/integrations/adapter-firebase/firestore#methods), with `getDoc` as the
default. Only `setDoc` returns something else: the Admin SDK `WriteResult` (with `writeTime`) instead of the payload.

### Read

```ts title="server/orders.ts"
export const getOrder = client.createRequest<{ response: OrderDoc | null }>()({
  endpoint: "orders/:orderId",
});

const { data } = await getOrder.setParams({ orderId: "a1" }).send();
```

### Write

```ts title="server/orders.ts"
import type { WriteResult } from "firebase-admin/firestore";

export const addOrder = client.createRequest<{
  response: OrderDoc;
  payload: Order;
}>()({
  endpoint: "orders",
  method: "addDoc",
});

export const saveOrder = client.createRequest<{
  response: WriteResult;
  payload: Order;
}>()({
  endpoint: "orders/:orderId",
  // add options: { merge: true } to merge into the existing document
  method: "setDoc",
});

export const markPaid = client.createRequest<{
  response: Partial<Order>;
  payload: Partial<Order>;
}>()({
  endpoint: "orders/:orderId",
  method: "updateDoc",
});

const { data: created } = await addOrder.send({
  payload: { status: "open", total: 40, createdAt: Date.now() },
});
const { error } = await markPaid
  .setParams({ orderId: created!.__key })
  .send({ payload: { status: "paid" } });
```

## Querying

The chain and its typing match the [web package](/docs/integrations/adapter-firebase/firestore#querying). Import
`FirestoreQueryParams` from `@hyper-fetch/firebase-admin`.

```ts title="server/orders.ts"
import type { FirestoreQueryParams } from "@hyper-fetch/firebase-admin";

export const listOrders = client.createRequest<{
  response: OrderDoc[];
  queryParams?: FirestoreQueryParams<Order>;
}>()({
  endpoint: "orders",
  method: "getDocs",
});
```

### Pagination

```ts title="server/orders.ts"
const page1 = await listOrders.send({
  queryParams: (c) => c.orderBy("createdAt", "desc").limit(100),
});
const last = page1.data?.at(-1);

const page2 = await listOrders.send({
  queryParams: (c) =>
    c.orderBy("createdAt", "desc").startAfter(last!.createdAt).limit(100),
});
```

### Constraints as data

The `$`-helpers (`$where`, `$orderBy`, `$limit` and the cursors) are exported from `@hyper-fetch/firebase-admin` and work
as on the [web](/docs/integrations/adapter-firebase/firestore#constraints-as-data).

## Firestore in your app

Send requests from route handlers, server actions or jobs, after you checked that the caller may do it. Admin requests
bypass security rules.

```ts title="server/routes/pay.ts"
import { markPaid } from "../orders";

export async function payOrder(orderId: string, userId: string) {
  // check that userId owns orderId before writing
  const { error, status } = await markPaid
    .setParams({ orderId })
    .send({ payload: { status: "paid" } });

  return error ? { ok: false, status } : { ok: true };
}
```

## Web and admin differences

Firestore requests work the same in [`@hyper-fetch/firebase`](/docs/integrations/adapter-firebase/firestore), except:

| Topic           | `@hyper-fetch/firebase` (web)   | `@hyper-fetch/firebase-admin` (server) |
| --------------- | ------------------------------- | -------------------------------------- |
| `setDoc` `data` | the payload                     | the Admin SDK `WriteResult`            |
| Security rules  | enforced for the signed-in user | bypassed                               |

---

:::secondary Summary

- The same six methods as the web package, with `getDoc` as the default.
- `setDoc` resolves with the `WriteResult`; the other methods return the same data as on the web.
- Queries are a `queryParams` callback, and cursors page through ordered results.

:::
