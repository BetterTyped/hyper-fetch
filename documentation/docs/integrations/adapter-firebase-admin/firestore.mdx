# Firestore with the Firebase Admin SDK in Node.js

To use Firestore from the firebase admin sdk node side, this package turns each operation into a HyperFetch request with
a Firestore `method`. Requests behave like the [web package](/docs/integrations/adapter-firebase/firestore), with the
Admin SDK underneath, so security rules do not apply and your code decides who may do what.

---

:::tip Purpose

1.  **Read** documents and collections with `getDoc` and `getDocs`.
2.  **Write** with `addDoc`, `setDoc`, `updateDoc` and `deleteDoc`, with the payload typed per request.
3.  **Query** collections with constraints and cursors.

:::

---

## Setup

```ts
import { Client } from "@hyper-fetch/core";
import { FirebaseAdminAdapter } from "@hyper-fetch/firebase-admin";
import { initializeApp } from "firebase-admin/app";
import { getFirestore } from "firebase-admin/firestore";

initializeApp();

export const client = new Client({ url: "" }).setAdapter(FirebaseAdminAdapter(getFirestore()));

type Order = { status: "open" | "paid"; total: number; createdAt: number };
type OrderDoc = Order & { __key: string }; // __key is the document id, added by the adapter
```

---

## Methods

| Method      | Path       | `data`                                  | `extra`                              |
| ----------- | ---------- | --------------------------------------- | ------------------------------------ |
| `getDocs`   | collection | documents with `__key`, `[]` when empty | `ref`, `snapshot` (QuerySnapshot)    |
| `getDoc`    | document   | the document with `__key`, or `null`    | `ref`, `snapshot` (DocumentSnapshot) |
| `addDoc`    | collection | the payload plus the new `__key`        | `ref` of the new document            |
| `setDoc`    | document   | the Admin SDK `WriteResult`             | `ref`                                |
| `updateDoc` | document   | the payload                             | `ref`                                |
| `deleteDoc` | document   | `null`                                  | `ref`                                |

`getDoc` is the default, so a request without `method` reads one document.

```ts
import type { WriteResult } from "firebase-admin/firestore";

const getOrder = client.createRequest<{ response: OrderDoc | null }>()({
  endpoint: "orders/:orderId",
});

const addOrder = client.createRequest<{ response: OrderDoc; payload: Order }>()({
  endpoint: "orders",
  method: "addDoc",
});

const saveOrder = client.createRequest<{ response: WriteResult; payload: Order }>()({
  endpoint: "orders/:orderId",
  method: "setDoc",
  // options: { merge: true } merges the payload into the existing document
});

const markPaid = client.createRequest<{ response: Partial<Order>; payload: Partial<Order> }>()({
  endpoint: "orders/:orderId",
  method: "updateDoc",
});

const deleteOrder = client.createRequest<{ response: null }>()({
  endpoint: "orders/:orderId",
  method: "deleteDoc",
});

const { data: created } = await addOrder.send({ payload: { status: "open", total: 40, createdAt: Date.now() } });
const { error } = await markPaid.setParams({ orderId: created!.__key }).send({ payload: { status: "paid" } });
```

:::info setDoc returns the write result

Unlike the web package, `setDoc` resolves with the Admin SDK `WriteResult` (with `writeTime`), not the payload. Read the
document with `getDoc` when you need its saved state.

:::

## Querying

```ts
import type { FirestoreQueryParams } from "@hyper-fetch/firebase-admin";

const getOrders = client.createRequest<{ response: OrderDoc[]; queryParams?: FirestoreQueryParams<Order> }>()({
  endpoint: "orders",
  method: "getDocs",
});

const page1 = await getOrders.send({
  queryParams: (c) => c.where("status", "==", "open").orderBy("createdAt", "desc").limit(100),
});
const last = page1.data?.at(-1);
const page2 = await getOrders.send({
  queryParams: (c) => c.where("status", "==", "open").orderBy("createdAt", "desc").startAfter(last!.createdAt).limit(100),
});
```

Constraints apply in order, fields and values are checked against `Order`, and cursors take one value per `orderBy`.
The constraints array built with the `$`-helpers works too. The full list is on the
[web Firestore page](/docs/integrations/adapter-firebase/firestore#querying).

---

:::secondary Summary

1.  The same six methods as the web package, with `getDoc` as the default.
2.  `setDoc` resolves with the `WriteResult`, unlike the web package; the other methods return the same data as there.
3.  Queries are a `queryParams` callback, and cursors page through ordered results.

:::
