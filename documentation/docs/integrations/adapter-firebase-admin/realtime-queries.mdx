Server code can listen to Firestore and Realtime Database changes through `@hyper-fetch/sockets` with
`FirebaseSocketsAdminAdapter`. Listeners work like the
[web package listeners](/docs/integrations/adapter-firebase/realtime-queries), with a few server-side differences.

---

:::tip Purpose

1.  **Listen** to Firestore queries and Realtime Database paths from workers and long-running servers.
2.  **Filter** live queries with the same constraints as requests.
3.  **Process** changes with `groupByChangeType`, or read once with `onlyOnce`.

:::

---

## Setup

```ts
import { Socket } from "@hyper-fetch/sockets";
import { FirebaseSocketsAdminAdapter } from "@hyper-fetch/firebase-admin";
import { initializeApp } from "firebase-admin/app";
import { getDatabase } from "firebase-admin/database";
import { getFirestore } from "firebase-admin/firestore";

initializeApp({ databaseURL: process.env.FIREBASE_DATABASE_URL });

export const firestoreSocket = new Socket({ url: "", adapter: FirebaseSocketsAdminAdapter(getFirestore()) });
export const realtimeSocket = new Socket({ url: "", adapter: FirebaseSocketsAdminAdapter(getDatabase()) });
```

Create the adapter inside each `new Socket(...)`. An adapter binds to the socket it was created for.

---

## Listening

```ts
import { $where } from "@hyper-fetch/firebase-admin";

type Job = { __key: string; state: "queued" | "running" | "done"; payload: unknown };

const onQueuedJobs = firestoreSocket.createListener<Job[]>()({
  topic: "jobs",
  options: { constraints: [$where("state", "==", "queued")], groupByChangeType: true },
});

const stop = onQueuedJobs.listen(({ data, extra }) => {
  const added = extra.groupedResult?.added ?? [];
  console.log(`${data.length} queued, ${added.length} new`);
});

process.on("SIGTERM", () => stop());
```

Every snapshot is delivered once, as the full current result. It includes items you already handled, so make side
effects such as sending mail idempotent, for example with a transaction or a status check.

| Option              | Database          | Effect                                                                                                                                   |
| ------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `constraints`       | both              | Constraints for the live query, the same `$`-helpers as `queryParams`.                                                                   |
| `groupByChangeType` | Firestore         | On collection listeners, adds `extra.groupedResult` with the `added`, `modified` and `removed` documents. Document listeners get `null`. |
| `onlyOnce`          | Realtime Database | Uses `once("value")`: receives the first value and stops.                                                                                |

`extra` holds `ref`, `snapshot` and `status`, plus `unsubscribe` and `groupedResult` for Firestore. `groupedResult` is
`null` when the snapshot has no document changes, and its documents have no `__key`.

```ts
const onSettings = realtimeSocket.createListener<Settings | null>()({
  topic: "settings",
  options: { onlyOnce: true },
});
```

---

:::caution Server-side differences

1.  **The Firestore socket cannot connect or disconnect.** `connect()` and `disconnect()` throw. Stop listeners with the
    function `listen` returns, and shut Firebase down with `app.delete()` from `firebase-admin/app`.
2.  **Realtime Database document listeners add `__key`.** On an even-segment path `data` is the value plus its `__key`,
    and the value should be an object.
3.  **One listener per topic on a socket.** Listeners on the same socket and topic also receive each other's snapshots.

:::

---

:::secondary Summary

1.  Create each socket with its own `FirebaseSocketsAdminAdapter(db)`.
2.  Listeners deliver every snapshot once as the full current result; keep side effects idempotent.
3.  Filter with `options.constraints`, group with `groupByChangeType`, read once with `onlyOnce`.
4.  Stop listeners with their stop function; the Firestore socket cannot disconnect.

:::
