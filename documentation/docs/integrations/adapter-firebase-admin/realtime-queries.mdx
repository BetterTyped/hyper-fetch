# Firebase Admin realtime listeners in Node.js

`FirebaseSocketsAdminAdapter` runs Admin SDK `onSnapshot` and `on("value")` through a [Socket](/docs/sockets/socket),
so a Node.js worker can react to changes, for example send an email when an order is paid. Listeners work like the
[web package listeners](/docs/integrations/adapter-firebase/realtime-queries), with the differences listed below.

:::tip Purpose

1. **Listen** to Firestore queries and Realtime Database paths from workers and long-running servers.
2. **Filter** live queries with `setQueryParams((c) => ...)`, the same chain as requests.
3. **Group** Firestore changes into added, modified and removed, or read a Realtime Database path once.

:::

---

## Setup

Install `@hyper-fetch/sockets`, then create a socket per database. Call `FirebaseSocketsAdminAdapter(db)` inside each
`new Socket(...)`, because an adapter binds to the socket it was created for.

```ts title="server/sockets.ts"
import { Socket } from "@hyper-fetch/sockets";
import { FirebaseSocketsAdminAdapter } from "@hyper-fetch/firebase-admin";
import { initializeApp } from "firebase-admin/app";
import { getDatabase } from "firebase-admin/database";
import { getFirestore } from "firebase-admin/firestore";

initializeApp({ databaseURL: process.env.FIREBASE_DATABASE_URL });

export const firestoreSocket = new Socket({
  url: "",
  adapter: FirebaseSocketsAdminAdapter(getFirestore()),
});
export const realtimeSocket = new Socket({
  url: "",
  adapter: FirebaseSocketsAdminAdapter(getDatabase()),
});
```

## Listening

Same as the [web package](/docs/integrations/adapter-firebase/realtime-queries#listening): the path is
`socket.url + topic`, `listen` returns a stop function, and every snapshot arrives once as the full current result.
That result includes items you already handled, so make side effects such as sending mail idempotent.

```ts title="server/workers/jobs.ts"
type Job = { __key: string; state: "queued" | "running" | "done" };

const onJobs = firestoreSocket.createListener<Job[]>()({ topic: "jobs" });

const stop = onJobs.listen(({ data }) => console.log(`${data.length} jobs`));

process.on("SIGTERM", () => stop());
```

---

## Filtering

Same as the [web package](/docs/integrations/adapter-firebase/realtime-queries#filtering): a callback or the `$`-helper
array, set with `setQueryParams`.

```ts title="server/workers/jobs.ts"
const onQueuedJobs = onJobs.setQueryParams((c) =>
  c.where("state", "==", "queued"),
);
```

---

## Options

The same `groupByChangeType` (Firestore) and `onlyOnce` (Realtime Database) options as the
[web package](/docs/integrations/adapter-firebase/realtime-queries#options).

### Grouping changes

`groupedResult` is `null` on document listeners and when a snapshot has no document changes. On the server its
documents have no `__key`.

```ts title="server/workers/jobs.ts"
const onJobChanges = firestoreSocket.createListener<Job[]>()({
  topic: "jobs",
  options: { groupByChangeType: true },
});

onJobChanges.listen(({ extra }) => {
  const added = extra.groupedResult?.added ?? [];
  console.log(`${added.length} new jobs`);
});
```

### Reading once

`onlyOnce` uses `once("value")`: the listener receives the first value and stops.

```ts title="server/settings.ts"
const onSettings = realtimeSocket.createListener<Settings | null>()({
  topic: "settings",
  options: { onlyOnce: true },
});
```

## Listeners in your app

Start listeners when the worker starts and stop them on shutdown. Every `listen()` holds an open Firebase subscription
until its stop function runs. Shut Firebase down with `app.delete()` from `firebase-admin/app`.

---

## Web and admin differences

Listeners work the same in [`@hyper-fetch/firebase`](/docs/integrations/adapter-firebase/realtime-queries), except:

| Topic                                        | `@hyper-fetch/firebase` (web)                | `@hyper-fetch/firebase-admin` (server)         |
| -------------------------------------------- | -------------------------------------------- | ---------------------------------------------- |
| Socket adapter                               | `FirebaseSocketsAdapter`                     | `FirebaseSocketsAdminAdapter`                  |
| Firestore socket `connect()`, `disconnect()` | toggle the network of the instance           | throw, stop listeners with their stop function |
| Realtime document listener `data`            | the value                                    | the value plus `__key`                         |
| Firestore listener `extra`                   | `ref`, `snapshot`, `status`, `groupedResult` | the same, plus `unsubscribe`                   |
| Documents in `groupedResult`                 | with `__key`                                 | without `__key`                                |

---

## Limits

The [web limits](/docs/integrations/adapter-firebase/realtime-queries#limits) apply: one listener per topic on a socket,
and sockets cannot emit. On the Realtime Database, document listeners spread the value into an object with `__key`, so
store objects at those paths.

---

:::secondary Summary

- Create each socket with its own `FirebaseSocketsAdminAdapter(db)`.
- Every snapshot arrives as the full current result, so keep side effects idempotent.
- Filter with `setQueryParams((c) => ...)`, group with `groupByChangeType`, read once with `onlyOnce`.
- Stop listeners with their stop function; the Firestore socket cannot disconnect.

:::
