Realtime Database operations from server code are HyperFetch requests with a Realtime Database `method`. They behave
like the [web package](/docs/integrations/adapter-firebase/realtime), with the Admin SDK underneath.

---

:::tip Purpose

1.  **Read** values and lists with `get`.
2.  **Write** with `set`, `push`, `update` and `remove`, with the payload typed per request.
3.  **Query** lists with ordering, limits and cursors.

:::

---

## Setup

```ts
import { Client } from "@hyper-fetch/core";
import { FirebaseAdminAdapter } from "@hyper-fetch/firebase-admin";
import { initializeApp } from "firebase-admin/app";
import { getDatabase } from "firebase-admin/database";

initializeApp({ databaseURL: process.env.FIREBASE_DATABASE_URL });

export const client = new Client({ url: "" }).setAdapter(FirebaseAdminAdapter(getDatabase()));

type Session = { userId: string; lastSeen: number };
```

---

## Methods

| Method   | `data`                           | `extra`                       |
| -------- | -------------------------------- | ----------------------------- |
| `get`    | the value, or a list             | `ref`, `snapshot`             |
| `set`    | the payload                      | `ref`                         |
| `push`   | the payload plus the new `__key` | `ref` of the new child, `key` |
| `update` | the payload                      | `ref`                         |
| `remove` | `null`                           | `ref`                         |

`get` is the default, so a request without `method` reads.

```ts
const getSessions = client.createRequest<{ response: (Session & { __key: string })[] | null }>()({
  endpoint: "sessions",
});

const startSession = client.createRequest<{ response: Session & { __key: string }; payload: Session }>()({
  endpoint: "sessions",
  method: "push",
});

const touchSession = client.createRequest<{ response: Partial<Session>; payload: Partial<Session> }>()({
  endpoint: "sessions/:sessionId",
  method: "update",
});

const endSession = client.createRequest<{ response: null }>()({
  endpoint: "sessions/:sessionId",
  method: "remove",
});

const { data: session } = await startSession.send({ payload: { userId: "u1", lastSeen: Date.now() } });
await touchSession.setParams({ sessionId: session!.__key }).send({ payload: { lastSeen: Date.now() } });
```

`set` replaces the value at the path, and a `null` payload deletes it.

---

## Values and lists

As in the web package, `get` returns an odd-segment path (`sessions`) as an array of children, each spread into an
object with its `__key`, or `null` when empty. An even-segment path (`sessions/abc`) returns the stored value as is.
Lists should hold objects.

---

## Querying

```ts
import type { RealtimeDBQueryParams } from "@hyper-fetch/firebase-admin";

const getStaleSessions = client.createRequest<{
  response: (Session & { __key: string })[] | null;
  queryParams?: RealtimeDBQueryParams<Session>;
}>()({
  endpoint: "sessions",
  method: "get",
});

const { data } = await getStaleSessions.send({
  queryParams: (c) => c.orderByChild("lastSeen").limitToFirst(100),
});
const last = data?.at(-1);
const next = await getStaleSessions.send({
  queryParams: (c) => c.orderByChild("lastSeen").startAfter(last!.lastSeen, last!.__key).limitToFirst(100),
});
```

A query can have one `orderBy*`, and `orderByChild` needs an `.indexOn` rule; a missing one arrives in
`response.error`. The full list of chain methods is on the
[web Realtime Database page](/docs/integrations/adapter-firebase/realtime#querying).

---

:::secondary Summary

1.  `get` reads; `set` and `update` resolve with the payload, `push` adds `__key`, and `remove` resolves with `null`.
2.  Odd-segment paths return lists of objects with `__key`; even-segment paths return the value.
3.  Queries are a `queryParams` callback, and cursors take a value and an optional tie-breaking key.

:::
