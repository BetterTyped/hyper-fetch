# Realtime Database with the Firebase Admin SDK

Each Realtime Database operation from Node.js is a request with a Realtime Database `method`, run by the Admin SDK.
Methods, lists and queries match the [web Realtime Database page](/docs/integrations/adapter-firebase/realtime), so this
page shows the server setup and the differences.

:::tip Purpose

1. **Read** values and lists with `get`.
2. **Write** with `set`, `push`, `update` and `remove`, with the payload typed per request.
3. **Query** lists with ordering, limits and cursors.

:::

---

## Setup

Pass the Admin SDK Realtime Database instance to `FirebaseAdminAdapter`. `initializeApp` needs a `databaseURL`.

```ts title="server/firebase.ts"
import { createClient } from "@hyper-fetch/core";
import { FirebaseAdminAdapter } from "@hyper-fetch/firebase-admin";
import { initializeApp } from "firebase-admin/app";
import { getDatabase } from "firebase-admin/database";

initializeApp({ databaseURL: process.env.FIREBASE_DATABASE_URL });

export const client = createClient({ url: "" }).setAdapter(FirebaseAdminAdapter(getDatabase()));

export type Session = { userId: string; lastSeen: number };
```

---

## Methods

The same five methods as the [web package](/docs/integrations/adapter-firebase/realtime#methods), with `get` as the
default and the same `data` and `extra`.

### Read

```ts title="server/sessions.ts"
export const getSessions = client.createRequest<{ response: (Session & { __key: string })[] | null }>()({
  endpoint: "sessions",
});
```

### Write

```ts title="server/sessions.ts"
export const startSession = client.createRequest<{ response: Session & { __key: string }; payload: Session }>()({
  endpoint: "sessions",
  method: "push",
});

export const touchSession = client.createRequest<{ response: Partial<Session>; payload: Partial<Session> }>()({
  endpoint: "sessions/:sessionId",
  method: "update",
});

const { data: session } = await startSession.send({ payload: { userId: "u1", lastSeen: Date.now() } });
await touchSession.setParams({ sessionId: session!.__key }).send({ payload: { lastSeen: Date.now() } });
```

---

## Values and lists

Same as the [web package](/docs/integrations/adapter-firebase/realtime#values-and-lists): an odd-segment path
(`sessions`) returns an array of children with their `__key`, or `null` when empty, and an even-segment path
(`sessions/abc`) returns the stored value.

---

## Querying

The chain and its typing match the [web package](/docs/integrations/adapter-firebase/realtime#querying). Import
`RealtimeDBQueryParams` from `@hyper-fetch/firebase-admin`. `orderByChild` needs an `.indexOn` rule, and a missing one
arrives in `response.error`.

```ts title="server/sessions.ts"
import type { RealtimeDBQueryParams } from "@hyper-fetch/firebase-admin";

export const listSessions = client.createRequest<{
  response: (Session & { __key: string })[] | null;
  queryParams?: RealtimeDBQueryParams<Session>;
}>()({
  endpoint: "sessions",
  method: "get",
});
```

### Pagination

```ts title="server/sessions.ts"
const page1 = await listSessions.send({ queryParams: (c) => c.orderByChild("lastSeen").limitToFirst(100) });
const last = page1.data?.at(-1);

const page2 = await listSessions.send({
  queryParams: (c) => c.orderByChild("lastSeen").startAfter(last!.lastSeen, last!.__key).limitToFirst(100),
});
```

### Constraints as data

The `$`-helpers (`$orderByChild`, `$limitToFirst`, `$equalTo` and the cursors) are exported from
`@hyper-fetch/firebase-admin` and work as on the [web](/docs/integrations/adapter-firebase/realtime#constraints-as-data).

## Realtime Database in your app

Send requests from route handlers, server actions or jobs, after you checked that the caller may do it. A cleanup job,
for example:

```ts title="server/jobs/cleanup.ts"
import { listSessions } from "../sessions";

export async function findStaleSessions(olderThan: number) {
  const { data, error } = await listSessions.send({
    queryParams: (c) => c.orderByChild("lastSeen").endAt(olderThan),
  });

  return error ? [] : (data ?? []);
}
```

## Web and admin differences

Realtime Database requests work the same in [`@hyper-fetch/firebase`](/docs/integrations/adapter-firebase/realtime),
except:

| Topic                      | `@hyper-fetch/firebase` (web)    | `@hyper-fetch/firebase-admin` (server)            |
| -------------------------- | -------------------------------- | ------------------------------------------------- |
| Database instance          | `getDatabase(app)` from `firebase/database` | `getDatabase()` from `firebase-admin/database`, with `databaseURL` in `initializeApp` |
| Security rules             | enforced for the signed-in user  | bypassed                                          |

---

:::secondary Summary

- `get` reads; `set` and `update` resolve with the payload, `push` adds `__key`, and `remove` resolves with `null`.
- Odd-segment paths return lists of objects with `__key`; even-segment paths return the value.
- Queries are a `queryParams` callback, and cursors take a value and an optional tie-breaking key.

:::
