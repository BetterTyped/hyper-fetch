# Ruby on Rails

rswag describes your Rails API in request specs and writes an OpenAPI document from them. The
[HyperFetch CLI](/docs/cli/overview) turns that document into a typed TypeScript SDK, so the frontend calls every
endpoint with the shapes your specs check.

:::tip Purpose

1. **Tested contract**: the document comes from specs that run against your API.
2. **Typed client**: responses, bodies and params follow the schemas in your specs.
3. **One command to resync**: change a spec, regenerate, and the compiler shows every call to fix.

:::

---

## Install

On the server, add rswag to the Gemfile and run `bundle install` and its installers (`rails g rswag:api:install` and
`rails g rswag:specs:install`). In the frontend, install HyperFetch and the CLI:

```ruby title="server/Gemfile"
gem "rswag-specs", group: [:development, :test]
gem "rswag-api"
```

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
npm install -D @hyper-fetch/cli
```

---

## 1. Serve the OpenAPI document

The CLI reads JSON, so set the output format in `spec/swagger_helper.rb`:

```ruby title="server/spec/swagger_helper.rb"
RSpec.configure do |config|
  config.openapi_root = Rails.root.join("swagger").to_s
  config.openapi_specs = {
    "v1/openapi.json" => {
      openapi: "3.0.1",
      info: { title: "Shop API", version: "v1" },
      paths: {}
    }
  }
  # highlight-next-line
  config.openapi_format = :json
end
```

Describe each endpoint in a spec, then write the document:

```bash title="server"
rails rswag:specs:swaggerize
```

It lands in `swagger/v1/openapi.json`, and `rswag-api` serves it on `/api-docs/v1/openapi.json`.

---

## 2. Generate the SDK

Run the CLI in the frontend project while the server is running:

```bash title="frontend"
npx hyper-fetch generate --template openapi --fileName rails.sdk.ts \
  --overwrite --url http://localhost:3000/api-docs/v1/openapi.json
```

It writes `src/api/rails.sdk.ts`. The folder comes from `api.json`, which the first run creates. Every path becomes
nested keys and every method a `$` key, so `GET /users/{id}` is `sdk.users.$id.$get`.

---

## 3. Call your API

```ts title="frontend/src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

import { createSdk } from "./rails.sdk";

export const client = createClient({ url: "http://localhost:3000" });
export const sdk = createSdk(client);
```

```ts title="frontend/src/users.ts"
import { sdk } from "./api/client";

// data is typed from the response schema in your spec
const { data, error } = await sdk.users.$id.$get.setParams({ id: 42 }).send();
```

Every entry is a regular [Request](/docs/core/request), so it also works with `useFetch` and `useSubmit` from
[`@hyper-fetch/react`](/docs/react/overview).

---

## Framework quirks

- **JSON only**: rswag writes YAML by default. Keep `openapi_format = :json`, because the CLI does not read YAML.
- **No running server**: pass the path of `swagger/v1/openapi.json` to `--url`. A local path is resolved from the
  frontend project.

---

## Keep the SDK in sync

Add a script so regenerating is one command locally and in CI. This one reads the file, so run
`rails rswag:specs:swaggerize` first. `-o` overwrites the old file without asking:

```json title="frontend/package.json"
{
  "scripts": {
    "api:generate": "hyper-fetch generate -t openapi -u ../server/swagger/v1/openapi.json -f rails.sdk.ts -o"
  }
}
```

---

:::secondary Summary

- rswag writes an OpenAPI document from your request specs.
- `hyper-fetch generate` turns it into a typed SDK.
- `createSdk(client)` gives you typed requests for `send()`, `useFetch` and `useSubmit`.

:::
