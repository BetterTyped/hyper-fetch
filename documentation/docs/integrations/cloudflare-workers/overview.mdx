# Cloudflare Workers

Cloudflare Workers, Vercel Edge Functions and other edge runtimes run web standard APIs instead of Node.js. HyperFetch
only needs one of them, `fetch`, so typed requests, retries and response mapping run there unchanged.

:::tip Purpose

1. **Web standards only**: the default adapter uses `fetch` and nothing from Node.js.
2. **Typed calls at the edge**: call upstream APIs with typed requests or a generated SDK.
3. **Safe for shared isolates**: outside the browser the client caches nothing unless a request has a scope.

:::

## Install

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
```

## Send a request

The client needs the API URL from `env`, so create it inside the handler:

```ts title="src/index.ts"
import { createClient } from "@hyper-fetch/core";

type Env = { API_URL: string };

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    // highlight-next-line
    const client = createClient({ url: env.API_URL });
    const getProduct = client.createRequest<{ response: { id: string; price: number } }>()({
      endpoint: "/products/:id",
    });

    const id = new URL(request.url).searchParams.get("id") ?? "";
    const { data, error } = await getProduct.setParams({ id }).setRetry(1).send();

    return Response.json(error ?? data, { status: error ? 502 : 200 });
  },
};
```

The same handler shape works in Vercel Edge Functions and in Next.js route handlers on the edge runtime.

## Use it in a server

An isolate serves many requests, and the [client](/docs/core/client) runs in `"server"` mode there: the cache stays off
unless a request has a scope, so one user's response never answers another's. To cache per user, add
`setScope(userId)`. For a typed SDK of the API you call, generate it with the CLI and create it from the client:

```bash
npx @hyper-fetch/cli@latest generate --template openapi --fileName upstream.sdk.ts --overwrite \
  --url https://api.example.com/openapi.json
```

```ts title="src/index.ts"
// createSdk comes from the generated upstream.sdk.ts
const sdk = createSdk(createClient({ url: env.API_URL }));
const { data } = await sdk.products.$id.$get.setParams({ id }).send();
```

---

## Runtime quirks

- **No Node.js APIs needed**: HyperFetch works without the `nodejs_compat` flag.
- **Bindings**: `env` values such as `API_URL` reach the Worker only through the handler, which is why the client is
  created there. A client built from a constant URL can live at module level.
