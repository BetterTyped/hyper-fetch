# oRPC client for React with caching and hooks

`@hyper-fetch/orpc` calls the procedures of an [oRPC](https://orpc.dev/docs/getting-started) `RPCHandler` as HyperFetch
requests, typed from your router or contract. Use it instead of `createORPCClient` when you want one client for oRPC,
REST, GraphQL and sockets, with caching, deduplication, retries, offline queues and the React hooks.

:::tip Purpose

1. **Call oRPC procedures** with the request API you use for REST and GraphQL.
2. **Infer types from your router or contract** through the regular [`createSdk`](/docs/core/sdk).
3. **Keep rich types** such as `Date`, `BigInt`, `Map`, `Set` and files, encoded by the oRPC serializer.
4. **Listen to event iterators** over HTTP streams or a WebSocket, see
   [event iterators](/docs/integrations/adapter-orpc/event-iterators).

:::

---

## Install

`@orpc/client` (v1) is a required peer dependency: the adapter encodes data with its serializer, so client and server
always speak the same format. `@orpc/server` is only needed for the `OrpcSchema<typeof router>` type.

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/orpc @orpc/client
```

---

## Setup

1. Point the client at the URL where your `RPCHandler` is mounted.

```ts title="api/client.ts"
import { createClient } from "@hyper-fetch/core";
import { OrpcAdapter } from "@hyper-fetch/orpc";

export const client = createClient({
  url: "http://localhost:3000/rpc",
}).setAdapter(OrpcAdapter());
```

2. Describe the router with `OrpcSchema` and create the SDK. `camelCaseToKebabCase: false` keeps procedure names as
   written in the router (`findById`, not `find-by-id`).

```ts title="api/sdk.ts"
import { createSdk } from "@hyper-fetch/core";
import type { OrpcSchema } from "@hyper-fetch/orpc";

import type { router } from "../server/router";
import { client } from "./client";

export const api = createSdk<typeof client, OrpcSchema<typeof router>>(client, {
  camelCaseToKebabCase: false,
});
```

3. Call procedures with `send()` or the hooks. Every procedure is available as `$query` and `$mutation`, and its input
   is the payload.

```tsx title="Planet.tsx"
import { useFetch, useSubmit } from "@hyper-fetch/react";

import { api } from "./api/sdk";

export const Planet = ({ id }: { id: number }) => {
  const { data, loading } = useFetch(api.planet.find.$query.setPayload({ id }));
  const { submit, submitting } = useSubmit(api.planet.create.$mutation);

  if (loading) return <p>Loading...</p>;

  return (
    <button
      disabled={submitting}
      onClick={() => submit({ payload: { name: "Mars" } })}
    >
      Add a planet next to {data?.name}
    </button>
  );
};
```

For contract-first APIs pass the client type of the contract, which works without `@orpc/server`:
`createSdk<typeof client, OrpcSchema<ContractRouterClient<typeof contract>>>(client, { camelCaseToKebabCase: false })`.
`OrpcSchema<RouterClient<typeof router>>` works the same way.

## How it maps

| oRPC                                      | HyperFetch                                                                                    |
| ----------------------------------------- | --------------------------------------------------------------------------------------------- |
| `RPCHandler` URL with its `prefix`        | client `url`                                                                                  |
| Procedure path (`planet.find`)            | `endpoint` `planet/find`, or `api.planet.find` in the SDK                                     |
| Procedure                                 | request with method `QUERY` (default, `$query`) or `MUTATION` (`$mutation`)                   |
| Input                                     | `payload`, serialized with the oRPC serializer                                                |
| Output                                    | `data`, with `Date`, `BigInt`, `Map`, `Set` and files restored                                |
| `ORPCError`                               | `error` in the shape of `ORPCError.toJSON()`, with the response's HTTP `status`               |
| Response headers                          | `extra.headers`                                                                               |
| Event iterator procedure                  | a listener with `OrpcStreamAdapter` or `OrpcWebsocketAdapter`, see [event iterators](/docs/integrations/adapter-orpc/event-iterators) |

On the wire, both methods send `POST {url}/planet/find` with the serialized input, which is what `RPCHandler` accepts by
default. The adapter adds the serialized input to the cache and query keys, so `{ id: 1 }` and `{ id: 2 }` are cached,
deduplicated and queued separately. The abort key has no input, so `request.abort()` stops every running call of the
procedure. Queries are deduplicated by default, mutations are not.

Without the SDK, create the request yourself:

```ts title="api/planets.ts"
type Planet = { id: number; name: string };

export const findPlanet = client.createRequest<{
  response: Planet;
  payload: { id: number };
}>()({
  endpoint: "planet/find",
  method: "QUERY",
});
```

## Adapter options

| Option                  | Default  | Description                                                                         |
| ----------------------- | -------- | ----------------------------------------------------------------------------------- |
| `queryMethod`           | `"POST"` | HTTP method of `QUERY` requests. Mutations always use `POST`.                       |
| `customJsonSerializers` | -        | Serializers of custom types. The server's `RPCHandler` needs the same list.          |

Request `options` are passed to `fetch` (except `method`, `headers`, `body` and `signal`), plus `timeout` in
milliseconds (default `5000`) and a per-request `queryMethod`.

```ts title="api/client.ts"
export const client = createClient({
  url: "http://localhost:3000/rpc",
}).setAdapter(
  OrpcAdapter({ queryMethod: "GET", customJsonSerializers: [moneySerializer] }),
);

const { data } = await api.planet.list.$query
  .setOptions({ queryMethod: "POST", timeout: 10000 })
  .send();
```

With `queryMethod: "GET"`, queries go as `GET {url}/planet/find?data=...`, so browsers, proxies and CDNs can cache them.
`RPCHandler` accepts `GET` only for procedures declared with `.route({ method: "GET" })`, unless you turn off its
`strictGetMethodPluginEnabled` option; others fail with `METHOD_NOT_SUPPORTED` and status `405`. Requests with files,
or with a URL longer than 2083 characters, are sent with `POST`, as in `RPCLink`.

## Errors

Failed procedures resolve with the error the server sent and the HTTP status. With `OrpcSchema`, defined errors keep
their code and data types, so checking `error.defined` and `error.code` narrows `error.data`.

```ts title="planet.ts"
const { error, status } = await api.planet.find.$query
  .setPayload({ id: 999 })
  .send();

// `error` also includes the client's global error (`Error` by default), so
// check for the oRPC shape first
if (
  error &&
  "defined" in error &&
  error.defined &&
  error.code === "NOT_FOUND"
) {
  // 404, "Planet not found", { id: 999 }
  console.log(status, error.message, error.data);
}
```

Errors outside the `.errors()` map have `defined: false` and `unknown` data. A response that did not come from a
procedure, such as an HTML page from a proxy, resolves with an `UnexpectedError`. For requests created by hand, type
errors with `OrpcErrorType`.

## Limits

- Request batching is not supported.
- Event iterator procedures are left out of `OrpcSchema`. Use the [socket adapters](/docs/integrations/adapter-orpc/event-iterators).
- The SDK can't reach a procedure named like a request property, such as `send` or `method`. Use `createRequest` with
  the procedure path for those.
- A `cancelable` request only replaces a running call with the same input. To cancel on every keystroke of a search,
  share one query key: `api.planet.search.$query.setCancelable(true).setDeduplicate(false).setQueryKey("planet-search")`.
- Query params are appended to the URL. The `data` key is reserved by the oRPC format and skipped.

---

:::secondary Summary

- `OrpcAdapter()` calls procedures with the RPC protocol, and `OrpcSchema` types them through `createSdk`.
- Every procedure is available as `$query` and `$mutation`, and its input is the payload.
- The oRPC serializer keeps `Date`, `BigInt`, files and other rich types.
- Errors keep the `ORPCError` shape, and defined errors are typed by code.

:::
