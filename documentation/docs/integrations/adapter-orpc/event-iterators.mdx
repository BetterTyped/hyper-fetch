# oRPC event iterators and streaming in React

An oRPC event iterator is a procedure that returns an async generator, so the server keeps sending events after one
call: chat messages, job progress or model tokens. `OrpcStreamAdapter` and `OrpcWebsocketAdapter` turn each one into a
typed [Listener](/docs/sockets/listener) on a [Socket](/docs/sockets/socket), with the procedure input as the payload.

:::tip Purpose

1. **Listen to event iterators** with the `Socket`, `Listener` and `useListener` API of other realtime sources.
2. **Infer types from your router or contract** with `OrpcSocketSchema` and `createSocketSdk`.
3. **Share one server subscription** between listeners with the same input.
4. **Resume after reconnecting** from the id of the last event, set with `withEventMeta`.

:::

---

## Install

The socket adapters ship in `@hyper-fetch/orpc` and need `@hyper-fetch/sockets`.

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/sockets @hyper-fetch/orpc @orpc/client
```

## Listen over HTTP

`OrpcStreamAdapter` calls the procedure like the `RPCLink` of `@orpc/client/fetch`: `POST {url}/planet/onUpdate` with the
serialized input, answered with a `text/event-stream`. It works with the HTTP `RPCHandler` that already serves your
queries.

```ts title="server/router.ts"
import { EventPublisher, os, withEventMeta } from "@orpc/server";
import { z } from "zod";

type Planet = { id: number; name: string; version: number };

const publisher = new EventPublisher<Record<string, Planet>>();

export const router = {
  planet: {
    onUpdate: os.input(z.object({ id: z.number() })).handler(async function* ({ input, signal }) {
      for await (const planet of publisher.subscribe(`planet/${input.id}`, { signal })) {
        yield withEventMeta(planet, { id: String(planet.version) });
      }
    }),
  },
};
```

```ts title="api/socket.ts"
import { createSocketSdk, Socket } from "@hyper-fetch/sockets";
import { OrpcStreamAdapter } from "@hyper-fetch/orpc";
import type { OrpcSocketSchema } from "@hyper-fetch/orpc";

import type { router } from "../server/router";

export const socket = new Socket({ url: "http://localhost:3000/rpc", adapter: OrpcStreamAdapter() });

export const sdk = createSocketSdk<typeof socket, OrpcSocketSchema<typeof router>>(socket, {
  camelCaseToKebabCase: false,
});

const stop = sdk.planet.onUpdate.$listener.setPayload({ id: 1 }).listen(({ data, extra }) => {
  console.log(data.name, extra.id);
});
```

Every subscription is its own request, so "connected" means the adapter opens streams: `connect()` starts every
listener's stream, `disconnect()` aborts them (the server cancels the generators, listeners stay registered), and
`reconnect()` restarts them with the id of their last event. A failed or timed out stream starts again after the
`retry` of its last event or the socket's `reconnectTime`, until the socket's `reconnect` attempts run out.

## Listen over WebSocket

`OrpcWebsocketAdapter` speaks the protocol of the `RPCHandler` of `@orpc/server/ws`, like the `RPCLink` of
`@orpc/client/websocket`. Every subscription is a request on one shared connection.

```ts title="server/ws.ts"
import { RPCHandler } from "@orpc/server/ws";
import { WebSocketServer } from "ws";

import { router } from "./router";

const handler = new RPCHandler(router);
const wss = new WebSocketServer({ port: 3000 });

wss.on("connection", (ws) => handler.upgrade(ws, { context: {} }));
```

```ts title="api/socket.ts"
import { OrpcWebsocketAdapter } from "@hyper-fetch/orpc";

export const socket = new Socket({ url: "ws://localhost:3000", adapter: OrpcWebsocketAdapter() });
```

A lost connection comes back with the [socket reconnection](/docs/guides/sockets/connection) backoff, and every running
subscription starts again with the id of its last event.

Pick `OrpcStreamAdapter` when your API already runs on an HTTP `RPCHandler`, behind proxies and CDNs, or in serverless
functions. Pick `OrpcWebsocketAdapter` when a client holds many subscriptions, since they share one connection.

---

## Inputs and shared subscriptions

`OrpcSocketSchema` turns every event iterator procedure into a `$listener`: the response is the yielded value, the
payload is the input and the topic is the procedure path, such as `planet/onUpdate`. Regular procedures are left out,
call them with [`OrpcSchema`](/docs/integrations/adapter-orpc/overview).

```ts title="api/planets.ts"
sdk.planet.onUpdate.$listener.setPayload({ id: 1 }).listen(({ data }) => {});
sdk.planet.onUpdate.$listener.listen(({ data }) => {}, { payload: { id: 2 } });
```

- Listeners with the same topic and payload share one server subscription, and the last one to unsubscribe cancels it.
- Payloads are compared in the oRPC wire format, so `{ at: new Date(0) }` and `{ at: new Date(1) }` are different
  subscriptions. Each listener receives only the events of its own payload.
- For contract-first APIs use `OrpcSocketSchema<ContractRouterClient<typeof contract>>`.

---

## Event ids and resuming

The `extra` of every event holds the meta the server set with `withEventMeta`: `extra.id` and, when set,
`extra.retry` in milliseconds. When a subscription starts again after a reconnect or a failed stream, the adapter sends
the last id as the `last-event-id` header, and oRPC passes it to the procedure as `lastEventId`.

```ts title="server/router.ts"
onUpdate: os.input(z.object({ id: z.number() })).handler(async function* ({ input, lastEventId }) {
  for (const planet of await history.after(input.id, lastEventId)) {
    yield withEventMeta(planet, { id: String(planet.version) });
  }
  // ...then the live events
}),
```

## Subscriptions in React

[`useListener`](/docs/react/sockets/use-listener) subscribes on mount and unsubscribes on unmount. A new payload starts
a new subscription and cancels the previous one. In `StrictMode` the server keeps one subscription.

```tsx title="Planet.tsx"
import { useListener } from "@hyper-fetch/react";

import { sdk } from "./api/socket";

export const Planet = ({ id }: { id: number }) => {
  const { data, extra, status, error } = useListener(sdk.planet.onUpdate.$listener.setPayload({ id }));

  if (status === "failed") return <p>{error?.message}</p>;

  return (
    <p>
      {data?.name}, event {extra?.id} ({status})
    </p>
  );
};
```

`status` is `"idle"`, `"starting"` until the server confirms the subscription, `"listening"`, then `"ended"` or
`"failed"` with the `OrpcSocketError` in `error`.

## Errors

Subscription errors never throw into your code. They reach `socket.onError` as an `OrpcSocketError`:

| Property                            | Description                                                                        |
| ----------------------------------- | ---------------------------------------------------------------------------------- |
| `topic`, `payload`                  | The failed subscription. `topic` is `null` for a WebSocket frame that can't be read |
| `shape`                             | The server error as `ORPCError.toJSON()`, `null` when there was none               |
| `defined`, `code`, `status`, `data` | Read from `shape`. `defined` is `true` for errors from the `.errors()` map          |
| `cause`                             | The original error: the `ORPCError`, an `ErrorEvent`, or the network error         |

```ts title="api/socket.ts"
import { OrpcSocketError } from "@hyper-fetch/orpc";

socket.onError(({ error }) => {
  if (error instanceof OrpcSocketError && error.defined && error.code === "OVERHEATED") {
    console.log(error.topic, error.payload, error.data);
  }
});
```

An `error` event of the iterator and a call rejected before the iterator started (failed input validation or
middleware) carry the `ORPCError`. A procedure that returns a regular output, malformed data, and a failed or timed out
stream have `shape: null`. A listener callback that throws is reported on its own, and other listeners still get the
event.

## Subscription lifecycle

Both adapters report when the server confirms a subscription and when it ends. Pass `onStart` and `onEnd` to `listen()`.

```ts title="api/countdown.ts"
sdk.countdown.$listener.setPayload({ from: 3 }).listen(({ data }) => console.log(data), {
  onStart: ({ topic }) => console.log(`${topic} is live`), // also after every restart
  onEnd: ({ topic, error }) => console.log(topic, error ? "failed" : "finished"),
});
```

- `onStart` runs when the response carries the event iterator, right away for a listener that joins a running
  subscription, and again after every restart.
- `onEnd` runs with `error: null` after the `done` event or when the server closes the stream, and with the
  `OrpcSocketError` after an error, a rejected call, a procedure that is not an event iterator, or a stream that stopped
  restarting.
- A recovered failure, such as a dropped connection that reconnects, does not end the subscription.
- Events before the end are delivered first, including a pending `delivery` batch. The generator's return value is not.
- A reconnect never restarts an ended subscription. A new `listen()` starts a fresh one without the old event id.

## Options

Both adapter factories take `customJsonSerializers`, the same list as the server's `RPCHandler`. Connection options go
in the socket's `adapterOptions`, or per connection attempt in `socket.onConnect`, for example to send a fresh token.

| Option         | Adapter                | Description                                            |
| -------------- | ---------------------- | ------------------------------------------------------ |
| `autoConnect`  | both                   | Connect when the socket is created, default `true`     |
| `headers`      | both                   | Headers of every subscription request                  |
| `fetch`        | `OrpcStreamAdapter`    | The `fetch` to use, the global one by default          |
| `fetchOptions` | `OrpcStreamAdapter`    | Options passed to `fetch`, such as `credentials`       |
| `WebSocket`    | `OrpcWebsocketAdapter` | The `WebSocket` class, the global one by default       |
| `protocols`    | `OrpcWebsocketAdapter` | Subprotocols of the `WebSocket`                        |

```ts title="api/socket.ts"
export const socket = new Socket({
  url: "http://localhost:3000/rpc",
  adapter: OrpcStreamAdapter({ customJsonSerializers: [moneySerializer] }),
  adapterOptions: { headers: { authorization: `Bearer ${token}` }, fetchOptions: { credentials: "include" } },
});
```

The socket's `connectionTimeout` (default 5 seconds) limits one connection attempt or stream response, and
`reconnectTime` is the minimum delay before the next attempt. Query params of the socket are appended to the URL.
`socket.destroy()` closes everything the adapter opened.

---

## Limits

- The adapters only subscribe. Emitting throws; use `OrpcAdapter` for regular procedures.
- Inputs with files are not supported over WebSocket.
- Event iterators in the input (client streaming) and request batching are not supported.
- In a runtime without a global `fetch` or `WebSocket`, pass one in the options, or the connection fails.

---

:::secondary Summary

- `OrpcStreamAdapter` reads event iterators from HTTP event streams, `OrpcWebsocketAdapter` from one WebSocket.
- `OrpcSocketSchema` types every event iterator procedure as a listener, with the input as the payload.
- The event id from `withEventMeta` is in `extra` and resumes the subscription after a reconnect.
- Errors arrive in `socket.onError` as an `OrpcSocketError` with the topic, payload and server error.

:::
