# Electron

HyperFetch runs in both Electron processes with `fetch`. The renderer is a Chromium page, so it works there like in a
browser, React hooks included, and the main process is Node.js, so calls that need secrets or run in the background go
there.

:::tip Purpose

1. **Renderer like a web app**: `useFetch`, `useSubmit`, the cache and focus refetching work with no setup.
2. **Main process on Node.js**: background sync and calls that need secrets stay out of the renderer.
3. **One set of requests**: define requests once and import them in both processes.

:::

## Install

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/react
```

## Send a request

In the renderer, use HyperFetch as in any browser app:

```ts title="src/renderer/client.ts"
import { createClient } from "@hyper-fetch/core";

export const client = createClient({ url: "https://api.example.com" });

export const getProjects = client.createRequest<{
  response: { id: string; name: string }[];
}>()({
  endpoint: "/projects",
});
```

Window focus and `online` / `offline` events come from Chromium, so [refetch on focus](/docs/react/hooks/use-fetch)
and offline queues work as they do in the browser.

---

## Use it in the main process

The main process has Node.js `fetch`, so the same client code runs there. Keep calls that use secrets, like a token from
the system keychain, in the main process and hand only the result to the renderer over IPC:

```ts title="src/main/projects.ts"
import { ipcMain } from "electron";
import { createClient } from "@hyper-fetch/core";

// One user per app, so the main process can cache like a browser
// highlight-next-line
const client = createClient({ url: "https://api.example.com", mode: "client" });

const getProjects = client.createRequest<{
  response: { id: string; name: string }[];
}>()({
  endpoint: "/projects",
});

ipcMain.handle("projects:list", async () => {
  // readToken() reads the token from the system keychain
  const token = await readToken();
  const { data, error } = await getProjects
    .setHeaders({ Authorization: `Bearer ${token}` })
    .send();
  return { data, error };
});
```

## Runtime quirks

- **Cache in the main process**: there is no `window` there, so the [client](/docs/core/client) picks `"server"` mode
  and caches nothing. One person uses the app, so `mode: "client"` turns the cache back on.
- **CORS**: a renderer loaded from `file://` or a custom protocol sends requests from its own origin, so the API has to
  allow it. If you cannot change the API, send those requests from the main process.
- **Focus and network from IPC**: to drive them from the main process, see the
  [Electron environment](/docs/react/environments/electron) page.
