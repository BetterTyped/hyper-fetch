# Sentry

HyperFetch reports failures through the response instead of throwing, so a failed request never reaches Sentry's global
error handler on its own. A small [plugin](/docs/core/plugin) on the client sends them to Sentry with the method, the
endpoint and the status attached. Nothing is needed beyond Sentry's own SDK.

:::tip Purpose

1. **Every failed request reported**: one plugin covers every request of the client, generated SDKs included.
2. **Grouped by endpoint**: failures of `/users/:id` land in one issue, not one per user id.
3. **Tracing included**: Sentry's `fetch` instrumentation already records each call as a span and a breadcrumb.

:::

---

## Install

Use the Sentry SDK for your platform: `@sentry/react`, `@sentry/nextjs`, `@sentry/node`, `@sentry/bun` or
`@sentry/react-native`. The plugin is the same on all of them.

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @sentry/react
```

---

## Report failed requests

Initialize Sentry first, then add the plugin to your client. `onRequestError` runs after every failed attempt, with the
response and the request:

```ts title="client.ts"
import * as Sentry from "@sentry/react";
import { AbortError, createClient, Plugin } from "@hyper-fetch/core";

// highlight-start
const sentryPlugin = new Plugin({ name: "sentry" }).onRequestError(({ response, request }) => {
  // Cancelled requests and expected 4xx answers are not bugs
  const isServerError = !response.status || Number(response.status) >= 500;
  if (response.error instanceof AbortError || !isServerError) return;

  // The endpoint before params were filled in, like /users/:id
  const endpoint = String(request.requestOptions.endpoint);

  Sentry.captureException(new Error(`${request.method} ${endpoint} failed with status ${response.status}`), {
    fingerprint: ["hyper-fetch", request.method, endpoint],
    tags: { method: request.method, endpoint, status: String(response.status) },
    extra: { error: response.error },
  });
});
// highlight-end

export const client = createClient({ url: "https://api.example.com" }).addPlugin(sentryPlugin);
```

Status `0` means the request never got an answer: a network failure or a timeout. A request with
[retries](/docs/guides/core/basics/retries) reports each failed attempt. A plugin only observes, so the request still
resolves with the same response.

## Tracing and breadcrumbs

HyperFetch sends requests with the global `fetch`, which Sentry instruments. With tracing on, every request shows up as
an `http.client` span and a breadcrumb with no extra code. To connect frontend spans to your backend, list your API in
`tracePropagationTargets`, so Sentry adds its trace headers to those requests:

```ts title="sentry.ts"
import * as Sentry from "@sentry/react";

Sentry.init({
  dsn: "https://examplePublicKey@o0.ingest.sentry.io/0",
  integrations: [Sentry.browserTracingIntegration()],
  tracesSampleRate: 0.2,
  // highlight-next-line
  tracePropagationTargets: ["https://api.example.com"],
});
```

Your API has to allow the `sentry-trace` and `baggage` headers in its CORS settings.
