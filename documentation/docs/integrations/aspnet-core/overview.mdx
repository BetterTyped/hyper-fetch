# ASP.NET Core

`Microsoft.AspNetCore.OpenApi` describes your ASP.NET Core minimal APIs and controllers as an OpenAPI document. The
[HyperFetch CLI](/docs/cli/overview) turns that document into a typed TypeScript SDK, so the frontend calls every
endpoint with your C# records translated to TypeScript.

:::tip Purpose

1. **Built into .NET**: `AddOpenApi()` and `MapOpenApi()` are all the server needs.
2. **Records as TypeScript types**: request bodies, responses and params follow your C# types.
3. **One command to resync**: change an endpoint, regenerate, and the compiler shows every call to fix.

:::

---

## Install

On the server (.NET 9 or newer), add the OpenAPI package. In the frontend, install HyperFetch and the CLI:

```bash title="server"
dotnet add package Microsoft.AspNetCore.OpenApi
```

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
npm install -D @hyper-fetch/cli
```

---

## 1. Serve the OpenAPI document

Register the document and map its endpoint:

```csharp title="server/Program.cs"
var builder = WebApplication.CreateBuilder(args);
// highlight-next-line
builder.Services.AddOpenApi();

var app = builder.Build();
// highlight-next-line
app.MapOpenApi();

app.MapGet("/users/{id}", (int id) => new User(id, "Ada"));

app.Run();

record User(int Id, string Name);
```

The document is on `/openapi/v1.json`.

---

## 2. Generate the SDK

Run the CLI in the frontend project while the server is running:

```bash title="frontend"
npx hyper-fetch generate --template openapi --fileName dotnet.sdk.ts \
  --overwrite --url http://localhost:5000/openapi/v1.json
```

It writes `src/api/dotnet.sdk.ts`. The folder comes from `api.json`, which the first run creates. Every path becomes
nested keys and every method a `$` key, so `GET /users/{id}` is `sdk.users.$id.$get`.

---

## 3. Call your API

```ts title="frontend/src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

import { createSdk } from "./dotnet.sdk";

export const client = createClient({ url: "http://localhost:5000" });
export const sdk = createSdk(client);
```

```ts title="frontend/src/users.ts"
import { sdk } from "./api/client";

// data is typed from the User record
const { data, error } = await sdk.users.$id.$get.setParams({ id: 42 }).send();
```

Every entry is a regular [Request](/docs/core/request), so it also works with `useFetch` and `useSubmit` from
[`@hyper-fetch/react`](/docs/react/overview).

---

## Framework quirks

- **Older .NET versions**: Swashbuckle serves the document on `/swagger/v1/swagger.json`. Pass that URL instead.
- **Port**: the project templates pick the port in `Properties/launchSettings.json`. Use that one in `--url` and in the
  client.
- **No running server**: `Microsoft.Extensions.ApiDescription.Server` writes the document to a file on build. Pass that
  path to `--url`. A local path is resolved from the frontend project.

---

## Keep the SDK in sync

Add a script so regenerating is one command locally and in CI. `-o` overwrites the old file without asking:

```json title="frontend/package.json"
{
  "scripts": {
    "api:generate": "hyper-fetch generate -t openapi -u http://localhost:5000/openapi/v1.json -f dotnet.sdk.ts -o"
  }
}
```

---

:::secondary Summary

- ASP.NET Core serves your endpoints as an OpenAPI document with `MapOpenApi()`.
- `hyper-fetch generate` turns it into a typed SDK.
- `createSdk(client)` gives you typed requests for `send()`, `useFetch` and `useSubmit`.

:::
