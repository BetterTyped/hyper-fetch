> The Hyper Fetch GraphQL Adapter provides a seamless way to integrate GraphQL with Hyper Fetch, enabling you to make
> queries and mutations with ease.

:::tip Purpose

1. **Simplify GraphQL integration** in both server and browser environments.
2. **Provide a type-safe way** to handle GraphQL operations.
3. **Offer seamless integration** with the Hyper Fetch ecosystem.
4. **Support both queries and mutations** with a consistent API.

:::

---

## Installation

To get started, you need to install the `@hyper-fetch/graphql` package. You will also need `graphql` and `graphql-tag`
as recommended companion packages.

```bash
npm install @hyper-fetch/graphql graphql graphql-tag
```

---

## Getting Started

Whether you're developing a server-side GraphQL API or a client-side application that consumes GraphQL data, you can use
Hyper Fetch GraphQL to interact with it. The setup process is simple and straightforward.

```tsx
import { Client } from "@hyper-fetch/core";
import { GraphqlAdapter } from "@hyper-fetch/graphql";
import gql from "graphql-tag";

// 1. Create a client
const client = new Client({ url: "http://localhost:3000/graphql" }).setAdapter(GraphqlAdapter());

// 2. Define an interface for your data
interface User {
  user: {
    username: string;
    firstName: string;
  };
}

// 3. Create a request
const getUser = client.createRequest<{ response: User }>()({
  endpoint: gql`
    query GetUser {
      user {
        username
        firstName
      }
    }
  `,
});

// 4. Send the request and get the response
const { data, error } = await getUser.send();
```

## Queries

To perform a query, create a request with the `gql` tag and your GraphQL query string.

```ts
import { Client } from "@hyper-fetch/core";
import { GraphqlAdapter } from "@hyper-fetch/graphql";
import gql from "graphql-tag";

const client = new Client({ url: "http://localhost:3000/graphql" }).setAdapter(GraphqlAdapter());

const getUsers = client.createRequest<{ response: any[] }>()({
  endpoint: gql`
    query GetUsers {
      users {
        id
        name
      }
    }
  `,
});
```

---

## Mutations

Mutations work just like queries. Define your mutation string and use it in a request.

```ts
import { Client } from "@hyper-fetch/core";
import { GraphqlAdapter } from "@hyper-fetch/graphql";
import gql from "graphql-tag";

const client = new Client({ url: "http://localhost:3000/graphql" }).setAdapter(GraphqlAdapter());

const addUser = client.createRequest<{ response: any }>()({
  endpoint: gql`
    mutation AddUser($name: String!) {
      addUser(name: $name) {
        id
        name
      }
    }
  `,
});
```

## Variables

You can pass variables to your queries and mutations using the `payload` option in the `send` method.

```ts
const { data, error } = await addUser.send({
  payload: { name: "John Doe" },
});
```

This will pass the `name` variable to the `AddUser` mutation.

## Typed documents

With [GraphQL Code Generator](https://the-guild.dev/graphql/codegen) or [gql.tada](https://gql-tada.0no.co/), every
document carries its result and variables types. Pass it as the `endpoint` and the request takes its `response` and
`payload` from the document - no generics to write, and nothing that can drift from the query.

```ts
import { GetUserDocument } from "./gql/graphql"; // generated

const getUser = client.createRequest()({ endpoint: GetUserDocument });

const { data } = await getUser.send({ payload: { id: "1" } }); // payload and data are typed by the document
```

- A document without variables needs no `payload`.
- Generics you declare win over the document: `createRequest<{ response: UserView }>()` keeps the variables from the
  document and uses your response type.
- An untyped `DocumentNode` or string keeps the `undefined` response and payload, so declare them with generics.

With the `document` option the `endpoint` is a URL path, so read the types with `GraphqlDocumentTypes`:

```ts
import { GraphqlDocumentTypes } from "@hyper-fetch/graphql";

const getUser = client.createRequest<GraphqlDocumentTypes<typeof GetUserDocument>>()({
  endpoint: "/User",
  document: GetUserDocument,
});
```

## What is sent

Each operation is sent in the [GraphQL over HTTP](https://graphql.github.io/graphql-over-http/) format.

- The body (or the query string for `GET`) holds `query`, `variables` and `operationName` - the name of the first
  operation in the document. Anonymous operations are sent without it.
- The `Accept` header asks for `application/graphql-response+json` with `application/json` as the fallback, so servers
  that follow the spec answer invalid requests with a 4xx status. An `Accept` header you set wins.
- The cache and query keys contain the operation name, a fingerprint of the document and the variables. Two documents
  with one operation name but other fields have their own cache entries and are never deduplicated into one request.

## Persisted queries

With automatic persisted queries, the request sends the SHA-256 hash of the query instead of the full text. Servers that
support them, like Apollo Server, run the query they stored under the hash. Requests get smaller, and hashed `GET`
requests have short urls, so a CDN can cache them.

```ts
const getUser = client.createRequest()({
  endpoint: GetUserDocument,
  method: GraphqlMethod.GET, // optional - lets a CDN cache the response
  options: { persistedQueries: true },
});

// Or for every request of the client
const adapter = GraphqlAdapter().setAdapterDefaults(() => ({ persistedQueries: true }));
```

- The first request sends only the hash, in `extensions.persistedQuery`.
- When the server answers `PersistedQueryNotFound`, the request is sent again with the query, so the server stores it.
  The response of that request is the one you get.
- When the server answers `PersistedQueryNotSupported`, the request is sent again with the query, and the adapter sends
  full queries from then on.
- Without Web Crypto (`crypto.subtle`, missing on insecure origins) the full query is sent.
- One `timeout` covers the hashed request and the one that registers the query.

## Errors

GraphQL reports most errors in the `errors` list of a `200` response. The adapter turns them into a failed response, with
the list as `error`. Network, abort and timeout failures are also a list, with a single `Error` and status `0`.

Type the error with `GraphqlErrorType` on the client:

```ts
import { Client } from "@hyper-fetch/core";
import { GraphqlAdapter, GraphqlErrorType } from "@hyper-fetch/graphql";

const client = new Client<GraphqlErrorType>({ url: "http://localhost:3000/graphql" }).setAdapter(GraphqlAdapter());

const { error, status } = await getUser.send({ payload: { id: "1" } });

if (error && status === 0) {
  // network, abort or timeout error
} else if (error) {
  error.forEach((graphqlError) => console.log(graphqlError.message));
}
```

### Partial data

A response can hold both `data` and `errors`, when only some fields failed. The `errorPolicy` option decides what it
resolves to:

- `"none"` (default) - the request fails, `data` is `null` and `error` holds the errors.
- `"all"` - the request succeeds with the partial `data`, and the errors are in `extra.errors`. A response without
  `data`, or with a 4xx/5xx status, still fails.

```ts
const getDashboard = client.createRequest<{ response: Dashboard }>()({
  endpoint: GetDashboardDocument,
  options: { errorPolicy: "all" },
});

const { data, extra } = await getDashboard.send();

if (extra?.errors) {
  // show the data, and mark the fields listed in extra.errors[].path as unavailable
}
```

`errorPolicy` is an adapter option, like `timeout`, so a request sets it in `options`. To set it for every request, use
the adapter defaults. The request `options` still win over them:

```ts
const client = new Client({ url: "http://localhost:3000/graphql" }).setAdapter(
  GraphqlAdapter().setAdapterDefaults(() => ({ errorPolicy: "all" })),
);
```

The server errors are in `extra.errors` with both policies, whenever the response has any.

## URL path per operation

By default, `endpoint` holds the GraphQL document and every operation goes to `client.url`. When gateways, WAF/CDN
rules, APM or access logs group the traffic by URL, pass the document separately with the `document` option. The
`endpoint` then becomes a URL path appended to `client.url`, the same way as in the `HttpAdapter`.

```ts
const getUser = client.createRequest<{ response: User; payload: { id: number } }>()({
  endpoint: "/User", // URL path, supports params like "/tenant/:tenantId/User"
  document: gql`
    query User($id: ID!) {
      user(id: $id) {
        username
      }
    }
  `, // string | DocumentNode, sent as `query`
});

await getUser.send({ payload: { id: 1 } });
// POST {client.url}/User
// body: { query, variables: { id: 1 } }
```

- Without `document` nothing changes: `endpoint` is the document and the URL is `client.url`.
- The cache, query and abort keys contain the operation name from `document` and the path from `endpoint`, so the same
  operation sent to two paths is not shared in the cache.
- Devtools display the operation name from `document`.
- Variables are typed with the `payload` generic, the same as without the `document` option.

## Query params

Query params are appended to the URL, with or without the `document` option. This lets access logs and APM filter
requests without parsing the body.

```ts
await getUser.setQueryParams({ source: "app", build: "1.2.3" }).send({ payload: { id: 1 } });
// POST {client.url}/User?source=app&build=1.2.3
// body: { query, variables: { id: 1 } }
```

For the `GET` method they are merged with `query`, `operationName` and `variables` in the query string. If a key
collides, `query`, `operationName` and `variables` take precedence.

They go through the query params mapper of the adapter, so you can change the format with the mapper config or replace
the mapper. It can return a query string or an object.

```ts
import { stringifyDefaultOptions } from "@hyper-fetch/core";

// The config replaces the defaults, so spread them to keep the encoding
const adapter = GraphqlAdapter().setQueryParamsMapperConfig({ ...stringifyDefaultOptions, arrayFormat: "comma" });
```
