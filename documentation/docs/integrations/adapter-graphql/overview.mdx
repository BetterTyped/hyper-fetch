# GraphQL and React with a typed GraphQL client

`@hyper-fetch/graphql` connects HyperFetch to a GraphQL server. `GraphqlAdapter` sends queries and mutations over HTTP,
`GraphqlWsAdapter` listens to subscriptions over WebSocket, and React components read both with the same `useFetch`,
`useSubmit` and `useListener` hooks you use for REST.

:::tip Purpose

1. **One request API** for GraphQL operations in the browser and on the server.
2. **Typed operations** from generics or from typed documents of GraphQL Code Generator and gql.tada.
3. **Cache, deduplicate and retry** queries with the usual [request](/docs/core/request) options.
4. **Subscriptions** over `graphql-transport-ws` with typed [listeners](/docs/sockets/listener).

:::

---

## Install

`graphql` is a peer dependency, and so is `@hyper-fetch/sockets`, which subscriptions need. `graphql-tag` gives you the
`gql` tag.

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/sockets @hyper-fetch/graphql \
  graphql graphql-tag
```

## Setup

1. Set the adapter on your client. `GraphqlAdapter` is a factory, call it once per client.

```ts title="client.ts"
import { createClient } from "@hyper-fetch/core";
import { GraphqlAdapter, GraphqlErrorType } from "@hyper-fetch/graphql";

export const client = createClient<{ error: GraphqlErrorType }>({
  url: "http://localhost:4000/graphql",
}).setAdapter(GraphqlAdapter());
```

2. Create a request. The document is the `endpoint`, the variables are the `payload`.

```ts title="api/users.ts"
import gql from "graphql-tag";

import { client } from "./client";

type User = { id: string; name: string };

export const getUser = client.createRequest<{
  response: { user: User | null };
  payload: { id: string };
}>()({
  endpoint: gql`
    query GetUser($id: ID!) {
      user(id: $id) {
        id
        name
      }
    }
  `,
});
```

3. Send it, or read it in a component with [`useFetch`](/docs/react/hooks/use-fetch).

```tsx title="Profile.tsx"
import { useFetch } from "@hyper-fetch/react";

import { getUser } from "./api/users";

export const Profile = ({ id }: { id: string }) => {
  const { data, loading, error } = useFetch(getUser.setPayload({ id }));

  if (loading) return <p>Loading...</p>;
  if (error) return <p>Could not load the user</p>;

  return <h1>{data?.user?.name}</h1>;
};
```

With [GraphQL Code Generator](https://the-guild.dev/graphql/codegen) or [gql.tada](https://gql-tada.0no.co/), pass the
typed document as the `endpoint` and drop the generics. The request reads its `response` and `payload` from the document,
and generics you still declare win over it.

```ts title="api/users.ts"
import { GetUserDocument } from "./gql/graphql"; // generated

export const getUser = client.createRequest()({ endpoint: GetUserDocument });
```

## How it maps

| GraphQL                                  | HyperFetch                                                                                    |
| ---------------------------------------- | --------------------------------------------------------------------------------------------- |
| GraphQL endpoint URL                     | client `url`. With the `document` option, `endpoint` becomes a path appended to it            |
| Document (`query`, `mutation`)           | request `endpoint`: a `gql` `DocumentNode`, a typed document or a string                      |
| `operationName`                          | read from the document, sent with it and used in the cache key                                |
| `variables`                              | `payload`, set with `send({ payload })` or `setPayload`                                       |
| Transport                                | `POST` with a JSON body by default, `GraphqlMethod.GET` puts everything in the query string    |
| `data`                                   | `data`                                                                                        |
| `errors`                                 | `error`, always a list. Network, abort and timeout failures are a list of one `Error`          |
| `extensions`, response headers           | `extra.extensions`, `extra.headers`, and `extra.errors` when the server sent any               |
| Subscription                             | a `Listener` of a `Socket` with `GraphqlWsAdapter`, see [subscriptions](/docs/integrations/adapter-graphql/subscriptions) |

- **Wire format**: [GraphQL over HTTP](https://graphql.github.io/graphql-over-http/), with
  `Accept: application/graphql-response+json, application/json;q=0.9` unless you set your own `Accept` header.
- **Keys**: the adapter replaces the client's cache, query and abort key mappers. Keys hold the operation name, a
  fingerprint of the document and the variables, so every operation and set of variables is its own cache entry.
- **Custom key mappers**: set them after `setAdapter`, or the adapter overwrites them.

## Adapter options

Request `options` take the `fetch` `RequestInit` fields except `method`, `headers`, `body` and `signal`, plus:

| Option             | Default  | Description                                                                          |
| ------------------ | -------- | ------------------------------------------------------------------------------------ |
| `timeout`          | `5000`   | Milliseconds until the request fails with a timeout error                            |
| `errorPolicy`      | `"none"` | What a response with both `data` and `errors` resolves to, see [partial data](#partial-data) |
| `persistedQueries` | `false`  | Send the SHA-256 hash of the query first, see [persisted queries](#persisted-queries) |

Set them per request in `options`, or for every request with the adapter defaults. Request `options` win.

```ts title="client.ts"
export const client = createClient({
  url: "http://localhost:4000/graphql",
}).setAdapter(
  GraphqlAdapter().setAdapterDefaults(() => ({
    timeout: 10000,
    errorPolicy: "all",
  })),
);
```

Requests of a `GraphqlAdapter` client also accept a `document` option, described in
[URL path per operation](#url-path-per-operation).

### Partial data

A response can hold both `data` and `errors` when only some fields failed. `errorPolicy` decides what it resolves to:

- `"none"` (default): the request fails, `data` is `null` and `error` holds the errors.
- `"all"`: the request succeeds with the partial `data`, and the errors are in `extra.errors`. A response without `data`,
  or with a 4xx/5xx status, still fails.

```ts title="api/dashboard.ts"
const getDashboard = client.createRequest()({
  endpoint: GetDashboardDocument,
  options: { errorPolicy: "all" },
});

const { data, extra } = await getDashboard.send();
// extra.errors lists the fields that failed, data holds the rest
```

### Persisted queries

With `persistedQueries: true` the request sends the SHA-256 hash of the query in `extensions.persistedQuery` instead of
the text. Combined with `GraphqlMethod.GET`, the URLs stay short, so a CDN can cache them.

- When the server answers `PersistedQueryNotFound`, the request is sent again with the query, so the server stores it.
- When it answers `PersistedQueryNotSupported`, the request is sent again with the query, and this adapter sends full
  queries from then on.
- Without Web Crypto (`crypto.subtle`, missing on insecure origins) the full query is sent. One `timeout` covers both
  attempts.

## URL path per operation

By default every operation goes to `client.url`. When gateways, WAF or CDN rules, APM or access logs group traffic by
URL, pass the document with the `document` option. The `endpoint` then becomes a URL path, with params, like in the HTTP
adapter.

```ts title="api/users.ts"
import { GraphqlDocumentTypes } from "@hyper-fetch/graphql";

const getUser = client.createRequest<
  GraphqlDocumentTypes<typeof GetUserDocument>
>()({
  endpoint: "/tenant/:tenantId/GetUser",
  document: GetUserDocument,
});

await getUser
  .setParams({ tenantId: 7 })
  .setQueryParams({ source: "app" })
  .send({ payload: { id: "1" } });
// POST {client.url}/tenant/7/GetUser?source=app with body { query,
// operationName, variables }
```

- `GraphqlDocumentTypes` reads the response and variables types from a typed document passed this way.
- The path is part of the cache key, so the same operation on two paths has two cache entries.
- Query params are appended to the URL with or without `document`. With `GET`, `query`, `operationName`, `variables` and
  `extensions` win over a query param with the same key.

## Limits and differences

Compared with the HTTP adapter:

- `error` is always a list, even for network failures, so type the client with `GraphqlErrorType`.
- A `200` response with `errors` is a failure unless `errorPolicy` is `"all"`.
- Deduplication is off by default. Set `deduplicate: true` on the request to share in-flight calls.
- Keep mutations on `POST`. `GraphqlMethod.GET` is for queries that browsers or CDNs should cache.
- A string literal document with `$id: ID!` in `endpoint` is read as a URL param by TypeScript. Use `gql` or `document`.

Compared with Apollo Client:

| Need                                     | Apollo Client                               | `@hyper-fetch/graphql`                      |
| ---------------------------------------- | ------------------------------------------- | ------------------------------------------- |
| Cache model                              | Normalized by `__typename` and `id`         | Per operation and variables                 |
| React hooks                              | `useQuery`, `useMutation`, `useSubscription` | `useFetch`, `useSubmit`, `useListener`     |
| Refetch after a write                    | `refetchQueries`                            | `cache.invalidate(matchGqlOperation(...))`  |
| Offline request queue                    | Not built in                                | `offline`                                   |
| REST, Firebase and sockets in one client | No                                          | Swap the adapter                            |

If many queries overlap on the same entities and you rely on a normalized cache to update them all, Apollo is built for
that. HyperFetch fits when GraphQL is one of several backends, or when you want predictable per-request caching.

---

:::secondary Summary

- `GraphqlAdapter()` sends documents as requests: the document is the `endpoint`, the variables the `payload`.
- Typed documents type `data` and `payload` without generics.
- `error` is a list of GraphQL errors. `errorPolicy: "all"` keeps partial data.
- `GraphqlWsAdapter()` covers subscriptions on a `Socket`.

:::
