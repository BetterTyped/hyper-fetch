# GraphQL query examples with variables

A graphql query reads data. You name the fields you want, the server returns exactly those fields, and nothing changes on
the server. This page shows the parts of a query, then how to send one with HyperFetch: written with `graphql-tag`,
typed with generics, and run from a React component.

:::tip What you'll learn

- How to create a basic GraphQL query.
- How to use TypeScript with your queries.
- How to pass variables to your queries.

:::

---

## Anatomy of a GraphQL query

```graphql
query GetUserById($userId: ID!) {
  user(id: $userId) {
    username
    firstName
  }
}
```

| Part                    | In the example        | What it does                                                        |
| ----------------------- | --------------------- | ------------------------------------------------------------------- |
| Operation type          | `query`               | Reads data. `mutation` writes, `subscription` streams.              |
| Operation name          | `GetUserById`         | Names the operation in logs, tooling and the cache key              |
| Variable definitions    | `$userId: ID!`        | Inputs with types. `!` means required.                              |
| Arguments               | `id: $userId`         | Pass a variable to a field                                          |
| Selection set           | `username firstName`  | The fields the response will contain, nothing more                  |

Always pass dynamic values as variables instead of building the query string by hand. The query text stays the same, so
servers can cache the parsed query, persisted queries work, and you never have to escape user input.

On the wire, a query is a `POST` with a JSON body of `query`, `variables` and `operationName`, or a `GET` with the same
fields in the query string. The [overview](./overview.mdx#what-is-sent) has the details.

## Basic Query

Here's how to create a simple query to fetch a user's data.

```tsx
import { Client } from "@hyper-fetch/core";
import { GraphqlAdapter } from "@hyper-fetch/graphql";
import gql from "graphql-tag";

// 1. Initialize Client with adapter
const client = new Client({ url: "http://localhost:3000/graphql" }).setAdapter(GraphqlAdapter());

// 2. Define an interface for your data
interface User {
  user: {
    username: string;
    firstName: string;
  };
}

// 3. Create a request
const getUser = client.createRequest<{ response: User }>()({
  endpoint: gql`
    query GetUser {
      user {
        username
        firstName
      }
    }
  `,
});

// 4. Send the request
const { data, error } = await getUser.send();
```

## Query Variables

You often need to pass variables to your queries to filter results or fetch specific data. You can do this by defining
variables in your GraphQL query and passing them in the `send` method.

```tsx
import { Client } from "@hyper-fetch/core";
import { GraphqlAdapter } from "@hyper-fetch/graphql";
import gql from "graphql-tag";

const client = new Client({ url: "http://localhost:3000/graphql" }).setAdapter(GraphqlAdapter());

// 1. Define types for the response and variables
type User = {
  username: string;
  firstName: string;
};
type Variables = {
  userId: string;
};

// 2. Create the request with variables in the query
const getUser = client.createRequest<{ response: { user: User }; payload: Variables }>()({
  endpoint: gql`
    query GetUserById($userId: ID!) {
      user(id: $userId) {
        username
        firstName
      }
    }
  `,
});

// 3. Pass variables when sending the request
const { data, error } = await getUser.send({
  payload: { userId: "1" },
});
```

You can also use the `.setPayload()` method to set variables before sending the request. This is useful when you want to
separate setting the variables from sending the request.

```ts
const { data, error } = await getUser.setPayload({ userId: "1" }).send();
```

## Queries in React

`useFetch` sends the query when the component mounts and again when the variables change. The result is cached by the
operation and its variables, so another component with the same query reads the cached data. Add `deduplicate: true` to
the request to merge identical queries that start at the same time into one network call.

```tsx
import { useFetch } from "@hyper-fetch/react";

export const UserName = ({ userId }: { userId: string }) => {
  const { data, loading } = useFetch(getUser.setPayload({ userId }));

  if (loading && !data) return <p>Loading...</p>;

  return <p>{data?.user.firstName}</p>;
};
```

To refetch queries after a write, see [mutations](./mutations.mdx#refetching-queries-after-a-mutation). For the cache
options behind `useFetch`, see [cache](../../core/cache.mdx).
