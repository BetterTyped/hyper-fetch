# GraphQL query examples with variables

A GraphQL query reads data: you name the fields you want and the server returns exactly those, without changing
anything. With the [GraphQL adapter](/docs/integrations/adapter-graphql/overview) a query is a request whose `endpoint`
is the document and whose `payload` is the variables.

:::tip Purpose

1. **Read the parts** of a query: operation, variables, arguments and selection set.
2. **Send typed queries** with generics or typed documents.
3. **Cache queries in React** per operation and variables.

:::

---

## Anatomy of a GraphQL query

```graphql title="GetUserById.graphql"
query GetUserById($userId: ID!) {
  user(id: $userId) {
    username
    firstName
  }
}
```

| Part                 | In the example       | What it does                                           |
| -------------------- | -------------------- | ------------------------------------------------------ |
| Operation type       | `query`              | Reads data. `mutation` writes, `subscription` streams. |
| Operation name       | `GetUserById`        | Names the operation in logs, devtools and the cache key |
| Variable definitions | `$userId: ID!`       | Typed inputs. `!` means required.                      |
| Arguments            | `id: $userId`        | Pass a variable to a field                             |
| Selection set        | `username firstName` | The fields the response contains, nothing more         |

Pass dynamic values as variables instead of building the query string. The query text stays the same, so servers can
cache the parsed query, persisted queries work, and you never escape user input.

---

## Send a query

Declare the response and the variables with generics, then pass the variables as the `payload`.

```ts title="api/users.ts"
import gql from "graphql-tag";

import { client } from "./client";

type User = { username: string; firstName: string };

export const getUser = client.createRequest<{
  response: { user: User };
  payload: { userId: string };
}>()({
  endpoint: gql`
    query GetUserById($userId: ID!) {
      user(id: $userId) {
        username
        firstName
      }
    }
  `,
});

const { data, error } = await getUser.send({ payload: { userId: "1" } });
// or: await getUser.setPayload({ userId: "1" }).send();
```

A query without variables needs no `payload`.

---

## Typed documents

A typed document from GraphQL Code Generator or gql.tada carries its result and variables types, so the request needs no
generics and the variables are checked against the schema.

```ts title="api/users.ts"
import { GetUserByIdDocument } from "./gql/graphql"; // generated

export const getUser = client.createRequest()({
  endpoint: GetUserByIdDocument,
});

// data and payload typed by the document
const { data } = await getUser.send({ payload: { userId: "1" } });
```

## Queries in React

[`useFetch`](/docs/react/hooks/use-fetch) sends the query on mount and again when the variables change. The result is
cached per operation and variables, so another component with the same query reads the cached data.

```tsx title="UserName.tsx"
import { useFetch } from "@hyper-fetch/react";

import { getUser } from "./api/users";

export const UserName = ({ userId }: { userId: string }) => {
  const { data, loading } = useFetch(getUser.setPayload({ userId }));

  if (loading && !data) return <p>Loading...</p>;

  return <p>{data?.user.firstName}</p>;
};
```

Add `deduplicate: true` to the request to merge identical queries that start at the same time into one network call.
To refetch a query after a write, see [mutations](/docs/integrations/adapter-graphql/mutations#refetch-queries-after-a-mutation).

---

## Send a query with GET

Queries go as `POST` by default. `GraphqlMethod.GET` puts `query`, `operationName` and `variables` in the query string, so
browsers and CDNs can cache the response. Add `persistedQueries` to keep the URL short.

```ts title="api/users.ts"
import { GraphqlMethod } from "@hyper-fetch/graphql";

export const listUsers = client.createRequest()({
  endpoint: ListUsersDocument,
  method: GraphqlMethod.GET,
  options: { persistedQueries: true },
});
```

A `GET` request sends no `Content-Type`, so it needs no CORS preflight. See
[persisted queries](/docs/integrations/adapter-graphql/overview#persisted-queries) for how the hash is negotiated.

---

## Errors

`send()` resolves with `error` as a list: the GraphQL `errors`, or one `Error` for a network failure, abort or timeout. A
response with both `data` and `errors` fails unless `errorPolicy` is `"all"`. See
[partial data](/docs/integrations/adapter-graphql/overview#partial-data).

---

:::secondary Summary

- A query is a request: the document is the `endpoint`, the variables the `payload`.
- Typed documents type `data` and `payload` without generics.
- `useFetch` caches each operation and set of variables on its own.

:::
