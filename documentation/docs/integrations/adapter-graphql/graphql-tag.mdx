# graphql-tag and the gql template literal

`graphql-tag` exports one template literal tag, `gql`, which parses a GraphQL string into a `DocumentNode`, the AST the
`graphql` package and most GraphQL tools work with. A syntax error throws when the document is created, not when the
server answers. The [GraphQL adapter](/docs/integrations/adapter-graphql/overview) accepts a `DocumentNode` or a plain
string, so the tag is optional.

```bash npm2yarn2pnpm
npm install graphql graphql-tag
```

:::tip Purpose

1. **Catch syntax errors early**: an invalid document throws where it is defined.
2. **Editor support**: GraphQL plugins highlight and autocomplete the content of `gql` literals.
3. **Safe variables in types**: a `gql` document never turns `$id: ID!` into a URL param, which a string literal can.

:::

---

## Send a gql document

Pass the result of `gql` as the `endpoint`. The adapter prints the document back to a string when it sends the request
and reads the operation name from it for the cache key.

```ts title="api/users.ts"
import gql from "graphql-tag";

import { client } from "./client";

type User = { username: string; firstName: string };

export const getUser = client.createRequest<{ response: { user: User } }>()({
  endpoint: gql`
    query GetUser {
      user {
        username
        firstName
      }
    }
  `,
});

const { data, error } = await getUser.send();
```

## gql documents, strings and typed documents

| Endpoint                                | Response and variables types | When to use                                     |
| --------------------------------------- | ---------------------------- | ----------------------------------------------- |
| Plain string                            | Declare them with generics   | Quick scripts without variables                 |
| `gql` from `graphql-tag`                | Declare them with generics   | Hand-written documents with editor support      |
| Typed document from codegen or gql.tada | Read from the document       | Apps that want types generated from the schema  |

An inline string literal that declares variables, like `query ($id: ID!)`, makes TypeScript read `:` as a URL param and
ask for `params`. Wrap it in `gql`, or pass it with the `document` option.

---

:::secondary Summary

- `gql` turns a string into a `DocumentNode` and fails early on syntax errors.
- The adapter accepts `gql` documents, strings and typed documents as the `endpoint`.
- Typed documents are the only kind that types the request without generics.

:::
