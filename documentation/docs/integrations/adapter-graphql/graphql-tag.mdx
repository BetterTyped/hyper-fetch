# graphql-tag and the gql template literal

`graphql-tag` is a small library that exports one template literal tag, `gql`. It parses a GraphQL query string into a
`DocumentNode`, the AST that the `graphql` package and most GraphQL tools work with. A syntax error in the query throws
when the document is created, not when the server answers.

The GraphQL adapter accepts a `DocumentNode` or a plain string as the `endpoint`. `graphql-tag` is not required, it is
a separate install, and most projects that write queries by hand use it.

```bash
npm install graphql graphql-tag
```

:::tip Why use `graphql-tag`?

- **Standardization**: It ensures that your GraphQL queries are valid and conform to the official specification.
- **Tooling Support**: It enables better tooling support, such as syntax highlighting and autocompletion in your editor.
- **Readability**: It makes your queries more readable by allowing you to write them as multi-line strings.

:::

## Usage

Write queries and mutations with `gql` and pass the result as the `endpoint`. The adapter prints the document back to a
string when it sends the request, and reads the operation name from it for the cache key.

```ts
import { Client } from "@hyper-fetch/core";
import { GraphqlAdapter } from "@hyper-fetch/graphql";
import gql from "graphql-tag";

const client = new Client({ url: "http://localhost:3000/graphql" }).setAdapter(GraphqlAdapter());

interface User {
  user: {
    username: string;
    firstName: string;
  };
}

const getUser = client.createRequest<{ response: User }>()({
  endpoint: gql`
    query GetUser {
      user {
        username
        firstName
      }
    }
  `,
});

const { data, error } = await getUser.send();
```

## gql documents, strings and typed documents

| Endpoint                           | Response and variables types     | When to use                                     |
| ---------------------------------- | -------------------------------- | ----------------------------------------------- |
| Plain string                       | Declare them with generics       | Quick scripts, no parsing step                  |
| `gql` from `graphql-tag`           | Declare them with generics       | Hand-written queries with editor support        |
| Typed document from codegen or gql.tada | Read from the document      | Larger apps that want types generated from the schema |

Editor plugins for GraphQL highlight and autocomplete the content of `gql` template literals, which is a large part of
why the tag is popular. For typed documents, see [typed documents](./overview.mdx#typed-documents). For more
examples, see [queries](./queries.mdx) and [mutations](./mutations.mdx).
