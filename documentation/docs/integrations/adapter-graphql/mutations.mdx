# GraphQL mutation examples with variables

A GraphQL mutation changes data on the server and returns the fields you select from the result. With the
[GraphQL adapter](/docs/integrations/adapter-graphql/overview) it is a request like a query: the document is the
`endpoint` and the variables are the `payload`. What changes is what comes after it: the queries you already cached may
now be stale.

:::tip Purpose

1. **Read the parts** of a mutation and how it differs from a query.
2. **Send typed mutations** with generics or typed documents.
3. **Refetch the queries** a mutation changed with `matchGqlOperation`.

:::

---

## Anatomy of a GraphQL mutation

```graphql title="UpdateUser.graphql"
mutation UpdateUser($id: ID!, $name: String!) {
  updateUser(id: $id, name: $name) {
    id
    name
  }
}
```

|                    | Query                               | Mutation                                 |
| ------------------ | ----------------------------------- | ---------------------------------------- |
| Purpose            | Read                                | Write                                    |
| Top-level fields   | The server may run them in parallel | The server runs them one after another   |
| Safe to send twice | Yes                                 | Not always, it can repeat the write      |
| After it succeeds  | Nothing to do                       | Refetch or update the queries it changed |

Select the changed fields in the result, like `updateUser { id name }` above. The response then tells you the new state.

---

## Send a mutation

Declare the response and the variables with generics, then pass the variables as the `payload`.

```ts title="api/users.ts"
import gql from "graphql-tag";

import { client } from "./client";

type User = { id: string; name: string };

export const updateUser = client.createRequest<{
  response: { updateUser: User };
  payload: { id: string; name: string };
}>()({
  endpoint: gql`
    mutation UpdateUser($id: ID!, $name: String!) {
      updateUser(id: $id, name: $name) {
        id
        name
      }
    }
  `,
});

const { data, error } = await updateUser.send({
  payload: { id: "1", name: "Ann" },
});
// or: await updateUser.setPayload({ id: "1", name: "Ann" }).send();
```

Keep mutations on the default `POST`. `GraphqlMethod.GET` is only for queries.

---

## Typed documents

A typed document from GraphQL Code Generator or gql.tada types the result and the variables, so the request needs no
generics.

```ts title="api/users.ts"
import { UpdateUserDocument } from "./gql/graphql"; // generated

export const updateUser = client.createRequest()({
  endpoint: UpdateUserDocument,
});
```

## Mutations in React

[`useSubmit`](/docs/react/hooks/use-submit) sends the mutation when you call `submit` and tracks `submitting`.

```tsx title="RenameButton.tsx"
import { useSubmit } from "@hyper-fetch/react";

import { updateUser } from "./api/users";

export const RenameButton = ({ id }: { id: string }) => {
  const { submit, submitting } = useSubmit(updateUser);

  return (
    <button
      disabled={submitting}
      onClick={() => submit({ payload: { id, name: "Ann" } })}
    >
      Rename
    </button>
  );
};
```

## Refetch queries after a mutation

`matchGqlOperation` matches the cache keys of every request of a query document, with any variables, params and query
params. Pass it to `client.cache.invalidate()` and the active queries of that operation refetch, like `refetchQueries` in
Apollo.

```ts title="api/users.ts"
import { matchGqlOperation } from "@hyper-fetch/graphql";

const { success } = await updateUser.send({ payload: { id: "1", name: "Ann" } });

if (success) {
  // GetUser with every id is marked stale and refetched where it is used
  client.cache.invalidate(matchGqlOperation(GetUserDocument));
}
```

- Pass a document to match it on every path of the `document` option, or a request to match only its own path.
- Documents with the same operation name but other fields are other operations and are not matched.
- `invalidate` takes a list, so one mutation can refetch several operations.

To write the result into the cache instead of refetching, see the
[GraphQL mutations example](/examples/integrations/graphql-mutations).

---

## Errors

`send()` resolves with `error` as a list: the GraphQL `errors`, or one `Error` for a network failure, abort or timeout.
HyperFetch [retries](/docs/guides/core/basics/retries) only when you turn them on, so a mutation that is not safe to
repeat runs once. See [partial data](/docs/integrations/adapter-graphql/overview#partial-data) for responses with both
`data` and `errors`.

---

:::secondary Summary

- A mutation is a request: the document is the `endpoint`, the variables the `payload`.
- `useSubmit` sends it on demand and tracks `submitting`.
- `client.cache.invalidate(matchGqlOperation(Document))` refetches the queries it changed.

:::
