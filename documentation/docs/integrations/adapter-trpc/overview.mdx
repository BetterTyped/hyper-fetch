# tRPC client with React hooks and caching

`@hyper-fetch/trpc` calls the procedures of a tRPC router as HyperFetch requests, typed from your `AppRouter`. Your
server stays as it is. Use it instead of tRPC's TanStack Query client when you want one client for tRPC, REST, GraphQL
and sockets, with caching, deduplication, retries, offline queues and the React hooks.

:::tip Purpose

1. **Call tRPC procedures** with the request API you use for REST and GraphQL.
2. **Infer types from your router** through the regular [`createSdk`](/docs/core/sdk).
3. **Cache every input separately**, without writing query keys by hand.
4. **Listen to subscriptions** over WebSocket or Server-Sent Events, see
   [subscriptions](/docs/integrations/adapter-trpc/subscriptions).

:::

---

## Install

`@trpc/server` (v11) is an optional peer dependency, only needed for the `TrpcSchema` type. The project that imports
your `AppRouter` type usually has it already.

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/trpc
```

---

## Setup

1. Point the client at the URL where your tRPC handler is mounted. With the Next.js App Router that is usually the route
   handler at `app/api/trpc/[trpc]/route.ts`, so `url: "/api/trpc"`. Server code needs an absolute URL.

```ts title="api/client.ts"
import { createClient } from "@hyper-fetch/core";
import { TrpcAdapter } from "@hyper-fetch/trpc";

export const client = createClient({
  url: "http://localhost:3000/trpc",
}).setAdapter(TrpcAdapter());
```

2. Describe the router with `TrpcSchema` and create the SDK. `camelCaseToKebabCase: false` keeps procedure names as
   written in the router (`byId`, not `by-id`).

```ts title="api/sdk.ts"
import { createSdk } from "@hyper-fetch/core";
import type { TrpcSchema } from "@hyper-fetch/trpc";

import type { AppRouter } from "../server/router";
import { client } from "./client";

export const api = createSdk<typeof client, TrpcSchema<AppRouter>>(client, {
  camelCaseToKebabCase: false,
});
```

3. Call queries under `$query` and mutations under `$mutation`. The procedure input is the payload.

```tsx title="User.tsx"
import { useFetch, useSubmit } from "@hyper-fetch/react";

import { api } from "./api/sdk";

export const User = ({ id }: { id: number }) => {
  const { data, loading } = useFetch(api.user.byId.$query.setPayload({ id }));
  const { submit, submitting } = useSubmit(api.user.create.$mutation);

  if (loading) return <p>Loading...</p>;

  return (
    <button
      disabled={submitting}
      onClick={() => submit({ payload: { name: "John" } })}
    >
      Invite a friend of {data?.name}
    </button>
  );
};
```

## How it maps

| tRPC                                     | HyperFetch                                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| Handler URL (`/trpc`, `/api/trpc`)       | client `url`                                                                             |
| Procedure path (`user.byId`)             | `endpoint` `user.byId`, or `api.user.byId` in the SDK                                    |
| `query` procedure                        | method `QUERY` (default, `$query`), sent as `GET {url}/user.byId?input=...`              |
| `mutation` procedure                     | method `MUTATION` (`$mutation`), sent as `POST {url}/user.create` with a JSON body       |
| `subscription` procedure                 | a listener with `TrpcWebsocketAdapter` or `TrpcSseAdapter`, see [subscriptions](/docs/integrations/adapter-trpc/subscriptions) |
| Input                                    | `payload`, passed through the `transformer`                                              |
| Output                                   | `data`                                                                                   |
| `TRPCError`                              | `error` (`message`, `code`, `data.code`, `data.httpStatus`) with the HTTP `status`       |
| Response headers                         | `extra.headers`                                                                          |

The adapter adds the input to the cache and query keys, so `{ id: 1 }` and `{ id: 2 }` are cached, deduplicated and
queued separately. Queries are deduplicated by default, mutations are not. The abort key has no input, so
`request.abort()` stops every running call of the procedure. The paths `user.byId` and `/user/byId` share the cache.

Without the SDK, create the request yourself:

```ts title="api/users.ts"
type User = { id: number; name: string };

export const getUser = client.createRequest<{
  response: User;
  payload: { id: number };
}>()({
  endpoint: "user.byId",
  method: "QUERY",
});
```

## Adapter options

`TrpcAdapter` takes a `transformer`, the same one the server passes to `initTRPC.create()`. It handles the input, the
output and the errors. Any object with `serialize` and `deserialize` works; for separate transformers per direction pass
`{ serialize: input.serialize, deserialize: output.deserialize }`.

```ts title="api/client.ts"
import superjson from "superjson";

export const client = createClient({
  url: "http://localhost:3000/trpc",
}).setAdapter(TrpcAdapter({ transformer: superjson }));
```

Request `options` are passed to `fetch` (except `method`, `headers`, `body` and `signal`), plus `timeout` in
milliseconds, default `5000`.

```ts title="api/users.ts"
export const getMe = client.createRequest<{ response: User }>()({
  endpoint: "user.me",
  options: { credentials: "include", timeout: 10000 },
});
```

## Errors

Failed procedures resolve with the error the server sent and the HTTP status. With `TrpcSchema` the error type follows
the router, including a custom `errorFormatter`. For requests created by hand, use `TrpcErrorType`.

```ts title="user.ts"
const { error, status } = await api.user.byId.$query
  .setPayload({ id: 999 })
  .send();

// `error` also includes the client's global error (`Error` by default), so
// check for the tRPC shape first
if (error && "data" in error) {
  // 404, "User not found", "NOT_FOUND"
  console.log(status, error.message, error.data.code);
}
```

A response that did not come from a procedure, such as an HTML page from a proxy, resolves with an `UnexpectedError`.

## Limits

- Request batching is not supported.
- Subscriptions are left out of `TrpcSchema`. Use the [socket adapters](/docs/integrations/adapter-trpc/subscriptions).
- A `null` payload removes the payload, so the procedure receives no input. Wrap it: `{ value: null }`.
- The SDK can't reach a procedure named like a request property, such as `send` or `method`. Use `createRequest` with
  the procedure path.
- A `cancelable` request only replaces a running call with the same input. To cancel on every keystroke of a search,
  share one query key: `api.user.search.$query.setCancelable(true).setDeduplicate(false).setQueryKey("user-search")`.
- Query params are appended to the URL. The `input` and `batch` keys are reserved by the tRPC format and skipped.

---

:::secondary Summary

- `TrpcAdapter()` calls procedures over tRPC's HTTP format, and `TrpcSchema` types them through `createSdk`.
- Queries go as `GET` under `$query`, mutations as `POST` under `$mutation`. The input is the payload.
- Pass the server's `transformer`, such as `superjson`, to keep rich types.
- Errors keep the tRPC shape and resolve with the HTTP status.

:::
