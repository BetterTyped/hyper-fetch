# tRPC subscriptions over WebSocket and SSE

A tRPC subscription is a procedure that keeps sending events after one call, such as chat messages or job progress.
`TrpcSseAdapter` speaks the protocol of `httpSubscriptionLink` and `TrpcWebsocketAdapter` the one of `wsLink`, so each
subscription becomes a typed [Listener](/docs/sockets/listener) on a [Socket](/docs/sockets/socket) without server
changes, with the procedure input as the payload.

:::tip Purpose

1. **Listen to subscriptions** with the `Socket`, `Listener` and `useListener` API of other realtime sources.
2. **Infer types from your router** with `TrpcSocketSchema` and `createSocketSdk`.
3. **Share one server subscription** between listeners with the same input.
4. **Resume after reconnecting** from the last `tracked()` event.

:::

---

## Install

The socket adapters ship in `@hyper-fetch/trpc` and need `@hyper-fetch/sockets`.

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/sockets @hyper-fetch/trpc
```

## Listen over HTTP

On the server, a subscription is an async generator. Each `yield` sends one event, and `tracked(id, data)` gives it an
id the client can resume from. `TrpcSseAdapter` works with the HTTP handlers of tRPC (`createHTTPServer`,
`fetchRequestHandler` and the others), so point the socket at the same URL as your queries.

```ts title="server/router.ts"
import { initTRPC, tracked } from "@trpc/server";

const t = initTRPC.create();

export const appRouter = t.router({
  chat: t.router({
    onMessage: t.procedure
      .input((value) => value as { room: string; lastEventId?: string })
      .subscription(async function* ({ input, signal }) {
        for await (const message of messages(input.room, { after: input.lastEventId, signal })) {
          yield tracked(message.id, message);
        }
      }),
  }),
});

export type AppRouter = typeof appRouter;
```

```ts title="api/socket.ts"
import { createSocketSdk, Socket } from "@hyper-fetch/sockets";
import { TrpcSseAdapter } from "@hyper-fetch/trpc";
import type { TrpcSocketSchema } from "@hyper-fetch/trpc";

import type { AppRouter } from "../server/router";

export const socket = new Socket({ url: "http://localhost:3000/trpc", adapter: TrpcSseAdapter() });

export const realtime = createSocketSdk<typeof socket, TrpcSocketSchema<AppRouter>>(socket, {
  camelCaseToKebabCase: false,
});

const stop = realtime.chat.onMessage.$listener.setPayload({ room: "general" }).listen(({ data, extra }) => {
  console.log(data.text, extra.eventId);
});
```

Every subscription gets its own `EventSource`, opened as `GET {url}/chat.onMessage?input=...`. The socket counts as
connected once it can open streams, and `socket.disconnect()` closes all of them.

## Listen over WebSocket

`TrpcWebsocketAdapter` works with `applyWSSHandler` from `@trpc/server/adapters/ws` and keeps one connection for every
subscription.

```ts title="server/ws.ts"
import { applyWSSHandler } from "@trpc/server/adapters/ws";
import { WebSocketServer } from "ws";

import { appRouter } from "./router";

applyWSSHandler({ wss: new WebSocketServer({ port: 3001 }), router: appRouter });
```

```ts title="api/socket.ts"
import { TrpcWebsocketAdapter } from "@hyper-fetch/trpc";

export const socket = new Socket({ url: "ws://localhost:3001", adapter: TrpcWebsocketAdapter() });
```

Pick SSE when you already serve tRPC over HTTP, behind proxies or on serverless platforms. Pick WebSocket when a client
holds many subscriptions at once. Both adapters share the schema, the payloads and the `extra`, so switching only
changes the socket.

## Inputs and shared subscriptions

`TrpcSocketSchema` turns every subscription procedure into a `$listener`. Its topic is the procedure path with slashes
(`chat/onMessage`), and its payload is the input: required, optional or absent, as the procedure declares. Queries and
mutations are left out, send them with the [`TrpcAdapter`](/docs/integrations/adapter-trpc/overview).

```ts title="api/chat.ts"
realtime.chat.onMessage.$listener.setPayload({ room: "general" }).listen(onMessage);
realtime.chat.onMessage.$listener.listen(onMessage, { payload: { room: "general" } });
```

- Listeners with the same input share one server subscription. The last one to leave stops it (`subscription.stop`
  over WebSocket, closing the stream over SSE).
- Listeners with different inputs are separate subscriptions and never receive each other's events.
- Listeners created before the socket connects wait and start when it connects.

---

## Event ids and resuming

Events yielded with `tracked(id, data)` reach the listeners as `data`, without the wrapper. `extra.eventId` holds the
id (`null` for untracked events) and `extra.payload` the input. After a reconnect every subscription restarts with the
last id as `input.lastEventId`, so the procedure can send the events the client missed. Over SSE the `EventSource` also
sends it as `Last-Event-ID` when it reconnects on its own.

## Subscriptions in React

[`useListener`](/docs/react/sockets/use-listener) works with both adapters. Changing the payload stops the previous
subscription and starts a new one, and unmounting stops it.

```tsx title="ChatRoom.tsx"
import { useListener } from "@hyper-fetch/react";

import { realtime } from "./api/socket";

export const ChatRoom = ({ room }: { room: string }) => {
  const { data, extra, status, error } = useListener(realtime.chat.onMessage.$listener.setPayload({ room }));

  if (status === "failed") return <p>{error?.message}</p>;

  return (
    <p>
      {status === "listening" ? "Live" : "Connecting..."} {data?.text} ({extra?.eventId})
    </p>
  );
};
```

`status` is `"idle"`, `"starting"` until the server confirms the subscription, `"listening"`, then `"ended"` or
`"failed"` with the `error`. Call `listen()` from the hook to subscribe again.

## Errors

Subscription errors reach `socket.onError` as a `TrpcSocketError`. Its `shape` holds the server error after the
transformer, and `topic` and `payload` tell which subscription failed.

```ts title="api/socket.ts"
import { TrpcSocketError } from "@hyper-fetch/trpc";

socket.onError(({ error }) => {
  if (error instanceof TrpcSocketError) {
    console.log(error.topic, error.payload, error.shape.data.code); // topic is null when the whole connection failed
  }
});
```

- Over WebSocket, an error ends the subscription on the server.
- Over SSE, `INTERNAL_SERVER_ERROR` errors keep the stream and the `EventSource` reconnects. Other errors end the
  subscription, as in `httpSubscriptionLink`.
- Messages that break the protocol and callbacks that throw are reported too. Other listeners keep their events.

## Subscription lifecycle

The server confirms every subscription and tells when it is over. Pass `onStart` and `onEnd` to `listen()`.

```ts title="api/chat.ts"
realtime.chat.onMessage.$listener.setPayload({ room: "general" }).listen(onMessage, {
  onStart: ({ topic }) => {}, // accepted by the server, and again after every reconnect
  onEnd: ({ topic, error }) => {}, // the procedure returned (error is null) or failed with a TrpcSocketError
});
```

| Event               | WebSocket                 | Server-Sent Events                                      |
| ------------------- | ------------------------- | ------------------------------------------------------- |
| `onStart`           | `started` result          | `connected` event of the stream                         |
| `onEnd`, no error   | `stopped` result          | `return` event                                          |
| `onEnd`, with error | error of the subscription | `serialized-error` that is not retryable, failed stream |

- A listener that joins a confirmed subscription gets `onStart` right away.
- On the end, events pending in a `delivery` strategy are delivered first, then `onEnd` runs.
- A reconnect never restarts an ended subscription. A new `listen()` starts a fresh one without the old event id.
- Errors of the whole connection, such as a failing `createContext`, reach `socket.onError` and don't end subscriptions.
- Unsubscribing yourself does not call `onEnd`.

## Options

Adapter options go in the socket's `adapterOptions`:

| Option             | Adapter                | Description                                                         |
| ------------------ | ---------------------- | ------------------------------------------------------------------- |
| `autoConnect`      | both                   | Connect when the socket is created, default `true`                  |
| `connectionParams` | both                   | Read by the server in `createContext` as `info.connectionParams`    |
| `WebSocket`        | `TrpcWebsocketAdapter` | The `WebSocket` class, for example from `ws`. The global by default |
| `protocols`        | `TrpcWebsocketAdapter` | Subprotocols of the `WebSocket`                                     |
| `keepAlive`        | `TrpcWebsocketAdapter` | `{ enabled, intervalMs?, pongTimeoutMs? }`, ping a quiet connection |
| `EventSource`      | `TrpcSseAdapter`       | The `EventSource` class, for example from `eventsource` in Node.js  |
| `eventSourceInit`  | `TrpcSseAdapter`       | Passed to the `EventSource` constructor                             |

### Connection params

The WebSocket adapter sends `connectionParams` as the first message of every connection, the SSE adapter adds them to
the URL of every stream. For a fresh token per attempt, change them in `socket.onConnect`.

```ts title="api/socket.ts"
socket.onConnect(async ({ connection }) => ({
  ...connection,
  adapterOptions: { ...connection.adapterOptions, connectionParams: { token: await refreshToken() } },
}));
```

### Keep-alive

The WebSocket adapter always answers the server's `PING`. With `keepAlive` it also sends its own on a quiet connection
and reconnects when the `PONG` is late. Over SSE the server decides: with `sse.client.reconnectAfterInactivityMs` in
`initTRPC.create()`, a stream without events or pings for that long restarts from the last event.

### Timeouts and cleanup

The socket's `connectionTimeout` (default 5 seconds) limits one connection attempt, including a stream that has not
received its `connected` event. `reconnectTime` (default 1 second) and `maxReconnectTime` (default 30 seconds) bound
the jittered backoff of the WebSocket adapter, see [reconnection](/docs/guides/sockets/connection). `socket.destroy()`
closes the connection for good.

### Transformers

Pass the server's transformer to the adapter factory. It handles inputs, events and errors.

```ts title="api/socket.ts"
import superjson from "superjson";

export const socket = new Socket({ url: "ws://localhost:3001", adapter: TrpcWebsocketAdapter({ transformer: superjson }) });
```

## Limits

- The adapters handle subscriptions only. `emit()` throws; send queries and mutations with the `TrpcAdapter`.
- WebSocket batching, lazy connections and custom encoders (`experimental_encoder`) are not supported.
- A procedure that yields its own `{ id, data }` objects without `tracked()` is typed as tracked. Wrap the events with
  `tracked()` or use other field names.

---

:::secondary Summary

- `TrpcSseAdapter` and `TrpcWebsocketAdapter` connect a `Socket` to tRPC subscriptions over SSE or WebSocket.
- `TrpcSocketSchema` maps a router's subscriptions to `$listener`s with typed payloads and events.
- Listeners with the same input share one server subscription; `extra.eventId` resumes it after a reconnect.
- Errors arrive in `socket.onError` as a `TrpcSocketError`.

:::
