# A React Query devtools alternative for HyperFetch

[Read the API Reference »](/docs/api/plugin-devtools/Functions/DevtoolsPlugin.mdx)

If you came looking for react query devtools, this is the HyperFetch equivalent. The devtools plugin connects your
client to [HyperFlow](/docs/hyper-flow), a desktop app for macOS, Windows and Linux. HyperFlow shows every request and
response, lets you inspect, edit, invalidate and delete cache entries, and stops, starts and clears the request queues.
It is not a browser extension and it does not render inside your page.

---

:::tip Purpose

1.  **Real-time request inspection**: See every request your client sends and the response or error it got.
2.  **Cache control**: Inspect cached data, change it, invalidate it or delete it, and watch the app react.
3.  **Queue control**: Stop, start and clear the fetch and submit queues to test slow or offline flows.
4.  **Sockets and backends**: Inspect sockets next to requests, and connect Node.js services as well as browsers.

:::

## React Query Devtools, React DevTools and HyperFlow

Three tools with similar names do different jobs:

| Tool                        | What it is                                                          | What it shows                                    |
| --------------------------- | ------------------------------------------------------------------- | ------------------------------------------------ |
| React Query Devtools        | A React component from `@tanstack/react-query-devtools`, rendered inside your app as a floating or embedded panel | The TanStack Query cache: queries, their state and data |
| React DevTools (Chrome, Firefox, Edge) | A browser extension from the React team                  | The component tree, props, state, hooks and the profiler |
| HyperFlow                   | A desktop app that your client connects to through this plugin      | HyperFetch requests, cache, queues and sockets   |

[React Query Devtools](https://tanstack.com/query/latest/docs/framework/react/devtools) is the right tool for a
TanStack Query app. It mounts in the page, and by default it is only included in development builds. Chrome's React
DevTools does not show network traffic or a data cache at all. It answers "why did this component render", not "what did
this request return".

HyperFlow runs outside the browser. The plugin opens a WebSocket to the app on `ws://localhost:2137`, so the same window
can show a browser tab and a Node.js backend side by side, each under its `appName`.

---

## Install the Plugin

Install the DevTools plugin using npm or yarn. The plugin talks to HyperFlow through `@hyper-fetch/sockets`, so install it
too:

```bash npm2yarn2pnpm
npm install @hyper-fetch/plugin-devtools @hyper-fetch/sockets
```

---

## Usage

Import the plugin and use it in your application:

(@import plugin-devtools DevtoolsPlugin type=import)

```tsx
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";

const client = new Client({ url: "http://localhost:3000" }).addPlugin(
  DevtoolsPlugin({
    // highlight-start
    appName: "My App",
    // highlight-end
  }),
);
```

(@import plugin-devtools DevtoolsPluginOptions type=returns)

---

## Inspecting sockets

Pass your sockets in the `sockets` option to inspect their connection, messages and errors in HyperFlow, next to the
requests of the client. See the [Socket Inspector](/docs/hyper-flow/features/sockets).

```tsx
const socket = new Socket({ url: "ws://localhost:3000" });

const client = new Client({ url: "http://localhost:3000" }).addPlugin(
  DevtoolsPlugin({
    appName: "My App",
    // highlight-next-line
    sockets: [socket],
  }),
);
```

---

## Node.js backends

The plugin reports from servers and scripts too, so you can inspect the requests your backend sends. Use the
`environment` option to tell the backend apart from your frontend in HyperFlow.

```tsx
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";

const client = new Client({ url: "http://localhost:3000" }).addPlugin(
  DevtoolsPlugin({
    appName: "My API",
    environment: "backend",
  }),
);
```

On Node.js 22+, Deno and Bun the plugin uses the global `WebSocket`. On Node.js 18 and 20 install `ws` and pass its
class:

```tsx
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";
import { WebSocket } from "ws";

const client = new Client({ url: "http://localhost:3000" }).addPlugin(
  DevtoolsPlugin({
    appName: "My API",
    environment: "backend",
    // highlight-next-line
    WebSocket: WebSocket as unknown as typeof globalThis.WebSocket,
  }),
);
```

## Only in development

The plugin connects whenever it is added, so add it only in builds where you want HyperFlow to see the traffic:

```tsx
const client = new Client({ url: "http://localhost:3000" });

if (process.env.NODE_ENV === "development") {
  client.addPlugin(DevtoolsPlugin({ appName: "My App" }));
}
```

If you changed the port in HyperFlow, pass the address with the `url` option. Set `debug: true` to log what the plugin
sends. Read [connecting HyperFlow](../../hyper-flow/connecting.mdx) for the full setup and the
[network inspector](../../hyper-flow/features/network.mdx) for what you see once it connects.
