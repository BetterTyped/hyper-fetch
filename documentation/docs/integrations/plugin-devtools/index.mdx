# A React Query devtools alternative for HyperFetch

`@hyper-fetch/plugin-devtools` connects your client to [HyperFlow](/docs/hyper-flow), a desktop devtools app for macOS,
Windows and Linux. HyperFlow shows every request and response, and lets you edit the cache and control the queues while
the app runs. It is the HyperFetch counterpart of React Query Devtools, but it runs outside the browser.

<Screenshot
  src="/img/hyper-flow/network.webp"
  alt="The HyperFlow Network page listing the requests of a connected app with their method, endpoint, status and timing."
  caption="Every request of the connected client, live, in HyperFlow."
/>

:::tip Purpose

1. **Request inspection**: see every request your client sends and the response or error it got.
2. **Cache and queue control**: edit, invalidate or delete cached data, and stop, start or clear the queues.
3. **Sockets, dbs and backends**: inspect sockets and dbs next to requests, and connect Node.js services as well as
   browsers.

:::

---

## Install

The plugin talks to HyperFlow through `@hyper-fetch/sockets`, so install both:

```bash npm2yarn2pnpm
npm install @hyper-fetch/plugin-devtools @hyper-fetch/sockets
```

---

## Connect your client

Add the plugin to the client. It opens a WebSocket to HyperFlow on `ws://localhost:2137`, and the app appears there
under its `appName`. The plugin connects whenever it is added, so add it only in development:

```ts title="src/api/client.ts"
import { createClient } from "@hyper-fetch/core";
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";

export const client = createClient({ url: "http://localhost:3000" });

if (process.env.NODE_ENV === "development") {
  // highlight-next-line
  client.addPlugin(DevtoolsPlugin({ appName: "My App" }));
}
```

---

## Network

The [network inspector](/docs/hyper-flow/features/network) lists every request with its payload, headers, response,
status and timings. Failed and paused requests are marked, so you see retries and offline queues as they happen.

---

## Cache

The [cache inspector](/docs/hyper-flow/features/cache) lists every cache entry with its freshness and observers. Edit a
value, mark it stale, remove it or replace it with an error, and your hooks pick up the change at once.

## Queues

The [queue inspector](/docs/hyper-flow/features/queues) shows the fetch and submit queues. Stop, start and clear them
to test slow or offline flows without touching the server.

---

## Sockets and dbs

Pass your sockets in `sockets` to inspect their connection, messages and errors next to the requests, see the
[socket inspector](/docs/hyper-flow/features/sockets). Pass [`@hyper-fetch/db`](/docs/db/overview) dbs in `dbs` to
inspect their collections, loaded subsets, live queries and outbox, see the [db inspector](/docs/hyper-flow/features/db).

```ts title="src/api/client.ts"
client.addPlugin(DevtoolsPlugin({ appName: "My App", sockets: [socket], dbs: [db] }));
```

## Options

| Option        | Type                          | Default                  | Description                                                          |
| ------------- | ----------------------------- | ------------------------ | -------------------------------------------------------------------- |
| `appName`     | `string`                      | required                 | Name the app is listed under in HyperFlow                            |
| `url`         | `string`                      | `"ws://localhost:2137"`  | HyperFlow address, change it when you change the port in HyperFlow   |
| `environment` | `string`                      | -                        | Shown next to the app name, for example `"backend"` or `"staging"`   |
| `debug`       | `boolean`                     | `false`                  | Logs what the plugin sends                                           |
| `WebSocket`   | `typeof WebSocket`            | global `WebSocket`       | `WebSocket` class for runtimes without a global one                  |
| `sockets`     | `SocketInstance[]`            | -                        | Sockets to inspect                                                   |
| `dbs`         | `DevtoolsDb[]`                | -                        | `@hyper-fetch/db` dbs to inspect                                     |

---

## Node.js backends

The plugin reports from servers and scripts too. Set `environment` to tell the backend apart from the frontend. On
Node.js 22+, Deno and Bun the plugin uses the global `WebSocket`. On Node.js 18 and 20, install `ws` and pass its class:

```ts title="server/client.ts"
import { createClient } from "@hyper-fetch/core";
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";
import { WebSocket } from "ws";

export const client = createClient({ url: "http://localhost:3000" }).addPlugin(
  DevtoolsPlugin({
    appName: "My API",
    environment: "backend",
    // highlight-next-line
    WebSocket: WebSocket as unknown as typeof globalThis.WebSocket,
  }),
);
```

## React Query Devtools, React DevTools and HyperFlow

Three tools with similar names do different jobs:

| Tool                 | What it is                                                         | What it shows                                    |
| -------------------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| React Query Devtools | A component from `@tanstack/react-query-devtools`, inside your app | The TanStack Query cache: queries, state, data   |
| React DevTools       | A browser extension from the React team                            | The component tree, props, state and profiler    |
| HyperFlow            | A desktop app your client connects to through this plugin          | HyperFetch requests, cache, queues and sockets   |

Because HyperFlow runs outside the browser, one window can show a browser tab and a Node.js backend side by side.

---

## Troubleshooting

- **The app does not appear**: check that HyperFlow is open and that `url` matches its port, see
  [connecting HyperFlow](/docs/hyper-flow/connecting).
- **Nothing is logged**: set `debug: true` to see what the plugin sends.
- **No connection from Node.js 18 or 20**: these versions have no global `WebSocket`, pass the `ws` class in the
  `WebSocket` option.
