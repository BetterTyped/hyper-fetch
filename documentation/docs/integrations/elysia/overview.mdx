# Elysia client with types from your app

`@hyper-fetch/elysia` turns the type of an [Elysia](https://elysiajs.com/) app into a schema for
[`createSdk`](/docs/core/sdk), so the frontend calls your backend through an SDK whose responses, errors, payloads,
query params and URL params come from your routes and schemas. The package exports types only and adds no code to your
bundle.

:::tip Purpose

1. **One source of truth**: Elysia route definitions type the frontend, with no codegen and no hand-written schema.
2. **Typed inputs**: `body` and `query` schemas type the payload and query params, `:param` segments type `setParams()`.
3. **Typed errors**: 2xx bodies type `data`, every other status, including Elysia's `422` validation error, types
   `error`.
4. **Full HyperFetch features**: every route is a regular `Request` with cache, retries, deduplication and React hooks.

:::

---

## Install

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/elysia
```

`elysia` 1.3 or newer is a peer dependency. Install the package where you export the schema type, usually the backend.
The schema is a type, so it works whether the backend runs on Bun, Node.js or another runtime Elysia supports.

---

## 1. Export the app schema

Chain your routes and export the schema type. Elysia only types routes defined in one chain, the same rule as its own
Eden client.

```ts title="backend/src/app.ts"
import { Elysia, t } from "elysia";
import type { ElysiaSchema } from "@hyper-fetch/elysia";

const users = new Elysia({ prefix: "/users" })
  .get("/", () => [{ id: "1", name: "Ann" }])
  .get("/:userId", ({ params }) => ({ id: params.userId, name: "Ann" }))
  .post("/", ({ body, status }) => status(201, { id: "2", name: body.name }), {
    body: t.Object({ name: t.String() }),
  });

export const app = new Elysia().use(users);

// highlight-next-line
export type AppSchema = ElysiaSchema<typeof app>;
```

---

## 2. Create the SDK

Pass the schema to `createSdk` on the frontend. Use `import type`, so no backend code reaches the client bundle.

```ts title="frontend/src/api.ts"
import { createClient, createSdk } from "@hyper-fetch/core";
import type { AppSchema } from "@my-app/backend";

export const client = createClient({ url: "https://api.example.com" });

// highlight-next-line
export const sdk = createSdk<typeof client, AppSchema>(client);
```

---

## 3. Send requests

Types follow the Elysia route definitions:

```ts title="frontend/src/users.ts"
const { data } = await sdk.users.$get.send();

const { data: user, error } = await sdk.users.$userId.$get
  .setParams({ userId: "1" })
  .send();

const { data: created } = await sdk.users.$post
  .setPayload({ name: "Bob" })
  .send();
```

The same requests work with `useFetch` and `useSubmit` from [`@hyper-fetch/react`](/docs/react/overview).

## How routes map to the SDK

| Elysia route                             | SDK accessor                                  | Endpoint                      |
| ---------------------------------------- | --------------------------------------------- | ----------------------------- |
| `app.get("/", ...)`                      | `sdk.$get`                                    | `/`                           |
| `new Elysia({ prefix: "/users" })` + `/` | `sdk.users.$get`                              | `/users`                      |
| `.get("/:userId/posts", ...)`            | `sdk.users.$userId.posts.$get`                | `/users/:userId/posts`        |
| `.get("/auth/google-login", ...)`        | `sdk.auth.googleLogin.$get`                   | `/auth/google-login`          |
| `.get("/files/:fileId?", ...)`           | `sdk.files.$get` and `sdk.files.$fileId.$get` | `/files` and `/files/:fileId` |
| `.group("/v1", (app) => app.use(users))` | `sdk.v1.users.$get`                           | `/v1/users`                   |

- `:param` segments become `$param` properties, kebab-case segments become camelCase, and `createSdk` turns them back
  when it builds the URL.
- Methods become lowercase keys: `$get`, `$post`, `$put`, `$patch`, `$delete`, and custom methods registered with
  `.route()`, such as `$propfind`.
- An optional `:param?` adds the route with and without the param, because HyperFetch params are always required.
- The schema leaves out `.ws()` routes (connect a [`Socket`](/docs/sockets/overview)), `.all()` routes, wildcard `*`
  segments, handlers attached with `.mount()` and paths with ten or more segments. At nine segments `createSdk` stops
  injecting the client into the request.

## How request types are read

| Request generic | Comes from                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------ |
| Response        | The bodies the handler returns with a 2xx status, `undefined` when it only returns others  |
| Local error     | The bodies of every other status, such as `status(404, { message })` and the `422` error   |
| Payload         | The `body` schema, `FormData` when it has a `t.File()` or `t.Files()` field                |
| Query params    | The `query` schema, `undefined` without one                                                |
| Endpoint        | The full Elysia path, which types `setParams()`                                            |

`headers` schemas do not type the request, so pass headers with `setHeaders()`. `params` schemas such as `t.Numeric()`
are not read either, params are typed from the path. The client's [global error type](/docs/core/client) applies next
to the local error of each route.

---

## What arrives over HTTP

Elysia types the value a handler returns, but the client receives it after it went over HTTP. The types follow what
HyperFetch reads:

| Handler returns                                                    | Typed as     | Why                                          |
| ------------------------------------------------------------------ | ------------ | -------------------------------------------- |
| A `Date`, also inside objects and arrays                           | `string`     | JSON sends dates as ISO strings              |
| `null` or `undefined`                                              | `""`         | Elysia sends an empty body                   |
| Nothing, or `any`                                                  | `unknown`    | Elysia types both the same way               |
| A generator, `sse()`, a `ReadableStream`, a `Response` or `form()` | `unknown`    | The body is not JSON                         |
| An error the handler throws                                        | global error | Elysia does not type it, the status is `500` |

Read a streamed route with `setOptions({ streaming: true })` and parse the stream yourself.

---

## Elysia quirks

- **Array query params**: HyperFetch encodes arrays as `tags[]=a&tags[]=b` by default, which Elysia rejects with a
  `422`. Send repeated keys with `client.adapter.setQueryParamsMapperConfig({ arrayFormat: "none" })`.
- **File uploads**: build the `FormData` yourself, HyperFetch sends it as it is:

```ts title="frontend/src/upload.ts"
const form = new FormData();
form.append("title", "report");
form.append("file", file);

await sdk.upload.$post.setPayload(form).send();
```

## Elysia Eden or HyperFetch

Elysia ships its own client, [Eden](https://elysiajs.com/eden/overview). It reads the app type the same way, as Eden
Treaty (`treaty<App>(url)`) or Eden Fetch (`edenFetch<App>(url)`), and Treaty also covers WebSocket routes. If you only
need typed calls, Eden is the shortest path. This package puts each route behind a HyperFetch `Request` instead:

| Need                      | Eden Treaty  | `@hyper-fetch/elysia`                                       |
| ------------------------- | ------------ | ----------------------------------------------------------- |
| Types from the Elysia app | Yes          | Yes                                                         |
| Typed errors per status   | Yes          | Yes, non-2xx statuses type `error`                          |
| Response cache            | Not built in | [Built-in cache](/docs/core/cache)                          |
| Retries and deduplication | Not built in | Request options                                             |
| React hooks               | Not built in | `useFetch` and `useSubmit`                                  |
| WebSocket routes          | Yes          | Left out, connect a [`Socket`](/docs/sockets/socket)        |

Pick this package when the same data is read in many components, when you need offline queues, or when the frontend
also talks to services that are not Elysia. Earlier releases called `ElysiaSchema` `ElysiaAppToHyperFetch`, and the old
name still works as `@deprecated`.

---

:::secondary Summary

- `ElysiaSchema<typeof app>` turns a chained Elysia app into a schema for `createSdk`.
- 2xx bodies type the response, every other status types the local error.
- Response types follow the wire: dates are strings, empty bodies are `""`, streams are `unknown`.
- The package ships types only, so import it with `import type` on the frontend.

:::
