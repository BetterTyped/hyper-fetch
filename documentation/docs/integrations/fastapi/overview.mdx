# FastAPI

FastAPI serves an OpenAPI document for every app, built from your path operations and Pydantic models. The
[HyperFetch CLI](/docs/cli/overview) turns it into a typed TypeScript SDK, so the frontend gets the same models as
types. Nothing is added on the Python side.

:::tip Purpose

1. **Nothing to add to FastAPI**: `/openapi.json` is there from the first route.
2. **Pydantic models as TypeScript types**: response models, request bodies, path and query params are all typed.
3. **Validation errors typed too**: the `422` response FastAPI documents becomes the request's error type.

:::

---

## Install

The server needs nothing new. In the frontend, install HyperFetch and the CLI:

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
npm install -D @hyper-fetch/cli
```

---

## 1. Serve the OpenAPI document

FastAPI builds the document for you. Give your routes a response model, through `response_model` or a return type, so
the SDK knows what they return:

```python title="server/main.py"
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI(title="Shop API")

class User(BaseModel):
    id: int
    name: str
    email: str | None = None

@app.get("/users/{user_id}")
def get_user(user_id: int) -> User:
    return find_user(user_id)
```

Run the app and the document is on `http://localhost:8000/openapi.json`.

---

## 2. Generate the SDK

Run the CLI in the frontend project while the server is running:

```bash title="frontend"
npx hyper-fetch generate --template openapi --fileName fastapi.sdk.ts \
  --overwrite --url http://localhost:8000/openapi.json
```

It writes `src/api/fastapi.sdk.ts`. The folder comes from `api.json`, which the first run creates. Every path becomes
nested keys and every method a `$` key, so `GET /users/{user_id}` is `sdk.users.$user_id.$get`.

---

## 3. Call your API

```ts title="frontend/src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

import { createSdk } from "./fastapi.sdk";

export const client = createClient({ url: "http://localhost:8000" });
export const sdk = createSdk(client);
```

```ts title="frontend/src/users.ts"
import { sdk } from "./api/client";

// data: { id: number; name: string; email?: string | null } | null
const { data, error } = await sdk.users.$user_id.$get
  .setParams({ user_id: 42 })
  .send();
```

Every entry is a regular [Request](/docs/core/request), so it also works with `useFetch` and `useSubmit` from
[`@hyper-fetch/react`](/docs/react/overview).

---

## Framework quirks

- **Response models**: a route without `response_model` or a return type documents an empty response schema, so its
  response is untyped.
- **No running server**: dump the document from Python
  (`python -c "import json; from main import app; print(json.dumps(app.openapi()))" > openapi.json`) and pass that
  path to `--url`. A local path is resolved from the frontend project.

---

## Keep the SDK in sync

Add a script so regenerating is one command locally and in CI. `-o` overwrites the old file without asking:

```json title="frontend/package.json"
{
  "scripts": {
    "api:generate": "hyper-fetch generate -t openapi -u http://localhost:8000/openapi.json -f fastapi.sdk.ts -o"
  }
}
```

---

:::secondary Summary

- FastAPI serves `/openapi.json` for every app.
- `hyper-fetch generate` turns it into a typed SDK with your Pydantic models as types.
- `createSdk(client)` gives you typed requests for `send()`, `useFetch` and `useSubmit`.

:::
