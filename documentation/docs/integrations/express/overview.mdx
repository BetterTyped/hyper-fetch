# Express

Describe your Express routes as an OpenAPI document and the [HyperFetch CLI](/docs/cli/overview) turns it into a typed
SDK, so the frontend calls every route with typed responses, payloads, params and query params. Express has no schema of
its own, so a tool such as `swagger-jsdoc` writes the document. There is no Express package to install.

:::tip Purpose

1. **No glue package**: any tool that writes OpenAPI for Express works with the CLI.
2. **One source of truth**: the document behind your API docs also types your client.
3. **One command to resync**: change a route, regenerate, and the compiler shows every call to fix.

:::

---

## Install

On the server, install the tool that writes the document. In the frontend, install HyperFetch and the CLI:

```bash title="server"
npm install swagger-jsdoc
```

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
npm install -D @hyper-fetch/cli
```

---

## 1. Serve the OpenAPI document

`swagger-jsdoc` reads the `@openapi` comments above your routes and builds the document. Serve it as JSON:

```ts title="server/app.ts"
import express from "express";
import swaggerJsdoc from "swagger-jsdoc";

const app = express();

const openapi = swaggerJsdoc({
  definition: { openapi: "3.0.0", info: { title: "Shop API", version: "1.0.0" } },
  apis: ["./src/routes/*.ts"],
});

// highlight-next-line
app.get("/openapi.json", (_req, res) => res.json(openapi));

app.listen(3000);
```

```ts title="server/src/routes/users.ts"
/**
 * @openapi
 * /users/{id}:
 *   get:
 *     parameters:
 *       - { in: path, name: id, required: true, schema: { type: string } }
 *     responses:
 *       200:
 *         content:
 *           application/json:
 *             schema:
 *               type: object
 *               properties: { id: { type: string }, name: { type: string } }
 */
router.get("/users/:id", getUser);
```

---

## 2. Generate the SDK

Run the CLI in the frontend project while the server is running:

```bash title="frontend"
npx hyper-fetch generate --template openapi --fileName express.sdk.ts \
  --overwrite --url http://localhost:3000/openapi.json
```

It writes `src/api/express.sdk.ts`. The folder comes from `api.json`, which the first run creates. Every path becomes
nested keys and every method a `$` key, so `GET /users/{id}` is `sdk.users.$id.$get`.

---

## 3. Call your API

```ts title="frontend/src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

import { createSdk } from "./express.sdk";

export const client = createClient({ url: "http://localhost:3000" });
export const sdk = createSdk(client);
```

```ts title="frontend/src/users.ts"
import { sdk } from "./api/client";

// data is typed from the 200 response of GET /users/{id}
const { data, error } = await sdk.users.$id.$get.setParams({ id: "42" }).send();
```

Every entry is a regular [Request](/docs/core/request), so it also works with `useFetch` and `useSubmit` from
[`@hyper-fetch/react`](/docs/react/overview).

---

## Framework quirks

- **Other ways to write the document**: tsoa generates routes and the document from typed controllers (`tsoa spec`), and
  `@asteasolutions/zod-to-openapi` builds it from the zod schemas you validate with. Any OpenAPI 3 JSON document works.
- **No running server**: write `openapi` to a file in a small script (`writeFileSync("openapi.json",
  JSON.stringify(openapi))`) and pass that path to `--url`. A local path is resolved from the frontend project.

---

## Keep the SDK in sync

Add a script so regenerating is one command locally and in CI. `-o` overwrites the old file without asking:

```json title="frontend/package.json"
{
  "scripts": {
    "api:generate": "hyper-fetch generate -t openapi -u http://localhost:3000/openapi.json -f express.sdk.ts -o"
  }
}
```
