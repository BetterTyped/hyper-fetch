# Hono client with types from your Hono app

`@hyper-fetch/hono` turns the type of a [Hono](https://hono.dev/) app into a schema for [`createSdk`](/docs/core/sdk),
so the frontend calls your backend through an SDK whose responses, payloads, query params and URL params come from your
routes and validators. The package exports types only and adds no code to your bundle.

:::tip Purpose

1. **One source of truth**: Hono route definitions type the frontend, with no codegen and no hand-written schema.
2. **Typed inputs**: `json` and `query` validators type the payload and query params, `:param` segments type
   `setParams()`.
3. **Full HyperFetch features**: every route is a regular `Request` with cache, retries, deduplication and React hooks.

:::

---

## Install

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/hono
```

`hono` 4 or newer is a peer dependency. Install the package where you export the schema type, usually the backend.

---

## 1. Export the app schema

Chain your routes and export the schema type. Hono only types routes defined in one chain, the same rule as its own RPC
client.

```ts title="backend/src/app.ts"
import { Hono } from "hono";
import { validator } from "hono/validator";
import type { HonoSchema } from "@hyper-fetch/hono";

const users = new Hono()
  .get("/", (c) => c.json([{ id: "1", name: "Ann" }]))
  .get("/:userId", (c) => c.json({ id: c.req.param("userId"), name: "Ann" }))
  .post(
    "/",
    validator("json", (value: { name: string }) => value),
    (c) => c.json({ id: "2", name: c.req.valid("json").name }, 201),
  );

export const app = new Hono().route("/users", users);

// highlight-next-line
export type AppSchema = HonoSchema<typeof app>;
```

---

## 2. Create the SDK

Pass the schema to `createSdk` on the frontend. Use `import type`, so no backend code reaches the client bundle.

```ts title="frontend/src/api.ts"
import { createClient, createSdk } from "@hyper-fetch/core";
import type { AppSchema } from "@my-app/backend";

export const client = createClient({ url: "https://api.example.com" });

// highlight-next-line
export const sdk = createSdk<typeof client, AppSchema>(client);
```

---

## 3. Send requests

Types follow the Hono route definitions:

```ts title="frontend/src/users.ts"
const { data } = await sdk.users.$get.send();

const { data: user } = await sdk.users.$userId.$get
  .setParams({ userId: "1" })
  .send();

const { data: created } = await sdk.users.$post
  .setPayload({ name: "Bob" })
  .send();
```

The same requests work with `useFetch` and `useSubmit` from [`@hyper-fetch/react`](/docs/react/overview).

## How routes map to the SDK

| Hono route                          | SDK accessor                                  | Endpoint                      |
| ----------------------------------- | --------------------------------------------- | ----------------------------- |
| `app.get("/", ...)`                 | `sdk.$get`                                    | `/`                           |
| `app.route("/users", users)` + `/`  | `sdk.users.$get`                              | `/users`                      |
| `.get("/:userId/posts", ...)`       | `sdk.users.$userId.posts.$get`                | `/users/:userId/posts`        |
| `.get("/files/:fileId?", ...)`      | `sdk.files.$get` and `sdk.files.$fileId.$get` | `/files` and `/files/:fileId` |
| `.get("/posts/:postId{[0-9]+}")`    | `sdk.posts.$postId.$get`                      | `/posts/:postId`              |
| `.get("/auth/google-login", ...)`   | `sdk.auth.googleLogin.$get`                   | `/auth/google-login`          |
| `new Hono().basePath("/api")`       | `sdk.api.users.$get`                          | `/api/users`                  |

- `:param` segments become `$param` properties, kebab-case segments become camelCase, and `createSdk` turns them back
  when it builds the URL.
- Methods become lowercase `$get`, `$post`, `$put`, `$patch` and `$delete` keys. An `.all()` route gets every standard
  method, as in Hono's own client.
- An optional `:param?` adds the route with and without the param, because HyperFetch params are always required.
- A regex param keeps only its name. The server still checks the pattern, so a value it rejects resolves with a `404`.
- The endpoint never ends with a slash. In Hono's default strict mode a route registered as `/users/` only answers on
  `/users/`, so drop the trailing slash or add the `appendTrailingSlash()` middleware.

## How request types are read

| Request generic | Comes from                                                      |
| --------------- | --------------------------------------------------------------- |
| Response        | The handler output, for example the value passed to `c.json()`  |
| Payload         | The output of the route's `json` validator, `undefined` without |
| Query params    | The input of the route's `query` validator, `undefined` without |
| Endpoint        | The Hono path as `createSdk` sends it, which types `setParams()` |

When a handler returns different bodies per status, such as `c.json(user)` and `c.json({ message }, 404)`, the
response type is the union of both. At runtime a `404` still resolves with `success: false` and the body in `error`.
The client's [global error type](/docs/core/client) applies to every route.

## Hono quirks

- **Array query params**: HyperFetch sends `tags[]=a&tags[]=b` by default, which Hono reads as a key named `tags[]`.
  Send repeated keys with `client.adapter.setQueryParamsMapperConfig({ arrayFormat: "none" })`.
- **`form` validators** do not type the payload. Send `FormData` from a request created with
  `client.createRequest<{ payload: FormData }>()`.
- **`header` and `cookie` validators** do not type the request. Set them with `setHeaders()`.
- **`c.text()`** is typed as its literal text, but a text that is valid JSON, such as `"42"`, resolves parsed.
- **Empty bodies** from `c.body(null)` are typed as `null` and resolve as `""`.
- **`c.redirect()`** is typed as `undefined`. `fetch` follows the redirect, so the data is the body of the target.
- **WebSocket and SSE routes**: see [Realtime](/docs/integrations/hono/realtime).

## Hono RPC client or HyperFetch

Hono ships its own [RPC client](https://hono.dev/docs/guides/rpc): `hc<AppType>(url)` from `hono/client` reads the
same route types and returns a `fetch` response. If you only need typed calls, it is a good choice. This package puts
every route behind a HyperFetch `Request` instead:

| Need                      | `hc` from `hono/client` | `@hyper-fetch/hono`                                         |
| ------------------------- | ----------------------- | ----------------------------------------------------------- |
| Types from the Hono app   | Yes                     | Yes                                                         |
| Call shape                | `client.users.$get()`   | `sdk.users.$get.send()`                                     |
| Response cache            | Not built in            | [Built-in cache](/docs/core/cache)                          |
| Retries and deduplication | Not built in            | Request options                                             |
| React hooks               | Not built in            | `useFetch` and `useSubmit`                                  |
| WebSocket routes          | `$ws()` on the route    | A `Socket` with a typed URL, see [Realtime](/docs/integrations/hono/realtime) |

Earlier releases called `HonoSchema` and `HonoSocketPath` `HonoAppToHyperFetch` and `HonoWebSocketPath`. The old names
still work and are marked `@deprecated`.
