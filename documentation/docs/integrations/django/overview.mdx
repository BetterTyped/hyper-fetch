# Django

`drf-spectacular` describes your Django REST Framework views and serializers as an OpenAPI document, and the
[HyperFetch CLI](/docs/cli/overview) turns that document into a typed TypeScript SDK. The frontend then gets your
serializers as types. There is no Django package to install.

:::tip Purpose

1. **Serializers as TypeScript types**: responses and request bodies follow your serializers.
2. **No server needed to generate**: `drf-spectacular` writes the document to a file.
3. **One command to resync**: change a serializer, regenerate, and the compiler shows every call to fix.

:::

---

## Install

On the server, install `drf-spectacular`. In the frontend, install HyperFetch and the CLI:

```bash title="server"
pip install drf-spectacular
```

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
npm install -D @hyper-fetch/cli
```

---

## 1. Serve the OpenAPI document

Make `drf-spectacular` the schema class of Django REST Framework:

```python title="server/settings.py"
INSTALLED_APPS = [
    # ...
    "rest_framework",
    "drf_spectacular",
]

REST_FRAMEWORK = {
    "DEFAULT_SCHEMA_CLASS": "drf_spectacular.openapi.AutoSchema",
}
```

Then write the document to a JSON file:

```bash title="server"
python manage.py spectacular --format openapi-json --file openapi.json
```

---

## 2. Generate the SDK

Run the CLI in the frontend project and point it at the file:

```bash title="frontend"
npx hyper-fetch generate --template openapi --fileName django.sdk.ts \
  --overwrite --url ../server/openapi.json
```

It writes `src/api/django.sdk.ts`. The folder comes from `api.json`, which the first run creates. Every path becomes
nested keys and every method a `$` key, so `GET /api/users/{id}/` is `sdk.api.users.$id.$get`.

---

## 3. Call your API

```ts title="frontend/src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

import { createSdk } from "./django.sdk";

export const client = createClient({ url: "http://localhost:8000" });

// Django routes end with a slash, the SDK builds them without one
// highlight-start
client.adapter.setEndpointMapper((endpoint) =>
  endpoint.endsWith("/") ? endpoint : `${endpoint}/`,
);
// highlight-end

export const sdk = createSdk(client);
```

```ts title="frontend/src/users.ts"
import { sdk } from "./api/client";

// data is typed from the serializer of GET /api/users/{id}/
const { data, error } = await sdk.api.users.$id.$get.setParams({ id: 42 }).send();
```

Every entry is a regular [Request](/docs/core/request), so it also works with `useFetch` and `useSubmit` from
[`@hyper-fetch/react`](/docs/react/overview).

---

## Framework quirks

- **Trailing slashes**: the endpoint mapper above adds the slash Django expects, so `POST` requests do not hit the
  `APPEND_SLASH` redirect. Skip it when your router has none (`DefaultRouter(trailing_slash=False)`).
- **Serving the document**: add `SpectacularAPIView` to `urls.py` to serve it over HTTP. It returns YAML by default, so
  pass the URL with `?format=json` to `--url`.

---

## Keep the SDK in sync

Add a script so regenerating is one command locally and in CI. Run the `spectacular` command first, or chain both in CI.
`-o` overwrites the old file without asking:

```json title="frontend/package.json"
{
  "scripts": {
    "api:generate": "hyper-fetch generate -t openapi -u ../server/openapi.json -f django.sdk.ts -o"
  }
}
```

:::secondary Summary

- `drf-spectacular` writes your Django REST Framework API as an OpenAPI document.
- `hyper-fetch generate` turns it into a typed SDK with your serializers as types.
- An endpoint mapper keeps the trailing slash Django expects.

:::
