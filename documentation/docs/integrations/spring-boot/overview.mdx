# Spring Boot

`springdoc-openapi` describes your Spring Boot controllers as an OpenAPI document, with your DTOs as schemas. The
[HyperFetch CLI](/docs/cli/overview) turns that document into a typed TypeScript SDK, so the frontend calls every
endpoint with your Java types translated to TypeScript.

:::tip Purpose

1. **One dependency on the server**: `springdoc-openapi` serves the document with no configuration.
2. **DTOs as TypeScript types**: request bodies, responses and params follow your Java classes.
3. **One command to resync**: change a controller, regenerate, and the compiler shows every call to fix.

:::

---

## Install

On the server, add the springdoc starter for Spring MVC. Use 2.x on Spring Boot 3 and 3.x on Spring Boot 4. In the
frontend, install HyperFetch and the CLI:

```xml title="server/pom.xml"
<dependency>
  <groupId>org.springdoc</groupId>
  <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
  <version>3.2.1</version>
</dependency>
```

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
npm install -D @hyper-fetch/cli
```

---

## 1. Serve the OpenAPI document

Your controllers need no changes:

```java title="server/UserController.java"
@RestController
@RequestMapping("/users")
class UserController {
  @GetMapping("/{id}")
  UserDto getUser(@PathVariable long id) {
    return users.find(id);
  }
}
```

The document is on `http://localhost:8080/v3/api-docs`.

---

## 2. Generate the SDK

Run the CLI in the frontend project while the server is running:

```bash title="frontend"
npx hyper-fetch generate --template openapi --fileName spring.sdk.ts \
  --overwrite --url http://localhost:8080/v3/api-docs
```

It writes `src/api/spring.sdk.ts`. The folder comes from `api.json`, which the first run creates. Every path becomes
nested keys and every method a `$` key, so `GET /users/{id}` is `sdk.users.$id.$get`.

---

## 3. Call your API

```ts title="frontend/src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

import { createSdk } from "./spring.sdk";

export const client = createClient({ url: "http://localhost:8080" });
export const sdk = createSdk(client);
```

```ts title="frontend/src/users.ts"
import { sdk } from "./api/client";

// data is typed from UserDto
const { data, error } = await sdk.users.$id.$get.setParams({ id: 42 }).send();
```

Every entry is a regular [Request](/docs/core/request), so it also works with `useFetch` and `useSubmit` from
[`@hyper-fetch/react`](/docs/react/overview).

---

## Framework quirks

- **WebFlux**: use `springdoc-openapi-starter-webflux-ui` instead of the webmvc starter.
- **No running server**: `springdoc-openapi-maven-plugin` (goal `generate`) and `springdoc-openapi-gradle-plugin`
  (task `generateOpenApiDocs`) write `openapi.json` during the build. Pass that path to `--url`. A local path is
  resolved from the frontend project.

---

## Keep the SDK in sync

Add a script so regenerating is one command locally and in CI. `-o` overwrites the old file without asking:

```json title="frontend/package.json"
{
  "scripts": {
    "api:generate": "hyper-fetch generate -t openapi -u http://localhost:8080/v3/api-docs -f spring.sdk.ts -o"
  }
}
```

---

:::secondary Summary

- `springdoc-openapi` serves your controllers as an OpenAPI document at `/v3/api-docs`.
- `hyper-fetch generate` turns it into a typed SDK.
- `createSdk(client)` gives you typed requests for `send()`, `useFetch` and `useSubmit`.

:::
