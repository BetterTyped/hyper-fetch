# Laravel

Scramble reads your Laravel routes, form requests and API resources and builds an OpenAPI document without
annotations. The [HyperFetch CLI](/docs/cli/overview) turns that document into a typed TypeScript SDK, so the frontend
calls every route with your validation rules and resources as types.

:::tip Purpose

1. **No annotations**: Scramble infers the document from the code you already have.
2. **Validation rules as types**: form request rules become the payload type of each request.
3. **One command to resync**: change a route, regenerate, and the compiler shows every call to fix.

:::

---

## Install

On the server, install Scramble. In the frontend, install HyperFetch and the CLI:

```bash title="server"
composer require dedoc/scramble
```

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
npm install -D @hyper-fetch/cli
```

---

## 1. Serve the OpenAPI document

Scramble documents the routes under `api/` with no configuration:

```php title="server/routes/api.php"
Route::get('/users/{user}', fn (User $user) => new UserResource($user));
```

The document is on `http://localhost:8000/docs/api.json`, next to the UI on `/docs/api`.

---

## 2. Generate the SDK

Run the CLI in the frontend project while the server is running:

```bash title="frontend"
npx hyper-fetch generate --template openapi --fileName laravel.sdk.ts --overwrite \
  --url http://localhost:8000/docs/api.json
```

It writes `src/api/laravel.sdk.ts`. The folder comes from `api.json`, which the first run creates. Every path becomes
nested keys and every method a `$` key, so `GET /users/{user}` is `sdk.users.$user.$get`.

---

## 3. Call your API

```ts title="frontend/src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

import { createSdk } from "./laravel.sdk";

// Scramble leaves the api/ prefix out of the paths, so it goes into the base URL
export const client = createClient({ url: "http://localhost:8000/api" });
export const sdk = createSdk(client);
```

```ts title="frontend/src/users.ts"
import { sdk } from "./api/client";

// data is typed from UserResource
const { data, error } = await sdk.users.$user.$get.setParams({ user: 42 }).send();
```

Every entry is a regular [Request](/docs/core/request), so it also works with `useFetch` and `useSubmit` from
[`@hyper-fetch/react`](/docs/react/overview).

---

## Framework quirks

- **The `/api` prefix**: Scramble lists paths without the `api/` prefix and puts it in the server URL of the document.
  Give the HyperFetch client the same base URL, ending with `/api`.
- **No running server**: `php artisan scramble:export` writes the document to a file. Pass that path to `--url`. A
  local path is resolved from the frontend project.

---

## Keep the SDK in sync

Add a script so regenerating is one command locally and in CI. `-o` overwrites the old file without asking:

```json title="frontend/package.json"
{
  "scripts": {
    "api:generate": "hyper-fetch generate -t openapi -u http://localhost:8000/docs/api.json -f laravel.sdk.ts -o"
  }
}
```
