# Fastify

`@fastify/swagger` turns the JSON schemas on your Fastify routes into an OpenAPI document, and the
[HyperFetch CLI](/docs/cli/overview) turns that document into a typed SDK. The schemas that validate requests on the
server then type them on the client. There is no Fastify package to install.

:::tip Purpose

1. **Schemas you already have**: the route schemas that validate requests also type the client.
2. **No glue package**: `@fastify/swagger` and the CLI are all you need.
3. **One command to resync**: change a schema, regenerate, and the compiler shows every call to fix.

:::

---

## Install

On the server, install the plugin that writes the document. In the frontend, install HyperFetch and the CLI:

```bash title="server"
npm install @fastify/swagger
```

```bash npm2yarn2pnpm
npm install @hyper-fetch/core
npm install -D @hyper-fetch/cli
```

---

## 1. Serve the OpenAPI document

Register `@fastify/swagger` before your routes so it sees all of them, then serve `app.swagger()` as JSON:

```ts title="server/server.ts"
import Fastify from "fastify";
import swagger from "@fastify/swagger";

const app = Fastify();

// highlight-start
await app.register(swagger, {
  openapi: { info: { title: "Shop API", version: "1.0.0" } },
});
// highlight-end

const userSchema = {
  params: {
    type: "object",
    properties: { id: { type: "string" } },
    required: ["id"],
  },
  response: {
    200: {
      type: "object",
      properties: { id: { type: "string" }, name: { type: "string" } },
    },
  },
};

app.get<{ Params: { id: string } }>(
  "/users/:id",
  { schema: userSchema },
  async (request) => getUser(request.params.id),
);

// hide: true keeps this route out of the document
// highlight-next-line
app.get("/openapi.json", { schema: { hide: true } }, () => app.swagger());

await app.listen({ port: 3000 });
```

---

## 2. Generate the SDK

Run the CLI in the frontend project while the server is running:

```bash title="frontend"
npx hyper-fetch generate --template openapi --fileName fastify.sdk.ts \
  --overwrite --url http://localhost:3000/openapi.json
```

It writes `src/api/fastify.sdk.ts`. The folder comes from `api.json`, which the first run creates. Every path becomes
nested keys and every method a `$` key, so `GET /users/{id}` is `sdk.users.$id.$get`.

---

## 3. Call your API

```ts title="frontend/src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

import { createSdk } from "./fastify.sdk";

export const client = createClient({ url: "http://localhost:3000" });
export const sdk = createSdk(client);
```

```ts title="frontend/src/users.ts"
import { sdk } from "./api/client";

// data is typed from the 200 response schema of GET /users/:id
const { data, error } = await sdk.users.$id.$get.setParams({ id: "42" }).send();
```

Every entry is a regular [Request](/docs/core/request), so it also works with `useFetch` and `useSubmit` from
[`@hyper-fetch/react`](/docs/react/overview).

---

## Framework quirks

- **TypeBox and zod**: TypeBox schemas are JSON schemas and need nothing extra. With `fastify-type-provider-zod`, pass
  its `jsonSchemaTransform` as the `transform` option of `@fastify/swagger`.
- **Register order**: routes registered before `@fastify/swagger` are missing from the document.
- **No running server**: in a small script, `await app.ready()`, write `app.swagger()` to a JSON file and pass that path
  to `--url`. A local path is resolved from the frontend project.

---

## Keep the SDK in sync

Add a script so regenerating is one command locally and in CI. `-o` overwrites the old file without asking:

```json title="frontend/package.json"
{
  "scripts": {
    "api:generate": "hyper-fetch generate -t openapi -u http://localhost:3000/openapi.json -f fastify.sdk.ts -o"
  }
}
```

---

:::secondary Summary

- `@fastify/swagger` turns your route schemas into an OpenAPI document.
- `hyper-fetch generate` turns that document into a typed SDK.
- `createSdk(client)` gives you typed requests for `send()`, `useFetch` and `useSubmit`.

:::
