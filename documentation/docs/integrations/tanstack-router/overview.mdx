# TanStack Router

TanStack Router runs a route's loader before it renders, and with `defaultPreload: "intent"` already when a link is
hovered. A typed HyperFetch request fits in the loader directly. Pass the signal of the loader's `abortController` so
an outdated load cancels its call, and `throwOnError` so a failed response shows the route's `errorComponent`. There is
no package to install beyond `@hyper-fetch/core`, and `@hyper-fetch/react` if components read the data too.

---

:::tip Purpose

1.  **Typed loaders**: Params, response and error types come from the request.
2.  **Cancelled when outdated**: `abortController.signal` aborts the call when the router drops the load.
3.  **Errors in the errorComponent**: `throwOnError` rejects with the `error` of a failed response.
4.  **Prefetch on hover**: Preloading runs the loader, so HyperFetch has the data before the click.

:::

## Return data from a loader

```tsx title="routes/product.tsx"
import { createRoute } from "@tanstack/react-router";

export const productRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: "/products/$productId",
  loader: async ({ params, abortController }) => {
    const { data } = await getProduct
      .setParams({ productId: Number(params.productId) })
      .send({
        // highlight-start
        signal: abortController.signal,
        throwOnError: true,
        // highlight-end
      });
    return data;
  },
  component: () => <h1>{productRoute.useLoaderData().title}</h1>,
});
```

Loaders use `send()`, so HyperFetch caches, deduplicates and retries them. The `errorComponent` gets the `error` of the
response as its `error` prop. Narrow it before reading it, the router does not know its type.

## Share the cache with hooks

To keep one cache for loaders, hooks and mutations, let the loader only fill the HyperFetch cache and read it with
`useFetch`. Turn off the router's own cache of loader results, so it runs the loader on every preload and navigation:

```tsx title="router.tsx"
import { useFetch } from "@hyper-fetch/react";
import { createRoute, createRouter } from "@tanstack/react-router";

const productDetails = (productId: number) =>
  getProduct.setParams({ productId });

const productRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: "/products/$productId",
  params: {
    parse: ({ productId }) => ({ productId: Number(productId) }),
    stringify: ({ productId }) => ({ productId: String(productId) }),
  },
  loader: async ({ params, abortController }) => {
    // highlight-next-line
    await productDetails(params.productId).send({
      cachePolicy: "cache-first",
      signal: abortController.signal,
    });
  },
  component: () => {
    const { productId } = productRoute.useParams();
    const { data } = useFetch(productDetails(productId), { revalidate: false });
    return <h1>{data?.title}</h1>;
  },
});

export const router = createRouter({
  routeTree,
  // highlight-start
  defaultPreload: "intent",
  defaultPreloadStaleTime: 0,
  // highlight-end
});
```

`cache-first` makes the repeated loader runs free while HyperFetch has fresh data. Hover a link and the request goes out
before the click.

If you use TanStack Query, call `queryClient.ensureQueryData()` in the loader with the query function from the
[TanStack Query integration](/docs/integrations/tanstack-query/overview) instead.

:::note When it's helpful

- Apps on TanStack Router that want typed loaders with HyperFetch caching, retries and deduplication.
- Lists of links to slow pages, where prefetching on hover hides the wait.
- Teams that keep one cache for loaders, hooks and mutations instead of the router's loader cache.

:::
