# React Query Devtools vs HyperFlow

React Query Devtools are a panel inside your app that shows the TanStack Query cache. [HyperFlow](/docs/hyper-flow) is
a desktop app that shows what a HyperFetch client does: requests, cache, queues, sockets and dbs. Each one works only
with its own library, so this page helps you know what to expect when you move between them.

:::info How this page was written

React Query Devtools claims come from the [TanStack Query v5 devtools docs](https://tanstack.com/query/latest/docs/framework/react/devtools).
HyperFlow claims match the [HyperFlow docs](/docs/hyper-flow) and the plugin source. If something is out of date,
[open an issue](https://github.com/BetterTyped/hyper-fetch/issues) and we will fix it.

:::

---

## When to choose which

- **React Query Devtools** when your app uses TanStack Query. HyperFlow does not read a TanStack cache.
- **HyperFlow** when your app uses HyperFetch, on any adapter.
- **HyperFlow** when you want a frontend and a Node.js backend in one window, or socket traffic next to HTTP.
- **React Developer Tools** for component questions: props, state, and why something re-rendered. Use them with either
  of the above.

---

## Feature comparison

**Yes**: built in. **Partial**: possible with your own code or an extra package. **No**: not available.

| Capability                  | React Query Devtools                    | HyperFlow                                                 |
| --------------------------- | --------------------------------------- | --------------------------------------------------------- |
| Works with                  | TanStack Query                          | HyperFetch, any adapter                                   |
| Where it runs               | Panel rendered in your app ¹            | Desktop app for macOS, Windows and Linux                  |
| Setup                       | Render `<ReactQueryDevtools />`         | `client.addPlugin(DevtoolsPlugin({ appName }))`           |
| Left out of production      | Yes, by default ²                       | Partial, you add the plugin conditionally                 |
| Browse and edit cache data  | Yes                                     | Yes, plus invalidate and remove                           |
| Simulate errors             | Yes, `errorTypes`                       | Yes, **Simulate Error** on a cache entry                  |
| Mutations                   | Yes, since v5                           | Yes, listed with every other request                      |
| Request headers and timings | No, it shows cache state                | Yes, [network inspector](/docs/hyper-flow/features/network) |
| Request queues              | No                                      | Yes, stop, start, clear and force loading                 |
| WebSocket and SSE traffic   | No                                      | Yes, with the `sockets` option                            |
| Server-side apps            | Partial, third-party tools ³            | Yes, Node.js, Bun and Deno                                |
| Maturity                    | Stable                                  | Alpha                                                     |

1. `ReactQueryDevtools` is a floating panel with a toggle button. `ReactQueryDevtoolsPanel` is embedded and opened with
   your own UI.
2. They are bundled only when `process.env.NODE_ENV` is `development`. A separate production build can be lazy loaded.
3. The docs list third-party browser extensions for Chrome, Firefox and Edge, and a third-party macOS app for React
   Native.

## Side by side

### Connect the devtools

<Tabs>
<TabItem value="hf" label="HyperFlow">

```ts title="api/client.ts"
import { createClient } from "@hyper-fetch/core";
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";

export const client = createClient({ url: "https://api.example.com" });

// The plugin connects as soon as it is added, so keep it to development
if (process.env.NODE_ENV === "development") {
  client.addPlugin(DevtoolsPlugin({ appName: "Storefront" }));
}
```

</TabItem>
<TabItem value="tq" label="React Query Devtools">

```tsx title="app.tsx"
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { ReactQueryDevtools } from "@tanstack/react-query-devtools";

const queryClient = new QueryClient();

export function App() {
  return (
    <QueryClientProvider client={queryClient}>
      {/* your app */}
      <ReactQueryDevtools initialIsOpen={false} />
    </QueryClientProvider>
  );
}
```

</TabItem>
</Tabs>

HyperFlow needs `@hyper-fetch/plugin-devtools` and `@hyper-fetch/sockets` installed and the app
[downloaded](/docs/hyper-flow/download). The plugin talks to it over `ws://localhost:2137`, so nothing renders in your
page.

### Inspect a backend and its sockets

```ts title="server/client.ts"
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";
import { WebSocket } from "ws";

client.addPlugin(
  DevtoolsPlugin({
    appName: "Storefront API",
    environment: "server",
    sockets: [socket],
    // Only on Node.js 18 and 20. Node.js 22+, Bun and Deno have a global
    // WebSocket.
    WebSocket: WebSocket as unknown as typeof globalThis.WebSocket,
  }),
);
```

React Query Devtools have no equivalent: they render inside a React tree. See
[connect your app](/docs/hyper-flow/connecting) for every plugin option.

## Where React Query Devtools are the better choice

- **No extra app.** The panel sits next to your UI, in the same window.
- **Stable.** They are the official, mature tool for TanStack Query. HyperFlow is in alpha.
- **Data Explorer search.** You can filter queries by key or data and search nested values.
- **Production debugging.** A lazy-loaded production build can be toggled in a deployed app.

The React Developer Tools extension is a different tool: it inspects components, props and state, not requests or a
data cache.
