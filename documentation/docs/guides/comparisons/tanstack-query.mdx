# HyperFetch vs TanStack Query

TanStack Query (often still called React Query) caches and syncs the result of async functions you write. HyperFetch
defines and sends the request too, as a typed object with cache, queues and offline handling attached. This page
compares the two on the tasks you do every day.

:::info How this page was written

TanStack Query claims come from the [TanStack Query v5 docs](https://tanstack.com/query/latest/docs/framework/react/overview),
linked where they are used. HyperFetch claims are checked against its source. If something is out of date,
[open an issue](https://github.com/BetterTyped/hyper-fetch/issues) and we will fix it.

:::

---

## When to choose which

- **TanStack Query** when you already have an HTTP client or SDK and only want caching on top of it.
- **TanStack Query** when you use Vue, Solid or Svelte, or share code across several frameworks.
- **HyperFetch** when you want each endpoint defined once, with its types, and used the same way in React, Node and
  tests.
- **HyperFetch** when you need WebSockets or SSE, request queues or offline writes next to HTTP, from one library.

---

## Feature comparison

**Yes**: built in. **Partial**: possible with your own code or an extra package. **No**: not available.

| Capability            | TanStack Query                             | HyperFetch                                                   |
| --------------------- | ------------------------------------------ | ------------------------------------------------------------ |
| Sends HTTP requests   | No, you write the `queryFn`                | Yes, `fetch` adapter built in                                |
| Request definition    | Query key and query function               | [`createRequest`](/docs/core/request) object with types      |
| Cache identity        | Query key you write                        | Cache key derived from the request                           |
| Data stale after      | Immediately (`staleTime: 0`)               | 5 minutes, change it with `staleTime`                        |
| Unused data removed   | After 5 minutes (`gcTime`)                 | After 5 minutes, change it with `cacheTime`                  |
| Refetch on focus      | Yes, on by default                         | Yes, off by default, turn it on with `refetchOnFocus`        |
| Retries on failure    | 3, exponential backoff                     | 0, change it with `retry` and `retryTime`                    |
| Deduplication         | Yes, per query key                         | Yes, on by default for GET and QUERY                         |
| Realtime              | Partial ¹                                  | Yes, [`@hyper-fetch/sockets`](/docs/sockets/overview)        |
| Offline mutations     | Yes, paused and resumed ²                  | Yes, through the [request queue](/docs/guides/core/advanced/offline) ³ |
| Upload progress       | Partial, up to your `queryFn`              | Yes, with the [Axios adapter](/docs/integrations/adapter-axios/overview) |
| Devtools              | In-app panel                               | [HyperFlow](/docs/hyper-flow) desktop app                    |
| UI frameworks         | React, Solid, Svelte, Vue                  | React                                                        |
| Normalized cache      | No                                         | No ⁴                                                         |

1. TanStack Query does not open connections. You open the socket and write messages into the cache with
   [`setQueryData` or `invalidateQueries`](https://tanstack.com/query/latest/docs/reference/QueryClient).
2. In the default `online` [network mode](https://tanstack.com/query/latest/docs/framework/react/guides/network-mode),
   queries and mutations pause without a connection. Per the
   [mutations guide](https://tanstack.com/query/latest/docs/framework/react/guides/mutations), persisted mutations
   resume after a reload only with a default mutation function registered through `setMutationDefaults`.
3. Requests have `offline: true` by default, so a request sent offline waits for the connection. With the dispatcher's
   `lazyStorage` the queue survives a reload, and stored requests are rebuilt without re-registering functions.
4. The separate [`@hyper-fetch/db`](/docs/db/overview) package keeps records as rows shared by every query.

## Side by side

Three common tasks in both libraries: a list, a write that refreshes it and a socket update.

### Fetch a list

<Tabs>
<TabItem value="hf" label="HyperFetch">

```tsx title="todos.tsx"
import { createClient } from "@hyper-fetch/core";
import { useFetch } from "@hyper-fetch/react";

export const client = createClient({ url: "https://api.example.com" });

// Defined once, outside components. The cache key comes from the request.
export const getTodos = client.createRequest<{ response: Todo[] }>()({
  endpoint: "/todos",
});

function Todos() {
  // Non-2xx responses land in `error`, there is no `response.ok` check
  const { data, loading, error } = useFetch(getTodos);
}
```

</TabItem>
<TabItem value="tq" label="TanStack Query">

```tsx title="todos.tsx"
import { useQuery } from "@tanstack/react-query";

function Todos() {
  const { data, isPending, error } = useQuery({
    queryKey: ["todos"],
    queryFn: async () => {
      const response = await fetch("https://api.example.com/todos");
      if (!response.ok) throw new Error("Request failed");
      return response.json();
    },
  });
}
```

</TabItem>
</Tabs>

The same `getTodos` runs outside React with `await getTodos.send()`, which resolves with `{ data, error, status }` and
never throws.

### Write and refresh the list

<Tabs>
<TabItem value="hf" label="HyperFetch">

```tsx title="add-todo.tsx"
import { useSubmit } from "@hyper-fetch/react";

export const createTodo = client.createRequest<{
  response: Todo;
  payload: { title: string };
}>()({
  endpoint: "/todos",
  method: "POST",
});

function AddTodo() {
  const { submit, submitting, onSubmitSuccess } = useSubmit(createTodo);

  // Mounted useFetch hooks for getTodos refetch
  onSubmitSuccess(() => client.cache.invalidate(getTodos));

  return (
    <button
      disabled={submitting}
      onClick={() => submit({ payload: { title: "Buy milk" } })}
    >
      Add
    </button>
  );
}
```

</TabItem>
<TabItem value="tq" label="TanStack Query">

```tsx title="add-todo.tsx"
import { useMutation, useQueryClient } from "@tanstack/react-query";

function AddTodo() {
  const queryClient = useQueryClient();
  const mutation = useMutation({
    mutationFn: addTodo,
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["todos"] }),
  });

  return (
    <button
      disabled={mutation.isPending}
      onClick={() => mutation.mutate({ title: "Buy milk" })}
    >
      Add
    </button>
  );
}
```

</TabItem>
</Tabs>

`submit` resolves with the response and never throws, while `mutateAsync` rejects on error. `client.cache.invalidate`
also takes a cache key string or a RegExp. See [cache revalidation](/docs/guides/core/advanced/cache-revalidation).

### Update the list from a socket

<Tabs>
<TabItem value="hf" label="HyperFetch">

```ts title="realtime.ts"
import { createSocketClient } from "@hyper-fetch/sockets";

export const socket = createSocketClient({ url: "wss://api.example.com" });
export const onTodoAdded = socket.createListener<Todo>()({ topic: "todo-added" });

onTodoAdded.listen(() => client.cache.invalidate(getTodos));
```

</TabItem>
<TabItem value="tq" label="TanStack Query">

```ts title="realtime.ts"
const ws = new WebSocket("wss://api.example.com");

ws.addEventListener("message", (event) => {
  const message = JSON.parse(event.data);
  if (message.topic === "todo-added") {
    queryClient.invalidateQueries({ queryKey: ["todos"] });
  }
});
```

</TabItem>
</Tabs>

In React, [`useListener`](/docs/react/sockets/use-listener) returns the latest message and the connection state.

## Where TanStack Query is the better choice

- **Other frameworks.** It has official adapters for React, Solid, Svelte and Vue. HyperFetch ships React bindings only.
- **Any async source.** A `queryFn` can call `fetch`, Axios, a GraphQL client or an SDK. HyperFetch asks you to
  describe your API as requests first.
- **Fresh data by default.** Its [important defaults](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)
  refetch on mount, focus and reconnect and retry 3 times. HyperFetch leaves focus, reconnect and retries off until you
  turn them on.
- **An in-app panel.** [React Query Devtools](https://tanstack.com/query/latest/docs/framework/react/devtools) render
  next to your UI, with no extra app to run. See [React Query Devtools vs HyperFlow](/docs/guides/comparisons/react-query-devtools).
- **Community.** It has the most users, answers and integrations.
