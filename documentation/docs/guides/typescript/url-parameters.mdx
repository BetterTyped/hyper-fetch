# URL parameters type

HyperFetch reads URL parameters such as `:userId` from the endpoint string, so they need no generic. TypeScript then
requires each one before the request can be sent. This guide covers how the types are inferred and what they catch. For
sending params, see the [parameters guide](/docs/guides/core/basics/parameters).

:::secondary What you'll learn

1. How params are **inferred** from the endpoint string.
2. What TypeScript **catches**: missing and already set params.
3. Why the endpoint must stay a **string literal**.
4. How to **reuse** the params type with `ExtractParamsType`.

:::

---

## Params come from the endpoint

Each `:name` segment becomes a required key of type `string | number`. A name starts with a letter or `_`, so a port
(`localhost:3000`) is not a param.

```ts title="src/api/comments.ts"
export const getComment = client.createRequest<{ response: Comment }>()({
  endpoint: "/posts/:postId/comments/:commentId",
});

// params: { postId: string | number; commentId: string | number }
await getComment.send({ params: { postId: 10, commentId: 2 } });
```

---

## What TypeScript catches

```ts title="src/app.ts"
// error-next-line
await getComment.send(); // Expected 1 arguments, but got 0

// error-next-line
await getComment.send({ params: { postId: 10 } }); // commentId is missing

const prepared = getComment.setParams({ postId: 10, commentId: 2 });
await prepared.send(); // params are set, send() takes no params
```

`setParams` returns a request whose type records that params are set. Discarding the result keeps the original
requirement, which is the most common cause of an unexpected `Expected 1 arguments` error.

---

## Keep the endpoint a literal

Inference needs the literal string. An endpoint typed as `string`, for example built with a template string or read from
a variable typed `string`, turns the checks off: any params are accepted, including none.

```ts title="src/api/users.ts"
const base: string = "/users";

// Params unchecked
// diff-remove-next-line
const getUserLoose = client.createRequest<{ response: User }>()({ endpoint: `${base}/:userId` });
// Params checked
// diff-add-next-line
const getUserStrict = client.createRequest<{ response: User }>()({ endpoint: "/users/:userId" });
```

Write the endpoint inline, or as a `const` without a `string` annotation.

---

## Reuse the params type

`ExtractParamsType` reads the params type from a request, for helpers or route components:

```ts title="src/routes.ts"
import type { ExtractParamsType } from "@hyper-fetch/core";

type CommentParams = ExtractParamsType<typeof getComment>;
// { postId: string | number; commentId: string | number }

export const openComment = (params: CommentParams) => getComment.send({ params });
```
