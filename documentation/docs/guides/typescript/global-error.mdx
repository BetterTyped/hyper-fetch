# Global error type

Most APIs return errors in one shape, such as `{ message, code }`. Type it once on the client with the `error` generic,
and every request created from that client has its `error` typed. This guide covers the setup and why `Error` belongs in
the union.

:::secondary What you'll learn

1. How to type the **global error** on the client.
2. Why to keep **`Error`** in the union.
3. How to **narrow** the error in code.

:::

---

## Type the error on the client

```ts title="src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

export type ApiError = { message: string; code: string };

export const client = createClient<{ error: ApiError | Error }>({
  url: "https://api.example.com",
});

const getUser = client.createRequest<{ response: User }>()({
  endpoint: "/users/:userId",
});

const { error } = await getUser.send({ params: { userId: 1 } });
// error: ApiError | Error | null
```

Use `createClient` for this. The `Client` class takes positional generics, so `new Client<{ error: ApiError }>()` does
not type the error the way you expect.

---

## Keep Error in the union

Not every failure comes from your API. Timeouts, aborts, dropped connections and removed requests arrive as `Error`
instances: `TimeoutError`, `AbortError`, `DeletedError` or the network `TypeError`, with status `0` or `null`. Without
`Error` in the union, TypeScript would let you read `error.code` on them.

---

## Narrow the error

Check `Error` first, then read your API's fields:

```ts title="src/app.ts"
if (error instanceof Error) {
  console.error("Network or system error:", error.message);
} else if (error) {
  console.error(`API error ${error.code}: ${error.message}`);
}
```

Endpoints with their own error shape add it with a [local error](/docs/guides/typescript/local-error), which joins the
global one in a union.

---

:::success Congratulations!

You've learned how to type the global error.

- You can type the API's error once with **`createClient<{ error: ... }>`**.
- You keep **`Error`** in the union for system failures.
- You can **narrow** the error with `instanceof Error`.

:::
