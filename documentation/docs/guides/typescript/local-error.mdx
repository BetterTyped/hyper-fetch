# Local error type

Some endpoints return their own error shape, such as field errors of a form. Add it to that request with the `error`
generic. HyperFetch joins it with the client's [global error](/docs/guides/typescript/global-error), so the request's
`error` is a union of both.

:::secondary What you'll learn

1. How to add a **local error** to one request.
2. How it **joins** the global error.
3. How to **narrow** the union to the right shape.

:::

---

## Add a local error

```ts title="src/api/users.ts"
// The client is typed with { error: ApiError | Error }
type ValidationError = { fields: { name?: string[]; email?: string[] } };

export const createUser = client.createRequest<{
  response: User;
  payload: { name: string; email: string };
  error: ValidationError;
}>()({ endpoint: "/users", method: "POST" });

const { error } = await createUser.send({
  payload: { name: "Ann", email: "not-an-email" },
});
// error: ValidationError | ApiError | Error | null
```

Use a local error when:

- A **form endpoint** returns field errors.
- One endpoint has an **error shape** no other endpoint shares.
- A **third-party API** behind your client returns its own errors.

---

## Narrow the union

Check `Error` first, then a property that only one shape has:

```ts title="src/user-form.ts"
if (error instanceof Error) {
  showToast("Check your connection.");
} else if (error && "fields" in error) {
  showFieldErrors(error.fields);
} else if (error) {
  showToast(error.message);
}
```

`ExtractErrorType<typeof createUser>` returns the whole union, `ExtractLocalErrorType` only `ValidationError`. See
[request extractors](/docs/guides/typescript/request-extractors).

You've learned how to type endpoint-specific errors.

- You can add a **local error** with the request's `error` generic.
- You know it **joins** the global error in a union.
- You can **narrow** the union with `instanceof` and `in`.

:::
