# Custom adapter

An [adapter](/docs/core/adapter) performs the actual call for a request. HyperFetch ships a fetch-based HTTP adapter and
adapters for Axios, GraphQL, Firebase and others. Write your own to support another protocol, a platform API or an
HTTP client you already use. Caching, queues, retries and hooks keep working, because they live outside the adapter.

:::secondary What you'll learn

1. How to create an adapter with **`new Adapter()`** and **`setFetcher`**.
2. Which **bindings** the fetcher receives and which it must call.
3. How to **type** the adapter's options, methods, status and `extra`.
4. How to change how **query params, headers and payloads** are mapped.

:::

---

## Create the adapter

An adapter is an `Adapter` instance with a fetcher. The constructor takes the defaults the rest of HyperFetch reads, and
`setFetcher` receives the prepared request and must report its outcome with `onSuccess` or `onError`.

```ts title="src/api/adapter.ts"
import { Adapter, stringifyQueryParams } from "@hyper-fetch/core";

type Extra = { headers: Record<string, string> };
const defaultExtra: Extra = { headers: {} };

export const createJsonAdapter = () =>
  new Adapter<{ timeout?: number }, "GET" | "POST" | "PUT" | "DELETE", number, Extra>({
    name: "json-adapter",
    defaultMethod: "GET",
    defaultExtra,
    systemErrorStatus: 0, // status of failures that never reached the server
    systemErrorExtra: defaultExtra,
  })
    .setQueryParamsMapper(stringifyQueryParams)
    .setFetcher(async ({ request, url, endpoint, queryParams, headers, payload, ...bindings }) => {
      const { createAbortListener, getAbortController, onRequestStart, onSuccess, onError } = bindings;

      // Reports an abort as an AbortError response
      const unmount = createAbortListener({ status: 0, extra: defaultExtra });
      onRequestStart();

      try {
        const response = await fetch(`${url}${endpoint}${queryParams}`, {
          method: request.method,
          headers,
          body: request.method === "GET" ? undefined : (payload as BodyInit),
          signal: getAbortController()?.signal,
        });
        const data = await response.json().catch(() => null);
        const extra = { headers: Object.fromEntries(response.headers.entries()) };

        if (response.ok) onSuccess({ data, status: response.status, extra });
        else onError({ error: data, status: response.status, extra });
      } catch (error) {
        onError({ error, status: 0, extra: defaultExtra });
      } finally {
        unmount();
      }
    });
```

Set it on the client. Requests created afterwards are typed by it: their `method`, `options` and response `extra` come
from the adapter's generics.

```ts title="src/api/client.ts"
export const client = createClient({ url: "https://api.example.com" }).setAdapter(createJsonAdapter());

const getUser = client.createRequest<{ response: User }>()({
  endpoint: "/users/:userId",
  options: { timeout: 3000 },
});
```

A factory that returns a new adapter, like `createJsonAdapter`, lets every client get its own instance.

## Bindings the fetcher receives

The fetcher gets the request after interceptors and mappers ran, plus callbacks that drive the lifecycle.

| Binding                                     | What it is                                                         |
| ------------------------------------------- | ------------------------------------------------------------------ |
| `request`, `requestId`                      | The request to send and the id of this call                        |
| `url`, `endpoint`, `queryParams`            | Base URL, endpoint with params, query params after the mapper      |
| `headers`, `payload`                        | Headers and payload after the adapter's mappers                    |
| `adapterOptions`                            | Adapter defaults merged with the request's `options`               |
| `onSuccess`, `onError`                      | Report the outcome. Exactly one must be called                     |
| `onAbortError`, `onTimeoutError`            | Report an abort or a timeout with the built-in error               |
| `createAbortListener`, `getAbortController` | Connect `request.abort()` and `cancelable` to your transport       |
| `onRequestStart`, `onRequestProgress`, `onRequestEnd` | Upload lifecycle and progress events                     |
| `onResponseStart`, `onResponseProgress`, `onResponseEnd` | Download lifecycle and progress events                |

Interceptors, `onAuth`, request mappers, mocks and response interceptors run around the fetcher, so it only talks to the
transport. A fetcher that throws resolves the request with the error and `systemErrorStatus`.

## Type the adapter

The generics of `Adapter` type everything requests created from the client accept and return. The first seven are the
ones you usually set:

| Generic             | Types                                                  | Example                                |
| ------------------- | ------------------------------------------------------ | -------------------------------------- |
| `AdapterOptions`    | The request's `options` and `setAdapterDefaults`       | `{ timeout?: number }`                 |
| `MethodType`        | Allowed `method` values                                | `"GET" \| "POST"`                      |
| `StatusType`        | `response.status`                                      | `number`                               |
| `Extra`             | `response.extra`                                       | `{ headers: Record<string, string> }`  |
| `QueryParams`       | Allowed `queryParams` values                           | `QueryParamsType \| string \| null`    |
| `DefaultQueryParams`| Query params of a request without the generic          | `undefined`                            |
| `EndpointType`      | Allowed `endpoint` values                              | `string`                               |

A transport without HTTP semantics, such as a database SDK, can use its own method names and a string status. The
[Firebase adapter](/docs/integrations/adapter-firebase/overview) does that.

## Change how values are mapped

The adapter turns request values into what the fetcher receives. Replace a mapper when your transport needs another
format:

| Method                 | Default                                                       |
| ---------------------- | ------------------------------------------------------------- |
| `setQueryParamsMapper` | Passes query params through as they are                       |
| `setHeaderMapper`      | Adds `Content-Type: application/json` for object payloads     |
| `setPayloadMapper`     | `JSON.stringify`, except `FormData`, `Blob` and other binary bodies |
| `setEndpointMapper`    | Passes the endpoint through as it is                          |

`setRequestDefaults` and `setAdapterDefaults` set defaults for requests of this adapter, and `setInternalErrorMapping`
changes the shape of the built-in errors such as `TimeoutError`. See [global defaults](/docs/guides/core/basics/global-defaults).

Test the client with `request.setMock()`: mocks replace the fetcher, so the rest of the pipeline runs as in production.

You've learned how to write a custom adapter.

- You can create an adapter with **`new Adapter()`** and **`setFetcher`**.
- You can report outcomes with **`onSuccess`** and **`onError`** and support aborts with `createAbortListener`.
- You can **type** methods, options, status and `extra` with the adapter's generics.
- You can replace the **query params, header and payload mappers**.
