# Prefetching

Prefetching loads data before the user asks for it, so the next view renders from the cache without a spinner. In
HyperFetch a prefetch is a plain `send()`: every successful response is written to the cache, where the next view reads
it.

:::secondary What you'll learn

1. How a **prefetch fills the cache** and how the next view reads it.
2. How to prefetch **on start** and **on hover** for dynamic routes.
3. How to **skip a prefetch** when the cached data is still fresh.
4. How to prefetch **on the server** and hand the data to the browser.

:::

---

## A prefetch is a send

`send()` goes through the [dispatcher](/docs/core/dispatcher) and writes a successful response to the
[cache](/docs/core/cache) under the request's `cacheKey`. Reading the same request later finds it there.

```ts title="src/prefetch.ts"
// Fill the cache, no one waits for the result
getUsers.send();

// Later, in the next view
const cached = getUsers.read(); // the response, no network call
// The cached response when present, else the network
const { data } = await getUsers.send({ cachePolicy: "cache-first" });
```

A plain `send()` is network-only: it writes to the cache but never reads it. Read prefetched data with `read()`, a
`cachePolicy`, or [`useFetch`](/docs/react/hooks/use-fetch), which renders cached data at once and fetches only when it is
missing or stale.

---

## Prefetch on hover

For dynamic routes, start the request when the user shows intent, such as hovering a link. Each set of params has its
own `cacheKey`, so every user is cached separately.

```ts title="src/users-list.ts"
const prefetchUser = (userId: number) => {
  getUser.send({ params: { userId } });
};

link.addEventListener("pointerenter", () => prefetchUser(Number(link.dataset.userId)));
```

Hovering twice while the first request is in flight does not send a second one: GET requests are
[deduplicated](/docs/guides/core/advanced/deduplication) by default. When the user clicks, the view finds the response in
the cache or joins the request still in flight.

---

## Skip fresh data

A prefetch on every hover refetches data that is already fresh. Read the cache entry first and compare its age with its
`staleTime`, which `invalidate` sets to `0`:

```ts title="src/prefetch.ts"
import type { RequestInstance } from "@hyper-fetch/core";

const prefetchIfStale = (request: RequestInstance) => {
  const cached = client.cache.get(request.cacheKey);
  const isFresh = !!cached && Date.now() - cached.responseTimestamp < cached.staleTime;

  if (!isFresh) request.send();
};

prefetchIfStale(getUser.setParams({ userId: 1 }));
```

Prefetched data is removed after `cacheTime` (5 minutes by default) like any other entry. Prefetch what the user is
likely to open soon, not whole collections.

---

## Prefetch on the server

On the server, send the request, pack the response with `dehydrate` and write it into the browser's cache with
`client.hydrate`. The page then renders without a client-side request.

```ts title="server.ts"
// Scope the request: on the server only scoped requests are cached
const request = getUser.setParams({ userId: 1 }).setScope(session.id);
const response = await request.send();
const state = [request.dehydrate({ response })];
// Serialize `state` into the page, then in the browser: client.hydrate(state)
```

In React, the [`Hydrate`](/docs/react/hydrate) component does the browser part. Router loaders work the same way: they
send the request so the route component reads from the cache.

| When                 | How                                           |
| -------------------- | --------------------------------------------- |
| App start, login     | `send()` the data of the likely first screens |
| Hover, focus, viewport | `send()` with the params of the target      |
| Next page of a list  | `send()` the next page while the current one shows |
| Server rendering     | `send()`, `dehydrate()` and `hydrate()`       |

:::success Congratulations!

You've learned how to prefetch data.

- You can **prefetch** with `send()`, which fills the cache.
- You can prefetch **on hover** without duplicates, thanks to deduplication.
- You can **skip fresh data** by checking the cache entry's age against its `staleTime`.
- You can prefetch **on the server** and hydrate the browser cache.

:::
