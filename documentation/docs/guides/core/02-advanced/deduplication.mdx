# Deduplication

When we need to limit and optimize the number of requests sent to a server, we can use **deduplication**. This feature,
when enabled, combines identical requests sent while the first one is still in flight into a single request, preventing
redundant data fetching and reducing server load. We can enable it by setting the `deduplicate: true` option on a
request.

1.  How to **enable deduplication** on a request to optimize data fetching.

## Setup

To enable deduplication, you need to set the `deduplicate` option to `true` on your request. This tells Hyper-fetch to
prevent identical requests (same `queryKey`) from being sent again while one of them is still in flight.

```ts
const getUsers = client.createRequest()({
  endpoint: "/users",
  deduplicate: true,
});
```

## How it works

Let's see how deduplication works in practice. In the example below, we call the `getUsers.send()` method four times in
quick succession. Since `deduplicate` is enabled, Hyper-fetch will only send a single request to the backend. The
subsequent calls will receive the response from the first request.

```typescript
// We are using pre-build 'getUsers' request and 'client' instance

// highlight-start
const getUsers = client.createRequest()({
  endpoint: "/users",
  deduplicate: true,
});
// highlight-end

// Multiple calls of the same request
getUsers.send({
  onRequestStart: ({ request, requestId }) => {
    console.log("Request starting...", { requestId, request });
  },
});
getUsers.send();
getUsers.send();
getUsers.send();

// Only a single request will be sent to the backend,
// and you will see only one "Request starting..." log in the console.
```

## Deduplication Time

By default `deduplicateTime` is `null`: a new request joins an identical request for as long as that request is in
flight. Set `deduplicateTime` to a number of milliseconds to shorten this window. A new request then joins only an
in-flight request that started at most that many milliseconds ago. Once the first request has finished, the next call
is always sent, whatever the window.

In this example, we set `deduplicateTime` to 2000 milliseconds. An identical request sent within 2000ms of the first one
joins it, as long as the first one has not finished yet.

```typescript
// We are using pre-build 'getUsers' request and 'client' instance

// highlight-start
const getUsersWithTime = client.createRequest()({
  endpoint: "/users",
  deduplicate: true,
  deduplicateTime: 2000,
});
// highlight-end

getUsersWithTime.send({
  onRequestStart: ({ request, requestId }) => {
    console.log("Request starting with deduplicateTime...", { requestId, request });
  },
});

setTimeout(() => {
  getUsersWithTime.send({
    onRequestStart: ({ request, requestId }) => {
      // Not logged when the first request is still in flight, because it's within the 2000ms window
      console.log("Second request starting...", { requestId, request });
    },
  });
}, 500);
```
