# Request deduplication

Deduplication means that when an identical request is already on its way to the server, a second call does not open a
new one. It joins the first and gets the same response. This guide explains where duplicate calls come from and how
HyperFetch merges them.

:::secondary What you'll learn

1. Why apps make **duplicate API calls**.
2. How deduplication differs from **caching** and **cancellation**.
3. When deduplication is **on by default** and how to turn it on or off.
4. How to limit the window with **`deduplicateTime`**.

:::

---

## Why apps make duplicate API calls

The same `GET /users` twice in the network tab usually comes from one of these:

- **Several components need the same data.** A header avatar, a sidebar and a settings page each fetch the current user
  on mount.
- **React Strict Mode** runs effects twice in development, so a bare `fetch` in `useEffect` fires twice.
- **Effect dependencies** that are new objects on every render make the effect run again.
- **Fast repeated actions**, such as a double-click on refresh.

Moving fetching from components into a layer that knows what is already in flight fixes all of them. That is what
deduplication does.

| Technique     | A second identical request...                           | Use it for                                    |
| ------------- | ------------------------------------------------------- | --------------------------------------------- |
| Deduplication | Joins the request already in flight                     | Many callers asking for the same data at once |
| Caching       | Gets the stored response                                | Data asked for again later                    |
| Cancellation  | Aborts the earlier request and goes out itself          | Search inputs where only the latest matters   |

Deduplication covers the time a request is in flight, the [cache](/docs/guides/core/advanced/cache-revalidation) the time
after it. For the opposite behavior, see [cancellation](/docs/guides/core/advanced/cancellation).

## Turn deduplication on

With the fetch adapter, GET and QUERY requests are deduplicated by default. For other methods or adapters, set
`deduplicate: true`, and turn it off with `deduplicate: false` or `setDeduplicate(false)`.

```ts title="src/api/users.ts"
export const getUsers = client.createRequest<{ response: User[] }>()({
  endpoint: "/users",
  deduplicate: true, // already the default for GET with the fetch adapter
});
```

```ts title="src/app.ts"
// One network call, four identical responses
const responses = await Promise.all([
  getUsers.send(),
  getUsers.send(),
  getUsers.send(),
  getUsers.send(),
]);
```

Two requests are identical when they share a `queryKey`, which is built from the method, the filled endpoint and the
query params. `/users?page=1` and `/users?page=2` are never merged. A joined call does not start its own request, so its
`onRequestStart` does not fire. Track joins with `client.requestManager.events.onDeduplicated`.

In React, several components calling `useFetch(getUsers)` at once share one request in the same way. See
[fetching in React](/docs/guides/react/basics/fetching).

:::caution Mutations

Think twice before deduplicating `POST`, `PUT` or `DELETE`. Two clicks that create two orders are two intentions, and
merging them hides the second. For writes, disable the button while submitting, or [queue](/docs/guides/core/advanced/queueing)
the requests.

:::

## Limit the window with deduplicateTime

By default `deduplicateTime` is `null`: a request joins an identical one for as long as that one is in flight. A number
of milliseconds shortens the window, counted from the start of the in-flight request. After the first request has
finished, the next call is always sent.

```ts title="src/api/stats.ts"
export const getStats = client.createRequest<{ response: Stats }>()({
  endpoint: "/stats",
  deduplicate: true,
  deduplicateTime: 2000,
});

getStats.send();
// Within 2 s of the first call and while it is in flight: joins it
setTimeout(() => getStats.send(), 500);
// After 2 s: sent on its own, even if the first call is still running
setTimeout(() => getStats.send(), 2500);
```

Deduplication never applies when the request is `queued` or `cancelable`, which take precedence, or when it was marked
with `setUsed(true)`, such as a resend after a [token refresh](/docs/guides/core/basics/authentication#refresh-the-token-on-401).
