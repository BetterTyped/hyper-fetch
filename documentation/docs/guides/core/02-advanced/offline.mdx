# Offline-first requests

An offline-first app treats the network as something that comes and goes: reads show the last data you had, and writes
made without a connection wait and go out when it returns. In HyperFetch requests are held while offline by default, and
the [AppManager](/docs/core/managers#appmanager) tells the dispatchers when the connection drops and returns.

:::secondary What you'll learn

1. What **offline first** needs for reads and writes.
2. How requests are **held while offline** and when to fail fast instead.
3. How to show an **offline mode in React**.
4. How to plug in **custom network detection**, for example in React Native.

:::

---

## What offline first needs

An offline-first setup has three parts, plus an optional fourth. Each one has a HyperFetch piece:

| Part                          | What it does                                             | In HyperFetch                                |
| ----------------------------- | -------------------------------------------------------- | --------------------------------------------- |
| Network detection             | Knows when the connection drops and comes back           | `AppManager` (`online` / `offline` events)    |
| Reads from local data         | Shows the last response instead of an error              | [Cache](/docs/core/cache)                     |
| Writes that wait              | Keeps failed writes and sends them later                 | Dispatcher queue with `offline: true`         |
| Survives a reload (optional)  | Keeps cache and queued writes in storage                 | [Persistence](/docs/guides/core/advanced/persistence) |

One thing to know about detection: the browser's `online` flag is a hint, not a guarantee.
[MDN notes](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine) that `navigator.onLine` being `true`
doesn't mean the internet is reachable, only that the device is connected to some network. Treat offline detection as
the fast path and still handle request errors.

---

## Requests wait for the connection

By default, HyperFetch listens to the browser's `online` and `offline` events. No extra configuration is needed in a
standard web environment. When the browser reports a lost connection, the dispatcher stops sending requests and keeps
them in its queues. When the connection returns, it sends them.

Every request has an `offline` option, and it is `true` by default. A request sent while offline (or one that fails
because the connection dropped) is kept and sent again when the network comes back:

```ts title="src/api/posts.ts"
const createPost = client.createRequest<{
  response: Post;
  payload: { title: string; content: string };
}>()({
  endpoint: "/posts",
  method: "POST",
  // highlight-next-line
  offline: true, // the default, shown here for clarity
});

// If the user is offline when this is called, the request will be queued
// and automatically sent when the connection is restored
createPost.send({ payload: { title: "My Post", content: "Written offline" } });
```

The `send()` promise stays pending until the queued request is finally sent and answered. Offline failures don't use up
[retries](/docs/guides/core/basics/retries) either.

The queue lives in memory by default, so a closed tab loses it. Give the dispatcher a `lazyStorage` (IndexedDB,
AsyncStorage) and the queued writes are restored and sent on the next start. Requests the browser cancels while the page
unloads stay in the queue for that next start instead of failing. Setup is in
[persistence](/docs/guides/core/advanced/persistence).

Set `offline: false` when a late answer is worse than no answer, like a price check or a one-time code. Those requests
fail right away while the device is offline, and the request is dropped instead of waiting.

## Keep the order of offline writes

For writes that must keep their order, combine `offline: true` with `queued: true`. Requests in the same queue are then
sent one by one once the connection is restored:

```ts title="src/api/sync.ts"
const syncAction = client.createRequest()({
  endpoint: "/sync",
  method: "POST",
  offline: true,
  queued: true,
});
```

More on queue modes in [queueing](/docs/guides/core/advanced/queueing).

## Offline mode in React

The `useAppManager` hook gives a component the current network state, which is all you need for an offline banner:

```tsx title="src/components/offline-banner.tsx"
import { useAppManager } from "@hyper-fetch/react";
import { client } from "../api/client";

export function OfflineBanner() {
  const { isOnline } = useAppManager(client);

  if (isOnline) return null;
  return (
    <div className="p-2 text-center text-sm">
      You're offline. Changes will sync when you're back.
    </div>
  );
}
```

`useFetch` and `useSubmit` also have `onOfflineError` and `onSubmitOfflineError` callbacks. They fire when a request is
held because of the network, without triggering the normal error callbacks, so you can show a "saved, waiting to sync"
state instead of an error. And because `useFetch` reads the cache first, a screen you visited before still shows its
last data while offline. See [window and network events](/docs/guides/react/basics/window-focus-blur) for refetching
when the connection comes back.

## Custom network detection

The default browser events are not available in every environment, React Native being the common example. For these
cases, give the `AppManager` your own detection logic.

In React Native, `@react-native-community/netinfo` is the standard way to get information about the device's network
status. You can connect it to HyperFetch's `AppManager` like this:

```ts title="src/api/client.ts"
import { AppManager, createClient } from "@hyper-fetch/core";
import NetInfo from "@react-native-community/netinfo";

export const client = createClient({
  url: "https://api.example.com",
  appManager: () =>
    new AppManager({
      // Read the state once on start
      initiallyOnline: async () => !!(await NetInfo.fetch()).isConnected,
      // Report every change, and return the unsubscribe function for cleanup
      onlineEvent: (setOnline) =>
        NetInfo.addEventListener((state) => setOnline(!!state.isConnected)),
    }),
});
```

`focusEvent` and `initiallyFocused` do the same for window focus. More setup is in the
[React Native guide](/docs/react/environments/react-native).
