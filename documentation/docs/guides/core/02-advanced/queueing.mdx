# Request queueing

Some requests must run one at a time and in order: uploads that would saturate the connection, writes that depend on
the previous one, or changes made offline. With `queued: true`, HyperFetch sends them one by one. This guide covers
queued requests and how to pause, stop and resume a queue.

:::secondary What you'll learn

1. How to send requests **one by one** with `queued`.
2. How to make queueing the **default** for some requests.
3. How to **pause, stop, start and flush** a queue.
4. How to **watch** a queue's progress.

:::

---

## Send requests one by one

Every `send()` adds the request to a queue in the [dispatcher](/docs/core/dispatcher), named by its `queryKey`. With
`queued: true`, each request waits until the previous one in its queue finishes.

```ts title="src/api/files.ts"
export const uploadFile = client.createRequest<{
  response: { url: string };
  payload: FormData;
}>()({
  endpoint: "/files",
  method: "POST",
  queued: true,
});
```

```ts title="src/upload.ts"
for (const file of files) {
  const formData = new FormData();
  formData.append("file", file);

  // All added at once, sent in order, one at a time
  uploadFile.send({
    payload: formData,
    onRequestStart: () => console.log(`${file.name} started`),
    onResponse: ({ response }) =>
      console.log(`${file.name} ${response.success ? "done" : "failed"}`),
  });
}
```

Requests of one request share a queue because their default `queryKey` is the same (`POST_/files_`). Requests with
different keys, such as `/users/1` and `/users/2`, run in separate queues side by side. Give them one `queryKey` with
`setQueryKey` to put them in the same line.

---

## Make queueing the default

There is no client option for queueing. Return `queued: true` from `setRequestDefaults` for the requests that need it,
for example every write:

```ts title="src/api/client.ts"
client.adapter.setRequestDefaults((options) => {
  const method = options.method ?? "GET";
  if (method === "GET" || method === "QUERY") return { deduplicate: true };
  return { queued: true };
});

// Opt a write out
const ping = client.createRequest()({
  endpoint: "/ping",
  method: "POST",
  queued: false,
});
```

See [global defaults](/docs/guides/core/basics/global-defaults).

## Pause, stop and start a queue

Each client has two dispatchers: `fetchDispatcher` for GET and QUERY, `submitDispatcher` for the other methods. Both
control a queue by its `queryKey`.

| Method                 | Running request                | Waiting requests            |
| ---------------------- | ------------------------------ | --------------------------- |
| `pause(queryKey)`      | Finishes                       | Held                        |
| `stop(queryKey)`       | Canceled and kept in the queue | Held                        |
| `start(queryKey)`      | Sent again if it was stopped   | Sent in the queue's mode    |
| `flushQueue(queryKey)` | -                              | Sent now, unless stopped    |

```ts title="src/upload.ts"
const { submitDispatcher } = client;

// The user pauses the uploads: the current one finishes, the rest wait
submitDispatcher.pause(uploadFile.queryKey);

// And resumes them
submitDispatcher.start(uploadFile.queryKey);
```

A held request's `send()` promise stays pending until it is sent. To stop and resume a single request, use
`stopRequest(queryKey, requestId)` and `startRequest(queryKey, requestId)` with the id from `onBeforeSent`. There is no
priority option: order work with `queued`, separate `queryKey`s and these methods.

---

## Watch a queue

`dispatcher.getQueue(queryKey)` returns the requests and the queue status. The dispatcher's `events` report every
change, each with a `...ByKey` variant for one queue:

```ts title="src/upload.ts"
const unsubscribe = client.submitDispatcher.events.onQueueChangeByKey(
  uploadFile.queryKey,
  (queue) => {
    console.log(
      `${queue.requests.length} uploads left, stopped: ${queue.stopped}`,
    );
  },
);
```

In React, [`useQueue`](/docs/react/hooks/use-queue) returns the queue of a request with upload progress and
`stop`, `pause` and `start` functions. See [queues in React](/docs/guides/react/basics/queues).

Queued requests also wait out offline periods, and a dispatcher with `lazyStorage` keeps them through a reload. See
[offline](/docs/guides/core/advanced/offline) and [persistence](/docs/guides/core/advanced/persistence).

- You can send requests **one by one** with `queued: true` and a shared `queryKey`.
- You can make queueing the **default** with `setRequestDefaults`.
- You can **pause, stop, start and flush** a queue on the dispatcher.
- You can **watch** a queue with dispatcher events or `useQueue`.
