# Global defaults

Options such as `retry`, `staleTime` or a fetch `timeout` are often the same for most requests. Instead of repeating
them, set them once on the client's adapter and override them where a request needs something else. This guide also
covers custom key and request id mappers.

:::secondary What you'll learn

1. How to set **request defaults** with `setRequestDefaults`, per HTTP method.
2. How to set **adapter defaults** such as `timeout` with `setAdapterDefaults`.
3. How to change how **keys** and **request ids** are built.
4. How to set defaults per endpoint in an **SDK** with `$configure`.

:::

---

## Set request defaults

`client.adapter.setRequestDefaults` takes a callback. It receives the options of each new request and returns the
defaults for it, so they can depend on the method or the endpoint. Options set on the request always win.

```ts title="src/api/client.ts"
import { createClient, Time } from "@hyper-fetch/core";

export const client = createClient({ url: "https://api.example.com" });

client.adapter.setRequestDefaults((options) => {
  // method is undefined when the request relies on the default "GET"
  const method = options.method ?? "GET";

  if (method === "GET" || method === "QUERY") {
    return { deduplicate: true, retry: 2, staleTime: Time.MIN };
  }
  return { retry: 0, cache: false };
});

const getUser = client.createRequest()({ endpoint: "/users/:userId" }); // retry: 2
const getReport = client.createRequest()({ endpoint: "/reports", retry: 5 }); // retry: 5 wins
```

Two rules to keep in mind:

- **The callback replaces the built-in defaults.** The fetch adapter turns `deduplicate` on for GET and QUERY. Return
  `deduplicate: true` yourself to keep it, as above.
- **Defaults are read when a request is created.** Call `setRequestDefaults` right after `createClient`, before any
  module creates requests. Requests created earlier keep the old values.

Change a single request later with its setters, such as `getUser.setRetry(5)`. `setOptions` sets adapter options, not
request options.

## Set adapter defaults

Adapter options are what the adapter passes to the transport: for the fetch adapter, `RequestInit` fields such as
`credentials` or `mode`, plus `timeout`, `responseType` and `streaming`. `setAdapterDefaults` sets them for every
request, and the request's own `options` are merged on top.

```ts title="src/api/client.ts"
client.adapter.setAdapterDefaults(() => ({
  timeout: 10_000, // default 5000 ms
  credentials: "include",
}));

// One request needs longer
const exportData = client.createRequest()({ endpoint: "/export", options: { timeout: 60_000 } });
```

The callback receives the request, so a default can depend on it. See the [timeouts example](/examples/request-control/timeouts).

## Customize keys

Every request has a `cacheKey`, a `queryKey` and an `abortKey`, built from its method, endpoint and query params. A
`cacheKey` for `GET /users/1` looks like `GET_/users/1_`. Replace the builder for every request with
`setCacheKeyMapper`, `setQueryKeyMapper` or `setAbortKeyMapper`. Return a key for every request, and fall back to
`getRequestKey` for the ones you do not change.

```ts title="src/api/client.ts"
import { getRequestKey } from "@hyper-fetch/core";

// Share cache entries between tenants that serve the same public catalog
client.setCacheKeyMapper((request) => {
  if (request.endpoint.startsWith("/catalog")) return `catalog_${getRequestKey(request)}`;
  return getRequestKey(request);
});
```

A key that leaves out the query params or params makes different requests share one cache entry or queue. For a single
request, set the key with `setCacheKey`, `setQueryKey` or `setAbortKey`, see [Request keys](/docs/core/request#keys).

## Customize request ids

Each `send()` gets a random `requestId`, used in lifecycle events and to stop a single request. `setRequestIdMapper`
replaces the generator, for example to match ids in your backend logs or to get predictable ids in tests.

```ts title="src/api/client.ts"
let counter = 0;

client.setRequestIdMapper((request) => `${request.method}_${request.endpoint}_${++counter}`);
```

Ids must be unique among requests in flight.

## Defaults per endpoint in an SDK

With an [SDK](/docs/core/sdk), `$configure` sets defaults by endpoint pattern or SDK path, and function values have every
setter available:

```ts title="src/api/sdk.ts"
export const api = sdk.$configure({
  "*": { retry: 2 },
  "/users/*": { staleTime: 60_000 },
  "users.$userId.$delete": (request) => request.setCancelable(true),
});
```

| Tool                    | Scope                           | Use it for                               |
| ----------------------- | ------------------------------- | ---------------------------------------- |
| `setRequestDefaults`    | Every request of the client     | Retries, caching, deduplication per method |
| `setAdapterDefaults`    | Every request of the client     | `timeout`, `credentials` and other fetch options |
| `$configure`            | SDK endpoints by pattern        | Per-endpoint options and mappers         |
| Request option or setter| One request                     | Exceptions                               |
