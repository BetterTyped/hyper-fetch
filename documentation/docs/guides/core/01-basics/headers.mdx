# Headers

Headers carry metadata with a request, such as an auth token, a content type or a trace id. In HyperFetch you set them on
the request, at call time, or for every request through the client. This guide covers each level and how they combine.

:::secondary What you'll learn

1. How to set headers **on a request** and **at call time**.
2. How to add headers to **every request** of a client.
3. Why `setHeaders` **replaces** the headers instead of merging them.
4. Which headers the adapter **adds for you**.

:::

---

## Set headers on a request

Pass `headers` when you create the request for values that never change.

```ts title="src/api/reports.ts"
export const getReport = client.createRequest<{ response: Report }>()({
  endpoint: "/reports/:reportId",
  headers: { Accept: "application/json", "X-Api-Version": "2" },
});
```

---

## Set headers at call time

`setHeaders` returns a new request with the given headers, and `send({ headers })` sets them for one call. Both
**replace** the request's headers, so spread the existing ones to keep them:

```ts title="src/app.ts"
// Keep the request's headers and add one
const traced = getReport.setHeaders({
  ...getReport.headers,
  "X-Request-Id": crypto.randomUUID(),
});

// Or for one call only
await getReport.send({
  params: { reportId: 7 },
  headers: { ...getReport.headers, "X-Request-Id": crypto.randomUUID() },
});
```

`request.headers` is typed as `HeadersInit`, which can also be a `Headers` instance or an array of pairs. Spreading only
works for a plain object, so keep request headers as objects.

---

## Add headers to every request

The client has no `headers` option. Add shared headers in an interceptor that runs before each request:

- **`onAuth`** for credentials. It runs only for requests with `auth: true`, the default, so public endpoints can opt out
  with `auth: false`.
- **`onRequest`** for everything else, such as a locale or a trace id.

```ts title="src/api/client.ts"
export const client = createClient({ url: "https://api.example.com" })
  .onRequest((request) =>
    request.setHeaders({ "Accept-Language": getLocale(), ...request.headers }),
  )
  .onAuth((request) =>
    request.setHeaders({
      ...request.headers,
      Authorization: `Bearer ${getToken()}`,
    }),
  );
```

The order of the spread decides who wins. In `onRequest` above, a header set on the request overrides the shared one. In
`onAuth`, the interceptor's `Authorization` overrides the request's. See [authentication](/docs/guides/core/basics/authentication).

`setRequestDefaults` can also return `headers`, but a request that sets its own `headers` replaces them entirely. Use an
interceptor when headers must be merged.

---

## Headers the adapter adds

The fetch adapter sends `Content-Type: application/json` when the payload is an object or array. It leaves it out for
`FormData`, `Blob` and other binary bodies, so `fetch` can set the multipart boundary. A `content-type` header you set,
in any letter case, replaces the default. A header with an `undefined` or `null` value is not sent.

Other adapters treat headers their own way, and the Firebase adapters ignore them. Check the page of your adapter.

| Where                  | Scope                         | Combines with the request's headers   |
| ---------------------- | ----------------------------- | ------------------------------------- |
| `createRequest` option | Every call of the request     | It is the request's headers           |
| `setHeaders`           | The returned request          | Replaces them                          |
| `send({ headers })`    | One call                      | Replaces them                          |
| `onRequest` / `onAuth` | Every request of the client   | As you spread them                     |

---

:::success Congratulations!

You've learned how to manage headers.

- You can set headers **on a request**, with **`setHeaders`** or for **one call** in `send()`.
- You can add headers to **every request** with `onRequest` and `onAuth`.
- You know that `setHeaders` and `send({ headers })` **replace** headers, so you spread the existing ones.

:::
