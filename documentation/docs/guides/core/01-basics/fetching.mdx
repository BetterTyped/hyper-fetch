# Fetching

A request runs when you call `send()` on it. This guide sends a request, passes values to it, reads the response, picks
a cache policy, follows the lifecycle and aborts calls that are no longer needed.

:::secondary What you'll learn

1. How to **send** a request and read the **response object**.
2. How to pass **params, query params and payload** with setters or to `send()`.
3. How to read the **cache** with `cachePolicy` and `read()`.
4. How to follow the **lifecycle** and **abort** a request.
5. The difference between **`send()` and `exec()`**.

:::

---

## Send a request

`send()` resolves with a response object for every outcome, including HTTP errors, timeouts and aborts. It never
rejects, so you branch on the result instead of using `try/catch`.

```ts title="src/api/users.ts"
import { client } from "./client";

export const getUser = client.createRequest<{
  response: { id: number; name: string };
}>()({
  endpoint: "/users/:userId",
});
```

```ts title="src/app.ts"
const { data, error, status } = await getUser.send({ params: { userId: 1 } });

if (data) {
  console.log(data.name);
} else {
  console.error(status, error);
}
```

Check `data` rather than `success`: `data` stays typed as nullable after `if (success)`.

## Pass params, query params and payload

Set values ahead of time with setters, or pass them to `send()`. Both are typed from the request's generics and its
endpoint. Setters return a new request, so use the returned value.

```ts title="src/api/users.ts"
export const updateUser = client.createRequest<{
  response: { id: number; name: string };
  payload: { name: string };
  queryParams?: { notify?: boolean };
}>()({ endpoint: "/users/:userId", method: "PUT" });
```

```ts title="src/app.ts"
// Prepare it step by step
const prepared = updateUser
  .setParams({ userId: 1 })
  .setPayload({ name: "Ann" })
  .setQueryParams({ notify: true });
await prepared.send();

// Or pass everything at once
await updateUser.send({
  params: { userId: 1 },
  payload: { name: "Ann" },
  queryParams: { notify: true },
});
```

`send()` also accepts the other request options for one call, such as `retry`, `headers` or `options`. Each value has
its own guide: [parameters](/docs/guides/core/basics/parameters), [query params](/docs/guides/core/basics/query-params),
[payload](/docs/guides/core/basics/payload) and [headers](/docs/guides/core/basics/headers).

## Read from the cache

Plain `send()` is network-only: it writes a successful response to the [cache](/docs/core/cache) but never reads it. Pick
another `cachePolicy` to read first, or call `read()` to get the cached response without a request.

| `cachePolicy`              | Returns                                                         |
| -------------------------- | --------------------------------------------------------------- |
| `"network-only"` (default) | The network response                                            |
| `"cache-first"`            | The cached response when there is one, fresh or stale, else the network response |
| `"revalidate"`             | The cached response at once, and refetches in the background   |

```ts title="src/app.ts"
const request = getUser.setParams({ userId: 1 });

const fast = await request.send({ cachePolicy: "cache-first" });
const cached = request.read(); // response or undefined, no network call
```

Neither policy looks at `staleTime`. Hooks in `@hyper-fetch/react` do, see
[cache revalidation](/docs/guides/core/advanced/cache-revalidation).

## Follow the lifecycle

`send()` takes callbacks for one call. Each receives the `requestId` and the request.

```ts title="src/upload.ts"
await uploadFile.send({
  payload: formData,
  onBeforeSent: ({ requestId }) => console.log("queued", requestId),
  onRequestStart: () => showSpinner(),
  onUploadProgress: ({ progress, loaded, total }) =>
    console.log(`${progress}% (${loaded}/${total})`),
  onDownloadProgress: ({ progress }) => console.log(`download ${progress}%`),
  onRetry: ({ retry, delay }) => console.log(`retry ${retry} in ${delay} ms`),
  onResponse: ({ response }) => hideSpinner(response.success),
  onRemove: () => console.log("removed from the queue"),
});
```

`onBeforeSent` is the earliest point with the `requestId`. To track every call of a request instead of one, register
listeners with `request.$hooks`, see [Request lifecycle](/docs/core/request#listen-to-the-lifecycle).

```ts live
const { data } = await getUsers.send({
  onBeforeSent: ({ requestId }) =>
    console.log(`Request ${requestId} is about to be sent.`),
  onRequestStart: ({ requestId }) =>
    console.log(`Request ${requestId} has started.`),
  onResponseStart: ({ requestId }) =>
    console.log(`Response of ${requestId} has started.`),
  onDownloadProgress: ({ progress }) =>
    console.log(`Download progress: ${progress}%`),
  onResponse: ({ response, requestId }) =>
    console.log(`Request ${requestId} finished: ${response.status}`),
});
```

## Abort a request

`request.abort()` aborts every in-flight request with the same `abortKey`. The `send()` promise resolves with an
`AbortError` in `error`. `client.requestManager.abortByKey(abortKey)` does the same from anywhere.

```ts live
const promise = getUsers.send();

// Abort every request with this abortKey
getUsers.abort();

const { error } = await promise;

console.log(error);
```

To abort the previous call automatically when a new one starts, see [cancellation](/docs/guides/core/advanced/cancellation).

## Send without queues or cache: exec()

`exec()` calls the adapter directly. Interceptors and mappers run, but there is no deduplication, queue, retry, offline
handling or cache write. Use it for one-off calls, for example on a server where each call is independent.

```ts title="server/report.ts"
const { data, error } = await getUser.exec({ params: { userId: 1 } });
```

| Feature                                  | `send()` | `exec()` |
| ---------------------------------------- | -------- | -------- |
| Interceptors, mappers, mocks             | Yes      | Yes      |
| Deduplication, queues, retries, offline  | Yes      | No       |
| Cache write and `cachePolicy`            | Yes      | No       |
| Callbacks such as `onResponse`           | Yes      | No       |
