# Query parameters in requests

Query params are the `?key=value` pairs at the end of a URL, such as `/search?query=hooks&page=2`. APIs use them to
filter, sort and paginate. This guide shows how to build them for `fetch` by hand, then how HyperFetch types them and
turns them into a query string for you.

:::secondary What you'll learn

1. How to add **fetch query params** with `URLSearchParams`.
2. How to **type** query params, including optional ones and arrays.
3. How to set them with **`setQueryParams`** or pass them to **`send()`**.
4. How to change the **serialization** of arrays, dates and objects.

:::

---

## Fetch query params with URLSearchParams

`fetch` has no `params` option. You build the query string yourself, and
[`URLSearchParams`](https://developer.mozilla.org/en-US/docs/Web/API/URLSearchParams) does the encoding:

```ts title="search.ts"
const url = new URL("https://api.example.com/search");
url.searchParams.set("query", "react hooks"); // spaces and & are encoded for you
url.searchParams.set("page", String(2));

const response = await fetch(url);
// GET https://api.example.com/search?query=react+hooks&page=2
```

Three things trip people up:

- **Everything is a string.** Numbers and booleans need `String()`, and `undefined` becomes the text `"undefined"` unless
  you skip it.
- **Arrays have no standard format.** Backends expect different shapes, see the [table below](#change-the-serialization).
- **Dates and objects** need an agreed format, such as ISO dates or JSON.

In HyperFetch query params are part of the request type, so the compiler checks them, and the adapter serializes them.

---

## Type the query params

Declare the shape with the `queryParams` generic. The key decides whether they are required at `send()`:

| Generic                  | At `send()`                       |
| ------------------------ | --------------------------------- |
| `queryParams: Q`         | Required                          |
| `queryParams?: Q`        | Optional                          |
| no `queryParams` key     | None accepted                     |

```ts title="src/api/articles.ts"
export const getArticles = client.createRequest<{
  response: Article[];
  queryParams?: { search?: string; page?: number; tags?: string[] };
}>()({ endpoint: "/articles" });
```

Mark single keys optional with `?` as usual. Arrays are typed like any other value.

---

## Set them with setQueryParams or send()

`setQueryParams` returns a new request with the values stored. They are kept apart from the endpoint and serialized when
the request is sent.

```ts title="src/app.ts"
const request = getArticles.setQueryParams({
  search: "hooks",
  tags: ["react", "typescript"],
});

console.log(request.endpoint); // "/articles"
// { search: "hooks", tags: ["react", "typescript"] }
console.log(request.queryParams);

await request.send();
// GET /articles?search=hooks&tags[]=react&tags[]=typescript
```

Pass them to `send()` when they come from user input at call time:

```ts title="src/app.ts"
const { data } = await getArticles.send({
  queryParams: { search: "hooks", page: 2 },
});
```

As with [params](/docs/guides/core/basics/parameters#params-set-twice), a request that already has query params set no
longer accepts them in `send()`.

---

## Default serialization

The fetch adapter writes query params with these defaults:

- **Arrays** use brackets: `?tags[]=a&tags[]=b`.
- **Dates** use `toISOString()`. **Objects** use `JSON.stringify`.
- **`null`, `undefined` and `""`** values are skipped.
- **Keys and values** are URL-encoded.
- A **string** value is used as the query string as it is, with `?` added when missing.

Query params are part of the default `cacheKey` and `queryKey`, serialized with `JSON.stringify`. `{ a, b }` and
`{ b, a }` are two cache entries, so build query objects in a fixed order.

---

## Change the serialization

`client.adapter.setQueryParamsMapperConfig` changes the format for every request of the client. The config is merged
with the defaults, so pass only what you change.

| Format           | Query string            | `arrayFormat`          |
| ---------------- | ----------------------- | ---------------------- |
| Brackets         | `?tags[]=a&tags[]=b`    | `"bracket"` (default)  |
| Repeated key     | `?tags=a&tags=b`        | `"none"`               |
| Indexed          | `?tags[0]=a&tags[1]=b`  | `"index"`              |
| Comma-separated  | `?tags=a,b`             | `"comma"`              |
| Custom separator | `?tags=a\|b`            | `"separator"`          |

```ts title="src/api/client.ts"
client.adapter.setQueryParamsMapperConfig({
  arrayFormat: "comma",
  // Dates as YYYY-MM-DD instead of ISO strings, also inside arrays
  dateParser: (value) => (value as Date).toISOString().slice(0, 10),
  // Objects as "field:direction" instead of JSON
  objectParser: (value) => {
    const { field, direction } = value as { field: string; direction: string };
    return `${field}:${direction}`;
  },
});
```

Other options: `arraySeparator` (default `"|"`) for the `"separator"` format, `skipNull` and `skipEmptyString` (both
`true`) to keep empty values, and `encode` (default `true`). For a format these options cannot express, replace the
whole function with `client.adapter.setQueryParamsMapper`.
