# Authentication

Most APIs need credentials on each request: a bearer token, a session cookie or an API key. HyperFetch adds them in one
place, the client's `onAuth` interceptor, and refreshes expired tokens in `onError`. This guide covers bearer tokens,
token refresh, cookies and API keys.

:::secondary What you'll learn

1. How to attach a **bearer token** to every request with `onAuth`.
2. How to skip auth for **public endpoints**.
3. How to **refresh an expired token** on `401` without loops or parallel refreshes.
4. How to send **cookies** and **API keys**.

:::

---

## Attach a bearer token

`client.onAuth` runs before every request with `auth: true`, which is the default. Return the request with the headers
it needs.

```ts title="src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

export const client = createClient({ url: "https://api.example.com" }).onAuth(
  (request) => {
    const token = localStorage.getItem("token");
    if (!token) return request;

    return request.setHeaders({
      ...request.headers,
      Authorization: `Bearer ${token}`,
    });
  },
);
```

`setHeaders` replaces the headers, so spread `request.headers` to keep the ones set on the request. The token is read on
each request, so a new token after login is picked up without recreating anything.

---

## Skip auth for public endpoints

Mark endpoints that need no credentials with `auth: false`, such as login or health checks. `onAuth` does not run for
them.

```ts title="src/api/auth.ts"
export const login = client.createRequest<{
  response: { token: string; refreshToken: string };
  payload: { email: string; password: string };
}>()({ endpoint: "/auth/login", method: "POST", auth: false });
```

`setAuth(false)` does the same on an existing request.

---

## Refresh the token on 401

Access tokens expire. When the API answers `401`, refresh the token in an `onError` interceptor and send the original
request again. Two details keep it safe:

- **`request.used`** marks the resent request, so a second `401` returns the error instead of refreshing again.
- **One shared refresh**: when several requests fail at once, they all wait for the same refresh call.

```ts title="src/api/client.ts"
const refreshSession = client.createRequest<{
  response: { token: string; refreshToken: string };
  payload: { refreshToken: string };
}>()({ endpoint: "/auth/refresh", method: "POST", auth: false });

let refreshing: Promise<boolean> | null = null;

const refreshTokens = async () => {
  const refreshToken = localStorage.getItem("refreshToken");
  if (!refreshToken) return false;

  const { data } = await refreshSession.send({ payload: { refreshToken } });
  if (!data) return false;

  localStorage.setItem("token", data.token);
  localStorage.setItem("refreshToken", data.refreshToken);
  return true;
};

client.onError(async (response, request) => {
  if (response.status !== 401 || request.used) return response;

  // Requests that fail at the same time share one refresh
  refreshing ??= refreshTokens().finally(() => {
    refreshing = null;
  });

  if (!(await refreshing)) return response;

  // onAuth runs again and adds the new token
  return request.setUsed(true).send();
});
```

When the refresh fails, the original `401` response is returned. Handle it where you send the request, for example by
redirecting to the login page.

## Send cookies

Session cookies need no interceptor. `fetch` sends them to the same origin by default. For an API on another origin,
set `credentials: "include"` for every request with `setAdapterDefaults`:

```ts title="src/api/client.ts"
client.adapter.setAdapterDefaults(() => ({ credentials: "include" }));
```

The server must answer with `Access-Control-Allow-Credentials: true` and a specific `Access-Control-Allow-Origin`, not
`*`. For a single request, pass it in `options: { credentials: "include" }`.

---

## Send an API key

An API key goes in a header the same way as a token. On a server, read it from the environment:

```ts title="server/weather-client.ts"
export const weatherClient = createClient({
  url: "https://api.weather.example.com",
}).onAuth((request) =>
  request.setHeaders({
    ...request.headers,
    "X-Api-Key": process.env.WEATHER_API_KEY ?? "",
  }),
);
```

Never ship a secret key in browser code. Call the API from your server instead.

---

## Log out

Call `client.clear()` on logout. It aborts running requests and empties the queues and the cache, including persisted
storage, so the next user sees none of the previous user's data. Remove the stored tokens yourself.

| Approach          | Where                                    | Use it for                                    |
| ----------------- | ---------------------------------------- | --------------------------------------------- |
| `onAuth`          | Client, runs when `auth` is `true`       | Bearer tokens, API keys, signed requests      |
| `onError` + `used`| Client, runs on failed responses         | Refreshing tokens on `401`                    |
| `credentials`     | Adapter defaults or request `options`    | Cookies on another origin                     |
| `auth: false`     | Request                                  | Login, refresh, public endpoints              |

:::success Congratulations!

You've learned how to authenticate requests.

- You can attach credentials to every request with **`onAuth`** and skip it with **`auth: false`**.
- You can **refresh tokens** on `401` with `onError`, `setUsed(true)` and one shared refresh.
- You can send **cookies** across origins with `credentials: "include"`.
- You can clear all user data on logout with **`client.clear()`**.
