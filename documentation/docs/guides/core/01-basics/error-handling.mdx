# Error handling

HyperFetch requests never reject. `send()` resolves with `error` and `status` next to `data` for every failure: an HTTP
error, a timeout, an abort or a dropped connection. This guide shows the kinds of errors you get, how to type them and
where to handle them.

:::secondary What you'll learn

1. How to read errors **without `try/catch`**.
2. Which **kinds of errors** a request returns.
3. How to type a **global error** on the client and a **local error** per request.
4. How to **narrow** the error union and handle errors **in one place**.

:::

---

## Read the error from the response

Branch on `data` or `error` instead of catching. `status` tells an HTTP error from a failure that never reached the
server.

```ts title="src/app.ts"
const { data, error, status } = await getUser.send({ params: { userId: 1 } });

if (data) {
  renderUser(data);
} else {
  showError(status, error);
}
```

Prefer checking `data` over `success`. `success` does not narrow the types, so `data` stays nullable after
`if (success)`.

---

## Kinds of errors

| Cause                                    | `error`                               | `status`       |
| ---------------------------------------- | ------------------------------------- | -------------- |
| The server answered 4xx or 5xx           | The parsed response body              | The HTTP status |
| No connection, DNS or CORS failure       | The `fetch` error, usually `TypeError` | `0`            |
| Timeout (fetch adapter, default 5000 ms) | `TimeoutError`                        | `0`            |
| Aborted with `abort()` or `cancelable`   | `AbortError`                          | `0`            |
| Removed from the queue before it ended   | `DeletedError`                        | `null`         |
| A mapper or interceptor threw            | The thrown value                      | The response status |

The first row is your API's error shape. The others are `Error` instances, exported from `@hyper-fetch/core`, so you can
check them with `instanceof`.

---

## Type the global error

Type your API's error body once on the client with the `error` generic. Keep `Error` in the union, because the system
failures above are `Error` instances.

```ts title="src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

export type ApiError = { message: string; code: string };

export const client = createClient<{ error: ApiError | Error }>({
  url: "https://api.example.com",
});
```

Every request of this client now has `error` typed as `ApiError | Error | null`. See
[global error](/docs/guides/typescript/global-error).

---

## Add a local error per request

Some endpoints return their own error shape, such as field errors of a form. Add it with the request's `error` generic.
It is joined with the global error into a union.

```ts title="src/api/users.ts"
type ValidationError = { fields: Record<string, string[]> };

export const signUp = client.createRequest<{
  response: User;
  payload: { email: string; password: string };
  error: ValidationError;
}>()({ endpoint: "/users", method: "POST" });

// error: ValidationError | ApiError | Error | null
```

See [local error](/docs/guides/typescript/local-error).

---

## Narrow the error

Check system errors with `instanceof`, then tell API shapes apart by a property only one of them has.

```ts title="src/sign-up.ts"
import { AbortError, TimeoutError } from "@hyper-fetch/core";

const { data, error } = await signUp.send({ payload: { email, password } });

if (error instanceof AbortError) {
  // The user canceled, nothing to show
} else if (error instanceof TimeoutError) {
  showToast("The server took too long. Try again.");
} else if (error instanceof Error) {
  showToast("Check your connection.");
} else if (error && "fields" in error) {
  showFieldErrors(error.fields);
} else if (error) {
  showToast(error.message);
}
```

## Handle errors in one place

`client.onError` runs for every failed response, before `send()` resolves. Use it for logging, a global toast or
refreshing a token. Return the response, changed or not.

```ts title="src/api/client.ts"
client.onError((response, request) => {
  if (response.status && response.status >= 500) {
    reportToMonitoring({
      endpoint: request.endpoint,
      status: response.status,
      error: response.error,
    });
  }
  return response;
});
```

To turn errors of another shape into yours, map them in `setResponseMapper`, see
[data mapping](/docs/guides/core/basics/data-mapping). To retry failed requests, see
[retries](/docs/guides/core/basics/retries).

- You can handle errors **in one place** with `client.onError`.
