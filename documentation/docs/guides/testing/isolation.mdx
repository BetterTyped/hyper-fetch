The client is usually a module-level singleton, so the cache, queues and mocks of one test are still there in the next.
Without a reset, a test can pass only because an earlier one filled the cache. This guide shows what to reset and when.

:::secondary What you'll learn

1. How to reset the client with **`client.clear()`**.
2. Why to **clear mocks** after each test.
3. When you need a **fresh module** instead.

:::

---

## Reset the client before each test

`client.clear()` aborts running requests, removes queued ones, empties the cache (including its lazy storage), resets
optimistic state and creates the cache, dispatchers and app manager again from the client options.

```ts title="test/setup.ts"
import { client } from "../src/api/client";

beforeEach(() => {
  client.clear();
});
```

The adapter, interceptors, plugins and request defaults are kept, so the client still behaves like the production one.
The event listeners of the old modules are removed, so listeners you added yourself, for example with
`client.cache.events` or `client.requestManager.events`, must be added again after `clear()`.

---

## Clear mocks after each test

Unlike other setters, `setMock` changes the request instance instead of returning a copy. A mock set in one test stays on
the exported request until you remove it.

```ts title="test/setup.ts"
import { getUser, getUsers } from "../src/api/users";

afterEach(() => {
  getUsers.clearMock();
  getUser.clearMock();
});
```

To keep mocks out of shared requests altogether, put them in a [test SDK](/docs/guides/testing/mocking#centralize-mocks-in-a-test-sdk),
which creates its own request instances.

---

## Fresh modules

Vitest and Jest give each test file its own module registry, so test files that run in parallel never share a client.
Within one file, `client.clear()` is enough in most cases.

When a test needs a client created from scratch, for example to test code that runs at import time, reset the module
registry and import the client again:

```ts title="src/api/client.test.ts"
beforeEach(() => {
  vi.resetModules(); // jest.resetModules() in Jest
});

it("creates the client with defaults", async () => {
  const { client } = await import("./client"); // a new instance
  expect(client.url).toBe("https://api.example.com");
});
```

A statically imported `client` keeps pointing at the old instance after `resetModules`, so only modules imported after
the reset are fresh.

| Leaks between tests        | Reset with                             |
| -------------------------- | -------------------------------------- |
| Cache, queues, requests    | `client.clear()` in `beforeEach`       |
| Mocks on shared requests   | `request.clearMock()` in `afterEach`   |
| Module-level setup code    | `vi.resetModules()` and a dynamic import |
