Tests of a HyperFetch app use the same client and requests as production. You replace the network with
`request.setMock()`, reset the client between tests with `client.clear()`, and everything else (cache, queues, retries,
hooks) runs as it does for users. These guides cover both parts.

:::secondary What you'll learn

1. How to **mock requests** with `setMock` instead of a fake server.
2. How to **isolate tests** so cache and queues never leak between them.
3. How to **inject a test SDK** with all mocks in one place.

:::

---

## The approach

```ts title="src/components/users.test.tsx"
import { client } from "../api/client";
import { getUsers } from "../api/users";

beforeEach(() => client.clear()); // no cache or queue left from the previous test
afterEach(() => getUsers.clearMock()); // setMock changes the request instance

it("loads users", async () => {
  getUsers.setMock(() => ({ data: [{ id: 1, name: "Ann" }], status: 200 }));

  const { data } = await getUsers.send();

  expect(data).toEqual([{ id: 1, name: "Ann" }]);
});
```

- **Mocks are typed.** `setMock` checks the mocked `data` and `error` against the request's types, so a changed API type
  breaks the mock at compile time.
- **No duplicate setup.** Tests import the production client and requests, with their interceptors and defaults.
- **The real pipeline runs.** A mock replaces only the adapter call: interceptors, mappers, retries, cache writes and
  hook state behave as in the app.
