# Pagination in React

Numbered pagination is one piece of state, the current page, and a request that depends on it. This guide builds it with
[`useFetch`](/docs/react/hooks/use-fetch): the page goes into the query params, each page gets its own cache entry, and
the old page stays on screen while the next one loads. For a list that grows while scrolling, see
[infinite scroll](/docs/guides/react/basics/infinite-scroll).

:::secondary What you'll learn

1.  How to build **Next** and **Previous** buttons with the page in query params.
2.  How to keep the **previous page visible** instead of flashing a spinner.
3.  How to **prefetch** the next page so the click renders at once.
4.  When to pick **numbered pages** or **infinite scroll**.

:::

## Page buttons with query params

Put `page` and `limit` on the request with `setQueryParams`. When `page` changes, the request has a new cache key and
`useFetch` sends it. Pages already visited render from the cache.

```tsx title="components/paginated-posts.tsx"
import { useState } from "react";
import { useFetch } from "@hyper-fetch/react";
// queryParams: { page?: number; limit?: number }
import { getPosts } from "../api/posts";

const LIMIT = 10;

export function PaginatedPosts() {
  const [page, setPage] = useState(1);
  // highlight-start
  const {
    data: posts,
    loading,
    error,
  } = useFetch(getPosts.setQueryParams({ page, limit: LIMIT }));
  // highlight-end

  if (error) return <p className="p-4 text-red-500">{error.message}</p>;

  // A page shorter than the limit is the last one
  const isLastPage = !posts || posts.length < LIMIT;

  return (
    <div className="border rounded-md">
      <h2 className="text-xl font-bold p-4 border-b">Posts, page {page}</h2>
      <ul className={loading ? "divide-y opacity-50" : "divide-y"}>
        {posts?.map((post) => (
          <li key={post.id} className="p-4">
            {post.title}
          </li>
        ))}
      </ul>
      <div className="p-4 border-t flex justify-between">
        <button onClick={() => setPage((p) => p - 1)} disabled={page === 1}>
          Previous
        </button>
        <button
          onClick={() => setPage((p) => p + 1)}
          disabled={isLastPage || loading}
        >
          Next
        </button>
      </div>
    </div>
  );
}
```

When the API returns a total count, such as `{ data: Post[]; total: number }`, compute the last page from it and show
"Page 3 of 12" instead of guessing from a short page.

## Keep the old page on screen

The example dims the list instead of replacing it with a spinner. This works because only query params change between
pages, and `keepPreviousData` defaults to `"auto"`: `data` keeps the previous page until the next one arrives. Change it
with `keepPreviousData`:

| Value              | While the next page loads                                         |
| ------------------ | ----------------------------------------------------------------- |
| `"auto"` (default) | Keeps the old page when only query params change                  |
| `"preserve"`       | Always keeps the old data, also when URL params change            |
| `"clean"`          | Clears `data`, so you can show a spinner                          |

## Prefetch the next page

Send the next page ahead of time and it lands in the cache, so the Next click renders without waiting.
`cachePolicy: "cache-first"` skips the request when that page is already cached.

```tsx title="Prefetch on page change"
useEffect(() => {
  if (!isLastPage) {
    getPosts
      .setQueryParams({ page: page + 1, limit: LIMIT })
      .send({ cachePolicy: "cache-first" });
  }
}, [page, isLastPage]);
```

The [prefetching guide](/docs/guides/core/advanced/prefetching) shows prefetching on hover and on route changes.

## Numbered pages or infinite scroll

| Pattern                                         | Good for                                                   | Hook               |
| ----------------------------------------------- | ---------------------------------------------------------- | ------------------ |
| Numbered pages, one page on screen              | Tables, admin panels, search results people link to        | `useFetch`         |
| One growing list, a Load More button or scroll  | Feeds, chats, product grids                                | `useInfiniteFetch` |

Keep the page in the URL when people share links to it: read it from your router instead of `useState`, and the same
request works unchanged.
