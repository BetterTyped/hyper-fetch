# Pagination in React

Pagination in React comes down to one piece of state, the current page, and a request that depends on it. Change the
page, fetch the new slice, show it. The hard parts are around that: not flashing a spinner on every click, not
refetching pages the user already saw, and knowing when there is no next page. With Hyper Fetch you put the page in
the request's query params, and `useFetch` refetches when it changes. Each page gets its own cache entry, so going back
to a page you visited is instant.

:::secondary What you'll learn

1.  How to implement **pagination** using the `useFetch` hook.
2.  How to manage the **current page state** in a React component.
3.  How to create **"Next"** and **"Previous"** buttons to navigate through pages.
4.  How Hyper Fetch's **automatic re-fetching** and **caching** simplify pagination logic.
5.  How to keep the **previous page visible** and **prefetch** the next one.

## Numbered pages or infinite scroll

Two UI patterns sit on top of the same API:

- **Numbered pages** (this guide): the user moves between pages and sees one at a time. Good for tables, admin panels
  and search results people want to link to.
- **Infinite scroll**: pages are appended to one growing list. Good for feeds. See
  [infinite scroll in React](./infinite-scroll.mdx), which uses `useInfiniteFetch`.

For numbered pages the API usually takes `page` and `limit` (or `offset` and `limit`) as query params. If the server
also returns a total count, you can show "Page 3 of 12" and disable "Next" on the last page. Without it, the common trick
is the one used below: a page shorter than `limit` is the last one.

## Example

Let's build a component that displays a paginated list of posts. We'll add buttons to navigate back and forth between
pages.

```tsx
function PaginatedPosts() {
  const [page, setPage] = React.useState(1);

  // highlight-start
  const { data: posts, loading, error } = useFetch(getPosts.setQueryParams({ page, limit: 5 }));
  // highlight-end

  const goToNextPage = () => {
    setPage((p) => p + 1);
  };

  const goToPrevPage = () => {
    setPage((p) => Math.max(1, p - 1));
  };

  if (error) {
    return <p className="p-4 text-red-500">Failed to load posts.</p>;
  }

  return (
    <div className="border rounded-md">
      <h2 className="text-xl font-bold p-4 border-b">Posts (Page {page})</h2>
      {loading ? (
        <p className="p-4">Loading...</p>
      ) : (
        <ul className="divide-y divide-gray-200">
          {posts?.map((post) => (
            <li key={post.id} className="p-4">
              <p className="font-semibold">{post.title}</p>
            </li>
          ))}
        </ul>
      )}
      <div className="p-4 border-t flex justify-between">
        <button
          className="px-4 py-2 bg-gray-300 rounded disabled:opacity-50"
          onClick={goToPrevPage}
          disabled={page === 1 || loading}
        >
          Previous
        </button>
        <button
          className="px-4 py-2 bg-gray-300 rounded disabled:opacity-50"
          onClick={goToNextPage}
          disabled={!posts || posts.length < 5 || loading}
        >
          Next
        </button>
      </div>
    </div>
  );
}
```

### How It Works

1.  We use a React state variable, `page`, to keep track of the current page number.
2.  The `useFetch` hook is given a request that includes the `page` in its query parameters:
    `getPosts.setQueryParams({ page, limit: 5 })`.
3.  Whenever `page` changes (by clicking the "Next" or "Previous" buttons), the component re-renders.
4.  Hyper-fetch detects that a dependency of the request (`page`) has changed and automatically triggers a new fetch for
    the new page's data.
5.  The `loading` state from `useFetch` is used to give feedback to the user while the new page is being loaded.
6.  The "Next" button is disabled if the current page has fewer items than the limit, indicating we've reached the end.

This declarative approach keeps the pagination logic in one line.

## Keep the old page on screen

By default `useFetch` uses `keepPreviousData: "auto"`. When only the query params change, which is the pagination case,
the previous page stays in `data` until the new one arrives. So instead of swapping the list for a spinner, you can dim
it while `loading`:

```tsx
<ul className={loading ? "opacity-50" : ""}>
  {posts?.map((post) => (
    <li key={post.id}>{post.title}</li>
  ))}
</ul>
```

Set `keepPreviousData: "clean"` if you'd rather reset to empty on every page change.

## Prefetch the next page

Every page has its own cache entry, keyed by its query params. Sending the next page's request ahead of time puts it in
the cache, so the "Next" click renders without waiting:

```tsx
React.useEffect(() => {
  getPosts.setQueryParams({ page: page + 1, limit: 5 }).send();
}, [page]);
```

More patterns in [prefetching](../../core/02-advanced/prefetching.mdx), and the cache rules in
[cache invalidation](../../core/02-advanced/cache-revalidation.mdx). If you keep the page in the URL, read it from your
router instead of `useState`, and the same code works with shareable links.
