# Fetching Data in React

Fetching data in React usually starts with the Fetch API inside `useEffect`. That works for a demo, and then the
same questions come up in every component: where do loading and error state live, what happens when the user switches
pages before the response arrives, and why does the same request fire twice? This guide shows the plain version first,
then the `useFetch` hook from HyperFetch, which handles loading state, errors, caching and stale responses for you.

:::secondary What you'll learn

1.  How to fetch data with the **fetch API in React**, and where it falls short.
2.  How to use the **`useFetch` hook** to fetch data from an API.
3.  How to handle **loading** and **error states** in your components.
4.  How to pass **parameters** to your requests.
5.  What are the **main values** returned by the `useFetch` hook.
6.  How `useFetch` compares to React Query's **`useQuery`**.

:::

## The fetch API in React

Here is a typical React fetch with `useEffect`:

```tsx
type User = { id: number; name: string };

function UserList() {
  const [users, setUsers] = React.useState<User[] | null>(null);
  const [loading, setLoading] = React.useState(true);
  const [error, setError] = React.useState<Error | null>(null);

  React.useEffect(() => {
    const controller = new AbortController();

    fetch("/api/users", { signal: controller.signal })
      .then((response) => {
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        return response.json();
      })
      .then(setUsers)
      .catch((err) => {
        if (err.name !== "AbortError") setError(err);
      })
      .finally(() => setLoading(false));

    return () => controller.abort();
  }, []);

  // render loading, error, users...
}
```

Even this careful version leaves gaps:

- **No cache.** Every component that needs users fetches them again, and navigating back shows a spinner again.
- **No sharing.** Two components mounting at once send two requests. React's Strict Mode also runs the effect twice in
  development.
- **`fetch` doesn't fail on HTTP errors.** A `404` or `500` resolves normally, so you have to check `response.ok`
  yourself.
- **No types.** `response.json()` returns `any`.
- **No retries, refetch on focus, or refetch after a mutation.** Each one is more code in every component.

A data-fetching hook moves all of that out of the component. In HyperFetch that hook is `useFetch`. You describe the
request once, and every component that uses it shares the same cache and the same in-flight request.

## Basic Usage

To get started, you simply pass a `request` instance to the `useFetch` hook. It will automatically execute the request
when the component mounts.

{/* Here is a live example that fetches a list of users and displays them. */}

```tsx
function UserList() {
  // highlight-start
  const { data: users, loading, error } = useFetch(getUsers);
  // highlight-end

  if (loading) {
    return <div className="p-4">Loading users...</div>;
  }

  if (error) {
    return <div className="p-4 text-red-500">Oops! Something went wrong.</div>;
  }

  return (
    <div className="p-4">
      <h2 className="text-xl font-bold mb-2">Users</h2>
      <ul className="list-disc list-inside">{users?.map((user) => <li key={user.id}>{user.name}</li>)}</ul>
    </div>
  );
}
```

## Fetching with Parameters

Often, you'll need to fetch a specific resource by an identifier. You can pass parameters to your request using the
`.setParams()` method.

This example fetches a single user by their ID.

```tsx
function UserProfile() {
  const [userId, setUserId] = React.useState(1);

  // highlight-start
  const { data: user, loading, error } = useFetch(getUser.setParams({ userId }));
  // highlight-end

  const loadNextUser = () => {
    setUserId((id) => id + 1);
  };

  return (
    <div className="p-4 border rounded-md">
      <div className="flex justify-between items-center mb-4">
        <h2 className="text-xl font-bold">User Profile</h2>
        <button className="px-4 py-2 bg-blue-500 text-white rounded hover:bg-blue-600" onClick={loadNextUser}>
          Load Next User
        </button>
      </div>
      {loading && <div>Loading...</div>}
      {error && <div className="text-red-500">Could not fetch user data.</div>}
      {user && (
        <div>
          <p>
            <span className="font-semibold">ID:</span> {user.id}
          </p>
          <p>
            <span className="font-semibold">Name:</span> {user.name}
          </p>
          <p>
            <span className="font-semibold">Email:</span> {user.email}
          </p>
        </div>
      )}
    </div>
  );
}
```

The `useFetch` hook will automatically re-fetch the data whenever the `userId` state changes because HyperFetch tracks
the dependencies of your request.

## Returned Values

The `useFetch` hook returns a rich set of values beyond just `data`, `loading`, and `error`:

```tsx
const {
  data,               // The response data (typed)
  error,              // The error object if the request failed
  loading,            // Whether the request is in progress (stays true between retries)
  success,            // Whether the last request was successful
  status,             // HTTP status code
  extra,              // Adapter-specific extra data (e.g. response headers)
  retries,            // Number of retries performed
  refetch,            // Function to manually re-fetch data
  abort,              // Function to abort the current request
  onSuccess,          // Registrar for success callbacks
  onError,            // Registrar for error callbacks
  onFinished,         // Registrar for finished callbacks (success or error)
  onRequestStart,     // Registrar for request start callbacks
  onAbort,            // Registrar for abort callbacks
  onOfflineError,     // Registrar for offline error callbacks
  setData,            // Manually set the data state
  setError,           // Manually set the error state
  setLoading,         // Manually set the loading state
} = useFetch(getUsers);
```

## Hook Options

You can pass a second argument to `useFetch` to configure its behavior:

```tsx
const { data } = useFetch(getUser.setParams({ userId }), {
  // Set to true to skip fetching (e.g. until required data is available)
  disabled: false,

  // Keep showing previous data while a new request is loading
  keepPreviousData: "preserve",

  // Custom dependencies array - re-fetch when these change
  dependencies: [userId],
});
```

Key options include:

- **`disabled`**: When `true`, prevents the hook from fetching. Useful for conditional fetching.
- **`keepPreviousData`**: What happens to the current data when the request (cache key) changes. `"auto"` (default)
  keeps it when only query params change and clears it when URL params change, `"preserve"` always keeps it until new
  data arrives, `"clean"` always resets it.
- **`dependencies`**: An array of values that trigger a re-fetch when they change (similar to React's `useEffect` deps).
- **`initialResponse`**: Provide initial data for SSR or hydration scenarios.

## useFetch and useQuery

If you've used React Query, `useFetch` is the equivalent of
[`useQuery`](https://tanstack.com/query/latest/docs/framework/react/guides/queries). `useQuery` takes a `queryKey` and a
`queryFn` you write. `useFetch` takes a request object, and the cache key comes from the request's method, endpoint,
params and query params, so there is no key to keep in sync by hand.

| React Query `useQuery`                    | HyperFetch `useFetch`                          |
| ----------------------------------------- | ----------------------------------------------- |
| `useQuery({ queryKey, queryFn })`         | `useFetch(getUsers)`                            |
| `queryKey: ["user", id]`                  | `getUser.setParams({ userId: id })`             |
| `isPending`                               | `loading`                                       |
| `data`, `error`                           | `data`, `error`                                 |
| `enabled: false`                          | `disabled: true`                                |
| `refetch()`                               | `refetch()`                                     |
| `queryClient.invalidateQueries(...)`      | `client.cache.invalidate(...)`                  |

For writes, the counterpart of `useMutation` is `useSubmit`, covered in
[mutations in React with useSubmit](./submitting.mdx). For lists that grow while scrolling, see
[infinite scroll](./infinite-scroll.mdx). To understand when cached data gets refreshed, see
[cache invalidation](../../core/02-advanced/cache-revalidation.mdx).
