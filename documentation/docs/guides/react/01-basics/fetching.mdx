# Fetching Data in React

This guide loads server data into React components: first with `fetch` inside `useEffect`, then with the
[`useFetch`](/docs/react/hooks/use-fetch) hook, which adds loading and error state, a shared cache and refetching when
params change.

:::secondary What you'll learn

1.  What goes wrong with **`fetch` in `useEffect`**.
2.  How to load data with the **`useFetch` hook** and render loading and error states.
3.  How **params and query params** refetch on change, and when to use `dependencies`.
4.  How cached data and **background revalidation** work.
5.  How `useFetch` maps to React Query's **`useQuery`**.

:::

## The fetch API in useEffect

Here is a typical fetch in a component:

```tsx title="components/user-list.tsx"
function UserList() {
  const [users, setUsers] = useState<User[] | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);

  useEffect(() => {
    const controller = new AbortController();

    fetch("/api/users", { signal: controller.signal })
      .then((response) => {
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        return response.json();
      })
      .then(setUsers)
      .catch((err) => {
        if (err.name !== "AbortError") setError(err);
      })
      .finally(() => setLoading(false));

    return () => controller.abort();
  }, []);

  // render loading, error, users...
}
```

Even this careful version leaves gaps:

- **No cache.** Every component that needs users fetches them again, and going back to a page shows a spinner again.
- **No sharing.** Two components mounting at once send two requests.
- **HTTP errors resolve.** A `404` or `500` is a normal response, so you check `response.ok` by hand.
- **No types.** `response.json()` returns `any`.
- **No retries, refetch on focus or refetch after a mutation.** Each is more code in every component.

## Load data with useFetch

Describe the [request](/docs/core/request) once, at module level, and pass it to `useFetch`. The hook sends it when the
component mounts and returns typed `data`, `loading` and `error`.

```tsx title="components/user-list.tsx"
import { useFetch } from "@hyper-fetch/react";
import { getUsers } from "../api/users"; // client.createRequest<{ response: User[] }>()({ endpoint: "/users" })

export function UserList() {
  const { data: users, loading, error, refetch } = useFetch(getUsers);

  if (loading && !users) return <p className="p-4">Loading users...</p>;
  if (error) {
    return (
      <div className="p-4 text-red-500">
        <p>{error.message}</p>
        <button onClick={refetch}>Try again</button>
      </div>
    );
  }

  return (
    <ul className="p-4 list-disc list-inside">
      {users?.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

- `data` is `null` until the first response or a cached value exists.
- `error` holds the typed error of the request. HTTP errors land here, the hook never throws.
- Every component that renders `useFetch(getUsers)` shares one cache entry and one request in flight.

## Refetch when params change

Build the request in render with `setParams` or `setQueryParams`. When a value changes, the request gets a new cache key
and the hook sends it. An equal request on the next render sends nothing, so no `useMemo` is needed.

```tsx title="components/user-profile.tsx"
function UserProfile() {
  const [userId, setUserId] = useState(1);
  const { data: user, loading } = useFetch(getUser.setParams({ userId }));

  return (
    <div className="p-4 border rounded-md">
      <button onClick={() => setUserId((id) => id + 1)}>Next user</button>
      {loading && <p>Loading...</p>}
      {user && <p className="font-semibold">{user.name}</p>}
    </div>
  );
}
```

For values that are not part of the request, such as a version counter, pass them in `dependencies`. They are compared
with `Object.is`, so pass primitives: an object built in render refetches on every render.

```tsx title="Refetch on an outside value"
const { data } = useFetch(getUserPosts.setParams({ userId }), { dependencies: [version] });
```

## Show cached data first

When the cache already has data for the request, the first render shows it and a background request replaces it. This
is stale-while-revalidate, default `revalidate: true`, change it with `revalidate`. With `revalidate: false`, the hook
sends only when the cached data is missing or stale.

```tsx title="Skip the mount request while data is fresh"
// staleTime is set on the request: 5 minutes by default
const getCountries = client.createRequest<{ response: Country[] }>()({ endpoint: "/countries" }).setStaleTime(Time.HOUR);

const { data } = useFetch(getCountries, { revalidate: false });
```

When the cache key changes, `keepPreviousData` decides what stays on screen. The default `"auto"` keeps the old data
when only query params change (a page or a filter) and clears it when URL params change (another resource).

## useFetch and useQuery

`useFetch` fills the spot of React Query's `useQuery`. Instead of a `queryKey` and a `queryFn`, it takes a request
object, and the cache key comes from the request's method, endpoint, params and query params.

| React Query `useQuery`               | HyperFetch `useFetch`               |
| ------------------------------------ | ----------------------------------- |
| `useQuery({ queryKey, queryFn })`    | `useFetch(getUsers)`                |
| `queryKey: ["user", id]`             | `getUser.setParams({ userId: id })` |
| `isPending`                          | `loading`                           |
| `enabled: false`                     | `disabled: true`                    |
| `refetch()`                          | `refetch()`                         |
| `queryClient.invalidateQueries(...)` | `client.cache.invalidate(...)`      |

The [migration guide](/docs/guides/react/basics/migrating-from-react-query) maps the rest of the API.

## Which hook to use

| You want to                                       | Use                                                                    |
| ------------------------------------------------- | ---------------------------------------------------------------------- |
| Show data when the component mounts               | `useFetch`                                                             |
| Create, update or delete, or fetch on click       | [`useSubmit`](/docs/guides/react/basics/submitting)                    |
| Load a list page by page                          | [`useInfiniteFetch`](/docs/guides/react/basics/infinite-scroll)        |
| Wait for another request first                    | `useFetch` with [`disabled`](/docs/guides/react/basics/dependent-requests) |
| Read the cache without sending                    | [`useCache`](/docs/react/hooks/use-cache)                              |

Never send a `POST` with `useFetch`: it would fire on every mount and on every key change.

:::success Congratulations!

You can now load server data in React with `useFetch`.

- You can render **loading**, **error** and **data** states from one hook.
- You can refetch by changing **params** or **query params** on the request.
- You can use **`dependencies`** for values outside the request.
- You can control **background revalidation** with `revalidate` and `staleTime`.
