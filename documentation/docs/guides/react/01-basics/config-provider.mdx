# React Provider

The `Provider` from `@hyper-fetch/react` sets default options for the hooks below it, such as `refetchOnFocus` for every
`useFetch`. It is optional: hooks work without it. This guide sets app-wide defaults, changes them at runtime and shows
which settings belong on the request instead.

:::secondary What you'll learn

1.  How to set **default hook options** with `<Provider config>`.
2.  Which **config keys** exist and how hook options override them.
3.  How to **change the config at runtime** with `useProvider`.
4.  Which defaults belong on the **request or client** instead.

:::

---

## Set defaults for every hook

Wrap the app once, near the root. Each key of `config` holds the defaults of one hook.

```tsx title="main.tsx"
import { createRoot } from "react-dom/client";
import { Provider } from "@hyper-fetch/react";
import { App } from "./app";

createRoot(document.getElementById("root")!).render(
  <Provider
    config={{
      useFetchConfig: { refetchOnFocus: true, refetchOnReconnect: true },
      useInfiniteFetchConfig: { refetchOnFocus: true },
      useQueueConfig: { keepFinishedRequests: true },
    }}
  >
    <App />
  </Provider>,
);
```

| Key                      | Defaults for                                   |
| ------------------------ | ---------------------------------------------- |
| `useFetchConfig`         | [`useFetch`](/docs/react/hooks/use-fetch)      |
| `useInfiniteFetchConfig` | [`useInfiniteFetch`](/docs/react/hooks/use-infinite-fetch) |
| `useSubmitConfig`        | [`useSubmit`](/docs/react/hooks/use-submit)    |
| `useCacheConfig`         | [`useCache`](/docs/react/hooks/use-cache)      |
| `useQueueConfig`         | [`useQueue`](/docs/react/hooks/use-queue)      |
| `useListener`            | [`useListener`](/docs/react/sockets/use-listener) |
| `useEmitter`             | [`useEmitter`](/docs/react/sockets/use-emitter) |

Options passed to a hook override the Provider, which overrides the built-in defaults. `select` and `pagination`
describe one component or request, so they cannot be set here.

---

## Change the config at runtime

`useProvider()` returns the current `config` and `setConfig`. `setConfig` replaces the whole config, so spread the
current one to change a single option.

```tsx title="components/data-saver-toggle.tsx"
import { useProvider } from "@hyper-fetch/react";

export function DataSaverToggle() {
  const { config, setConfig } = useProvider();

  const enableDataSaver = () =>
    setConfig({ ...config, useFetchConfig: { ...config.useFetchConfig, refetchOnFocus: false, refresh: false } });

  return <button onClick={enableDataSaver}>Data saver</button>;
}
```

Passing a new `config` prop also updates the Provider. An inline object with equal values does not, so there is no need
to memoize it.

## Hook defaults or request defaults

The Provider only covers how hooks behave in components. Caching, retries and timeouts are properties of a request, so
they are set on the request or for every request on the client.

| Setting                                                     | Where                                                                  |
| ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| Refetch on focus, polling, `revalidate`, `bounce`, suspense | `Provider` config                                                      |
| `staleTime`, `cacheTime`, `retry`, `deduplicate`            | The request, or [`setRequestDefaults`](/docs/guides/core/basics/global-defaults) |
| Timeouts and other adapter options                          | [`setAdapterDefaults`](/docs/guides/core/basics/global-defaults)       |
| Headers and auth                                            | [Client interceptors](/docs/guides/core/basics/authentication)         |

A nested `Provider` replaces the outer config for its subtree instead of merging with it, so repeat the options you want
to keep.
