# Dependent Requests

A dependent request needs data from another one, such as the posts of the user you just loaded. This guide covers two
ways to wait for it with [`useFetch`](/docs/react/hooks/use-fetch): the `disabled` option and a child component that
renders once the data exists.

:::secondary What you'll learn

1.  How to hold a request with the **`disabled` option** until its data is ready.
2.  How to split a chain into a **child component** so params are never placeholders.
3.  How **`loading`** behaves while a request is disabled.
4.  When to use **which approach**.

:::

---

## Wait with disabled

Set `disabled` while the data you need is missing. Nothing is sent and `loading` stays `false`. As soon as `disabled`
turns `false`, the hook sends the request.

```tsx title="components/user-posts.tsx"
import { useFetch } from "@hyper-fetch/react";
import { getCurrentUser, getUserPosts } from "../api/users";

export function UserPosts() {
  const { data: user, loading: loadingUser } = useFetch(getCurrentUser);

  // highlight-start
  // The placeholder 0 keeps the request typed; nothing is sent until user exists
  const {
    data: posts,
    loading,
    error,
  } = useFetch(getUserPosts.setParams({ userId: user?.id ?? 0 }), {
    disabled: !user,
  });
  // highlight-end

  if (loadingUser) return <p>Loading user...</p>;

  return (
    <div className="flex flex-col gap-2">
      <h2 className="font-bold">{user?.name}</h2>
      {loading && <p>Loading posts...</p>}
      {error && <p className="text-red-500">{error.message}</p>}
      <ul className="list-disc list-inside">
        {posts?.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

Never call a hook conditionally (`if (user) useFetch(...)`): it breaks the rules of hooks. `disabled` keeps the hook
mounted and only holds the request.

## Render a child once the data exists

When the second request lives in its own part of the screen, render that part only after the first response. The child
receives real values, so no placeholder param and no `disabled` flag are needed.

```tsx title="components/user-page.tsx"
export function UserPage() {
  const { data: user } = useFetch(getCurrentUser);

  if (!user) return <p>Loading user...</p>;
  return <PostsList userId={user.id} />;
}

function PostsList({ userId }: { userId: number }) {
  const { data: posts } = useFetch(getUserPosts.setParams({ userId }));

  return <ul>{posts?.map((post) => <li key={post.id}>{post.title}</li>)}</ul>;
}
```

Both requests are cached, so going back to the page renders the user and the posts at once while they revalidate in the
background.

---

## Which approach to use

| Situation                                                     | Use                     |
| ------------------------------------------------------------- | ----------------------- |
| Both results render in one component                          | `disabled`              |
| The dependent data has its own section or component           | A child component       |
| The second request waits for a user action, not for data      | [`useSubmit`](/docs/guides/react/basics/submitting) |
| Two requests do not depend on each other                      | Two `useFetch` calls, they run in parallel |

Each step of a chain waits for the previous response, so a chain of three requests costs three round trips. When the
server can return the related data in one response, that is faster than any client-side chain.

You can now chain requests in React without effects.

- You can hold a request with **`disabled`** until its data exists.
- You can move the dependent request into a **child component**.
- You know that a disabled hook sends nothing and reports **`loading: false`**.

:::
