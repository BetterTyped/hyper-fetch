# Request Lifecycle Events

Every request goes through the same stages: it starts, the response arrives, and it ends with success, an error, an
abort or an offline error. The hooks expose a callback for each stage, so you can show toasts, log or track timing
without effects. This guide uses [`useFetch`](/docs/react/hooks/use-fetch); `useSubmit` has the same callbacks with an
`onSubmit` prefix.

:::secondary What you'll learn

1.  What the **stages of a request** are and in which order the callbacks fire.
2.  How to register callbacks like **`onSuccess`**, **`onError`** and **`onFinished`**.
3.  How **aborts**, **offline errors** and **retries** are reported.
4.  Which callbacks fire for **requests sent by other components**.

:::

## Log every stage

Call the registrars in the render body. The latest closure is used, so they can read current state. Each callback
receives one object with `response`, `request`, `requestId` and `details`.

```tsx title="components/lifecycle-log.tsx"
import { useState } from "react";
import { useFetch } from "@hyper-fetch/react";
import { getUser } from "../api/users";

export function LifecycleLog() {
  const [logs, setLogs] = useState<string[]>([]);
  const log = (message: string) => setLogs((prev) => [`${new Date().toLocaleTimeString()} ${message}`, ...prev]);

  const { refetch, abort, onRequestStart, onResponseStart, onSuccess, onError, onAbort, onOfflineError, onFinished } =
    useFetch(getUser.setParams({ userId: 1 }));

  onRequestStart(({ requestId }) => log(`Started ${requestId}`));
  onResponseStart(() => log("Response is arriving"));
  onSuccess(({ response }) => log(`Success: ${response.data.name}`));
  onError(({ response }) => log(`Error: ${response.error.message}`));
  onAbort(() => log("Aborted"));
  onOfflineError(() => log("Offline, will send again when online"));
  onFinished(({ response }) => log(`Finished with status ${response.status}`));

  return (
    <div className="border rounded-md p-4">
      <button onClick={refetch}>Fetch</button>
      <button onClick={abort}>Abort</button>
      <div className="font-mono text-sm">
        {logs.map((line, index) => (
          <p key={index}>{line}</p>
        ))}
      </div>
    </div>
  );
}
```

## The order of the callbacks

| Stage                 | Callback                                                      |
| --------------------- | ------------------------------------------------------------- |
| Request sent          | `onRequestStart`, then `onUploadProgress` while uploading     |
| First response bytes  | `onResponseStart`, then `onDownloadProgress` while downloading |
| Result, exactly one   | `onSuccess`, `onError`, `onAbort` or `onOfflineError`          |
| Always last           | `onFinished`                                                  |
| Next attempt planned  | `onRetry`, with the `retry` number and the `delay` in ms      |

- **`onAbort`** fires for canceled requests, such as `abort()` or a cancelable request replaced by a newer one. It never
  calls `onError`.
- **`onOfflineError`** fires when the request failed because the app is offline. The request is sent again once the
  network is back, so treat it as "waiting", not as a final error.
- **`onError` fires for every failed attempt** of a request with retries. `details.willRetry` tells whether another
  attempt is coming, so show the final error only when it is `false`.

```tsx title="Show only the final error"
onError(({ response, details }) => {
  if (!details.willRetry) toast(response.error.message);
});
onRetry(({ retry, delay }) => setStatus(`Retry ${retry} in ${delay / 1000}s`));
```

## Callbacks or returned state

| Use                                  | For                                                              |
| ------------------------------------ | ---------------------------------------------------------------- |
| Returned `data`, `loading`, `error`  | Rendering. They re-render the component                          |
| Callbacks                            | Side effects: toasts, analytics, navigation, writing other state |

`useFetch` callbacks fire for every response on the hook's cache key, also for requests sent by other components or by
`client.cache.invalidate`. A toast in `onSuccess` of a list shown in three components fires three times, so put
one-off side effects in one component, or use [`useSubmit`](/docs/guides/react/basics/submitting), whose callbacks fire
only for its own submits.

---

:::success Congratulations!

You can now run side effects at each stage of a request.

- You can register **`onRequestStart`**, **`onSuccess`**, **`onError`** and **`onFinished`** in the render body.
- You can tell **aborts** and **offline errors** apart from real errors.
- You can show only the **final error** of a retried request with `details.willRetry`.
- You know that `useFetch` callbacks also fire for **other components' requests**.

:::
