# Request Queues

A queued request waits for the previous one with the same query key and runs one at a time, in order. This guide builds
a file upload queue: [`useSubmit`](/docs/react/hooks/use-submit) adds uploads, [`useQueue`](/docs/react/hooks/use-queue)
shows each one with its progress, and the user can stop, pause or resume the queue.

:::secondary What you'll learn

1.  How to send requests **one by one** with `setQueued(true)`.
2.  How to show **queued requests and their progress** with `useQueue`.
3.  How to **stop, pause and start** the queue or a single request.
4.  When a queue fits, and when **cancelable** or **deduplicated** requests fit better.

:::

---

## Send requests one by one

Mark the request as queued. Every `submit()` adds a request to the queue of its query key, and the dispatcher sends the
next one when the previous one finishes.

```ts title="api/files.ts"
export const uploadFile = client
  .createRequest<{ response: { url: string }; payload: FormData }>()({ endpoint: "/files", method: "POST" })
  .setQueued(true);
```

---

## Show the queue with useQueue

`useQueue` follows the queue of a request and returns its `requests`, each with `uploading` and `downloading` progress
and `success`, `failed` and `canceled` flags. Finished requests leave the list, unless `keepFinishedRequests` is `true`.

```tsx title="components/upload-queue.tsx"
import { useSubmit, useQueue } from "@hyper-fetch/react";
import { uploadFile } from "../api/files";

export function UploadQueue() {
  const { submit } = useSubmit(uploadFile);
  const { requests, stopped, stop, start } = useQueue(uploadFile, { keepFinishedRequests: true });

  const onFiles = (event: React.ChangeEvent<HTMLInputElement>) => {
    Array.from(event.target.files ?? []).forEach((file) => {
      const payload = new FormData();
      payload.append("file", file);
      submit({ payload });
    });
  };

  return (
    <div className="border rounded-md p-4">
      <input type="file" multiple onChange={onFiles} />
      <button onClick={stopped ? start : stop}>{stopped ? "Start" : "Stop"}</button>
      {requests.map((item) => (
        <div key={item.requestId} className="py-2 border-b">
          <span>{item.success ? "Done" : item.failed ? "Failed" : item.stopped ? "Stopped" : "Waiting"}</span>
          <progress value={item.uploading.progress} max={100} />
          {!item.success && <button onClick={item.deleteRequest}>Remove</button>}
        </div>
      ))}
    </div>
  );
}
```

`useQueue` picks the dispatcher from the request method: the fetch dispatcher for `GET`, the submit dispatcher for the
other methods. For a `GET` sent with `useSubmit`, pass `{ dispatcherType: "submit" }`.

## Stop, pause and start

| Control                  | Effect                                                              |
| ------------------------ | ------------------------------------------------------------------- |
| `stop()`                 | Stops the queue and cancels the requests in progress                |
| `pause()`                | Lets the requests in progress finish, holds the next ones           |
| `start()`                | Resumes the queue                                                   |
| `item.stopRequest()`     | Stops one request, and cancels it when it is running                |
| `item.startRequest()`    | Resumes a stopped request                                           |
| `item.deleteRequest()`   | Removes one request from the queue                                  |

The queue lives in the client's dispatcher, not in the component, so it keeps running when the component unmounts and
shows its current state when it mounts again.

---

## Queue, cancel or deduplicate

| You want                                                  | Use                                                            |
| --------------------------------------------------------- | -------------------------------------------------------------- |
| Every call sent, in order, one at a time                  | `setQueued(true)`                                              |
| Only the latest call matters, older ones are aborted      | `setCancelable(true)`                                          |
| Identical calls at the same time share one request        | `setDeduplicate(true)`                                         |
| Calls made offline are sent once the network is back      | Default behavior, see [offline](/docs/guides/core/advanced/offline) |

Queued uploads of different endpoints run in parallel, because each query key has its own queue.
