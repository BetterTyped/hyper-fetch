# Mutations in React with useSubmit

A mutation changes data on the server: create, update or delete. It runs when the user acts, so it needs a manual
trigger, a `submitting` flag, a result to act on and a way to refresh the data it changed. In HyperFetch,
[`useSubmit`](/docs/react/hooks/use-submit) does this; [`useFetch`](/docs/guides/react/basics/fetching) is only for
reading.

:::secondary What you'll learn

1.  How to submit a **form** and act on the awaited result.
2.  How to pass **params and payload** to update and delete requests.
3.  How to **refresh other data** after a mutation: refetch, invalidate or write to the cache.
4.  How to **prevent double submits** with the hook and the request.
5.  How `useSubmit` maps to React Query's **`useMutation`**.

:::

## Submit a form

`submit()` sends a copy of the request with the values you pass and resolves with the response. It never rejects: HTTP
errors come back in `response.error`, so check `response.success` instead of using `try`/`catch`.

```tsx title="components/add-todo.tsx"
import { useState } from "react";
import { useSubmit } from "@hyper-fetch/react";
import { client } from "../api/client";
import { createTodo, getTodos } from "../api/todos";

export function AddTodo() {
  const [title, setTitle] = useState("");
  const { submit, submitting, error } = useSubmit(createTodo);

  const onSubmit = async (event: React.FormEvent) => {
    event.preventDefault();
    const response = await submit({ payload: { title, completed: false } });

    if (response.success) {
      setTitle("");
      // Every mounted useFetch(getTodos) sends again
      client.cache.invalidate(getTodos);
    }
  };

  return (
    <form onSubmit={onSubmit} className="flex gap-2">
      <input
        value={title}
        onChange={(e) => setTitle(e.target.value)}
        placeholder="What needs to be done?"
      />
      <button type="submit" disabled={submitting}>
        {submitting ? "Adding..." : "Add"}
      </button>
      {error && <p className="text-red-500">{error.message}</p>}
    </form>
  );
}
```

The state field is `submitting`, not `loading`. `data` and `error` hold the result of the last submit of this hook.

## Update and delete with params

Requests with URL params, such as `/todos/:todoId`, take them in `submit()`. TypeScript requires every value the request
does not have yet, so a missing `todoId` is a compile error.

```tsx title="components/todo-item.tsx"
function TodoItem({ todo }: { todo: Todo }) {
  const { submit: update } = useSubmit(updateTodo);
  const { submit: remove, submitting: removing } = useSubmit(deleteTodo);

  return (
    <li className="flex justify-between">
      <span
        onClick={() =>
          update({
            params: { todoId: todo.id },
            payload: { completed: !todo.completed },
          })
        }
      >
        {todo.title}
      </span>
      <button
        onClick={() => remove({ params: { todoId: todo.id } })}
        disabled={removing}
      >
        Delete
      </button>
    </li>
  );
}
```

One hook per action keeps each `submitting` flag separate. The request passed to the hook is never changed by
`submit()`.

## Refresh the data a mutation changed

A mutation has its own cache key, so a list that shows the changed item does not update by itself. Pick one of these:

```tsx title="Three ways to refresh"
const { submit, onSubmitSuccess } = useSubmit(createTodo);

onSubmitSuccess(({ response }) => {
  // 1. Refetch every mounted useFetch(getTodos), across components
  client.cache.invalidate(getTodos);

  // 2. Or write the result into the cached list, without a request
  client.cache.update(getTodos, (cached) => ({
    data: [...(cached?.data ?? []), response.data],
  }));
});

// 3. Or refetch only in this component: const { refetch } = useFetch(getTodos)
```

- **Invalidate** when the server may change more than the item, such as sorting or counters.
- **Update the cache** when the response is the full new item and you want no extra request.
- **`refetch()`** from `useFetch` refreshes one component only. `useSubmit().refetch()` invalidates the mutation's own key,
  not the list.

To show the change before the server answers, use [optimistic updates](/docs/guides/react/basics/optimistic-approach).
To refresh even after the form unmounted, declare it on the request with
`setOptimistic(() => ({ invalidate: [getTodos] }))`.

## Callbacks or the awaited result

Use the awaited result for logic tied to one call site, such as closing a dialog. Use callbacks for logic that applies
to every submit of the hook. Callbacks receive one object, fire only for this hook's submits, and fire in this order:
`onSubmitRequestStart`, then success, error, abort or offline error, then `onSubmitFinished`.

```tsx title="components/contact-form.tsx"
const { submit, onSubmitSuccess, onSubmitError, onSubmitFinished } =
  useSubmit(sendMessage);

onSubmitSuccess(() => toast("Message sent"));
onSubmitError(({ response, details }) => {
  // With retries, onSubmitError fires for every failed attempt
  if (!details.willRetry) toast(response.error.message);
});
onSubmitFinished(({ response }) => console.log("Done", response.success));
```

## Prevent double submits

Disabling the button with `submitting` covers most forms. For rapid calls, choose by what should happen:

| Behavior                                      | Set                                     |
| --------------------------------------------- | --------------------------------------- |
| Send only the last call within a time window  | `useSubmit(request, { bounce: true })`  |
| Abort the previous call when a new one starts | `request.setCancelable(true)`           |
| Send calls one at a time, in order            | `request.setQueued(true)`               |
| Share one request between identical calls     | `request.setDeduplicate(true)`          |

The [queues guide](/docs/guides/react/basics/queues) shows queued mutations with `useQueue`.

## useSubmit and useMutation

`useSubmit` fills the spot of React Query's `useMutation`. It takes a request that already knows its endpoint, method and
types, instead of a `mutationFn`.

| React Query `useMutation`            | HyperFetch `useSubmit`                                    |
| ------------------------------------ | --------------------------------------------------------- |
| `mutationFn: (vars) => fetch(...)`   | `useSubmit(createTodo)`                                   |
| `mutate(vars)` / `mutateAsync(vars)` | `submit({ payload, params, queryParams })`                |
| `mutateAsync` throws on error        | `submit` resolves with `{ data, error, success }`         |
| `isPending`                          | `submitting`                                              |
| `onMutate`                           | `setOptimistic` on the request                            |
| `onSuccess`, `onError`, `onSettled`  | `onSubmitSuccess`, `onSubmitError`, `onSubmitFinished`    |
| `invalidateQueries` in `onSuccess`   | `client.cache.invalidate(getTodos)`                       |
