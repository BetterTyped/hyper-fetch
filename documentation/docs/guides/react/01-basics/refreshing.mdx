# Auto-Refreshing Data

Dashboards, scores and job statuses go stale while they are on screen. This guide keeps them fresh with polling in
[`useFetch`](/docs/react/hooks/use-fetch), pauses it in background tabs, and refreshes on demand from a button or
another component.

:::secondary What you'll learn

1.  How to **poll** a request with `refresh` and `refreshTime`.
2.  How to **pause polling** in background tabs with `refetchBlurred`.
3.  How to show **when the data was updated** with `responseTimestamp`.
4.  How to **refresh on demand** with `refetch()` and cache invalidation.

:::

---

## Poll with refresh

Set `refresh: true` and an interval in `refreshTime`, default `Time.HOUR`. The [`Time`](/docs/api/core/Enums/Time)
enum from `@hyper-fetch/core` keeps intervals readable. `responseTimestamp` is the `Date` of the last response, so the
UI can show its age without extra state.

```tsx title="components/live-activity.tsx"
import { Time } from "@hyper-fetch/core";
import { useFetch } from "@hyper-fetch/react";
import { getActivities } from "../api/activities";

export function LiveActivity() {
  // highlight-start
  const { data: activities, loading, responseTimestamp } = useFetch(getActivities, {
    refresh: true,
    refreshTime: Time.SEC * 5,
  });
  // highlight-end

  return (
    <div className="border rounded-md">
      <div className="p-4 border-b flex justify-between">
        <h2 className="text-xl font-bold">Live activity</h2>
        <p className="text-sm text-gray-500">Updated {responseTimestamp?.toLocaleTimeString() ?? "-"}</p>
      </div>
      {loading && !activities && <p className="p-4">Loading feed...</p>}
      <ul className="divide-y">
        {activities?.map((activity) => (
          <li key={activity.id} className="p-4">
            {activity.name}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

- A tick is skipped when the same request is already running or queued, so slow responses never stack up.
- Every component with the same request shares the response, even when only one of them polls.
- Changing `refreshTime`, `disabled` or the request restarts the countdown.

## Pause polling in background tabs

Polling continues while the window is blurred, default `refetchBlurred: true`. Turn it off to save requests and battery,
and add `refetchOnFocus` so the data is fresh the moment the user comes back.

```tsx title="Poll only while the tab is visible"
const { data } = useFetch(getStats, {
  refresh: true,
  refreshTime: Time.SEC * 10,
  refetchBlurred: false,
  refetchOnFocus: true,
});
```

The [window focus and blur guide](/docs/guides/react/basics/window-focus-blur) covers focus and reconnect refetching.

---

## Refresh on demand

`refetch()` sends the request at once and restarts the polling countdown, so a scheduled tick never fires right after a
manual refresh. It bypasses deduplication, so the response is at least as new as the click.

```tsx title="Refresh button"
const { data, refetch, loading } = useFetch(getActivities, { refresh: true, refreshTime: Time.MIN });

return (
  <button onClick={refetch} disabled={loading}>
    Refresh now
  </button>
);
```

To refresh from somewhere else, such as after a mutation or a socket event, invalidate the cache. Every mounted
`useFetch` with that request sends again.

```ts title="Refresh from outside the component"
client.cache.invalidate(getActivities);
```

## Polling or realtime

| Situation                                                      | Use                                                        |
| -------------------------------------------------------------- | ---------------------------------------------------------- |
| Data changes every few seconds to minutes, a delay is fine     | `refresh` with `refreshTime`                               |
| Data must appear the moment it changes                         | [A socket listener](/docs/guides/react/sockets/listening)  |
| Data changes after the user's own action                       | Invalidate after the [mutation](/docs/guides/react/basics/submitting) |
| Data only needs to be fresh when the user looks at it          | `refetchOnFocus` without polling                           |

Short intervals multiply with users: 1,000 open tabs polling every second is 1,000 requests per second. Pick the longest
interval the screen can live with, and pause it in the background.
