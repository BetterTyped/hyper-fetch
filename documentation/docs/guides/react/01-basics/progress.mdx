# File Upload Progress Bar in React

A progress bar needs a transport that reports how many bytes have moved, and a component that turns those numbers into
a bar. This guide explains why `fetch` cannot report upload progress, which adapter can, and how to build upload and
download bars with the progress callbacks of [`useSubmit`](/docs/react/hooks/use-submit) and
[`useFetch`](/docs/react/hooks/use-fetch).

:::secondary What you'll learn

1.  Why the **Fetch API** has no upload progress event, and what **XMLHttpRequest** does differently.
2.  Which adapter reports **real upload progress**.
3.  What the **progress event** contains: percent, bytes and time left.
4.  How to build an **upload progress bar** with `onSubmitUploadProgress`.
5.  How to show **download progress** and cancel a transfer.

:::

## Why fetch cannot report upload progress

The Fetch API has no progress event. [MDN's fetch guide](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)
shows how to read the **response** body as a stream, chunk by chunk, which is enough for download progress. There is no
matching hook for the **request** body. Once you pass a `File` or `FormData` to `fetch()`, the browser sends it and you
only hear back when the response arrives.

`XMLHttpRequest` is different. It exposes an
[`xhr.upload`](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest/upload) object that fires `progress`
events while the body is being sent, each with `loaded` and `total` byte counts. That is what most upload progress bars
on the web run on, including the one in Axios.

Streaming a `ReadableStream` as the request body doesn't fix this in practice. Chrome added it in Chromium 105, and it
requires `duplex: "half"` and an HTTP/2 or HTTP/3 connection
([Chrome's write-up](https://developer.chrome.com/docs/capabilities/web-apis/fetch-streaming-requests)). Counting bytes
as you enqueue them also tells you what you handed to the browser, not what reached the server.

| Transport            | Upload progress          | Download progress               |
| -------------------- | ------------------------ | ------------------------------- |
| `fetch()`            | No progress event        | Yes, by reading the body stream |
| `XMLHttpRequest`     | Yes, `xhr.upload` events | Yes, `progress` events          |
| Axios (in a browser) | Yes, built on XHR        | Yes                             |

## How HyperFetch reports upload progress

HyperFetch normalizes progress for every adapter into one shape. The adapter reports raw `loaded` and `total` numbers,
and the core turns them into a `ProgressType` object that your callbacks receive:

| Field            | Meaning                                          |
| ---------------- | ------------------------------------------------ |
| `progress`       | Percentage from 0 to 100, rounded                |
| `loaded`         | Bytes transferred so far                         |
| `total`          | Total bytes                                      |
| `sizeLeft`       | Bytes still to go                                |
| `timeLeft`       | Estimated milliseconds left, `null` when unknown |
| `startTimestamp` | When the transfer started, in milliseconds       |

The event also carries `request` and `requestId`, so you can tell parallel uploads apart.

What fills those numbers depends on the adapter:

- The default `HttpAdapter` uses `fetch`. Download progress is real: it reads the response body stream and reports each
  chunk against the `content-length` header. A compressed response (`content-encoding: gzip` and the like) has no known
  total, because `content-length` counts the compressed bytes. There `total` follows `loaded`, so show the `loaded`
  bytes instead of a percentage. Upload progress is a start event and a finish event, so the bar jumps from 0 to 100.
- The [Axios adapter](/docs/integrations/adapter-axios/overview) wires Axios's `onUploadProgress` into Hyper
  Fetch. In a browser Axios runs on XHR, so you get real upload progress while the file is in flight.

For a file upload progress bar, switch the client to Axios. Your requests and hooks don't change:

```ts title="api/client.ts"
import { Client } from "@hyper-fetch/core";
import { AxiosAdapter } from "@hyper-fetch/axios";

// highlight-start
export const client = new Client({ url: "https://api.example.com" }).setAdapter(
  AxiosAdapter,
);
// highlight-end

export const uploadAvatar = client.createRequest<{
  response: { url: string };
  payload: FormData;
}>()({
  method: "POST",
  endpoint: "/avatar",
});
```

`FormData`, `Blob` and `ArrayBuffer` payloads are sent as they are. HyperFetch doesn't JSON-encode them and doesn't set
a `Content-Type` header, so the browser writes the multipart boundary itself.

## Upload file with progress bar: a component

Here is a small file input with a progress bar. It reads the progress event straight into state and renders the bar
width from `progress`.

```tsx title="components/avatar-upload.tsx"
import { useState } from "react";
import { useSubmit } from "@hyper-fetch/react";
import { uploadAvatar } from "./api";

export function AvatarUpload() {
  const [progress, setProgress] = useState(0);
  const [timeLeft, setTimeLeft] = useState<number | null>(null);

  const { submit, submitting, error, onSubmitUploadProgress } =
    useSubmit(uploadAvatar);

  // highlight-start
  onSubmitUploadProgress((event) => {
    setProgress(event.progress);
    setTimeLeft(event.timeLeft);
  });
  // highlight-end

  const handleChange = (event: React.ChangeEvent<HTMLInputElement>) => {
    const file = event.target.files?.[0];
    if (!file) return;

    const formData = new FormData();
    formData.append("file", file);

    setProgress(0);
    submit({ payload: formData });
  };

  return (
    <div className="space-y-2">
      <input type="file" onChange={handleChange} disabled={submitting} />
      <div className="h-2 w-full rounded-full bg-gray-200">
        <div
          className="h-2 rounded-full bg-blue-600"
          style={{ width: `${progress}%` }}
        />
      </div>
      <p className="text-sm">
        {progress}%
        {timeLeft !== null && submitting
          ? `, about ${Math.ceil(timeLeft / 1000)}s left`
          : ""}
      </p>
      {error && <p className="text-sm text-red-500">Upload failed</p>}
    </div>
  );
}
```

A few details that matter in a real form:

- Reset the bar before each `submit`, or a second upload starts from 100%.
- Check `timeLeft` for `null`. The estimate needs at least one progress event with a known total.
- Pair the bar with `abort()` from the same hook for a cancel button. See
  [request cancellation](/docs/guides/core/advanced/cancellation).

You can also pass the callback per call, which is handy outside React:

```ts title="Progress without React"
await uploadAvatar.send({
  payload: formData,
  onUploadProgress: ({ progress }) => console.log(`${progress}% uploaded`),
});
```

## Download progress

Download progress works with every adapter, including the default one. Use `onSubmitDownloadProgress` for a download
started by a click, or `onDownloadProgress` on `useFetch` for data loaded on mount.

```tsx title="components/report-download.tsx"
// getReport = client.createRequest<{ response: Blob }>()({ endpoint:
// "/reports/latest" })
export function ReportDownload() {
  const [loaded, setLoaded] = useState({ progress: 0, bytes: 0 });
  const { submit, submitting, abort, onSubmitDownloadProgress } =
    useSubmit(getReport);

  onSubmitDownloadProgress(({ progress, loaded: bytes }) =>
    setLoaded({ progress, bytes }),
  );

  return (
    <div className="space-y-2">
      <button onClick={() => submit()} disabled={submitting}>
        Download report
      </button>
      {submitting && <button onClick={abort}>Cancel</button>}
      <progress value={loaded.progress} max={100} />
      <p className="text-sm">{Math.round(loaded.bytes / 1024)} KB</p>
    </div>
  );
}
```

:::caution Upload progress with the default adapter

The default HTTP adapter uses `fetch`, which has no upload events. It reports `0%` when the request starts and `100%`
once the response arrives. For `FormData` and stream bodies, `loaded` and `total` are not byte counts. For a live upload
percentage, use the [Axios adapter](/docs/integrations/adapter-axios/overview).

:::

## Which transport to use

| You need                                         | Use                                               |
| ------------------------------------------------ | ------------------------------------------------- |
| Download progress                                | Any adapter, the default `fetch` one included     |
| A live upload percentage in the browser          | The Axios adapter                                 |
| Only "uploading" and "done" states               | The default adapter and `submitting`              |
| Several uploads, one after another               | A [queue](/docs/guides/react/basics/queues) with `useQueue` progress |
