# Socket Emitting

[`useEmitter`](/docs/react/sockets/use-emitter) gives a component an `emit` function for one topic, plus the connection
state. This guide sends chat messages from a form, handles messages that could not be sent, and gets a reply from the
server.

:::secondary What you'll learn

1.  How to **send a message** from a form with `emit`.
2.  How to pass **topic params** per component or per call.
3.  How to handle **failed sends** with `onEmitError`.
4.  How to get a **server reply** with a listener and a correlation id.

:::

---

## Send from a form

`emit` takes `{ payload, params }`, typed by the emitter. It returns `void`: there is no acknowledgement, and nothing is
queued while the socket is offline. Disable the send button while `connected` is `false`.

```tsx title="components/chat-input.tsx"
import { useState } from "react";
import { useEmitter } from "@hyper-fetch/react";
import { sendChatMessage } from "../api/socket"; // socket.createEmitter<{ text: string }>()({ topic: "rooms/:roomId" })

export function ChatInput({ roomId }: { roomId: string }) {
  const [text, setText] = useState("");
  const [warning, setWarning] = useState<string | null>(null);
  // highlight-next-line
  const { emit, connected, onEmitError } = useEmitter(sendChatMessage.setParams({ roomId }));

  onEmitError(({ error }) => setWarning(`Not sent: ${error.message}`));

  const onSubmit = (event: React.FormEvent) => {
    event.preventDefault();
    if (!text) return;
    // highlight-next-line
    emit({ payload: { text } });
    setText("");
  };

  return (
    <form onSubmit={onSubmit} className="flex gap-2">
      <input value={text} onChange={(e) => setText(e.target.value)} placeholder="Write a message..." />
      <button type="submit" disabled={!connected}>
        Send
      </button>
      {warning && <p className="text-red-500">{warning}</p>}
    </form>
  );
}
```

`setParams` in render fills the topic for every emit of this component. To choose the room per call, pass it in
`emit({ payload, params: { roomId } })` instead. Params the emitter does not have yet are required by the types.

## Handle failed sends

A message is dropped, not queued, when the socket is not connected or the payload cannot be encoded. `onEmitError`
receives `{ error }` for every dropped message of this topic. `onEmit` receives the emitter when a message starts
sending, which is a good place for logging.

| Situation                                   | What to do                                                       |
| ------------------------------------------- | ---------------------------------------------------------------- |
| The user can retry, such as a chat message  | Keep the text in the input and show a warning in `onEmitError`   |
| The message must arrive, such as an order   | Send it as an HTTP request with [`useSubmit`](/docs/guides/react/basics/submitting) |
| A stream of updates, such as a cursor       | Drop failed ones; the next update replaces them                  |

## Get a reply from the server

Emitters have no acknowledgement callback. When the server must answer, it sends the answer on another topic. Put an id
in the payload and match it in a [`useListener`](/docs/guides/react/sockets/listening) on the reply topic.

```tsx title="components/save-draft.tsx"
export function SaveDraft({ draft }: { draft: Draft }) {
  const [pendingId, setPendingId] = useState<string | null>(null);
  const { emit, connected } = useEmitter(saveDraft);
  const { onEvent } = useListener(onDraftSaved); // topic "drafts/saved", data: { requestId: string }

  onEvent(({ data }) => {
    if (data.requestId === pendingId) setPendingId(null);
  });

  const save = () => {
    const requestId = crypto.randomUUID();
    setPendingId(requestId);
    emit({ payload: { requestId, draft } });
  };

  return (
    <button onClick={save} disabled={!connected || !!pendingId}>
      {pendingId ? "Saving..." : "Save draft"}
    </button>
  );
}
```

## Emit or HTTP request

| Use                                                       | For                                               |
| --------------------------------------------------------- | ------------------------------------------------- |
| `useEmitter`                                              | Chat messages, typing indicators, cursors, presence |
| [`useSubmit`](/docs/guides/react/basics/submitting)       | Writes that need a response, retries, offline queueing or a status code |

A common split: writes go over HTTP, and the server broadcasts the result to every client over the socket.

- You can get a **reply** through a listener and a correlation id.
