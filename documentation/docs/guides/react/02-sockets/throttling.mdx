# Throttling & Batching in React

With [`useListener`](/docs/react/sockets/use-listener), every delivered message is a state update and a render. On a
stream of hundreds of messages per second, configure a `delivery` strategy on the listener; the hook then receives
fewer, grouped updates with no options and no throttling in effects.

:::secondary What you'll learn

1.  How a **`latest`** listener turns a price firehose into one render per frame.
2.  How a **`batch`** listener delivers arrays so you can append many rows in one state update.
3.  How to let the user **choose the refresh rate** with `setDelivery` and `useMemo`.
4.  Why **custom strategies** must live at module level.

:::

The framework-agnostic [throttling and batching guide](/docs/guides/sockets/throttling) explains the strategies with
timelines. This page covers the React side.

---

## Sampling a price ticker

Define the listener with a `latest` strategy. `useListener` needs no changes: `data` is the newest price of the last
window.

```ts title="api/socket.ts"
export const onPrice = socket.createListener<Price>()({
  topic: "prices",
  // highlight-next-line
  delivery: { strategy: "latest", interval: 16 },
});
```

```tsx title="PriceTicker.tsx"
import { useListener } from "@hyper-fetch/react";
import { onPrice } from "./api/socket";

export function PriceTicker() {
  // Renders at most about 60 times per second, however fast the server sends
  // highlight-next-line
  const { data, connected } = useListener(onPrice);

  if (!connected) return <span>Connecting...</span>;
  return <span>{data ? data.value.toFixed(2) : "-"}</span>;
}
```

## Batching a trade log

With `batch`, `data` and the `onEvent` payload are **arrays**, typed automatically as `Trade[]`. Append the whole batch
in a single state update.

```ts title="api/socket.ts"
export const onTrade = socket.createListener<Trade>()({
  topic: "trades",
  // highlight-next-line
  delivery: { strategy: "batch", interval: 100, maxSize: 500 },
});
```

```tsx title="TradeLog.tsx"
import { useState } from "react";
import { useListener } from "@hyper-fetch/react";
import { onTrade } from "./api/socket";

export function TradeLog() {
  const [trades, setTrades] = useState<Trade[]>([]);
  const { onEvent } = useListener(onTrade);

  onEvent(({ data }) => {
    // data is Trade[]: one state update per window instead of one per trade
    // highlight-next-line
    setTrades((previous) => [...previous, ...data].slice(-1000));
  });

  return (
    <ul>
      {trades.map((trade) => (
        <li key={trade.id}>
          {trade.symbol} {trade.price}
        </li>
      ))}
    </ul>
  );
}
```

## Letting the user pick the refresh rate

`setDelivery` returns a new listener. Memoize it on the user's choice and pass it to `useListener`; the hook
re-subscribes when the delivery changes and disposes the previous window.

```tsx title="PriceTicker.tsx"
import { useMemo, useState } from "react";
import { useListener } from "@hyper-fetch/react";
import { onPrice } from "./api/socket";

export function PriceTicker() {
  const [rate, setRate] = useState(16);
  // A new listener only when rate changes, not on every render
  // highlight-start
  const live = useMemo(
    () => onPrice.setDelivery({ strategy: "latest", interval: rate }),
    [rate],
  );
  // highlight-end
  const { data } = useListener(live);

  return (
    <>
      <select
        value={rate}
        onChange={(event) => setRate(Number(event.target.value))}
      >
        <option value={16}>Realtime</option>
        <option value={250}>Relaxed</option>
        <option value={1000}>Slow</option>
      </select>
      <span>{data?.value ?? "-"}</span>
    </>
  );
}
```

## Keep custom strategies at module level

`useListener` decides whether to re-subscribe by comparing the listener's `topic`, `options` and `delivery`:

- **Preset objects** (`{ strategy: "latest", interval: 16 }`) are compared **by value**. Writing them inline is fine.
- **Custom strategies** are compared **by identity**. Define them at module level, next to your listeners. A
  strategy created inside a component is a new function on every render and would re-subscribe each time, dropping
  whatever was buffered.

```ts title="api/socket.ts"
// Module level: a stable identity
export const summarize = createDeliveryStrategy<Trade, Summary>(/* ... */);
export const onTradeSummary = socket.createListener<Trade>()({
  topic: "trades",
  delivery: summarize,
});
```

:::success Congratulations!

You can now keep React UIs smooth on the busiest streams.

- You can cap renders at a chosen rate with a **`latest`** listener.
- You can append arrays in one state update with a **`batch`** listener.
- You can let the user control the rate with **`setDelivery`** and `useMemo`.
- You can keep custom strategies at **module level** for a stable identity.

:::
