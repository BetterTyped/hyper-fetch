# Socket Listening

[`useListener`](/docs/react/sockets/use-listener) subscribes a component to a socket topic while it is mounted and
unsubscribes on unmount. This guide shows three ways to use the messages: keep a list in state, write them into the
HTTP cache, or render only the latest value, plus how to show the connection state.

:::secondary What you'll learn

1.  How to **collect messages** into component state with `onEvent`.
2.  How to listen to **one room or resource** with topic params.
3.  How to **update the HTTP cache** from socket messages.
4.  How to show **connection and reconnect state**.
5.  When to use **`data`**, **`onEvent`** or the cache.

:::

---

## Collect messages in state

`data` holds only the latest message, so keep a list in state when you need history. `onEvent` fires for every
message with `{ data, extra }`.

```tsx title="components/chat-room.tsx"
import { useState } from "react";
import { useListener } from "@hyper-fetch/react";
import { onChatMessage } from "../api/socket"; // socket.createListener<ChatMessage>()({ topic: "rooms/:roomId" })

export function ChatRoom({ roomId }: { roomId: string }) {
  const [messages, setMessages] = useState<ChatMessage[]>([]);
  // setParams in render is fine: the hook subscribes again only when the topic changes
  const { connected, onEvent } = useListener(onChatMessage.setParams({ roomId }));

  onEvent(({ data }) => {
    setMessages((previous) => [...previous, data].slice(-200));
  });

  return (
    <div className="flex flex-col gap-2">
      {!connected && <p className="text-sm text-gray-500">Connecting...</p>}
      {messages.map((message) => (
        <p key={message.id}>
          <span className="font-bold">{message.author}:</span> {message.text}
        </p>
      ))}
    </div>
  );
}
```

- Each `roomId` is its own topic. Changing the prop subscribes to the new room and drops the old one.
- Keep the list bounded, as with `.slice(-200)`, so a long session does not grow memory without limit.
- There is no `disabled` option. To stop listening, stop rendering the component.

## Render only the latest value

For state-like data, such as a status, a score or a price, the latest message is all you need. Read `data` and skip
local state. `select` narrows it, so the component re-renders only when its part changes.

```tsx title="components/order-status.tsx"
function OrderStatus({ orderId }: { orderId: string }) {
  const { data: status } = useListener(onOrderUpdate.setParams({ orderId }), { select: (order) => order.status });

  return <span className="font-semibold">{status ?? "Waiting for updates"}</span>;
}
```

## Update the HTTP cache from messages

When the same data is also loaded over HTTP with [`useFetch`](/docs/react/hooks/use-fetch), write each message into the
request's cache. Every component that shows it updates, with no refetch and no duplicated state.

```tsx title="components/notes-sync.tsx"
import { client } from "../api/client";
import { getNote } from "../api/notes"; // client.createRequest<{ response: Note }>()({ endpoint: "/notes/:noteId" })

export function NotesSync() {
  const { onEvent } = useListener(onNoteChange);

  onEvent(({ data }) => {
    client.cache.update(getNote.setParams({ noteId: data.id }), { data });
  });

  return null;
}
```

Render it once near the root, so the cache stays in sync on every screen. When a message only says "something changed",
call `client.cache.invalidate(getNotes)` instead and let the mounted hooks refetch.

## Show connection state

`connected` and `connecting` are shared by every hook on the same socket. The callbacks fire on connection changes,
and the socket reconnects on its own.

```tsx title="components/connection-banner.tsx"
export function ConnectionBanner() {
  const [message, setMessage] = useState<string | null>(null);
  const { connected, onReconnecting, onReconnectingFailed, onConnected } = useListener(onChatMessage);

  onReconnecting(({ attempts }) => setMessage(`Reconnecting (attempt ${attempts})`));
  onReconnectingFailed(() => setMessage("Connection lost. Refresh the page to try again."));
  onConnected(() => setMessage(null));

  return connected ? null : <p className="bg-yellow-100 p-2">{message ?? "Connecting..."}</p>;
}
```

## Which approach to use

| Data                                              | Use                                           |
| ------------------------------------------------- | --------------------------------------------- |
| A stream of events: chat, logs, notifications     | `onEvent` into a bounded list in state        |
| State that changes: a status, a score, a price    | `data`, narrowed with `select`                |
| Records also loaded over HTTP                     | `onEvent` with `client.cache.update`          |
| Hundreds of messages per second                   | A [delivery strategy](/docs/guides/react/sockets/throttling) on the listener |
