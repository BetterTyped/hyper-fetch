# Emitting Events

An [emitter](/docs/sockets/emitter) sends typed messages to one topic over a WebSocket. This guide sends payloads, fills
topic params, transforms payloads before sending, handles messages that could not be sent and gets replies from the
server. In React, use the [emitting in React](/docs/guides/react/sockets/emitting) guide.

:::secondary What you'll learn

1.  How to **send a payload** with `emit()` or `setPayload()`.
2.  How to use **topic params** for rooms and users.
3.  How to **transform payloads** with `setPayloadMapper`.
4.  How to detect **dropped messages** with emitter errors.
5.  How to get a **reply from the server** without acknowledgements.

:::

---

## Send a payload

Create the emitter once with the payload type, then pass the payload to `emit()`.

```ts title="src/api/chat.ts"
import { socket } from "./socket";

export const sendChatMessage = socket.createEmitter<{ text: string }>()({
  topic: "chat",
});

sendChatMessage.emit({ payload: { text: "Hello" } });
```

`setPayload()` returns a new emitter with the payload set, so `emit()` needs no arguments. It suits a message prepared in
one place and sent from another. A payload passed to `emit()` wins over one set with `setPayload()`.

```ts title="Prepared message"
const ping = sendChatMessage.setPayload({ text: "ping" });

ping.emit();
```

Messages are sent in call order. `emit()` returns `void`: there is no acknowledgement and no promise.

## Fill topic params

Put params in the topic with a colon. Pass them in `emit()` or set them with `setParams()`; until they are set, the
types require them.

```ts title="src/api/direct-messages.ts"
export const sendDirectMessage = socket.createEmitter<{ text: string }>()({
  topic: "dm/:userId",
});

// Sent to "dm/user-123"
sendDirectMessage.emit({
  params: { userId: "user-123" },
  payload: { text: "Hi" },
});

// Or fill the param once and reuse the emitter
const toAnna = sendDirectMessage.setParams({ userId: "anna" });
toAnna.emit({ payload: { text: "Lunch?" } });
```

## Transform payloads before sending

`setPayloadMapper` runs right before every send, sync or async, and is kept on clones. Use it to add metadata or to
match a server format for one topic.

```ts title="src/api/chat.ts"
export const sendStampedMessage = sendChatMessage.setPayloadMapper((payload) => ({
  ...payload,
  sentAt: Date.now(),
}));
```

To change every outgoing message of a socket, use `socket.onSend` instead, and for a different frame format use
`encode` in the adapter options.

---

## Detect dropped messages

A message is dropped, not queued, when the socket is not connected or the payload mapper or encoding fails. The drop is
reported as an emitter error, never thrown. Listen for it per topic:

```ts title="src/chat-errors.ts"
const off = socket.events.onEmitterErrorByTopic(sendChatMessage, ({ error }) => {
  console.error("Message not sent:", error.message);
});
```

To avoid drops, emit only after the socket is connected, for example from `socket.onConnected()` or when
`socket.adapter.connected` is `true`. For messages that must arrive, send an HTTP request instead: it can retry and wait
for the network.

---

## Get a reply from the server

When the server must answer, it sends the reply on another topic. Put a correlation id in the payload and match it in a
listener.

```ts title="src/join-room.ts"
const sendJoin = socket.createEmitter<{ requestId: string; roomId: string }>()({
  topic: "rooms/join",
});
const onJoinReply = socket.createListener<{ requestId: string; ok: boolean }>()(
  { topic: "rooms/join/reply" },
);

export const joinRoom = (roomId: string) =>
  new Promise<boolean>((resolve) => {
    const requestId = crypto.randomUUID();
    const stop = onJoinReply.listen(({ data }) => {
      if (data.requestId !== requestId) return;
      stop();
      resolve(data.ok);
    });

    sendJoin.emit({ payload: { requestId, roomId } });
  });
```

Add a timeout to the promise in production, so a lost reply does not leave it pending forever.

## Emit or HTTP request

| Message                                                    | Send with                                    |
| ---------------------------------------------------------- | -------------------------------------------- |
| Frequent and disposable: typing, cursors, presence         | An emitter                                   |
| Chat messages the user can resend                          | An emitter, with a dropped-message warning   |
| Writes that must arrive or need a status: orders, payments | An HTTP [request](/docs/core/request)        |
