# Listening to Events

A [listener](/docs/sockets/listener) receives the messages of one topic with a typed `data`. This guide starts and
stops listeners, listens to one room with topic params, handles only the next message, writes messages into the HTTP
cache and observes every topic at once. In React, use the [listening in React](/docs/guides/react/sockets/listening)
guide.

:::secondary What you'll learn

1.  How to **start and stop** a listener and why cleanup matters.
2.  How to listen to **one resource** with topic params.
3.  How to handle **only the next message**.
4.  How to keep the **HTTP cache in sync** with messages.
5.  How to **observe every message** of a socket for logging.

:::

---

## Start and stop listening

`listen()` registers a callback and returns the function that removes it. The callback receives `{ data, extra }`:
`data` is typed by the listener, `extra` holds the adapter's details, such as the `MessageEvent` for WebSocket.

```ts title="src/chat.ts"
import { socket } from "./api/socket";

type ChatMessage = { id: string; author: string; text: string };

// Define once, at module level, and reuse
export const onChatMessage = socket.createListener<ChatMessage>()({ topic: "chat" });

const unlisten = onChatMessage.listen(({ data }) => {
  console.log(`${data.author}: ${data.text}`);
});

// When the screen closes
unlisten();
```

Every `listen()` call is its own subscription with its own remover, so two features can listen to one topic and stop
independently. Passing the same function twice does not add a second subscription. A listener that is never removed
keeps its callback alive for the life of the socket.

## Listen to one room with topic params

Put params in the topic with a colon. `setParams` returns a new listener for the filled topic and leaves the original
unchanged, so always use the returned value.

```ts title="src/rooms.ts"
export const onRoomMessage = socket.createListener<ChatMessage>()({ topic: "rooms/:roomId" });

// Listens on "rooms/general"
const stop = onRoomMessage.setParams({ roomId: "general" }).listen(({ data }) => console.log(data.text));
```

Each param combination is a separate topic, matched exactly, without prefixes or wildcards. A missing or misspelled
param is a type error.

---

## Handle only the next message

Call the remover inside the callback to react once, for example to wait for a "ready" message.

```ts title="src/wait-for-ready.ts"
const onReady = socket.createListener<{ version: string }>()({ topic: "server/ready" });

export const waitForReady = () =>
  new Promise<string>((resolve) => {
    const unlisten = onReady.listen(({ data }) => {
      unlisten();
      resolve(data.version);
    });
  });
```

## Keep the HTTP cache in sync

When the same records are loaded over HTTP, write each message into the matching request's cache. Every `useFetch` or
`send()` reading it gets the new data without a refetch.

```ts title="src/notes-sync.ts"
const getNote = client.createRequest<{ response: Note }>()({ endpoint: "/notes/:noteId" });
const onNoteChange = socket.createListener<Note>()({ topic: "notes" });

onNoteChange.listen(({ data }) => {
  client.cache.update(getNote.setParams({ noteId: data.id }), { data });
});
```

When the message only says that something changed, call `client.cache.invalidate(getNotes)` instead and let the
mounted hooks refetch.

---

## Observe every message

`socket.events.onListenerEvent` receives every incoming message with its `topic`, before any delivery strategy. Use it
for logging and debugging, not for features: it is not typed per topic.

```ts title="src/debug.ts"
const off = socket.events.onListenerEvent(({ topic, data }) => {
  console.debug("[socket]", topic, data);
});
```

## Which approach to use

| Need                                              | Use                                                         |
| ------------------------------------------------- | ----------------------------------------------------------- |
| React to a topic for a while                      | `listen()` and call the remover on cleanup                  |
| One room, user or resource                        | `setParams(...).listen()`                                   |
| Wait for one message                              | Call the remover inside the callback                        |
| Data that is also loaded over HTTP                | `client.cache.update` in the callback                       |
| Hundreds of messages per second                   | A [delivery strategy](/docs/guides/sockets/throttling)      |
| tRPC, oRPC or GraphQL subscriptions with input    | `setPayload` on the listener, see the [Listener](/docs/sockets/listener#start-a-server-side-subscription-with-a-payload) docs |
| Logging every message                             | `socket.events.onListenerEvent`                             |
