# Setup

This guide sets up realtime communication with `@hyper-fetch/sockets`: one socket for the server connection, a typed
listener for incoming messages and an emitter for outgoing ones. It ends with the socket SDK, for apps with many topics.

:::secondary What you'll learn

1.  How to create a **socket** for a WebSocket or Server-Sent Events server.
2.  How to define a typed **listener** and an **emitter**.
3.  How the default **message format** looks on the wire.
4.  When to switch to the **socket SDK**.

:::

---

## Install and create the socket

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/sockets
```

A [socket](/docs/sockets/socket) owns one connection. Create it once, at module level, and import it wherever you need
it. The WebSocket adapter is the default, and it connects as soon as the socket is created.

```ts title="src/api/socket.ts"
import { createSocketClient } from "@hyper-fetch/sockets";

export const socket = createSocketClient({ url: "wss://api.example.com/ws" });
```

For a server that only pushes data over HTTP, pass the Server-Sent Events adapter. Listeners work the same; emitting on it
throws, because SSE is one-way.

```ts title="src/api/events.ts"
import { createSocketClient, ServerSentEventsAdapter } from "@hyper-fetch/sockets";

export const events = createSocketClient({ url: "https://api.example.com/events", adapter: ServerSentEventsAdapter() });
```

## Define listeners and emitters

A [listener](/docs/sockets/listener) describes one topic you receive and the type of its messages. An
[emitter](/docs/sockets/emitter) describes one topic you send and the type of its payload. Define them once, next to
the socket. `createListener` and `createEmitter` are called twice: the first call takes the type, the second the
options.

```ts title="src/api/chat.ts"
import { socket } from "./socket";

type ChatMessage = { id: string; author: string; text: string };

export const onChatMessage = socket.createListener<ChatMessage>()({ topic: "chat/:roomId" });
export const sendChatMessage = socket.createEmitter<{ text: string }>()({ topic: "chat/:roomId" });
```

Use them anywhere in the app:

```ts title="src/chat.ts"
const unlisten = onChatMessage.setParams({ roomId: "general" }).listen(({ data }) => {
  console.log(`${data.author}: ${data.text}`);
});

sendChatMessage.emit({ params: { roomId: "general" }, payload: { text: "Hello" } });

unlisten(); // stop listening when the screen closes
```

The built-in adapters read and write JSON frames shaped `{ topic, data }`. When your server uses another shape, map it
with `decode` and `encode` in `adapterOptions`, as the [adapter docs](/docs/sockets/adapter) show.

## Many topics: the socket SDK

With dozens of topics, describe them once in a schema type and let [`createSocketSdk`](/docs/sockets/sdk) build the
listeners and emitters from the property path.

```ts title="src/api/sdk.ts"
import { createSocketSdk } from "@hyper-fetch/sockets";
import type { EmitterModel, ListenerModel } from "@hyper-fetch/sockets";

type ChatSchema = {
  chat: {
    messages: {
      $listener: ListenerModel<{ response: ChatMessage; topic: "chat/messages" }>;
      $emitter: EmitterModel<{ payload: { text: string }; topic: "chat/messages" }>;
    };
  };
};

export const sdk = createSocketSdk<typeof socket, ChatSchema>(socket);

sdk.chat.messages.$listener.listen(({ data }) => console.log(data.text));
```

| Setup                          | Good for                                                       |
| ------------------------------ | -------------------------------------------------------------- |
| `createListener` / `createEmitter` | A handful of topics, or topics defined next to the feature  |
| `createSocketSdk`              | Many topics, one typed tree, central config with `$configure`  |
