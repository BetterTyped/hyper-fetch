# Query Parameters

Connection query params are appended to the socket URL, such as `wss://api.example.com/ws?tenant=acme`. Servers use them
for tenants, client versions or tokens. This guide sets them once, changes them at runtime, and resolves them fresh for
every connection attempt.

:::secondary What you'll learn

1.  How to set **static query params** on the socket.
2.  How to **change them at runtime** with `setQueryParams` and `reconnect()`.
3.  How to **resolve them per attempt** with `onConnect`.
4.  How they are **typed** and how they differ from **listener query params**.

:::

---

## Set static query params

Pass `queryParams` when you create the socket. They are added to the URL of every connection attempt. Arrays and
objects are stringified the same way as in HTTP requests.

```ts title="src/api/socket.ts"
import { createSocketClient } from "@hyper-fetch/sockets";

export const socket = createSocketClient({
  url: "wss://api.example.com/ws",
  queryParams: { tenant: "acme", clientVersion: "2.4.0" },
});
// Connects to wss://api.example.com/ws?tenant=acme&clientVersion=2.4.0
```

A string such as `"tenant=acme"` works too, when you build the query yourself.

---

## Change them at runtime

`setQueryParams` replaces the query params of the **next** connection attempt. It does not reconnect, so call
`reconnect()` to apply them to a live connection. Listeners stay registered and receive messages from the new
connection.

```ts title="src/switch-tenant.ts"
export async function switchTenant(tenant: string) {
  socket.setQueryParams({ tenant, clientVersion: "2.4.0" });
  await socket.reconnect();
}
```

The current value is on the adapter, as `socket.adapter.queryParams`. `setUrl` works the same way for the URL itself.

---

## Resolve them per attempt

Values that change on their own, such as an access token, go stale between reconnects. `onConnect` runs right before
every attempt (the first one, automatic reconnects and manual reconnects) and returns the connection to use, so each
attempt reads the current value.

```ts title="src/api/socket.ts"
export const socket = createSocketClient({ url: "wss://api.example.com/ws" }).onConnect(async ({ connection }) => ({
  ...connection,
  // highlight-next-line
  queryParams: { clientVersion: "2.4.0", token: await getAccessToken() },
}));
```

Chain `onConnect` right after creating the socket, so it applies to the first connection. It receives the `attempt`
number, `0` for a fresh connection. Return the full query params: `connection.queryParams` can also be a string, so it
is not spread. The [authentication guide](/docs/guides/sockets/authentication) covers tokens in
depth.

---

## Which approach to use

| Value                                                  | Use                                       |
| ------------------------------------------------------ | ----------------------------------------- |
| Fixed for the whole session: client version, platform | `queryParams` option                      |
| Changes on a user action: tenant, region, language     | `setQueryParams` + `reconnect()`          |
| Changes by itself: tokens, expiring signatures         | `onConnect`                               |

---

## Types and listener query params

Connection query params are typed by the adapter: for WebSocket and SSE, a record of strings, numbers, booleans, arrays
and objects, or a string. `Socket` has no generic for them; its only generic is the adapter type, inferred from the
`adapter` option.

Listener query params are a different feature. Adapters such as
[Firebase](/docs/integrations/adapter-firebase/realtime-queries) let one listener ask for filters or limits with
`listener.setQueryParams(...)`. The WebSocket and SSE adapters have no listener query params, so that call does not
compile for them.
