# Connection

A socket connects on its own, reconnects after a loss and follows the network. This guide covers the parts you control:
when the connection opens and closes, how to read and show its state, how retries behave, and how to plug in network
events outside the browser.

:::secondary What you'll learn

1.  How to **connect on demand** instead of on creation.
2.  The difference between **`disconnect`**, **`reconnect`** and **`destroy`**.
3.  How to **observe connection state** with cleanup.
4.  How **retries, offline and focus** handling work.
5.  How to provide network events in **React Native and Node.js**.

:::

---

## Connect on demand

The WebSocket adapter connects as soon as the socket is created, default `autoConnect: true`, change it with
`adapterOptions`. Turn it off when the connection needs a logged-in user, or to avoid connecting during server rendering.

```ts title="src/api/socket.ts"
import { createSocketClient } from "@hyper-fetch/sockets";

export const socket = createSocketClient({
  url: "wss://api.example.com/ws",
  adapterOptions: { autoConnect: false },
});

// After login
await socket.connect();
```

`connect()` resolves once the connection is open and does nothing when it already is. `autoConnect` only decides the
first connection: once connected, the socket recovers from losses the same way in both modes.

## Disconnect, reconnect and destroy

| Method          | Effect                                                                                     | Typical use                    |
| --------------- | ------------------------------------------------------------------------------------------ | ------------------------------ |
| `disconnect()`  | Closes the connection. It stays closed until `connect()` or `reconnect()`                  | Pausing a feature              |
| `reconnect()`   | Replaces the connection with a fresh one, also after `disconnect()` or failed attempts     | New query params, account switch |
| `destroy()`     | Closes and stops following the network and focus, so nothing reconnects it                | Logout, leaving a tenant       |

```ts title="src/session.ts"
export async function switchAccount() {
  await socket.reconnect(); // onConnect reads the new user's token
}

export async function logout() {
  await socket.destroy();
}
```

A manual `reconnect()` is never refused by the `reconnect` attempt limit. Listeners stay registered across reconnects
and receive messages from the new connection.

## Observe connection state

`socket.on*` methods register permanent callbacks and return the socket, so chain them at setup. Code that starts and
stops, such as a screen or a component, uses `socket.events.*`, which return an unsubscribe function.

```ts title="src/api/socket.ts"
socket
  .onConnected(() => console.log("open"))
  .onDisconnected(() => console.log("closed"))
  .onReconnect(() => console.log("reconnecting"))
  .onReconnectFailed(() => console.log("gave up"))
  .onError(({ error }) => console.error(error));
```

```ts title="src/status-indicator.ts"
const offConnected = socket.events.onConnected(() => setStatus("online"));
const offDisconnected = socket.events.onDisconnected(() => setStatus("offline"));

// When the indicator is removed
offConnected();
offDisconnected();
```

The current state is on the adapter: `socket.adapter.connected`, `socket.adapter.connecting` and
`socket.adapter.reconnectionAttempts`. In React, [`useListener`](/docs/react/sockets/use-listener) and
[`useEmitter`](/docs/react/sockets/use-emitter) return `connected` and `connecting` and clean up for you.

## How retries work

A lost connection comes back on its own with exponential backoff and jitter, starting at `reconnectTime` (default
`1000` ms) and capped at `maxReconnectTime` (default `30000` ms).

- A normal closure (`1000`) from the server stays closed. Every other loss is retried, and closes you started never
  are.
- The attempt counter resets once a connection stays up for `minUptime`, so a server that accepts and drops at once
  still reaches the `reconnect` limit.
- An attempt that is not ready within `connectionTimeout` counts as failed.

```ts title="src/api/socket.ts"
export const socket = createSocketClient({
  url: "wss://api.example.com/ws",
  reconnect: 10, // attempts per outage, default Infinity
  maxReconnectTime: 15_000,
});
```

The [errors and reconnection guide](/docs/guides/sockets/websocket-reconnection-and-errors) covers close codes,
`shouldReconnect`, `reconnectDelay` and heartbeats.

## Offline and focus

Every socket follows the network and the app focus with its own app manager (`socket.appManager`):

- **Going offline** closes the connection at once. No attempts run or count while offline.
- **Coming back online** connects at once, without waiting for the backoff.
- **Regaining focus** skips the rest of a pending reconnect delay.

This applies until `disconnect()`. A socket you disconnected on purpose stays closed when the network returns.

In the browser the app manager reads `online`, `offline` and visibility events. In React Native or Node.js, pass your
own with the `appManager` option, and return a cleanup function from `onlineEvent`:

```ts title="src/api/socket.ts"
import NetInfo from "@react-native-community/netinfo";
import { AppManager } from "@hyper-fetch/core";
import { createSocketClient } from "@hyper-fetch/sockets";

export const socket = createSocketClient({
  url: "wss://api.example.com/ws",
  appManager: () =>
    new AppManager({
      initiallyOnline: async () => Boolean((await NetInfo.fetch()).isConnected),
      onlineEvent: (setOnline) => NetInfo.addEventListener((state) => setOnline(Boolean(state.isConnected))),
    }),
});
```

Node.js 22 and newer have a global `WebSocket`. On older versions, pass one from `ws` with
`adapterOptions: { WebSocket }`, as the [Node.js client guide](/docs/guides/sockets/nodejs-websocket-client) shows.
