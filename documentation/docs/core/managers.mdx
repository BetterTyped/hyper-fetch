Managers hold the app-wide state of a client. The **AppManager** tracks focus and online state, the **RequestManager**
emits request lifecycle events and aborts requests, and the **LoggerManager** creates the loggers every module uses.
Each client has one of each: `client.appManager`, `client.requestManager` and `client.loggerManager`.

:::tip Purpose

1. **Know the environment**: online, offline, focused or blurred.
2. **Observe every request**: start, progress, retry, response, abort and removal events.
3. **Log** what the client does, filtered by level and module.

:::

```ts
// Every listener returns an unsubscribe function
const unsubscribe = client.requestManager.events.onResponse(({ request, response }) => {
  console.log(request.endpoint, response.status);
});

unsubscribe();
```

## AppManager

[Read the API Reference »](/docs/api/core/Classes/AppManager)

The AppManager tracks whether the app is focused and online. The [dispatcher](/docs/core/dispatcher) holds offline
requests until it reports the connection is back, and React hooks use it to refetch on focus or reconnect.

```ts
client.appManager.isOnline; // boolean
client.appManager.isFocused; // boolean

const unsubscribe = client.appManager.events.onOffline(() => showBanner("You are offline"));
```

The events are `onFocus`, `onBlur`, `onOnline` and `onOffline`. `setOnline(boolean)` and `setFocused(boolean)` change the
state by hand, which helps in tests.

### Connect a non-browser environment

In the browser the AppManager listens to `window` events. In React Native, Electron or Node.js, pass your own sources
with `focusEvent` and `onlineEvent`. Each receives a setter and can return a cleanup function.

```ts title="api/client.ts"
import { AppManager, createClient } from "@hyper-fetch/core";
import NetInfo from "@react-native-community/netinfo";
import { AppState } from "react-native";

export const client = createClient({
  url: "https://api.example.com",
  appManager: () =>
    new AppManager({
      focusEvent: (setFocused) => {
        const subscription = AppState.addEventListener("change", (state) => setFocused(state === "active"));
        return () => subscription.remove();
      },
      onlineEvent: (setOnline) => NetInfo.addEventListener((state) => setOnline(!!state.isConnected)),
    }),
});
```

| Option             | Default                | Description                                   |
| ------------------ | ---------------------- | --------------------------------------------- |
| `initiallyFocused` | `true`                 | Focus state before the first event            |
| `initiallyOnline`  | `navigator.onLine`     | Online state before the first event           |
| `focusEvent`       | `window` focus and blur, `visibilitychange` | Subscribes to focus changes |
| `onlineEvent`      | `window` online events | Subscribes to network changes                 |

## RequestManager

[Read the API Reference »](/docs/api/core/Classes/RequestManager)

The RequestManager emits an event for every step of every request and keeps the abort controllers. Most events come in
three forms: for all requests, by key (`...ByQueue`, `...ByCache` or `...ByKey`) and by `requestId` (`...ById`).

```ts title="Progress and retries"
client.requestManager.events.onDownloadProgressById(requestId, ({ progress, timeLeft }) => {
  console.log(`${progress}%, ${timeLeft} ms left`);
});

client.requestManager.events.onRetry(({ request, retry, delay, response }) => {
  console.log(`${request.endpoint} failed with ${response.status}, retry ${retry} in ${delay} ms`);
});
```

### Abort requests

`request.abort()` aborts every request with the same [`abortKey`](/docs/core/request#keys).
`client.requestManager.abortAll()` aborts everything in flight, for example on logout or in test teardown. Aborted
requests resolve with an abort error, they do not reject.

```ts
getUser.abort();
client.requestManager.abortByRequestId(getUser.abortKey, requestId);
```

## LoggerManager

[Read the API Reference »](/docs/api/core/Classes/LoggerManager)

The LoggerManager prints what the client and its modules do. Nothing is printed until you call `setDebug(true)`. The
level is `"warning"` by default, change it with `setLogLevel`.

```ts title="api/client.ts"
client.setDebug(true).setLogLevel("debug"); // "debug" | "info" | "warning" | "error"

// Only logs of these modules
client.loggerManager.setModules(["Cache", "Dispatcher"]);
```

Send the logs somewhere else with `setLogger`, which takes a function returning a new `LoggerManager`:

```ts
import { LoggerManager } from "@hyper-fetch/core";

client.setLogger(() => new LoggerManager({ logger: ({ level, module, title }) => sendToMonitoring(level, module, title) }));
```

---

:::secondary Summary

- `client.appManager` knows focus and online state. Pass `focusEvent` and `onlineEvent` outside the browser.
- `client.requestManager.events` reports every request step. Listeners return an unsubscribe function.
- `client.setDebug(true)` turns on the logger, `setLogLevel` and `setModules` filter it.

:::
