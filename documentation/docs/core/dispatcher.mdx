A **Dispatcher** decides when a request goes out. Every `send()` adds the request to a queue named by its `queryKey`,
where the dispatcher applies deduplication, cancelation, one-by-one ordering, offline handling and retries before the
adapter runs. A client has two: `fetchDispatcher` for GET and QUERY requests and `submitDispatcher` for everything else.

:::tip Purpose

1. **Runs requests** from queues, one queue per `queryKey`.
2. **Applies the request mode**: concurrent, deduplicated, cancelable or queued.
3. **Controls queues**: pause, stop, start, flush and persist them.

:::

```ts title="src/queue.ts"
// Hold every request of one queue, then let them go
client.fetchDispatcher.stop(getUser.queryKey);
getUser.send();
client.fetchDispatcher.start(getUser.queryKey); // the held request is sent now
```

`exec()` skips the dispatcher. Only `send()` gets the features on this page.

## Choose a mode per queue

The mode comes from the request options. When a request joins a queue, the first matching rule wins.

| Order | Option              | Mode         | What happens                                                              |
| ----- | ------------------- | ------------ | ------------------------------------------------------------------------- |
| 1     | `queued: true`      | One by one   | Waits until the previous request in the queue finishes                    |
| 2     | `cancelable: true`  | Cancelable   | Aborts the running requests of the queue, then starts                     |
| 3     | `deduplicate: true` | Deduplicated | Joins the identical request still in flight and shares its response       |
| 4     | none of them        | Concurrent   | Starts at once, next to the others                                        |

Deduplication is on by default for GET and QUERY with the fetch adapter. It only joins requests in flight, it is not a
cache. Limit the window with `deduplicateTime`.

```tsx live title="Deduplication" size=md
const getUserDeduplicated =
  getUser.setDeduplicate(true);

const request1 =
  getUserDeduplicated.send();
// Joins the first call, no second
// request is made
const request2 =
  getUserDeduplicated.send();

const [response1, response2] =
  await Promise.all([
    request1,
    request2,
  ]);

console.log(response1, response2);
```

```tsx live title="One by one" size=md
const postFileQueued =
  postFile.setQueued(true);

// Sent one after another, in order
postFileQueued.send();
postFileQueued.send();
postFileQueued.send();
```

A cancelable search needs one shared `queryKey`, because the default key changes with the query params:
`getUsers.setCancelable(true).setQueryKey("users-search")`. Guides: [deduplication](/docs/guides/core/advanced/deduplication),
[cancellation](/docs/guides/core/advanced/cancellation) and [queueing](/docs/guides/core/advanced/queueing).

## Pause, stop and start a queue

| Method            | Running request         | Waiting requests                 |
| ----------------- | ----------------------- | -------------------------------- |
| `pause(queryKey)` | Finishes                | Stay in the queue, not started   |
| `stop(queryKey)`  | Canceled, kept in queue | Stay in the queue, not started   |
| `start(queryKey)` | -                       | Sent in the queue's mode         |

```tsx live title="Stopping request queue" size=md
getUser.send();

setTimeout(() => {
  // Cancels the running request and
  // holds the queue
  client.fetchDispatcher.stop(
    getUser.queryKey,
  );
}, 500);

setTimeout(() => {
  // Sends the held request again
  client.fetchDispatcher.start(
    getUser.queryKey,
  );
}, 3000);
```

A single request cannot be paused. Stop and resume it by id with `stopRequest(queryKey, requestId)` and
`startRequest(queryKey, requestId)`. Read the id from the `onBeforeSent` callback of `send()`.

`flushQueue(queryKey)` sends the pending requests of a queue right away, and `flush()` does it for every queue. Stopped
queues are skipped.

## Retry failed requests

`retry` sets how many more attempts a failed request gets, `retryTime` the delay between them (500 ms by default, or a
function such as `exponentialBackoff()`). `send()` resolves after the last attempt.

```ts title="api/reports.ts"
const getReport = client.createRequest()({
  endpoint: "/reports",
  retry: 3,
  retryTime: 1000,
});
```

Each scheduled retry calls `onRetry` with its number and delay. See the [retries guide](/docs/guides/core/basics/retries).

## Wait out offline periods

With `offline: true`, the default, a request is not sent while the app is offline, and one that fails because the
connection dropped stays in its queue. Both go out when the connection returns. Its `send()` promise waits until then. Set `offline: false` to fail at once.

```tsx live title="Offline handling" size=md
// Simulate the connection loss
client.appManager.setOnline(false);

getUser.send();

// Back online: the request is sent
setTimeout(() => {
  client.appManager.setOnline(true);
}, 2000);
```

Online state comes from the [AppManager](/docs/core/managers#appmanager). See the [offline guide](/docs/guides/core/advanced/offline).

## Persist queues across reloads

Give a dispatcher an async `lazyStorage` to keep its queues, for example offline writes, through a reload. On start it
reads the stored requests, puts them in front of the ones added meanwhile and sends them.

```ts title="api/client.ts"
import { createClient, Dispatcher } from "@hyper-fetch/core";
import { del, get, keys, set } from "idb-keyval";

export const client = createClient({
  url: "https://api.example.com",
  submitDispatcher: () =>
    new Dispatcher({
      lazyStorage: {
        get: (key) => get(key),
        set: (key, value) => set(key, value),
        keys: () => keys() as Promise<string[]>,
        delete: (key) => del(key),
      },
    }),
});
```

Requests are stored with `toJSON()`, so functions on them (mappers, a function `retryTime`) are not kept.

## Watch the queues

Each dispatcher has an `events` object with `onQueueChange`, `onQueueStatusChange`, `onDrained` and
`onRunningRequestsChange`, each with a `...ByKey` variant for one queue. They return an unsubscribe function.

```ts title="src/queue-monitor.ts"
const unsubscribe = client.fetchDispatcher.events.onRunningRequestsChange(
  ({ queryKey, runningRequests }) => {
    console.log(`${queryKey}: ${runningRequests.length} running`);
  },
);
```

[Plugins](/docs/core/plugin) get the same changes through `onDispatcherItemAdded`, `onDispatcherQueueDrained` and the
other dispatcher hooks. In React, [`useQueue`](/docs/react/hooks/use-queue) and
[`useIsFetching`](/docs/react/hooks/use-is-fetching) build on these events.

:::secondary Summary

- `send()` adds requests to a queue per `queryKey` in `fetchDispatcher` (GET, QUERY) or `submitDispatcher`.
- The mode is `queued`, then `cancelable`, then `deduplicate`, else concurrent.
- Queues can be paused, stopped, started, flushed and persisted with `lazyStorage`.

:::
