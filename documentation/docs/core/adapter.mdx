The **Adapter** is the transport a client sends requests with. It turns a request into a network call and the result
into a response, and it maps headers, payloads, endpoints and query params on the way. Swap it to talk to GraphQL,
Firebase or your own protocol, and the request API stays the same.

:::tip Purpose

1. **Sends requests** and reports progress, cancelation and errors.
2. **Maps** headers, payloads, endpoints and query params before sending.
3. **Holds defaults** for request options and adapter options.

:::

The built-in adapter uses `fetch` and runs in browsers, Node.js 18+, Bun and Deno. Replace it with `setAdapter`:

```ts title="api/client.ts"
import { createClient } from "@hyper-fetch/core";
import { GraphqlAdapter } from "@hyper-fetch/graphql";

export const client = createClient({
  url: "https://api.example.com/graphql",
}).setAdapter(GraphqlAdapter());
```

Available adapters: Axios, GraphQL, Firebase, Firebase Admin, tRPC and oRPC. See
[integrations](/docs/integrations/getting-started).

## Pass adapter options

Each adapter defines its own `options`, typed per request. For the fetch adapter they are `RequestInit` fields plus
`timeout`, `responseType` and `streaming`.

```ts
const getReport = client.createRequest<{ response: Report }>()({
  endpoint: "/reports/:id",
  options: { timeout: 20_000, credentials: "include" },
});
```

Set them for every request with `setAdapterDefaults`, and request options such as `retry` with `setRequestDefaults`:

```ts title="api/client.ts"
client.adapter
  .setAdapterDefaults(() => ({ timeout: 10_000 }))
  .setRequestDefaults((options) => {
    const method = options.method ?? "GET";
    // Replaces the built-in default, so keep deduplication for reads
    return method === "GET" || method === "QUERY"
      ? { deduplicate: true, retry: 2 }
      : {};
  });
```

## Set the timeout

The fetch adapter's `timeout` is 5000 ms by default, change it with `options: { timeout }`. It covers the whole exchange:
sending, waiting and downloading the body, so raise it for large files. `timeout: 0` turns it off. With
`streaming: true` it stops counting once the response headers arrive.

---

## Pick the response type

The fetch adapter decodes the body as text and parses it when it is valid JSON. Pick another shape of `data` with
`responseType`:

| `responseType`  | `data` of a successful response                          |
| --------------- | -------------------------------------------------------- |
| not set         | Parsed JSON, or the text when the body is not valid JSON |
| `"json"`        | The same as not set                                      |
| `"text"`        | The text, never parsed                                   |
| `"blob"`        | A `Blob` with the `Content-Type` of the response         |
| `"arrayBuffer"` | The raw bytes as an `ArrayBuffer`                        |

```ts title="Download a file"
const downloadAvatar = client.createRequest<{ response: Blob }>()({
  endpoint: "/users/:userId/avatar",
  options: { responseType: "blob", timeout: 60_000 },
});
```

The error body is parsed the default way whatever the response type. Download progress works for every type.

---

## Stream the response

With `streaming: true`, `data` is the raw `ReadableStream` of the body instead of parsed data. In React, the
[`useStream`](/docs/react/hooks/use-stream) hook reads it for you.

```ts title="Stream a completion"
const streamChat = client.createRequest<{
  response: ReadableStream<Uint8Array>;
}>()({
  endpoint: "/chat",
  method: "POST",
  options: { streaming: true },
});

const { data } = await streamChat.send();
const reader = data?.getReader();
```

## Map requests before sending

| Method                       | Called with                         | Default                                        |
| ---------------------------- | ----------------------------------- | ---------------------------------------------- |
| `setHeaderMapper`            | The request                         | Adds `Content-Type: application/json` for JSON |
| `setPayloadMapper`           | The raw payload and its config      | JSON as a string, `FormData` and binary as is   |
| `setEndpointMapper`          | The endpoint                        | Returns it unchanged                           |
| `setQueryParamsMapper`       | The query params                    | Encodes them into a query string               |
| `setQueryParamsMapperConfig` | Config for the query params mapper  | Encoding, array format, skipping empty values  |

The payload mapper gets the raw payload, typed `unknown` because one adapter serves every request, and the value set
with `setPayloadMapperConfig`. A request with its own `request.setPayloadMapper` skips the adapter's mapper.

```ts title="api/client.ts"
// Send arrays as ids[]=1&ids[]=2
client.adapter.setQueryParamsMapperConfig({ arrayFormat: "bracket" });

// Prefix every endpoint
client.adapter.setEndpointMapper((endpoint) => `/v2${endpoint}`);
```

An adapter can also accept query params as a callback, such as a typed query builder, with `setQueryParamsResolver`.
The resolver runs when the request gets the callback and stores the result, so keys and `toJSON()` keep working with
data. The [Firebase adapter](/docs/integrations/adapter-firebase/overview) uses it for typed constraints.

## Write your own adapter

An adapter is an `Adapter` instance with a fetcher. The fetcher receives the request and helpers that report progress
and resolve the response, so the dispatcher, cache and events work with it unchanged. The
[custom adapter guide](/docs/guides/core/advanced/custom-adapter) walks through one.
