A **Plugin** observes the lifecycle of a client: requests, the cache, the dispatchers and the adapter. Use plugins for
logging, metrics, error reporting or devtools. The [HyperFlow devtools](/docs/hyper-flow) connect through one.

:::tip Purpose

1. **Observe every request** of a client from one place, without touching the requests.
2. **React to cache and queue changes**, for example to report or sync them.
3. **Package behavior** you can add to any client with `addPlugin`.

:::

```ts title="api/plugins/logger.ts"
import { Plugin } from "@hyper-fetch/core";

// Wrap the plugin in a function to give it options
export const LoggerPlugin = ({ prefix }: { prefix: string }) =>
  new Plugin({ name: "logger" })
    .onRequestStart(({ request }) => console.log(prefix, "start", request.method, request.endpoint))
    .onRequestFinished(({ request, response }) => console.log(prefix, "done", request.endpoint, response.status));
```

```ts title="api/client.ts"
export const client = createClient({ url: "https://api.example.com" }).addPlugin(LoggerPlugin({ prefix: "[api]" }));
```

`removePlugin(plugin)` takes it off again and calls its `onUnmount`.

## Hooks

Each method registers one callback and returns the plugin for chaining. Calling the same method again replaces the
callback.

| Group      | Hook                       | Fires when                                                    | Receives                                 |
| ---------- | -------------------------- | ------------------------------------------------------------- | ---------------------------------------- |
| Plugin     | `onMount`                  | `addPlugin` adds it                                           | `{ client }`                             |
| Plugin     | `onUnmount`                | `removePlugin` removes it                                     | `{ client }`                             |
| Request    | `onRequestCreate`          | `createRequest` creates a request                             | `{ request }`                            |
| Request    | `onRequestTrigger`         | The adapter is about to send it                               | `{ request }`                            |
| Request    | `onRequestStart`           | The adapter starts sending it                                 | `{ request }`                            |
| Request    | `onRequestSuccess`         | A successful response arrives                                 | `{ response, request }`                  |
| Request    | `onRequestError`           | An error response arrives                                     | `{ response, request }`                  |
| Request    | `onRequestFinished`        | Either of the two above                                       | `{ response, request }`                  |
| Cache      | `onCacheItemChange`        | An entry is created or updated                                | `{ cache, cacheKey, prevData, newData }` |
| Cache      | `onCacheItemDelete`        | An entry is deleted                                           | `{ cache, cacheKey }`                    |
| Cache      | `onCacheItemInvalidate`    | An entry is invalidated                                       | `{ cache, cacheKey }`                    |
| Dispatcher | `onDispatcherQueueCreated` | A queue is created for a new `queryKey`                       | `{ dispatcher, queue }`                  |
| Dispatcher | `onDispatcherItemAdded`    | A request joins a queue                                       | `{ dispatcher, queue, queueItem }`       |
| Dispatcher | `onDispatcherItemDeleted`  | A request leaves a queue                                      | `{ dispatcher, queue, queueItem }`       |
| Dispatcher | `onDispatcherQueueRunning` | A queue is started, paused or stopped                         | `{ dispatcher, queue, status }`          |
| Dispatcher | `onDispatcherQueueDrained` | A queue has no pending requests left                          | `{ dispatcher, queue }`                  |
| Dispatcher | `onDispatcherQueueCleared` | A queue is cleared                                            | `{ dispatcher, queue }`                  |
| Dispatcher | `onDispatcherCleared`      | A whole dispatcher is cleared                                 | `{ dispatcher }`                         |
| Adapter    | `onAdapterFetch`           | The adapter starts executing a request                        | `{ adapter, request, requestId }`        |

A plugin only observes. When a hook throws, the request, the cache and the other plugins carry on, and the error is
thrown from a timer, where `window.onerror` or `uncaughtException` handlers see it.

## Report errors

A common plugin sends failed responses to an error tracker:

```ts title="api/plugins/errors.ts"
import { Plugin } from "@hyper-fetch/core";

export const ErrorReportingPlugin = (report: (message: string, extra: object) => void) =>
  new Plugin({ name: "error-reporting" }).onRequestError(({ request, response }) => {
    report(`${request.method} ${request.endpoint} failed`, { status: response.status, error: response.error });
  });
```

## Requests are serializable

Plugins often store requests. `request.toJSON()` returns plain data, and `Request.fromJSON(client, json)` or
`client.fromJSON(json)` builds the request again. Functions such as mappers and `$hooks` are not part of the JSON.

```ts live title="Serialize a request" console
const jsonRequest = getUser.toJSON();

console.log(jsonRequest);
```

```ts live title="Restore and send it" size=md console
const jsonRequest = getUser.toJSON();

// Recreate the request from the JSON
const request = Request.fromJSON(client, jsonRequest);

request.setMock(() => ({
  data: { name: "John Doe", age: 20 },
  status: 200,
}));

const response = await request.send();

console.log(response);
```

To keep unsent requests through a reload, you do not need a plugin: give the dispatcher a `lazyStorage`, see
[persist queues](/docs/core/dispatcher#persist-queues-across-reloads).

:::secondary Summary

- Create a plugin with `new Plugin({ name })` and chain hooks such as `onRequestFinished`.
- Add it with `client.addPlugin()`, remove it with `removePlugin()`.
- Hooks observe requests, cache, dispatchers and the adapter. A throwing hook never breaks a request.

:::
