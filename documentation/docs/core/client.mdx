The **Client** is the central configuration object for one backend. It owns the base URL, the
[adapter](/docs/core/adapter), the [cache](/docs/core/cache), the two [dispatchers](/docs/core/dispatcher) and the
[managers](/docs/core/managers), and it creates every request. Each client is isolated, so two clients never share
cache, queues or interceptors.

:::tip Purpose

1. **Builds requests** with `createRequest`, which inherit its configuration.
2. **Holds global behavior**: auth, interceptors, request defaults and plugins.
3. **Owns the modules**: adapter, cache, dispatchers and managers.

:::

```ts title="api/client.ts"
import { createClient } from "@hyper-fetch/core";

type ApiError = { message: string; code: number };

// Keep Error in the union: timeouts, aborts and network failures arrive as
// Error instances
export const client = createClient<{ error: ApiError | Error }>({
  url: "https://api.example.com",
});

export const getUser = client.createRequest<{
  response: { id: number; name: string };
}>()({
  endpoint: "/users/:userId",
});
```

Create the client once and export it. The `error` generic is the global error type, merged with each request's own
`error` type. See [global error](/docs/guides/typescript/global-error) for the patterns.

## Add authentication

`onAuth` runs before every request with `auth: true`, which is the default. Return the request with the headers it
needs. Mark public endpoints `auth: false` to skip it.

```ts title="api/client.ts"
client.onAuth((request) => {
  const token = localStorage.getItem("token");
  return token
    ? request.setHeaders({
        ...request.headers,
        Authorization: `Bearer ${token}`,
      })
    : request;
});

const getHealth = client.createRequest()({ endpoint: "/health", auth: false });
```

The [authentication guide](/docs/guides/core/basics/authentication) covers token refresh on `401`.

## Intercept requests and responses

Interceptors run in this order: `onRequest`, `onAuth` (only when `auth` is on), the adapter, then `onResponse`, and
`onSuccess` or `onError`. Request interceptors return a request, response interceptors return a response.

| Method       | Runs on                                   | Remove with                    |
| ------------ | ----------------------------------------- | ------------------------------ |
| `onRequest`  | Every request before it is sent           | `removeOnRequestInterceptors`  |
| `onAuth`     | Requests with `auth: true`                | `removeOnAuthInterceptors`     |
| `onResponse` | Every response                            | `removeOnResponseInterceptors` |
| `onSuccess`  | Successful responses                      | `removeOnSuccessInterceptors`  |
| `onError`    | Failed responses                          | `removeOnErrorInterceptors`    |

```ts title="api/client.ts"
client.onError(async (response, request) => {
  // `used` stops a resent request from refreshing again
  if (response.status !== 401 || request.used) return response;
  await refreshToken();
  return request.setUsed(true).send();
});
```

A request can skip them with `disableRequestInterceptors` or `disableResponseInterceptors`. The
[interceptors guide](/docs/guides/core/advanced/intercepting) has more patterns.

## Set defaults for every request

Request defaults live on the adapter. `setRequestDefaults` takes a callback with the options of each new request and
returns the defaults to apply. Options set on a request always win.

```ts title="api/client.ts"
client.adapter
  .setRequestDefaults((options) => {
    const method = options.method ?? "GET";
    // The callback replaces the built-in default, so keep deduplication for reads
    if (method === "GET" || method === "QUERY")
      return { deduplicate: true, retry: 2 };
    return { retry: 0 };
  })
  // fetch options, the timeout is 5000 ms by default
  .setAdapterDefaults(() => ({ timeout: 10_000 }));
```

Call both before you create requests: defaults are read when a request is created. See
[global defaults](/docs/guides/core/basics/global-defaults).

## Change the base URL

`setUrl` points the client at another server, for example when switching tenants or regions. Cache keys do not include
the base URL, so data of the old server stays until you invalidate it.

```ts
client.setUrl("https://us.example.com", { abort: true, invalidate: true });
```

| Option       | Default | Description                                                                  |
| ------------ | ------- | ---------------------------------------------------------------------------- |
| `abort`      | `false` | Abort requests still in progress for the old URL.                             |
| `invalidate` | `false` | Invalidate the whole cache, so mounted hooks refetch from the new URL.       |

## Cache safely on the server

The `mode` option decides how the cache behaves. Default `"auto"`: `"client"` in the browser, `"server"` everywhere
else. Change it with `mode: "client"` or `mode: "server"`.

In `"server"` mode nothing is cached unless the request has a scope, so one user's data never reaches another. Read
`client.mode` for the resolved value.

```ts title="server.ts"
// Cached for this session only
const { data } = await getUser
  .setParams({ userId: 1 })
  .setScope(session.id)
  .send();
```

See [Cache](/docs/core/cache#scope-the-cache-on-the-server) for scopes.

---

## Hydrate data from the server

`request.dehydrate()` packs a response for the browser, and `client.hydrate()` writes it into the cache there.

```ts title="Server and browser"
// On the server
const response = await getUser.setParams({ userId: 1 }).send();
const state = [getUser.setParams({ userId: 1 }).dehydrate({ response })];

// In the browser, before the components read the cache
client.hydrate(state);
```

In React, render the [`Hydrate`](/docs/react/hydrate) component instead. It writes the data before the hooks mount and
never replaces newer cache data with an older snapshot.

## Add plugins

Plugins observe the request, cache and dispatcher lifecycle. `addPlugin` mounts one, `removePlugin` unmounts it.

```ts title="api/client.ts"
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";

client.addPlugin(DevtoolsPlugin({ appName: "My App" }));
```

See [Plugin](/docs/core/plugin) to write your own.

---

## Reset the client

`clear()` aborts every request, empties both dispatchers and the cache (including `lazyStorage`), and creates the modules
again from the client options. Call it on logout and between tests.

```ts
client.clear();
```

## Options

| Option             | Default             | Description                                                     |
| ------------------ | ------------------- | --------------------------------------------------------------- |
| `url`              | required            | Base URL of every request.                                       |
| `mode`             | `"auto"`            | Cache mode: `"auto"`, `"client"` or `"server"`.                  |
| `cache`            | `() => new Cache()` | Factory of the cache, for example with `lazyStorage`.            |
| `appManager`       | `() => new AppManager()` | Factory of the focus and online state manager.              |
| `fetchDispatcher`  | `() => new Dispatcher()` | Factory of the dispatcher for GET and QUERY requests.       |
| `submitDispatcher` | `() => new Dispatcher()` | Factory of the dispatcher for every other method.           |

The other settings have setters: `setAdapter`, `setDebug`, `setLogLevel`, `setEnableGlobalMocking`, and
`setCacheKeyMapper`, `setQueryKeyMapper`, `setAbortKeyMapper` to change how [keys](/docs/core/request#keys) are built.
