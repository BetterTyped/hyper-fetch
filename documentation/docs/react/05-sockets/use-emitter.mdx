# useEmitter

`useEmitter` returns a typed `emit` function for a socket [emitter](/docs/sockets/emitter), with the connection state
and callbacks for failed sends. Use it to send WebSocket messages from components. To receive messages, use
[`useListener`](/docs/react/sockets/use-listener).

:::tip Purpose

1. **Typed payloads**: a wrong payload shape is a compile error.
2. **Connection state**: `connected` and `connecting` to disable sending while offline.
3. **Error callbacks**: `onEmitError` reports messages that could not be sent.

:::

---

## Usage

```tsx title="components/message-form.tsx"
import { useState } from "react";
import { useEmitter } from "@hyper-fetch/react";
import { socket } from "./api/socket";

export const emitMessage = socket.createEmitter<{ text: string }>()({ topic: "chat-message" });

function MessageForm() {
  const [text, setText] = useState("");
  const { emit, connected, onEmitError } = useEmitter(emitMessage);

  onEmitError(({ error }) => toast(`Message not sent: ${error.message}`));

  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        emit({ payload: { text } });
      }}
    >
      <input value={text} onChange={(event) => setText(event.target.value)} />
      <button type="submit" disabled={!connected}>
        Send
      </button>
    </form>
  );
}
```

## Options

| Option               | Default | Description                                                 |
| -------------------- | ------- | ----------------------------------------------------------- |
| `dependencyTracking` | `true`  | Re-render only for the returned fields the component reads. |

Set defaults for every `useEmitter` with the `useEmitter` key of the
[`Provider`](/docs/react/overview#global-defaults) config.

## Send a payload

Pass the payload to `emit`, or set it on the emitter with `setPayload` and call `emit()` without arguments.

```tsx title="Payload on the emitter"
const { emit } = useEmitter(emitMessage.setPayload({ text: "Hello" }));

emit();
```

`emit` returns `void` and takes no acknowledgement callback. Nothing is queued: a message emitted while the socket is
not connected is dropped and reported through `onEmitError`. When the server needs to answer, listen for the reply on
its own topic with [`useListener`](/docs/react/sockets/use-listener).

---

## Callbacks

| Callback                                          | Fires when                                                                         |
| ------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `onEmit`                                          | Right before a message is sent. Receives the emitter.                              |
| `onEmitError`                                     | A message could not be sent: socket not connected, payload mapper, encoder or transport failure. Receives `{ error }`. |
| `onConnected` / `onDisconnected` / `onConnecting` | The connection opens, closes or starts opening.                                    |
| `onReconnecting` / `onReconnectingFailed`         | A reconnect attempt starts, or all attempts failed. Receives `{ attempts }`.       |
| `onError`                                         | The socket reports an error.                                                       |

```tsx title="Log sends"
const { onEmit, onReconnectingFailed } = useEmitter(emitMessage);

onEmit((emitter) => console.log("Sending to", emitter.topic));
onReconnectingFailed(({ attempts }) => toast(`Could not reconnect after ${attempts} attempts`));
```

---

:::secondary Summary

1. `useEmitter` returns a typed `emit` and the connection state.
2. Messages sent while disconnected are dropped and reported by `onEmitError`.
3. Replies come through a separate listener with `useListener`.

:::
