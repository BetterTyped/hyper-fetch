# useListener

`useListener` subscribes a component to a socket [listener](/docs/sockets/listener) while it is mounted and returns the
latest message with the connection state. Use it for chats, notifications and live updates over WebSocket, SSE, tRPC or
oRPC subscriptions. To send messages, use [`useEmitter`](/docs/react/sockets/use-emitter).

:::tip Purpose

1. **Typed messages**: `data` has the listener's message type.
2. **Lifecycle handled**: subscribes on mount and unsubscribes on unmount.
3. **Connection state**: `connected`, `connecting` and reconnect callbacks.
4. **Subscription status**: follows subscriptions the server confirms and ends.

:::

---

## Usage

```tsx title="components/chat.tsx"
import { useState } from "react";
import { useListener } from "@hyper-fetch/react";
import { socket } from "./api/socket";

type ChatMessage = { id: string; text: string };

export const onChatMessage = socket.createListener<ChatMessage>()({ topic: "chat-message" });

function Chat() {
  const [messages, setMessages] = useState<ChatMessage[]>([]);
  const { connected, onEvent } = useListener(onChatMessage);

  onEvent(({ data }) => setMessages((prev) => [...prev, data]));

  if (!connected) return <p>Connecting...</p>;
  return (
    <ul>
      {messages.map((message) => (
        <li key={message.id}>{message.text}</li>
      ))}
    </ul>
  );
}
```

`data` holds only the latest message, so keep a list in state when you need history. There is no `disabled` option: to
stop listening, stop rendering the component that calls the hook.

---

## Options

| Option               | Default | Description                                                                       |
| -------------------- | ------- | --------------------------------------------------------------------------------- |
| `select`             | -       | `(data) => part`. `data` updates only when the selected part changes.             |
| `structuralSharing`  | `true`  | Keep references of the unchanged parts of the selected data.                      |
| `dependencyTracking` | `true`  | Re-render only for the returned fields the component reads.                       |

Set defaults for every `useListener` with the `useListener` key of the
[`Provider`](/docs/react/overview#global-defaults) config.

## Callbacks

Register callbacks by calling them in the render body; the latest closure is used.

| Callback                                           | Fires when                                                 |
| -------------------------------------------------- | ---------------------------------------------------------- |
| `onEvent`                                          | A message arrives. Receives `{ data, extra }`.             |
| `onError`                                          | The socket reports an error.                               |
| `onConnected` / `onDisconnected` / `onConnecting`  | The connection opens, closes or starts opening.            |
| `onReconnecting` / `onReconnectingFailed`          | A reconnect attempt starts, or all attempts failed. Receives `{ attempts }`. |
| `onStart` / `onEnd`                                | The subscription started, or the server ended it.          |

```tsx title="Connection toasts"
const { onReconnecting, onReconnectingFailed } = useListener(onChatMessage);

onReconnecting(({ attempts }) => toast(`Reconnecting (attempt ${attempts})`));
onReconnectingFailed(({ attempts }) => toast(`Could not reconnect after ${attempts} attempts`));
```

## Follow the subscription status

`status` tells where the hook's subscription is. With the tRPC and oRPC socket adapters the server confirms and ends
subscriptions, and the hook follows it. With topic-based adapters, like WebSocket and SSE, it is `listening` right after
mount.

| Status      | Meaning                                                               |
| ----------- | --------------------------------------------------------------------- |
| `idle`      | Not subscribed yet, for example during server rendering.              |
| `starting`  | Subscribed and waiting for the server to confirm it.                  |
| `listening` | Messages can arrive.                                                  |
| `ended`     | The server finished the subscription.                                 |
| `failed`    | The server ended the subscription with an error, available as `error`. |

After `ended` or `failed` the hook stays unsubscribed and keeps the last `data`. Call `listen()`, or change the
listener's payload or params, to subscribe again. `onStart` runs when the subscription starts, also after a reconnect;
`onEnd` runs once when the server ends it, not on unmount.

```tsx title="Job progress over a server subscription"
function Progress({ jobId }: { jobId: string }) {
  const { data, status, error, listen } = useListener(onJobProgress.setPayload({ jobId }));

  if (status === "failed") return <button onClick={listen}>Retry: {error?.message}</button>;
  return <progress value={data?.percent ?? 0} max={100} />;
}
```

## Throttle or batch fast topics

Every delivered message is a state update. For fast topics, set a
[delivery strategy](/docs/sockets/listener#throttle-or-batch-fast-topics) on the listener instead of throttling in the
component. The hook needs no options, and `data` follows the delivered type.

```tsx title="At most one render per frame"
export const onPrice = socket.createListener<Price>()({
  topic: "prices",
  delivery: { strategy: "latest", interval: 16 },
});
```

With `{ strategy: "batch", interval: 100 }`, `data` and `onEvent` receive arrays. To let the user change the rate,
memoize a `setDelivery` clone; custom strategy functions must be defined at module level, or the hook subscribes again on
every render.

---

## Select part of a message

`select` picks the part of each message the component uses. `data` updates only when the selected value changes, while
`onEvent` still receives the full message. Without `select`, every message updates `data`, even an equal one.

```tsx title="One symbol's price"
function SymbolPrice({ id }: { id: string }) {
  const { data: price } = useListener(onPrices, { select: (prices) => prices[id]?.price });

  return <span>{price}</span>;
}
```

---

## Server rendering

During server rendering the hook does not subscribe, `status` is `idle` and `data` is `null`. The socket itself still
connects when it is created on the server, because Node.js has a global `WebSocket`. Create it with
`adapterOptions: { autoConnect: typeof window !== "undefined" }`, or only on the client.

---

:::secondary Summary

1. `useListener` subscribes on mount, unsubscribes on unmount and returns the latest message.
2. Use `onEvent` to collect messages and `status` to follow server subscriptions.
3. Throttle fast topics with a delivery strategy on the listener, and narrow re-renders with `select`.

:::
