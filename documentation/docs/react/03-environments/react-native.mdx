# React Native

The hooks work in React Native as they do on the web. React Native has no window events, so connect the client's
[`AppManager`](/docs/core/managers) to `NetInfo` and `AppState` to get online and focus detection, and optionally keep
the request queues in persistent storage.

:::tip Purpose

1. **Online state** from `@react-native-community/netinfo`.
2. **Focus state** from `AppState`, so `refetchOnFocus` fires when the app returns to the foreground.
3. **Persistent queues** with MMKV, so offline requests survive app restarts.

:::

---

## Connect online and focus state

```bash npm2yarn2pnpm
npm install @react-native-community/netinfo
```

```ts title="api/client.ts"
import { AppState } from "react-native";
import NetInfo from "@react-native-community/netinfo";
import { AppManager, Client } from "@hyper-fetch/core";

export const client = new Client({
  url: "https://api.example.com",
  // React Native has no document, so the default "server" mode would turn the
  // cache off
  mode: "client",
  appManager: () =>
    new AppManager({
      initiallyOnline: () =>
        NetInfo.fetch().then((state) => !!state.isConnected),
      onlineEvent: (setOnline) =>
        NetInfo.addEventListener((state) => setOnline(!!state.isConnected)),
      initiallyFocused: () => AppState.currentState === "active",
      focusEvent: (setFocused) => {
        const subscription = AppState.addEventListener("change", (status) =>
          setFocused(status === "active"),
        );
        return () => subscription.remove();
      },
    }),
});
```

The app counts as focused while `AppState` is `active`, and blurred when it is `inactive` or in the `background`. Both
events return a cleanup function, so the listeners are removed when `client.clear()` runs.

## Keep queued requests across restarts

By default the dispatchers keep their queues in memory. Give them a persistent `storage`, such as
[MMKV](https://github.com/mrousavy/react-native-mmkv), so offline requests are sent after the app restarts. Requests
read back from JSON are turned into `Request` instances again.

```bash npm2yarn2pnpm
npm install react-native-mmkv
```

```ts title="api/client.ts"
import { MMKV } from "react-native-mmkv";
import { Client, Dispatcher } from "@hyper-fetch/core";
import type { DispatcherStorageType } from "@hyper-fetch/core";

const mmkv = new MMKV({ id: "dispatcher-storage" });

const dispatcherStorage: DispatcherStorageType = {
  set: (key, data) => mmkv.set(key, JSON.stringify(data)),
  get: (key) => {
    const value = mmkv.getString(key);
    return value ? JSON.parse(value) : undefined;
  },
  keys: () => mmkv.getAllKeys(),
  entries: function* entries() {
    for (const key of mmkv.getAllKeys()) {
      yield [key, JSON.parse(mmkv.getString(key) || "null")];
    }
  },
  delete: (key) => mmkv.delete(key),
  clear: () => mmkv.clearAll(),
};

export const client = new Client({
  url: "https://api.example.com",
  // React Native has no document, so the default "server" mode would turn the
  // cache off
  mode: "client",
  fetchDispatcher: () => new Dispatcher({ storage: dispatcherStorage }),
  submitDispatcher: () => new Dispatcher({ storage: dispatcherStorage }),
});
```

For an async storage such as AsyncStorage, use the dispatcher's `lazyStorage` option instead. Persistent queues fit
single-instance apps; in browsers, several tabs reading one queue can send requests twice.
