# useStream

The `useStream` hook consumes **streaming responses** chunk-by-chunk in React components. It works with any request
that uses the fetch adapter's streaming mode, providing both accumulated text (for LLM/SSE use cases) and raw binary
chunks (for file downloads).

:::tip Purpose

1. **Text streaming**: Consume AI/LLM chat responses word-by-word as they arrive.
2. **Binary streaming**: Stream file downloads with progress tracking.
3. **Full lifecycle control**: Start, abort, and reset streams programmatically.
4. **Reactive updates**: Component re-renders as each chunk arrives.

:::

---

## Quick Start

Provide a [`Request`](/docs/core/request) instance and call `start()` to begin streaming.

```tsx title="AI Chat Streaming"
import { useStream } from "@hyper-fetch/react";
import { chatCompletion } from "./api/ai";

function AiChat() {
  const { text, streaming, done, start, abort } = useStream(chatCompletion.setPayload({ prompt: "Hello!" }));

  return (
    <div>
      <div className="whitespace-pre-wrap">{text}</div>
      {streaming && <p>Streaming...</p>}
      {done && <p>Complete!</p>}
      <button type="button" onClick={start} disabled={streaming}>
        Start
      </button>
      <button type="button" onClick={abort} disabled={!streaming}>
        Stop
      </button>
    </div>
  );
}
```

:::info Streaming in Core

The hook sends the request with the adapter's `streaming: true` option and listens to its response chunks, so the
request goes through the regular lifecycle - plugins, devtools and retries work as usual. See
[adapter streaming](/docs/core/adapter#streaming).

:::

## Parsing Server-Sent Events and NDJSON

Set `format` to `"sse"` or `"ndjson"` to get parsed `events` next to the raw `text`. Unlike `EventSource`, this works
for `POST` requests, which is how most AI backends stream.

```tsx title="Parsing SSE"
function Events() {
  const { events, start } = useStream(chatRequest, {
    format: "sse",
    onEvent: ({ event, data }) => console.log(event, data),
  });

  return <ul>{events.map((event, index) => <li key={index}>{event.data}</li>)}</ul>;
}
```

For NDJSON you can type the parsed lines with the third generic:

```tsx
const { events } = useStream<typeof logsRequest, "ndjson", { level: string; message: string }>(logsRequest, {
  format: "ndjson",
});
```

## Auto Start

Set `autoStart: true` to begin streaming immediately when the component mounts. When this option is `false` (the
default), you must call `start()` manually to initiate the stream.

```tsx title="Auto-starting stream"
import { useStream } from "@hyper-fetch/react";
import { getEvents } from "./api/events";

function EventFeed() {
  const { text, streaming } = useStream(getEvents, { autoStart: true });

  return (
    <div>
      {streaming && <span>Live</span>}
      <pre>{text}</pre>
    </div>
  );
}
```

:::info Cleanup on unmount

When the component unmounts, an in-progress stream is automatically aborted, regardless of whether it was started
manually or via `autoStart`.

:::

## Resetting State

Use `reset()` to clear all accumulated data and allow a fresh stream. This also aborts any in-progress stream.

```tsx title="Reset and re-stream"
function StreamWithReset() {
  const { text, start, reset, done } = useStream(chatRequest);

  return (
    <div>
      <pre>{text}</pre>
      {done && (
        <button type="button" onClick={() => { reset(); start(); }}>
          Stream Again
        </button>
      )}
    </div>
  );
}
```

## Non-stream Response Handling

If the adapter does not emit chunks (for example a mocked request returning plain `data`, or an adapter without
streaming support), the hook falls back to the resolved response: `text` is set from the data (`JSON.stringify` for
non-string values), `chunks` stays empty and `done` becomes `true` once the request resolves.

---

## Performance

`chunks` and `events` are appended in place, so long streams don't copy the array on every chunk. Read them during
render, but don't use their identity as a `useMemo`/`useEffect` dependency - use `text`, `chunks.length` or
`events.length` instead.

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `autoStart` | `boolean` | `false` | When `true`, the stream starts automatically on mount. |
| `format` | `"text" \| "sse" \| "ndjson"` | `"text"` | Parse the stream into `events`. |
| `onEvent` | `(event) => void` | - | Called for every parsed event. |
| `onChunk` | `({ chunk, text, index }) => void` | - | Called for every raw chunk. |

---

## Return Values

| Property | Type | Description |
|----------|------|-------------|
| `text` | `string` | Accumulated text from all stream chunks decoded as UTF-8. |
| `chunks` | `Uint8Array[]` | Raw binary chunks received from the stream. |
| `events` | `ServerSentEventType[] \| unknown[]` | Parsed events when `format` is `"sse"` or `"ndjson"`. |
| `data` | `Response \| null` | Full parsed response once the stream is done. |
| `streaming` | `boolean` | Whether the stream is currently being consumed. |
| `done` | `boolean` | Whether the stream has finished (all chunks consumed). |
| `aborted` | `boolean` | Whether the stream was stopped with `abort()`. |
| `error` | `Error \| null` | Error from the request or stream parsing. |
| `extra` | `object \| null` | Response extra metadata (headers, etc.). |
| `status` | `number \| null` | HTTP status code from the response. |
| `start` | `() => void` | Start consuming the stream. |
| `abort` | `() => void` | Abort the ongoing stream and close the connection. |
| `reset` | `() => void` | Abort any ongoing stream and reset state, allowing a fresh stream. |
