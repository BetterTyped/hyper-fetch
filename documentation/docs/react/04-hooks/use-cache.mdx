# useCache

`useCache` subscribes a component to the [cache](/docs/core/cache) entry of a request without ever sending it. Use it
to show data that another component fetched, such as a header badge reading the cart that a page loaded with
[`useFetch`](/docs/react/hooks/use-fetch).

:::tip Purpose

1. **Read without fetching**: never sends a request.
2. **Share data across components**: re-renders when the cache entry changes.
3. **Invalidate**: make every `useFetch` on that key fetch again.

:::

---

## Usage

```tsx title="components/cart-badge.tsx"
import { useCache } from "@hyper-fetch/react";
import { getCart } from "./api/cart";

function CartBadge() {
  // Reads the entry that <CartPage /> filled with useFetch(getCart)
  const { data } = useCache(getCart);

  return <span>{data?.items.length ?? 0}</span>;
}
```

The request must have the same cache key as the one that was sent: set the same params and query params, for example
`useCache(getUser.setParams({ userId: 1 }))` to read `useFetch(getUser.setParams({ userId: 1 }))`. While the cache is
empty, `data` is `null`.

---

## Options

| Option               | Default | Description                                                                     |
| -------------------- | ------- | ------------------------------------------------------------------------------- |
| `initialResponse`    | `null`  | Data shown while the cache is empty.                                            |
| `select`             | -       | `(data) => part`. Re-renders only when the selected part changes.               |
| `structuralSharing`  | `true`  | Keep references of the unchanged parts of the selected data.                    |
| `deepCompare`        | `true`  | Equal incoming values keep their reference and do not re-render.                |
| `dependencyTracking` | `true`  | Re-render only for the returned fields the component reads.                     |

---

## Returns

(@import react useCache type=returns)

`useCache` has no `refetch`, `abort` or `onSuccess`: it observes the cache only. To fetch, use `useFetch`.

---

## Invalidate the cache

`invalidate()` marks the hook's cache entry as stale, so every mounted `useFetch` on that key fetches again and other
hooks fetch on their next mount. Pass a cache key, a RegExp, a request or an array of them to invalidate other entries.
Outside the hook, call [`client.cache.invalidate`](/docs/core/cache) with the same arguments.

```tsx title="Refresh button"
const { invalidate } = useCache(getCart);

<button onClick={() => invalidate()}>Refresh</button>;
<button onClick={() => invalidate(/\/products/)}>Refresh products</button>;
```

---

## Update data for every component

`setData`, `setError`, `setLoading` and `clearState()` change only this hook's state; the next cache update replaces
them. To change what every component sees, update the cache itself.

```tsx title="Write to the cache"
// Patches the entry for every component; does nothing when there is no entry yet
client.cache.update(getCart, { data: { items: [] } });
```

---

## Select part of the data

`select` subscribes to a part of the cached data. The component re-renders only when that part changes. It works like
[`select` in useFetch](/docs/react/hooks/use-fetch#select-part-of-the-response).

```tsx title="Count done todos"
function TodosCounter() {
  const { data: doneCount } = useCache(getTodos, {
    select: (todos) => todos.filter((todo) => todo.done).length,
  });

  return <span>{doneCount}</span>;
}
```

---

:::secondary Summary

1. `useCache` reads a cache entry and never sends a request.
2. The request needs the same cache key as the one that was sent.
3. `invalidate()` refetches every `useFetch` on that key; `client.cache.update` changes the data for everyone.

:::
