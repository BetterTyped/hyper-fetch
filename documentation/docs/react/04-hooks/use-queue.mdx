# useQueue

`useQueue` lists the requests of a [dispatcher](/docs/core/dispatcher) queue and controls it. Use it for upload lists,
offline outboxes or any UI that shows pending requests with their progress and lets the user pause, stop or cancel them.

:::tip Purpose

1. **See pending requests**: every running or waiting request of the queue, with upload and download progress.
2. **Control the queue**: `stop()`, `pause()` and `start()` for the whole queue.
3. **Control one request**: stop, start or delete it.

:::

---

## Usage

The queue is identified by the request's `queryKey` and scope. Mark the request with `setQueued(true)` to send its
requests one at a time; without it they are sent at once and still listed while running.

```tsx title="components/uploads.tsx"
import { useQueue, useSubmit } from "@hyper-fetch/react";

const uploadFile = client
  .createRequest<{ response: { url: string }; payload: FormData }>()({ endpoint: "/files", method: "POST" })
  .setQueued(true);

function Uploads() {
  const { submit } = useSubmit(uploadFile);
  const { requests, stopped, stop, pause, start } = useQueue(uploadFile);

  const upload = (file: File) => {
    const payload = new FormData();
    payload.append("file", file);
    submit({ payload });
  };

  return (
    <div>
      <input type="file" onChange={(e) => e.target.files?.[0] && upload(e.target.files[0])} />
      {stopped ? <button onClick={start}>Resume</button> : <button onClick={pause}>Pause</button>}
      <button onClick={stop}>Stop</button>
      {requests.map((item) => (
        <p key={item.requestId}>
          {item.uploading.progress}% <button onClick={item.deleteRequest}>Cancel</button>
        </p>
      ))}
    </div>
  );
}
```

---

## Options

| Option                 | Default  | Description                                                                                       |
| ---------------------- | -------- | ------------------------------------------------------------------------------------------------- |
| `dispatcherType`       | `"auto"` | Queue to read: `"auto"` (fetch dispatcher for GET and other safe methods, submit for the rest), `"fetch"` or `"submit"`. |
| `keepFinishedRequests` | `false`  | Keep finished requests in `requests` with their final flags instead of removing them.             |

`useSubmit` always uses the submit dispatcher. To watch a GET request sent with `useSubmit`, pass
`dispatcherType: "submit"`.

---

## Returns

(@import react useQueue type=returns)

Each item of `requests` is a [`QueueRequest`](/docs/api/react/Types/QueueRequest):

| Field                          | Description                                                                      |
| ------------------------------ | -------------------------------------------------------------------------------- |
| `requestId`, `request`         | The id and the request that was sent.                                            |
| `uploading`, `downloading`     | Progress: `progress` (0-100), `loaded`, `total`, `sizeLeft`, `timeLeft`.         |
| `stopped`                      | The request is held.                                                             |
| `success`, `failed`, `canceled`, `removed` | Final flags. `failed` is set after the last retry.                  |
| `startRequest()`, `stopRequest()`, `deleteRequest()` | Resume, hold or remove this request.                       |

---

## Stop, pause and start

- `stop()` cancels the running request, keeps it in the list as `canceled` and holds the rest. `start()` sends it again.
- `pause()` lets the running request finish and holds the next ones.
- `start()` resumes the queue after `stop()` or `pause()`.

A deleted request's `send()` or `submit()` promise resolves with an error response. The differences between the modes
are described on the [Dispatcher](/docs/core/dispatcher) page.

---

:::secondary Summary

1. `useQueue` lists the requests of the queue identified by the request's `queryKey`.
2. Use `setQueued(true)` to send them one at a time.
3. Control the whole queue with `stop`, `pause` and `start`, or one request with its own actions.

:::
