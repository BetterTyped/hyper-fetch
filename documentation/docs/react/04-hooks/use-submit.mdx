# useSubmit

`useSubmit` sends a [request](/docs/core/request) only when you call `submit()`, and tracks its `submitting` state and
response. Use it for forms and mutations (create, update, delete) or to fetch on click. To load data when the component
mounts, use [`useFetch`](/docs/react/hooks/use-fetch).

:::tip Purpose

1. **Send on demand**: `submit()` sends a copy of the request with the payload and params you pass.
2. **Always resolves**: `submit()` returns the response, success or error, and never rejects.
3. **Per-submit callbacks**: `onSubmitSuccess`, `onSubmitError` and the others fire only for this hook's submits.
4. **Optimistic updates**: changes described on the request are applied and rolled back by core.

:::

---

## Usage

```tsx live title="Creating a new user" size="lg"
import { useSubmit } from "@hyper-fetch/react";
import { createUser } from "./api/users";

function App() {
  const [name, setName] = useState("John Doe");
  const { submit, submitting, onSubmitError, data } = useSubmit(createUser);

  const handleSubmit = (event) => {
    event.preventDefault();
    submit({ payload: { name } });
  };

  onSubmitError(({ response }) => {
    toast({ title: "Error", message: response.error.message, type: "error" });
  });

  return (
    <form onSubmit={handleSubmit} className="flex flex-col gap-4">
      <TextField
        label="User Name"
        placeholder="Enter user name"
        value={name}
        onChange={(e) => setName(e.target.value)}
        disabled={submitting}
      />
      <Button type="submit" loading={submitting}>
        {submitting ? "Creating..." : "Create User"}
      </Button>
      {data && <Table data={[data]} />}
    </form>
  );
}
```

## Options

Pass options as the second argument. Hook options override [`Provider`](/docs/react/overview#global-defaults)
defaults, which override the ones below.

| Option               | Default      | Description                                                                              |
| -------------------- | ------------ | ---------------------------------------------------------------------------------------- |
| `disabled`           | `false`      | `submit()` sends nothing and resolves at once with an error response.                    |
| `bounce`             | `false`      | Debounce or throttle `submit()` calls.                                                   |
| `bounceType`         | `"debounce"` | `"debounce"` or `"throttle"`.                                                            |
| `bounceTime`         | `400`        | Debounce delay or throttle interval in milliseconds.                                     |
| `bounceTimeout`      | `bounceTime` | Throttle only: when the trailing held submit fires.                                      |
| `optimistic`         | -            | Optimistic changes for every submit of this hook. Replaces the request's `setOptimistic`. |
| `select`             | -            | Shapes `data` in the hook. `submit()` and callbacks still get the full response.         |
| `initialResponse`    | `null`       | Partial response (`{ data }`) shown before the first submit.                             |
| `dependencyTracking` | `true`       | Re-render only for the returned fields the component reads.                              |
| `deepCompare`        | `true`       | Equal incoming values keep their reference and do not re-render.                         |
| `structuralSharing`  | `true`       | Keep references of the unchanged parts of the selected data.                             |

## Returns

(@import react useSubmit type=returns)

The state field is `submitting`, not `loading`. `refetch()` invalidates the cache key of the request passed to this
hook only; to refresh a list after a mutation, invalidate the list request (see below).

---

## Pass payload and params to submit

`submit()` accepts `payload`, `params` and `queryParams`, plus send options such as `onUploadProgress` or `retry`. The
types require the values the request does not have yet. Values already set on the request are used when `submit()` omits
them, and the request passed to the hook is never changed.

```tsx title="Edit a user"
function RenameUser({ userId }: { userId: number }) {
  const { submit, submitting, error } = useSubmit(updateUser);

  const onSave = async (name: string) => {
    const response = await submit({ params: { userId }, payload: { name } });
    if (response.success) closeDialog();
  };

  return (
    <NameForm onSave={onSave} disabled={submitting} error={error?.message} />
  );
}
```

`submit()` resolves in every case: success, error after the last retry, abort, unmount, disabled hook or a call dropped
by bounce. Check `response.success` instead of wrapping it in `try/catch`.

## Callbacks

Callbacks fire only for submits of this hook instance. Each receives one object with `response`, `request`,
`requestId`, `details` and `mutationContext`. The order is `onSubmitRequestStart`, `onSubmitResponseStart`, then one of
success, error, abort or offline error, then `onSubmitFinished`.

| Callback                                              | Fires when                                                         |
| ----------------------------------------------------- | ------------------------------------------------------------------ |
| `onSubmitSuccess` / `onSubmitError`                   | A submit succeeds or fails. Read the error from `response.error`.  |
| `onSubmitAbort`                                       | The submit is canceled. Never calls `onSubmitError`.               |
| `onSubmitOfflineError`                                | The network dropped; the request is resent once online.            |
| `onSubmitFinished`                                    | After any of the above.                                            |
| `onSubmitRequestStart` / `onSubmitResponseStart`      | The request is sent, or the response starts arriving.              |
| `onSubmitUploadProgress` / `onSubmitDownloadProgress` | Progress changes. Receives `progress` (0-100), `timeLeft`, `loaded` and `total`. |
| `onSubmitRetry`                                       | A failed attempt schedules a retry, with `retry` and `delay`.      |

```tsx title="Notify and close"
const { submit, onSubmitSuccess, onSubmitError } = useSubmit(createUser);

onSubmitSuccess(({ response }) => toast(`Created ${response.data.name}`));
onSubmitError(({ response, details }) => {
  // With retries, onSubmitError fires for every failed attempt
  if (!details.willRetry) toast(response.error.message);
});
```

## Refresh other data after a mutation

A mutation has its own cache key, so lists that show the changed data do not update by themselves. Invalidate them in
`onSubmitSuccess`, or write the response into their cache entry.

```tsx title="Refresh the list after creating a user"
const { submit, onSubmitSuccess } = useSubmit(createUser);

onSubmitSuccess(() => {
  // Every mounted useFetch(getUsers...) sends again; others refetch on their
  // next mount
  client.cache.invalidate(getUsers);
});
```

To refresh even after the form unmounted, declare it on the request with
`setOptimistic(() => ({ invalidate: [getUsers] }))`.

---

## Debounce and throttle

With `bounce: true`, rapid `submit()` calls are debounced: only the last call within `bounceTime` is sent, and every call
of the batch resolves with its response. With `bounceType: "throttle"`, the first call is sent at once and the last held
one after `bounceTimeout`. `bounce.reset()` cancels a waiting call.

```tsx title="Autosave while typing"
const { submit } = useSubmit(updateUser, { bounce: true, bounceTime: 500 });

const onChange = (name: string) =>
  submit({ params: { userId: 1 }, payload: { name } });
```

To control concurrency on the request instead, use `setQueued(true)` (one at a time), `setCancelable(true)` (the last
call wins) or `setDeduplicate(true)` (calls in flight share one request).

---

## Optimistic updates

Describe the change on the mutation request with `setOptimistic` and the `optimistic()` helpers from
`@hyper-fetch/core`. Core applies it before the request is sent, rolls it back on failure and refreshes the targets
afterwards, even when the component unmounted. The component needs nothing special.

```tsx title="Optimistic update with rollback"
import { optimistic } from "@hyper-fetch/core";

export const patchUser = client
  .createRequest<{ response: User; payload: Partial<User> }>()({
    endpoint: "/users/:userId",
    method: "PATCH",
  })
  .setOptimistic(({ params, payload }) => ({
    context: { userId: params.userId },
    updates: [
      optimistic(getUsers)
        .patch(params.userId, payload)
        .rollback(({ data, previous }) => {
          const before = previous.find(
            (user) => user.id === Number(params.userId),
          );
          return data.map((user) =>
            user.id === Number(params.userId) && before ? before : user,
          );
        }),
    ],
  }));
```

- `context` reaches every submit callback, typed, as `mutationContext`.
- On error or abort, each `.rollback()` runs in reverse order before `onSubmitError` or `onSubmitAbort`.
- With retries, rollback runs only after the final failure.
- The hook option `optimistic` and `submit({ optimistic })` replace the request's callback; the call wins over the hook.
- With `bounce`, the optimistic callback runs once, when the bounced call is sent.

---

## Select part of the response

`select` shapes the hook's `data`. The promise returned by `submit()` and the callbacks still receive the full response.

```tsx title="Keep only the name"
const { data: userName } = useSubmit(createUser, { select: (user) => user.name });
```

---

:::secondary Summary

1. `useSubmit` sends only on `submit()`, and `submit()` always resolves with the response.
2. Callbacks fire only for this hook's submits and receive one object.
3. Refresh lists after a mutation with `client.cache.invalidate`, or declare it on the request.
4. Optimistic changes live on the request, so the component stays the same.

:::
