# useFetch

`useFetch` sends a [request](/docs/core/request) when the component mounts and again when the request changes, and
renders the response from the shared [cache](/docs/core/cache). Use it to read data. To create, update or delete, use
[`useSubmit`](/docs/react/hooks/use-submit), which sends only when you call it.

:::tip Purpose

1. **Read data declaratively**: pass a request, get `data`, `loading` and `error`.
2. **Refetch on change**: new params, query params or `dependencies` send a new request.
3. **Shared cache**: every component using the same request shares one response and one network call.
4. **Fewer re-renders**: the component re-renders only for the fields it reads.

:::

---

## Usage

```tsx live title="Fetching a list of users" size=md
import { useFetch } from "@hyper-fetch/react";
import { getUsers } from "./api/users";

function App() {
  const { data, loading, error } = useFetch(getUsers);

  if (error) {
    return (
      <Alert severity="error">
        <span>{error.message}</span>
      </Alert>
    );
  }

  return (
    <div>
      <h3 className="mb-4">Users:</h3>
      <Table data={data} loading={loading} />
    </div>
  );
}
```

`data` is `null` until the first response or cached value exists. Cached data renders on the first render and, by
default, a background request replaces it (stale-while-revalidate).

## Options

Pass options as the second argument. Hook options override [`Provider`](/docs/react/overview#global-defaults)
defaults, which override the ones below. Caching (`staleTime`, `cacheTime`, `retry`, `deduplicate`) is set on the
request, not on the hook.

| Option               | Default      | Description                                                                                       |
| -------------------- | ------------ | ------------------------------------------------------------------------------------------------- |
| `disabled`           | `false`      | Never send. Cached data and cache updates are still shown.                                        |
| `dependencies`       | `[]`         | Extra values compared with `Object.is`. A change sends the request again.                         |
| `revalidate`         | `true`       | Send on mount and on change even when cached data is fresh. `false` sends only for missing or stale data. |
| `initialResponse`    | `null`       | Partial response (`{ data }`) shown while the cache is empty. Never written to the cache.         |
| `keepPreviousData`   | `"auto"`     | What to show after the cache key changes: `"auto"`, `"preserve"` or `"clean"`.                    |
| `select`             | -            | `(data) => part`. Changes the type of `data` and re-renders only when the part changes.           |
| `structuralSharing`  | `true`       | Keep references of the unchanged parts of the selected data.                                      |
| `deepCompare`        | `true`       | Equal incoming values keep their reference and do not re-render. Accepts a compare function.     |
| `dependencyTracking` | `true`       | Re-render only for the returned fields the component reads.                                       |
| `suspense`           | `false`      | Suspend until the first response.                                                                 |
| `throwOnError`       | `false`      | Throw settled errors to the closest Error Boundary. Accepts `(error) => boolean`.                 |
| `refresh`            | `false`      | Poll the request.                                                                                 |
| `refreshTime`        | `Time.HOUR`  | Polling interval in milliseconds.                                                                 |
| `refetchBlurred`     | `true`       | Keep polling while the window or app is blurred.                                                  |
| `refetchOnFocus`     | `false`      | Send when the window or app gains focus.                                                          |
| `refetchOnBlur`      | `false`      | Send when the window or app loses focus.                                                          |
| `refetchOnReconnect` | `false`      | Send when the network comes back.                                                                 |
| `bounce`             | `false`      | Debounce or throttle sends caused by request or dependency changes.                               |
| `bounceType`         | `"debounce"` | `"debounce"` or `"throttle"`.                                                                     |
| `bounceTime`         | `400`        | Debounce delay or throttle interval in milliseconds.                                              |
| `bounceTimeout`      | `400`        | Throttle only: when the trailing call fires.                                                      |

## Returns

(@import react UseFetchReturnType type=returns)

`loading` stays `true` while a failed request waits for its retry. `error` already holds the failed attempt, but the
result is final only when the retries end.

---

## Refetch when the request changes

The hook compares the serialized request, so building it in render with `setParams` or `setQueryParams` is correct and
cheap. A new value sends a new request; an equal clone on the next render does nothing. Use `dependencies` only for
values that are not part of the request, and pass primitives: a new object or array on every render refetches every
time.

```tsx title="Params on the request, extra values in dependencies"
function UserPosts({ userId, version }: { userId: number; version: number }) {
  // Refetches when userId changes (new cache key) or when version changes
  // (dependency)
  const { data } = useFetch(getUserPosts.setParams({ userId }), {
    dependencies: [version],
  });

  return <PostsList posts={data ?? []} />;
}
```

With `revalidate: false`, a change sends only when the new key has no cached data or the data is stale.

---

## Debounce and throttle

Set `bounce: true` to delay sends caused by request or dependency changes, for example while the user types. The first
request on mount is never delayed. Use `bounceType: "throttle"` to send at most once per `bounceTime` instead.

```tsx live title="Search as you type" size=md
import { useFetch } from "@hyper-fetch/react";
import { getUsers } from "./api/users";

function App() {
  const [search, setSearch] = useState("");
  const { data, loading } = useFetch(getUsers.setQueryParams({ search }), {
    // Wait until the user stops typing for 400ms
    bounce: true,
    bounceTime: 400,
  });

  return (
    <div>
      <TextField
        label="Search"
        placeholder="Type to search by name"
        onChange={(e) => setSearch(e.target.value)}
      />
      {data && <Table data={data} loading={loading} />}
    </div>
  );
}
```

## Wait for another request

Use `disabled` for dependent or conditional requests, never a conditional hook call. Nothing is sent while the hook is
disabled and `loading` is `false`. It sends as soon as `disabled` becomes `false`.

```tsx title="Dependent request"
function Profile() {
  const { data: user } = useFetch(getCurrentUser);
  // The placeholder param keeps the request typed; nothing is sent until user
  // exists
  const { data: posts } = useFetch(
    getUserPosts.setParams({ userId: user?.id ?? 0 }),
    { disabled: !user },
  );

  return <PostsList posts={posts ?? []} />;
}
```

## Callbacks

Register callbacks by calling them in the render body; the latest closure is used. Each receives one object with
`response`, `request`, `requestId` and `details`. They fire for every response on the hook's cache key, also for
requests sent by other components.

| Callback                                 | Fires when                                                       |
| ---------------------------------------- | ---------------------------------------------------------------- |
| `onSuccess` / `onError`                  | A response succeeds or fails. Read the error from `response.error`. |
| `onAbort` / `onOfflineError`             | The request is canceled, or fails offline and waits to be resent. |
| `onFinished`                             | After any of the above.                                          |
| `onRequestStart` / `onResponseStart`     | The request is sent, or the response starts arriving.            |
| `onUploadProgress` / `onDownloadProgress` | Progress changes. Receives `progress` (0-100), `timeLeft`, `loaded` and `total`. |
| `onRetry`                                | A failed attempt schedules the next one.                         |

```tsx live title="Using callbacks" size=md
import { useFetch } from "@hyper-fetch/react";
import { getUsers } from "./api/users";

const UsersListPage = () => {
  const { data, loading, onSuccess, onError, onFinished } = useFetch(getUsers);

  onSuccess(({ response }) => {
    toast({
      title: "Success",
      message: `Fetched ${response.data.length} users`,
      type: "success",
    });
  });

  onError(({ response }) => {
    toast({ title: "Error", message: response.error.message, type: "error" });
  });

  onFinished(() => {
    toast({ title: "Finished", message: "Finished request", type: "default" });
  });

  return <Table data={data} loading={loading} />;
};
```

### Retries

A request with `setRetry(n)` sends again after a failed attempt. `onError` fires for every failed attempt, with
`details.willRetry` telling whether another one is coming. `onRetry` gets the `retry` number (from `1`) and the `delay`
in milliseconds.

```tsx title="Show the retry countdown"
const getUsersWithRetries = getUsers.setRetry(3).setRetryTime(2000);

function UsersList() {
  const [message, setMessage] = useState("");
  const { data, onRetry, onFinished } = useFetch(getUsersWithRetries);

  onRetry(({ retry, delay }) =>
    setMessage(`Retry ${retry} of 3 in ${delay / 1000}s`),
  );
  onFinished(({ details }) => {
    if (!details.willRetry) setMessage("");
  });

  return <UsersTable users={data ?? []} footer={message} />;
}
```

### Progress

```tsx live title="Upload and download progress" size=md
import { useFetch } from "@hyper-fetch/react";
import { postFile } from "./api/files";

const UploadStatus = () => {
  const { onDownloadProgress, onUploadProgress } = useFetch(postFile);

  onUploadProgress(({ progress }) => console.log(`Uploaded ${progress}%`));
  onDownloadProgress(({ progress }) => console.log(`Downloaded ${progress}%`));

  return <RequestsLifecycle request={postFile} dispatcherType="fetch" />;
};
```

## Polling and refetch on focus

`refresh: true` sends the request again every `refreshTime` milliseconds. `refetch()` restarts the countdown, so a
scheduled refresh never fires right after a manual one. Polling continues in background tabs, change it with
`refetchBlurred: false`.

```tsx title="Poll every 10 seconds while the tab is visible"
const { data } = useFetch(getStats, {
  refresh: true,
  refreshTime: Time.SEC * 10,
  refetchBlurred: false,
  refetchOnFocus: true,
  refetchOnReconnect: true,
});
```

## Keep previous data

When the cache key changes and the new key has nothing cached yet, `keepPreviousData` decides what the component shows
while the new request runs. Default `"auto"`, change it with `keepPreviousData`.

| Mode               | URL params change (another resource) | Only query params change (page, filter) |
| ------------------ | ------------------------------------ | --------------------------------------- |
| `"auto"` (default) | Clear and show loading               | Keep previous data while loading        |
| `"preserve"`       | Keep previous data                   | Keep previous data                      |
| `"clean"`          | Clear                                | Clear                                   |

```tsx title="Page buttons"
function UsersPage() {
  const [page, setPage] = useState(1);
  // Only a query param changes, so "auto" keeps the old page visible while the
  // next one loads
  const { data, loading } = useFetch(getUsers.setQueryParams({ page }));

  return (
    <UsersTable
      users={data ?? []}
      dimmed={loading}
      onNext={() => setPage((p) => p + 1)}
    />
  );
}
```

## Select part of the response

`select` picks or transforms the part of the data the component uses. The request and its cache stay shared, and the
component re-renders only when the selected value changes. The selector runs only when there is data, and callbacks
and the cache keep the full response.

```tsx title="Subscribe to one price"
function Price({ symbol }: { symbol: string }) {
  const { data: price } = useFetch(getQuotes, {
    select: (quotes) => quotes[symbol]?.price,
  });

  return <span>{price}</span>;
}
```

Responses and selected values are structurally shared: deeply equal parts keep their previous references, so
`useEffect`, `useMemo` and `React.memo` react only to real changes. Turn it off per request with
`setStructuralSharing(false)` or per hook with `structuralSharing: false`.

---

## Suspense and error boundaries

With `suspense: true` the hook suspends until the first response, so the nearest `<Suspense>` renders its fallback.
Cached or hydrated data never suspends, and a refetch after the first response does not suspend again. With
`throwOnError: true`, settled errors go to the closest Error Boundary; attempts that will retry, canceled and offline
requests never do.

```tsx title="Suspense with an error boundary"
function UsersList() {
  const { data } = useFetch(getUsers, { suspense: true, throwOnError: true });

  return <UsersTable users={data ?? []} />;
}

export function App() {
  return (
    <ErrorBoundary
      fallbackRender={({ resetErrorBoundary }) => (
        <button onClick={resetErrorBoundary}>Retry</button>
      )}
    >
      <Suspense fallback={<p>Loading users...</p>}>
        <UsersList />
      </Suspense>
    </ErrorBoundary>
  );
}
```

Errors are not cached, so resetting the boundary remounts the component and fetches again. Pass a function to throw
only some errors, for example `throwOnError: (error) => error.name !== "ValidationError"`.

---

## Re-render only for what you read

The returned object tracks which fields the component reads. A component that destructures only `data` does not
re-render when `loading` or `error` change. Destructure what you render and do not spread the whole result into
children. Set `dependencyTracking: false` to re-render on every change.

`setData`, `setError` and the other setters change only this hook's local state. To change data for every component,
update the cache with `client.cache.update(request, updater)`. `clearState()` resets the local state; call `refetch()`
after it to reload.

---

:::secondary Summary

1. `useFetch` sends on mount and when the request or `dependencies` change, and reads from the shared cache.
2. Use `disabled` for dependent requests and `bounce` for search inputs.
3. Callbacks receive one object; read errors from `response.error`.
4. `select`, structural sharing and dependency tracking keep re-renders to what changed.

:::
