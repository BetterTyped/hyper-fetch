# Quick start

You will build a user list with an "add user" form against a public test API. By the end, the list loads with typed
data, shows loading and error states, and refreshes after the form saves.

:::tip What you'll learn

1. **Define requests** once and share them across components.
2. **Read data** with `useFetch`.
3. **Write data** with `useSubmit` and refresh the list after it succeeds.

:::

---

## 1. Install

```npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/react
```

React 18 or later is required.

---

## 2. Create the client and requests

The client holds the base URL and the cache. Requests describe each endpoint with its types. Create both at module
level, outside components, so every component shares the same cache.

```ts title="api.ts"
import { createClient } from "@hyper-fetch/core";

export const client = createClient({ url: "https://jsonplaceholder.typicode.com" });

export type User = { id: number; name: string; email: string };

export const getUsers = client.createRequest<{ response: User[] }>()({
  endpoint: "/users",
});

export const createUser = client.createRequest<{
  response: User;
  payload: { name: string; email: string };
}>()({ endpoint: "/users", method: "POST" });
```

---

## 3. Show the list with `useFetch`

`useFetch` sends the request when the component mounts and returns its state. If the response is already cached, it
renders right away and refreshes in the background.

```tsx title="users-list.tsx"
import { useFetch } from "@hyper-fetch/react";

import { getUsers } from "./api";

export const UsersList = () => {
  // highlight-next-line
  const { data, loading, error, refetch } = useFetch(getUsers);

  // `loading` is also true while cached data refreshes, so show the spinner only without data
  if (loading && !data) return <p>Loading users...</p>;
  if (error && !data) return <button onClick={refetch}>Failed to load. Try again</button>;

  return (
    <ul>
      {data?.map((user) => (
        <li key={user.id}>
          {user.name} <small>{user.email}</small>
        </li>
      ))}
    </ul>
  );
};
```

Try mounting `<UsersList />` twice. Both lists render the same data from a single request.

---

## 4. Add a user with `useSubmit`

`useSubmit` sends nothing until you call `submit()`. It resolves with the response, so you can react to the result
right where you call it.

```tsx title="add-user-form.tsx"
import { useState } from "react";
import { useSubmit } from "@hyper-fetch/react";

import { client, createUser, getUsers } from "./api";

export const AddUserForm = () => {
  const [name, setName] = useState("");
  // highlight-next-line
  const { submit, submitting, error } = useSubmit(createUser);

  const onSubmit = async (event: React.FormEvent) => {
    event.preventDefault();
    // highlight-start
    const { success } = await submit({ payload: { name, email: `${name}@example.com` } });

    if (success) {
      setName("");
      client.cache.invalidate(getUsers); // every mounted useFetch(getUsers) refetches
    }
    // highlight-end
  };

  return (
    <form onSubmit={onSubmit}>
      <input value={name} onChange={(event) => setName(event.target.value)} placeholder="Name" />
      <button disabled={submitting}>{submitting ? "Saving..." : "Add user"}</button>
      {error && <p>{error.message}</p>}
    </form>
  );
};
```

:::info A real backend saves the user

The test API answers `201` but does not store new users, so the refetched list looks the same. Against your own API,
the new user appears in the list.

:::

---

## 5. Put it together

```tsx title="app.tsx"
import { AddUserForm } from "./add-user-form";
import { UsersList } from "./users-list";

export const App = () => (
  <main>
    <AddUserForm />
    <UsersList />
  </main>
);
```

You now have typed data in components, deduplicated requests, a cache that survives remounts and a list that refreshes
after a mutation, with no state management code.
