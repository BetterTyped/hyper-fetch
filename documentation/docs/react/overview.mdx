# React overview

`@hyper-fetch/react` connects the requests you define with [core](/docs/core/overview) to your components. You pass a
request to a hook and get typed `data`, `error` and loading state back. There are no query keys or fetcher functions to
write: the request already knows its endpoint, its types and its cache key.

```tsx title="users.tsx"
import { useFetch, useSubmit } from "@hyper-fetch/react";

import { client } from "./api/client";
import { getUsers, createUser } from "./api/users";

export const Users = () => {
  // highlight-start
  const { data, loading, error } = useFetch(getUsers);
  const { submit, submitting } = useSubmit(createUser);
  // highlight-end

  const addUser = async () => {
    const { success } = await submit({ payload: { name: "Ann" } });
    if (success) client.cache.invalidate(getUsers); // the list above refetches
  };

  if (loading && !data) return <p>Loading...</p>;
  if (error && !data) return <p>{error.message}</p>;

  return (
    <>
      {data?.map((user) => <p key={user.id}>{user.name}</p>)}
      <button onClick={addUser} disabled={submitting}>
        Add user
      </button>
    </>
  );
};
```

`data` is typed as `User[] | null` from the request, so the hook needs no generics.

## What the hooks handle

<Tabs>
<TabItem value="fetch" label="Fetch with params">

Derive a request inline. When `userId` changes, the hook switches to the new cache key and fetches, and it never shows
data of the previous user for the new one.

```tsx
const UserCard = ({ userId }: { userId: number }) => {
  // highlight-next-line
  const { data, loading, refetch } = useFetch(getUser.setParams({ userId }));

  if (loading && !data) return <Spinner />;
  return <h2 onClick={refetch}>{data?.name}</h2>;
};
```

</TabItem>
<TabItem value="shared" label="Shared state">

Components that use the same request share one cache entry and one in-flight call. Mount the same hook ten times and
the server sees one request.

```tsx
const Header = () => {
  const { data } = useFetch(getCurrentUser); // request #1
  return <Avatar user={data} />;
};

const Sidebar = () => {
  // highlight-next-line
  const { data } = useFetch(getCurrentUser); // joins request #1, same data
  return <p>{data?.name}</p>;
};
```

</TabItem>
<TabItem value="optimistic" label="Optimistic updates">

Describe the change once on the request. Core applies it to the cache before the server answers and rolls it back if
the request fails. The component stays plain.

```tsx
import { optimistic } from "@hyper-fetch/core";

const toggleTodo = client
  .createRequest<{ response: Todo; payload: { done: boolean } }>()({
    endpoint: "/todos/:todoId",
    method: "PATCH",
  })
  // highlight-start
  .setOptimistic(({ params, payload }) => [
    optimistic(getTodos).patch(params.todoId, payload),
  ]);
// highlight-end

const { submit } = useSubmit(toggleTodo);
submit({ params: { todoId: todo.id }, payload: { done: !todo.done } });
```

</TabItem>
<TabItem value="infinite" label="Infinite lists">

`useInfiniteFetch` pages through a list and flattens the pages into `items`.

```tsx
const { items, hasNextPage, fetchNextPage, isFetchingNextPage } =
  useInfiniteFetch(getFeed, {
    // highlight-next-line
    pagination: { cursor: "cursor", next: "nextCursor", items: "data" },
  });
```

</TabItem>
<TabItem value="realtime" label="Realtime">

With [`@hyper-fetch/sockets`](/docs/sockets/overview), `useListener` keeps the latest message of a topic and
`useEmitter` sends typed messages. Both clean up on unmount.

```tsx
const ChatRoom = ({ roomId }: { roomId: string }) => {
  // highlight-start
  const { data: lastMessage } = useListener(
    onChatMessage.setParams({ roomId }),
  );
  const { emit, connected } = useEmitter(sendChatMessage);
  // highlight-end

  return (
    <button
      disabled={!connected}
      onClick={() => emit({ params: { roomId }, payload: { text: "Hi" } })}
    >
      Reply to {lastMessage?.author}
    </button>
  );
};
```

</TabItem>
<TabItem value="renders" label="Fewer re-renders">

Hooks track which fields you read. This component re-renders when `data` changes and ignores changes of `loading`,
`error` and every other field.

```tsx
// highlight-next-line
const { data } = useFetch(getUsers);
```

Hook results also print readable values in `console.log`, such as `{ data: [...], loading: false }`.

</TabItem>
</Tabs>

## The hooks

| Hook                                                           | Use it to                                                               |
| -------------------------------------------------------------- | ----------------------------------------------------------------------- |
| [`useFetch`](/docs/react/hooks/use-fetch)                  | Load data on mount and whenever the request changes                     |
| [`useSubmit`](/docs/react/hooks/use-submit)                | Create, update or delete on demand with `submit()`                      |
| [`useInfiniteFetch`](/docs/react/hooks/use-infinite-fetch) | Load more pages for infinite scroll                                     |
| [`useCache`](/docs/react/hooks/use-cache)                  | Read and change a cache entry without sending a request                 |
| [`useQueue`](/docs/react/hooks/use-queue)                  | Show and control the requests waiting in a queue                        |
| [`useIsFetching`](/docs/react/hooks/use-is-fetching)       | Show a global loading indicator                                         |
| [`useAppManager`](/docs/react/hooks/use-app-manager)       | React to focus and online state                                         |
| [`useStream`](/docs/react/hooks/use-stream)                | Render a streamed response, such as LLM output, chunk by chunk          |
| [`useListener`](/docs/react/sockets/use-listener)          | Receive realtime messages of a topic                                    |
| [`useEmitter`](/docs/react/sockets/use-emitter)            | Send realtime messages                                                  |
| [`useLiveQuery`](/docs/react/db/use-live-query)            | Query a [`@hyper-fetch/db`](/docs/db/overview) collection that stays in sync |
| [`useLiveInfiniteQuery`](/docs/react/db/use-live-infinite-query) | Page through a `@hyper-fetch/db` collection                       |
| [`<Hydrate>`](/docs/react/hydrate)                         | Pass server-rendered responses to the first render                      |

## Global defaults

Hooks work without a provider. Add `<Provider>` when you want the same options on every hook, such as refetching when
the window regains focus. Options passed to a hook always win.

```tsx title="app.tsx"
import { Provider } from "@hyper-fetch/react";

export const App = () => (
  <Provider
    config={{
      // highlight-next-line
      useFetchConfig: { refetchOnFocus: true, refetchOnReconnect: true },
      useSubmitConfig: { bounce: true, bounceTime: 300 },
    }}
  >
    <Dashboard />
  </Provider>
);
```

:::warning React 18 or later

The hooks use `useSyncExternalStore`, which React 18 introduced, for concurrent rendering without tearing.

:::
