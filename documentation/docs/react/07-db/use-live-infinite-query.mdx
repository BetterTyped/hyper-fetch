# useLiveInfiniteQuery

`useLiveInfiniteQuery` shows an ordered [`@hyper-fetch/db`](/docs/db/overview) query page by page, for feeds and long
tables that grow as the user scrolls. Pages show at once when the db already holds their rows, and the query's loader
loads more only when the window runs past them. For a whole query at once, use
[`useLiveQuery`](/docs/react/db/use-live-query).

:::tip Purpose

1. **Pages of any size**: the UI's `pageSize` is independent of the backend's page size.
2. **Instant pages**: rows the db already holds show without a request.
3. **Live windows**: inserts shift rows across pages, and deletes pull the next row in.

:::

---

## Usage

```tsx title="components/feed.tsx"
import { eq } from "@hyper-fetch/db";
import { useLiveInfiniteQuery } from "@hyper-fetch/react";
import { db } from "./db";

function Feed({ teamId }: { teamId: number }) {
  const { data, hasNextPage, fetchNextPage, isFetchingNextPage } =
    useLiveInfiniteQuery(
      db.post
        .where((post) => eq(post.teamId, teamId))
        .orderBy((post) => post.createdAt, "desc"),
      { pageSize: 20 },
    );

  return (
    <div>
      {data?.map((post) => (
        <p key={post.id}>{post.title}</p>
      ))}
      {hasNextPage && (
        <button onClick={() => fetchNextPage()} disabled={isFetchingNextPage}>
          Load more
        </button>
      )}
    </div>
  );
}
```

The query must have `orderBy`, so a page never shifts between renders. Without it, the hook does not compile.

---

## Options

| Option     | Type     | Default  | Description                                                         |
| ---------- | -------- | -------- | ------------------------------------------------------------------- |
| `pageSize` | `number` | required | Rows per page. Independent of the backend's page size.              |

---

## Returns

Everything [`useLiveQuery`](/docs/react/db/use-live-query#returns) returns, plus:

| Field                | Type                  | Description                                                                 |
| -------------------- | --------------------- | --------------------------------------------------------------------------- |
| `data`               | rows or `undefined`   | Rows of every loaded page.                                                  |
| `pages`              | `Row[][]`             | `data` split into pages of `pageSize`.                                      |
| `isFetchingNextPage` | `boolean`             | More rows are loading to fill the window after `fetchNextPage`.            |
| `fetchNextPage`      | `() => Promise<void>` | Widen the window by one page. Two calls at once load one page.              |
| `refetch`            | `() => Promise<void>` | Load the query again from its first page.                                   |

---

## How pages load

- A cursor loader loads its next backend pages until the db holds one row past the window.
- A loader with `limit` and no cursor is sent the window size plus one, and keeps showing the last window while the
  wider one loads.
- A loader that is not paginated has loaded every row already.
- A page that fails to load keeps the pages shown so far and sets `error`, and the next call tries again.
- The same query keeps its loaded pages across renders. A different query or `pageSize` starts again from the first
  page.

Outside React, `query.infinite({ pageSize })` returns the same window with `subscribe`, `getSnapshot` and
`fetchNextPage`.

---

:::secondary Summary

1. `useLiveInfiniteQuery(query, { pageSize })` shows an ordered query page by page.
2. Pages show at once from rows the db holds, and load from the backend only when needed.
3. The window stays live as rows are inserted and deleted.

:::
