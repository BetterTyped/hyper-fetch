# Socket SDK

The **socket SDK** is a typed tree of every listener and emitter of a server, the realtime twin of the
[HTTP SDK](/docs/core/sdk). You describe the topics once in a schema type, and `createSocketSdk` builds the
[listener](/docs/sockets/listener) or [emitter](/docs/sockets/emitter) for a path when you access its `$listener` or
`$emitter` key.

```ts title="sdk.ts"
import { createSocketClient, createSocketSdk } from "@hyper-fetch/sockets";
import type { EmitterModel, ListenerModel } from "@hyper-fetch/sockets";

type ChatMessage = { text: string; user: string };

type ChatSchema = {
  chat: {
    messages: {
      $listener: ListenerModel<{ response: ChatMessage; topic: "chat/messages" }>;
      $emitter: EmitterModel<{ payload: { text: string }; topic: "chat/messages" }>;
    };
  };
};

export const socket = createSocketClient({ url: "wss://api.example.com/ws" });
export const sdk = createSocketSdk<typeof socket, ChatSchema>(socket);

sdk.chat.messages.$listener.listen(({ data }) => console.log(data.user, data.text));
sdk.chat.messages.$emitter.emit({ payload: { text: "Hello" } });
```

The generics are the socket type first and the schema second. Instances are created on access, so a large schema costs
nothing until you use it.

:::tip Purpose

1. **One typed tree** for every topic of a server, with responses and payloads checked.
2. **No per-topic boilerplate**: listeners and emitters are created from the path.
3. **Central configuration** with `$configure`, by topic, wildcard or path.

:::

## Topics come from the path

The runtime topic is built from the property path, not from the `topic` in the model. Keep the two equal, or the types
describe a topic the SDK never uses.

| Access                           | Topic            | Rule                                          |
| -------------------------------- | ---------------- | --------------------------------------------- |
| `sdk.chat.messages.$listener`    | `chat/messages`  | Segments are joined with `/`                  |
| `sdk.chat.$roomId.$listener`     | `chat/:roomId`   | A `$name` segment becomes a param             |
| `sdk.liveTrades.$listener`       | `live-trades`    | camelCase becomes kebab-case, default `true`  |

Turn the kebab-case conversion off with `createSocketSdk(socket, { camelCaseToKebabCase: false })`.

```ts title="rooms.ts"
type RoomSchema = {
  chat: {
    $roomId: {
      $listener: ListenerModel<{ response: ChatMessage; topic: "chat/:roomId" }>;
    };
  };
};

const rooms = createSocketSdk<typeof socket, RoomSchema>(socket);

rooms.chat.$roomId.$listener.setParams({ roomId: "general" }).listen(({ data }) => console.log(data.text));
```

## Describe topics with models

Use `ListenerModel` and `EmitterModel` for schema leaves. Fields you leave out stay strict, so a topic without a
payload rejects one. `ListenerInstance` and `EmitterInstance` default every field to `any` and are for generic
constraints in reusable helpers.

| Model           | Fields                                                     | Defaults                                         |
| --------------- | ---------------------------------------------------------- | ------------------------------------------------ |
| `ListenerModel` | `response`, `payload`, `topic`, `hasPayload`, `hasParams`, `delivered` | `unknown`, `undefined`, `string`, `false`, `false`, `response` |
| `EmitterModel`  | `payload`, `topic`, `hasPayload`, `hasParams`              | `undefined`, `string`, `false`, `false`          |

You never set `socket` in a model: `createSocketSdk(socket)` adds it to every leaf, with its adapter types.

Set `delivered` only when a [delivery strategy](/docs/sockets/listener#throttle-or-batch-fast-topics) changes what
callbacks receive, because a strategy configured at runtime cannot change schema types:

```ts title="trades.ts"
type TradesSchema = {
  liveTrades: {
    $listener: ListenerModel<{ response: Trade; topic: "live-trades"; delivered: Trade[] }>;
  };
};

const trades = createSocketSdk<typeof socket, TradesSchema>(socket, {
  defaults: { "live-trades": { delivery: { strategy: "batch", interval: 100 } } },
});

trades.liveTrades.$listener.listen(({ data }) => console.log(data.length)); // data: Trade[]
```

## Configure many topics at once

`defaults` in the options, or `sdk.$configure(map)`, applies settings to the leaves a key matches. `$configure` returns a
new SDK and merges with the defaults it already has.

```ts title="sdk.ts"
const configured = sdk.$configure({
  "chat/*": { delivery: { strategy: "latest", interval: 50 } },
  "chat.messages.$emitter": (emitter) => emitter.setPayloadMapper((payload) => ({ ...payload, sentAt: Date.now() })),
});
```

| Key                                       | Matches                                    |
| ----------------------------------------- | ------------------------------------------ |
| `"*"`                                     | Every listener and emitter                 |
| An exact topic, such as `"chat/messages"` | The leaves with that topic                 |
| A wildcard, such as `"chat/*"`            | Topics under `chat/`, and `chat` itself    |
| A dot path, such as `"chat.messages.$listener"` | That one leaf                        |

- A value is either an object or a function `(instance) => instance` with access to every setter.
- In an object, `options` goes to `setOptions` and `delivery` to `setDelivery`. Emitters ignore `delivery`.
- Keys apply in order: `"*"`, then topic keys, then dot paths, so the most specific one wins.
- `options` must be options the adapter understands. The WebSocket and SSE adapters have none.

To keep the configuration in its own file, type it with `createSocketConfiguration`:

```ts title="chat.config.ts"
import { createSocketConfiguration } from "@hyper-fetch/sockets";

export const chatConfig = createSocketConfiguration<ChatSchema>()({
  "chat/*": { delivery: { strategy: "latest", interval: 50 } },
});
```

---

:::secondary Summary

- Describe topics with `ListenerModel` and `EmitterModel`, and keep each `topic` equal to its path.
- `createSocketSdk<typeof socket, Schema>(socket)` builds listeners and emitters on access.
- `$name` segments become params, and camelCase keys become kebab-case topics unless you turn it off.
- Configure many leaves with `defaults` or `$configure`, from `"*"` to a single dot path.

:::
