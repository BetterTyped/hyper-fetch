# Socket

A **`Socket`** owns one connection to a realtime server. It holds the URL, the [adapter](/docs/sockets/adapter), the
reconnect policy and the auth hook, and it creates the [listeners](/docs/sockets/listener) and
[emitters](/docs/sockets/emitter) that use the connection. It is the realtime counterpart of the
[Client](/docs/core/client): create one per server, at module level.

```ts title="socket.ts"
import { createSocketClient } from "@hyper-fetch/sockets";

export const socket = createSocketClient({ url: "wss://api.example.com/ws" });

export const onMessage = socket.createListener<{ text: string }>()({ topic: "chat" });
export const sendMessage = socket.createEmitter<{ text: string }>()({ topic: "chat" });
```

`createSocketClient(options)` and `new Socket(options)` are the same. The WebSocket adapter connects as soon as the
socket is created, default `autoConnect: true`, change it with `adapterOptions: { autoConnect: false }`.

:::tip Purpose

1. **One connection per server**, shared by every listener and emitter created from it.
2. **Fresh credentials** on every connection attempt with `onConnect`.
3. **Automatic reconnects** with backoff, jitter, and network and focus handling.
4. **Lifecycle events** for connection state, messages and errors.

:::

## Pick the transport

The adapter decides how the socket talks to the server. WebSocket is the default. Pass another adapter, such as
Server-Sent Events, and your listeners keep working.

```ts title="events.ts"
import { createSocketClient, ServerSentEventsAdapter } from "@hyper-fetch/sockets";

export const events = createSocketClient({
  url: "https://api.example.com/events",
  adapter: ServerSentEventsAdapter(),
});
```

The [Adapter](/docs/sockets/adapter) page lists the built-in adapters, their options and how to map another message
format.

## Authenticate every connection attempt

`onConnect` runs before every attempt: the first connection, automatic reconnects and manual reconnects. It receives
the connection (`url`, `queryParams`, `adapterOptions`) and the `attempt` number, and returns the connection to use. It
can be async, so a reconnect never reuses an expired token.

```ts title="socket.ts"
export const socket = createSocketClient({ url: "wss://api.example.com/ws" }).onConnect(
  async ({ connection, attempt }) => {
    // attempt is 0 for a fresh connection
    const token = await getAccessToken({ forceRefresh: attempt > 0 });
    return { ...connection, queryParams: { token } };
  },
);
```

Chain `onConnect` right after creating the socket, so it applies to the first connection. If it throws, the attempt
fails, `onError` receives the error and the socket stays disconnected until you call `connect()` or `reconnect()`.

---

## Change query params or the URL at runtime

`setQueryParams` and `setUrl` change what the next attempt uses. Neither reconnects on its own, so call `reconnect()`
to apply them to a live connection. Listeners stay registered and receive messages from the new connection.

```ts title="switch-region.ts"
socket.setUrl("wss://eu.example.com/ws").setQueryParams({ tenant: "eu" });
await socket.reconnect();
```

For values that change with your app state, such as a token or a tenant, prefer `onConnect`.

---

## Tune reconnects

A lost connection comes back on its own. The delay before attempt `n` (from 0) is
`reconnectTime + random(0, min(maxReconnectTime - reconnectTime, reconnectTime * 2 ** n))`, an exponential backoff with
full jitter, so clients of a restarted server spread out.

```ts title="socket.ts"
import { createSocketClient, defaultShouldReconnect } from "@hyper-fetch/sockets";

export const socket = createSocketClient({
  url: "wss://api.example.com/ws",
  reconnect: 20, // attempts per outage
  maxReconnectTime: 15_000,
  // 4401 is an app-level "token rejected" close: retrying cannot fix it
  shouldReconnect: (loss) => defaultShouldReconnect(loss) && loss.code !== 4401,
});
```

- A normal closure (`1000`) from the server stays closed. Every other loss is retried. Closes started by the client are
  never retried.
- Going offline drops the connection without counting attempts, and coming back online connects at once. Regaining
  focus skips the rest of a pending delay.
- `reconnectDelay: ({ attempt, elapsed, reason }) => number | null` replaces the backoff. Return `null` to stop.
- A manual `reconnect()` is never refused by the `reconnect` limit.

The [reconnection guide](/docs/guides/sockets/websocket-reconnection-and-errors) shows close codes, error handling and
reconnect UI.

## Connect, disconnect and destroy

```ts title="lifecycle.ts"
// No-op when already connected
await socket.connect();

// A fresh connection, also after disconnect() or when attempts ran out
await socket.reconnect();

// Stays closed until connect() or reconnect()
await socket.disconnect();

// Closes and stops following the network, for logout or tenant switches
await socket.destroy();
```

`destroy()` also removes the adapter's app manager subscriptions, so nothing connects the socket again. An `appManager`
passed in the options stays mounted, because other sockets may share it.

## React to connection events

The `on*` methods register permanent callbacks and return the socket, so you can chain them at setup. For callbacks
that must be removed later, such as in a component, use `socket.events.*`, which return an unsubscribe function.

```ts title="socket.ts"
socket
  .onConnected(() => console.log("open"))
  .onDisconnected(() => console.log("closed"))
  .onReconnect(() => console.log("reconnecting"))
  .onReconnectFailed(() => console.log("gave up"))
  .onError(({ error }) => console.error(error));

const off = socket.events.onConnected(() => console.log("open"));
off();
```

The current state is on the adapter: `socket.adapter.connected`, `socket.adapter.connecting` and
`socket.adapter.reconnectionAttempts`. In React, `useListener` and `useEmitter` return it as `connected` and
`connecting`.

---

## Intercept messages

`onMessage` runs for every incoming message and returns the data delivered to listeners. `onSend` runs before every
emit and returns the emitter to send. Both must return a value.

```ts title="socket.ts"
socket
  .onMessage<{ text: string }>(({ event, topic }) => ({ ...event, text: event.text.trim() }))
  .onSend(({ emitter }) => emitter.setPayload({ ...emitter.payload, sentAt: Date.now() }));
```

`event` is the decoded message data, `topic` its topic, and `extra` the adapter's details, such as the `MessageEvent`.
Keep `onMessage` cheap, it runs before every delivery.

## Options

| Option              | Type                         | Default              | Description                                                               |
| ------------------- | ---------------------------- | -------------------- | ------------------------------------------------------------------------- |
| `url`               | `string`                     | required             | The server URL.                                                           |
| `adapter`           | `Adapter \| (() => Adapter)` | `WebsocketAdapter()` | The transport.                                                            |
| `adapterOptions`    | `object`                     | none                 | Options of the adapter, typed by it.                                      |
| `queryParams`       | `object \| string`           | none                 | Query params appended to the connection URL.                              |
| `reconnect`         | `number`                     | `Infinity`           | Reconnection attempts in one outage.                                      |
| `reconnectTime`     | `number`                     | `1000`               | Minimum delay in ms before an attempt. The backoff starts here.           |
| `maxReconnectTime`  | `number`                     | `30000`              | Maximum delay in ms before an attempt.                                    |
| `minUptime`         | `number`                     | `5000`               | How long in ms a connection stays up before the attempt counter resets.  |
| `connectionTimeout` | `number`                     | `5000`               | How long in ms one attempt may take, handshake included.                  |
| `reconnectDelay`    | `function`                   | jittered backoff     | `({ attempt, elapsed, reason }) => number \| null`. `null` stops.         |
| `shouldReconnect`   | `function`                   | retry all but `1000` | `({ code, reason, error }) => boolean`. Which lost connections retry.     |
| `appManager`        | `() => AppManager`           | `new AppManager()`   | Tracks online and focus state, for example in React Native or Node.js.    |

The [Socket API reference](/docs/api/sockets/Classes/Socket) lists every method.

---

## TypeScript

`Socket` has one generic, the adapter type. It is inferred from the `adapter` option and types `adapterOptions`,
`queryParams`, listener and emitter `options`, the `extra` of every message and the connection in `onConnect`. You never
pass it by hand.

---

:::secondary Summary

- Create one socket per server and define its listeners and emitters next to it.
- Resolve tokens in `onConnect`, so every attempt uses a fresh one.
- Let the socket reconnect, and tune it with `reconnect`, `reconnectTime`, `maxReconnectTime` and `shouldReconnect`.
- Call `destroy()` when the socket is no longer needed.

:::
