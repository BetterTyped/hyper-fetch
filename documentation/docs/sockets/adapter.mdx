Adapter is a class that specifies how to communicate with the server. It defines the way to send and receive data,
handle errors, handle reconnects, and more. The `@hyper-fetch/sockets` package ships with two built-in adapters:
`WebsocketAdapter` and `ServerSentEventsAdapter`. Other integrations such as Firebase Realtime Database are available as
separate packages (e.g., `@hyper-fetch/firebase`).

---

## Built in Adapters

There are two built in adapters - `WebsocketAdapter` and `ServerSentEventsAdapter` providing basic functionality for the
`Websocket` and `Server Sent Events (SSE)` connection types.

Both use the global `WebSocket` / `EventSource` of the runtime, so they work in browsers, Bun, Deno and Node.js 22+ (for
`WebSocket`). Where a global is missing, pass the constructor in `adapterOptions` - for example Node.js has no global
`EventSource`:

```ts
import { EventSource } from "eventsource";

const socket = new Socket({
  url: "http://localhost:3000/events",
  adapter: ServerSentEventsAdapter(),
  adapterOptions: { EventSource },
});
```

:::caution Server rendering

A socket connects wherever the runtime has a `WebSocket`, the server included - Node.js 22+ has one. When a socket is
created while rendering on the server (Next.js, Remix), it opens a connection from the server. Create sockets on the
client only, or turn the automatic connection off on the server:

```ts
const socket = new Socket({ url, adapterOptions: { autoConnect: typeof window !== "undefined" } });
```

:::

### Websocket Adapter

The default adapter is used to communicate with the `Websocket` server.

(@import sockets WebsocketAdapter type=import)

```tsx
import { createSocketClient, WebsocketAdapter } from "@hyper-fetch/sockets";

const socket = createSocketClient({
  url: "ws://localhost:3000",
  adapter: WebsocketAdapter(),
});
```

#### Options

You can pass adapter-specific options via the `adapterOptions` constructor option on `Socket`.

| Option             | Type                                                                           | Default                           | Description                                                                             |
| ------------------ | ------------------------------------------------------------------------------ | --------------------------------- | --------------------------------------------------------------------------------------- |
| `autoConnect`      | `boolean`                                                                      | `true`                            | Automatically connect when the socket is created.                                       |
| `WebSocket`        | `typeof WebSocket`                                                             | global `WebSocket`                | The WebSocket constructor, e.g. from the `ws` package, for runtimes without the global. |
| `protocols`        | `string \| string[]`                                                           | —                                 | Subprotocols passed to the `WebSocket` constructor (`Sec-WebSocket-Protocol` header).   |
| `heartbeat`        | `boolean`                                                                      | —                                 | Enable heartbeat messages to keep the connection alive.                                 |
| `heartbeatMessage` | `string`                                                                       | —                                 | The message payload sent for heartbeats.                                                |
| `pingTimeout`      | `number`                                                                       | —                                 | Timeout (ms) to wait for a ping response.                                               |
| `pongTimeout`      | `number`                                                                       | —                                 | Timeout (ms) to wait for a pong response.                                               |
| `decode`           | `(event: MessageEvent) => { topic, data } \| null`                             | JSON `{ topic, data }`            | Turns an incoming frame into a listener event. Return `null` to ignore the frame.       |
| `encode`           | `({ topic, payload }) => string \| ArrayBufferLike \| Blob \| ArrayBufferView` | `JSON.stringify({ topic, data })` | Turns an emitted message (and the heartbeat) into the frame passed to `websocket.send`. |

```tsx
const socket = createSocketClient({
  url: "ws://localhost:3000",
  adapterOptions: {
    autoConnect: false,
    protocols: ["v1"],
    heartbeat: true,
    heartbeatMessage: "ping",
  },
});
```

#### Custom message format

By default every frame is a JSON `{ topic, data }` object. When your server speaks a different format - for example
`{ type, payload }` - map it with the `decode` and `encode` options instead of writing a custom adapter. Frames decoded
to `null` (pings, unknown messages) are ignored, and errors thrown by either function are reported through `onError`.

```tsx
const socket = createSocketClient({
  url: "wss://example.com/ws",
  adapterOptions: {
    // highlight-start
    decode: (event) => {
      const message = JSON.parse(event.data);
      if (message.type === "pong") return null;
      return { topic: message.type, data: message.payload };
    },
    encode: ({ topic, payload }) => JSON.stringify({ type: topic, payload }),
    // highlight-end
  },
});
```

#### Dynamic options

Every adapter option can be resolved right before a connection attempt with the `onConnect` interceptor on the socket.
It runs for the initial connection, automatic reconnects and manual reconnects, so short-lived values such as auth
tokens passed through `protocols` are always fresh.

```tsx
const socket = createSocketClient({
  url: "wss://example.com/ws",
}).onConnect(({ connection }) => ({
  ...connection,
  adapterOptions: {
    ...connection.adapterOptions,
    protocols: ["authorization", authStore.getState().accessToken],
  },
}));
```

### Server Sent Events (SSE) Adapter

The `ServerSentEventsAdapter` is used to communicate with the `Server Sent Events (SSE)` server.

:::caution SSE is receive-only

The SSE adapter does **not** support emitting events. Calling `emit` on an emitter with this adapter will throw an
error. Use the `WebsocketAdapter` if you need bidirectional communication.

:::

(@import sockets ServerSentEventsAdapter type=import)

```tsx
import { createSocketClient, ServerSentEventsAdapter } from "@hyper-fetch/sockets";

const socket = createSocketClient({
  url: "http://localhost:3000",
  adapter: ServerSentEventsAdapter(),
});
```

#### Options

| Option            | Type                                               | Default                | Description                                                                                                   |
| ----------------- | -------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------- |
| `autoConnect`     | `boolean`                                          | `true`                 | Automatically connect when the socket is created.                                                             |
| `EventSource`     | `typeof EventSource`                               | global `EventSource`   | The EventSource constructor, e.g. from the `eventsource` package in Node.js.                                  |
| `eventSourceInit` | `EventSourceInit`                                  | —                      | Options passed to the underlying `EventSource` constructor (e.g., `withCredentials`).                         |
| `decode`          | `(event: MessageEvent) => { topic, data } \| null` | JSON `{ topic, data }` | Turns an incoming message, named events included, into a listener event. Return `null` to ignore the message. |

Unnamed messages carry `{ topic, data }` JSON. A **named event** (`event: tick` on the wire) goes to the listeners whose
topic is the event name, with the data parsed as JSON, or kept as text when it is not JSON:

```tsx
// server: event: tick\ndata: {"count":1}
socket
  .createListener<{ count: number }>()({ topic: "tick" })
  .listen(({ data }) => console.log(data.count));
```

```tsx
const socket = createSocketClient({
  url: "http://localhost:3000",
  adapter: ServerSentEventsAdapter(),
  adapterOptions: {
    autoConnect: false,
    eventSourceInit: { withCredentials: true },
  },
});
```

## Custom Adapter

There is nothing to prevent you from changing this and creating the adapter you need. Thanks to event communication, you
can set your own adapter as you wish by only fulfilling the typescript requirements. This way you can create your own
adapters for existing libraries like `socket.io`. Refer to the `SocketAdapter` API reference for the full contract your
custom adapter must satisfy.

The connector receives a set of bindings that keep your adapter consistent with the rest of the system. Pass them to
`createReconnectingConnection` and describe only your transport - the engine owns the lifecycle every built-in adapter
shares: one attempt at a time, the connection timeout, backoff with jitter, the retry policy, network and focus
handling, and closing on purpose.

```ts
import {
  SocketAdapter,
  createReconnectingConnection,
  defaultShouldReconnect,
  getSocketUrl,
} from "@hyper-fetch/sockets";

const MyAdapter = () =>
  new SocketAdapter({ name: "my-adapter" }).setConnector((bindings) => {
    // The transport of the current attempt
    let transport: MyTransport | null = null;

    const connection = createReconnectingConnection({
      bindings,
      autoConnect: bindings.adapter.adapterOptions?.autoConnect ?? true,
      // The protocol's close codes that retrying can't fix, on top of the default - the socket's option wins over it
      shouldReconnect: (loss) => defaultShouldReconnect(loss) && loss.code !== 4401,
      open: (attempt) => {
        const url = getSocketUrl(attempt.connection.url, bindings.getQueryParams(attempt.connection.queryParams));
        const current = new MyTransport(url, attempt.connection.adapterOptions);
        transport = current;

        current.on("open", () => attempt.ready());
        current.on("close", ({ code, reason }) => attempt.lost({ code, reason }));
        current.on("message", (message) => {
          if (attempt.isCurrent()) {
            bindings.onEvent({ topic: message.topic, data: message.data, extra: message });
          }
        });

        return {
          close: () => {
            if (transport === current) transport = null;
            current.close();
          },
        };
      },
    });

    return {
      ...connection,
      listen: (listener, callback) => bindings.onListen({ listener, callback }),
      emit: (emitter) => transport?.send(emitter.payload),
    };
  });
```

- `open` runs for every attempt with the connection details after the `onConnect` interceptors. Return `null` when the
  transport can't be created - after reporting it with `bindings.onConnectFailed({ error })`.
- Call `ready()` once the connection can carry messages - on open, or after the handshake of a protocol that has one.
  The connection timeout covers the whole way there.
- Call `lost()` when the transport is gone. The engine closes it, reports the disconnection and plans the next attempt.
- Call `interrupted()` for a transport that reconnects by itself, like `EventSource`. The socket is reported as
  connecting, `ready()` brings it back, and the connection timeout replaces it if it doesn't come back in time.
- Events of a replaced or closed transport never reach the socket. `isCurrent()` tells your own handlers the same.

The connection's `dispose` removes the app manager listeners. Return it from the connector - it runs on
`socket.destroy()` and before the adapter is initialized for another socket.

### Subscriptions with a payload

When the server starts a subscription per request, like tRPC or oRPC, read the
[subscription payload](/docs/sockets/listener#subscription-payload) from `listener.payload` in `listen`. Listeners of
one topic can then carry different payloads, so pass `callbacks` to `onEvent` to deliver a message only to the listeners
of its subscription.

```ts
const listen = (listener, callback) => {
  const subscription = subscribe(listener.topic, listener.payload, (data) => {
    onEvent({ topic: listener.topic, data, extra: undefined, callbacks: subscription.callbacks });
  });
  subscription.callbacks.add(callback);

  return onListen({ listener, callback, onUnmount: () => subscription.remove(callback) });
};
```

When the server confirms and ends subscriptions, create the adapter with `confirmsSubscriptions: true` and report both
with `onListenerStart` and `onListenerEnd`. Listeners then follow the server: `onEnd` runs, the listener unsubscribes
and `useListener` switches its `status` to `ended` or `failed`.

```ts
const adapter = new SocketAdapter({ name: "rpc", confirmsSubscriptions: true }).setConnector(
  ({ onListen, onEvent, onListenerStart, onListenerEnd }) => {
    // ...
    server.on("started", (subscription) => {
      onListenerStart({ topic: subscription.topic, callbacks: subscription.callbacks });
    });
    server.on("stopped", (subscription, error) => {
      onListenerEnd({ topic: subscription.topic, callbacks: subscription.callbacks, error: error ?? null });
    });
    // ...
  },
);
```

Call `onListenerStart` again after a reconnect restarted a subscription, and for a callback that joins a subscription
that is already running. Without `confirmsSubscriptions` a listener counts as started as soon as it is registered.

#### Listener query params

An adapter can let listeners carry query params, such as filters, with the seventh `SocketAdapter` generic. Your
`listen` reads them from `listener.queryParams`. To accept a callback, register `setListenerQueryParamsResolver`: the
resolver runs when the listener is created or `setQueryParams` is called, and the listener stores what it returns.

```ts
const adapter = new SocketAdapter<Extra, undefined, ListenerOptions, undefined, undefined, DefaultMapperType, Filters>({
  name: "my-adapter",
}).setListenerQueryParamsResolver((callback) => callback(createFilters()).toJSON());
```
