# Adapter

A socket **adapter** is the transport of a [socket](/docs/sockets/socket): it opens the connection, turns incoming
frames into listener messages and sends what emitters emit. `@hyper-fetch/sockets` ships `WebsocketAdapter`, the
default, and `ServerSentEventsAdapter`. Swap the adapter and your listeners keep working.

```ts title="events.ts"
import {
  createSocketClient,
  ServerSentEventsAdapter,
} from "@hyper-fetch/sockets";

export const events = createSocketClient({
  url: "https://api.example.com/events",
  adapter: ServerSentEventsAdapter(),
  adapterOptions: { eventSourceInit: { withCredentials: true } },
});
```

`adapterOptions` is typed by the adapter you pass.

:::tip Purpose

1. **Pick a transport**: WebSocket for both directions, Server-Sent Events for a stream from the server.
2. **Match your server's format** with `decode` and `encode`, without a custom adapter.
3. **Reconnect the same way** on every adapter, through one shared reconnection engine.

:::

| Transport                 | Adapter                                                                   | Emits |
| ------------------------- | ------------------------------------------------------------------------- | :---: |
| WebSocket                 | `WebsocketAdapter` (default)                                              |  Yes  |
| Server-Sent Events        | `ServerSentEventsAdapter`                                                 |  No   |
| GraphQL subscriptions     | `GraphqlWsAdapter` from [`@hyper-fetch/graphql`](/docs/integrations/adapter-graphql/subscriptions) |  No   |
| Firestore and Realtime DB | `FirebaseSocketsAdapter` from [`@hyper-fetch/firebase`](/docs/integrations/adapter-firebase/realtime-queries) |  No   |
| tRPC and oRPC             | from [`@hyper-fetch/trpc`](/docs/integrations/adapter-trpc/overview) and [`@hyper-fetch/orpc`](/docs/integrations/adapter-orpc/overview) |  No   |

## WebSocket adapter

`WebsocketAdapter` is used when you pass no adapter. It uses the global `WebSocket` of browsers, Node.js 22+, Bun and
Deno. Elsewhere, pass the class from `ws` in `adapterOptions`.

```ts title="socket.ts"
import { createSocketClient } from "@hyper-fetch/sockets";
import { WebSocket } from "ws";

export const socket = createSocketClient({
  url: "wss://api.example.com/ws",
  adapterOptions: {
    WebSocket: WebSocket as unknown as typeof globalThis.WebSocket,
    protocols: ["v1"],
    heartbeat: true,
  },
});
```

| Option             | Type                                               | Default                           | Description                                                                          |
| ------------------ | -------------------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------ |
| `autoConnect`      | `boolean`                                          | `true`                            | Connect when the socket is created.                                                  |
| `WebSocket`        | `typeof WebSocket`                                 | global `WebSocket`                | The WebSocket class, such as the one from `ws`.                                      |
| `protocols`        | `string \| string[]`                               | none                              | Subprotocols, sent in the `Sec-WebSocket-Protocol` header.                           |
| `heartbeat`        | `boolean`                                          | `false`                           | Send a ping after `pingTimeout` and reconnect when nothing arrives within `pongTimeout`. |
| `heartbeatMessage` | `string`                                           | `"heartbeat"`                     | The payload of the ping, sent on the `heartbeat` topic.                              |
| `pingTimeout`      | `number`                                           | `5000`                            | Time in ms before a ping is sent.                                                    |
| `pongTimeout`      | `number`                                           | `5000`                            | Time in ms to wait for any message after a ping.                                     |
| `decode`           | `(event: MessageEvent) => { topic, data } \| null` | JSON `{ topic, data }`            | Turns an incoming frame into a listener message. `null` ignores the frame.           |
| `encode`           | `({ topic, payload }) => frame`                    | `JSON.stringify({ topic, data })` | Turns an emitted message, and the heartbeat, into the frame to send.                 |

Heartbeat detects dead connections behind proxies. Any incoming frame counts as the answer to a ping.

## Server-Sent Events adapter

`ServerSentEventsAdapter` receives a stream over plain HTTP. It cannot send: `emit()` on an SSE socket throws. Send to
the server with a [request](/docs/core/request) instead.

| Option            | Type                                               | Default                | Description                                                            |
| ----------------- | -------------------------------------------------- | ---------------------- | ---------------------------------------------------------------------- |
| `autoConnect`     | `boolean`                                          | `true`                 | Connect when the socket is created.                                    |
| `EventSource`     | `typeof EventSource`                               | global `EventSource`   | The EventSource class, such as the one from `eventsource` in Node.js.  |
| `eventSourceInit` | `EventSourceInit`                                  | none                   | Options of the `EventSource`, such as `withCredentials`.               |
| `decode`          | `(event: MessageEvent) => { topic, data } \| null` | JSON `{ topic, data }` | Turns a message, named events included, into a listener message.      |

Unnamed messages carry `{ topic, data }` JSON. A **named event** (`event: tick` on the wire) goes to the listeners whose
topic is the event name, with its data parsed as JSON, or kept as text when it is not JSON.

```ts title="ticks.ts"
// server sends: event: tick\ndata: {"count":1}
events
  .createListener<{ count: number }>()({ topic: "tick" })
  .listen(({ data }) => console.log(data.count));
```

Node.js has no global `EventSource`. Pass the one from the `eventsource` package with `adapterOptions: { EventSource }`.

## Map your server's message format

By default every frame is JSON `{ topic, data }`. When your server speaks another format, such as `{ type, payload }`,
map it with `decode` and `encode`. Frames decoded to `null`, such as pings, are ignored, and errors thrown by either
function are reported through `onError`.

```ts title="socket.ts"
export const socket = createSocketClient({
  url: "wss://example.com/ws",
  adapterOptions: {
    decode: (event) => {
      const message = JSON.parse(event.data);
      if (message.type === "pong") return null;
      return { topic: message.type, data: message.payload };
    },
    encode: ({ topic, payload }) => JSON.stringify({ type: topic, payload }),
  },
});
```

## Resolve options per connection attempt

Any adapter option can be set right before each attempt with the socket's `onConnect`, for example a short-lived token
sent as a subprotocol.

```ts title="socket.ts"
export const socket = createSocketClient({
  url: "wss://example.com/ws",
}).onConnect(({ connection }) => ({
  ...connection,
  adapterOptions: {
    ...connection.adapterOptions,
    protocols: ["authorization", getAccessToken()],
  },
}));
```

:::caution Server rendering

A socket connects wherever the runtime has a `WebSocket`, the server included. When a socket module is evaluated while
rendering on the server (Next.js, Remix), it opens a connection from the server. Create sockets on the client only, or
pass `adapterOptions: { autoConnect: typeof window !== "undefined" }`.

:::

## Write a custom adapter

Write an adapter for a protocol the built-in ones do not speak, such as socket.io. A `SocketAdapter` gets a connector
with bindings that keep it consistent with the rest of the system. Pass them to `createReconnectingConnection` and
describe only your transport. The [reconnection engine](/docs/sockets/socket#tune-reconnects) owns the rest: one attempt
at a time, the connection timeout, backoff with jitter, the retry policy, network and focus handling.

```ts title="my-adapter.ts"
import {
  SocketAdapter,
  createReconnectingConnection,
  defaultShouldReconnect,
  getSocketUrl,
} from "@hyper-fetch/sockets";

const MyAdapter = () =>
  new SocketAdapter({ name: "my-adapter" }).setConnector((bindings) => {
    // The transport of the current attempt
    let transport: MyTransport | null = null;

    const connection = createReconnectingConnection({
      bindings,
      autoConnect: bindings.adapter.adapterOptions?.autoConnect ?? true,
      // Close codes retrying can't fix, on top of the default. The socket's
      // option wins over it
      shouldReconnect: (loss) =>
        defaultShouldReconnect(loss) && loss.code !== 4401,
      open: (attempt) => {
        const url = getSocketUrl(
          attempt.connection.url,
          bindings.getQueryParams(attempt.connection.queryParams),
        );
        const current = new MyTransport(url, attempt.connection.adapterOptions);
        transport = current;

        current.on("open", () => attempt.ready());
        current.on("close", ({ code, reason }) =>
          attempt.lost({ code, reason }),
        );
        current.on("message", (message) => {
          if (attempt.isCurrent()) {
            bindings.onEvent({
              topic: message.topic,
              data: message.data,
              extra: message,
            });
          }
        });

        return {
          close: () => {
            if (transport === current) transport = null;
            current.close();
          },
        };
      },
    });

    return {
      ...connection,
      listen: (listener, callback) => bindings.onListen({ listener, callback }),
      emit: (emitter) => transport?.send(emitter.payload),
    };
  });
```

- `open` runs for every attempt with the connection details after the `onConnect` interceptors. Return `null` when the
  transport can't be created, after reporting it with `bindings.onConnectFailed({ error })`.
- Call `ready()` once the connection can carry messages: on open, or after the handshake of a protocol that has one.
  The connection timeout covers the whole way there.
- Call `lost()` when the transport is gone. The engine closes it, reports the disconnection and plans the next attempt.
- Call `interrupted()` for a transport that reconnects by itself, like `EventSource`. The socket is reported as
  connecting, `ready()` brings it back, and the connection timeout replaces it if it doesn't come back in time.
- Events of a replaced or closed transport never reach the socket. `isCurrent()` tells your own handlers the same.

The connection's `dispose` removes the app manager listeners. Return it from the connector: it runs on
`socket.destroy()` and before the adapter is initialized for another socket.

### Subscriptions with a payload

When the server starts a subscription per request, like tRPC or oRPC, read the
[subscription payload](/docs/sockets/listener#start-a-server-side-subscription-with-a-payload) from `listener.payload` in `listen`. Listeners of
one topic can then carry different payloads, so pass `callbacks` to `onEvent` to deliver a message only to the listeners
of its subscription.

```ts title="my-adapter.ts"
const listen = (listener, callback) => {
  const subscription = subscribe(listener.topic, listener.payload, (data) => {
    onEvent({
      topic: listener.topic,
      data,
      extra: undefined,
      callbacks: subscription.callbacks,
    });
  });
  subscription.callbacks.add(callback);

  return onListen({
    listener,
    callback,
    onUnmount: () => subscription.remove(callback),
  });
};
```

When the server confirms and ends subscriptions, create the adapter with `confirmsSubscriptions: true` and report both
with `onListenerStart` and `onListenerEnd`. Listeners then follow the server: `onEnd` runs, the listener unsubscribes
and `useListener` switches its `status` to `ended` or `failed`.

```ts title="rpc-adapter.ts"
const adapter = new SocketAdapter({
  name: "rpc",
  confirmsSubscriptions: true,
}).setConnector(({ onListen, onEvent, onListenerStart, onListenerEnd }) => {
  // ...
  server.on("started", (subscription) => {
    onListenerStart({
      topic: subscription.topic,
      callbacks: subscription.callbacks,
    });
  });
  server.on("stopped", (subscription, error) => {
    onListenerEnd({
      topic: subscription.topic,
      callbacks: subscription.callbacks,
      error: error ?? null,
    });
  });
  // ...
});
```

Call `onListenerStart` again after a reconnect restarted a subscription, and for a callback that joins a subscription
that is already running. Without `confirmsSubscriptions` a listener counts as started as soon as it is registered.

### Listener query params

An adapter can let listeners carry query params, such as filters, with the seventh `SocketAdapter` generic. Your
`listen` reads them from `listener.queryParams`. To accept a callback, register `setListenerQueryParamsResolver`: the
resolver runs when the listener is created or `setQueryParams` is called, and the listener stores what it returns.

```ts title="filters-adapter.ts"
const adapter = new SocketAdapter<
  Extra,
  undefined,
  ListenerOptions,
  undefined,
  undefined,
  DefaultMapperType,
  Filters
>({
  name: "my-adapter",
}).setListenerQueryParamsResolver((callback) =>
  callback(createFilters()).toJSON(),
);
```

---

:::secondary Summary

- `WebsocketAdapter` is the default. `ServerSentEventsAdapter` receives only.
- Map another message format with `decode` and `encode` before reaching for a custom adapter.
- Pass `WebSocket` or `EventSource` in `adapterOptions` where the runtime has no global one.
- Custom adapters describe only their transport and get reconnects from `createReconnectingConnection`.

:::
