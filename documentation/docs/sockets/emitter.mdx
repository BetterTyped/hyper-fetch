# Emitter

An **`Emitter`** describes one topic you send to the server and the type of its payload. Define it once next to the
[socket](/docs/sockets/socket), then call `emit()` wherever you send that message. TypeScript checks the payload and the
topic params before anything goes out.

```ts title="emitters.ts"
import { socket } from "./socket";

export const sendChatMessage = socket.createEmitter<{ text: string }>()({ topic: "chat" });

sendChatMessage.emit({ payload: { text: "Hello" } });
```

`createEmitter` is called twice: the first call takes the payload type, the second the options, so the topic stays a
literal type. The WebSocket adapter sends the message as JSON `{ "topic": "chat", "data": { "text": "Hello" } }`.

:::tip Purpose

1. **Typed payloads**: `emit` accepts only the payload type you declared.
2. **Typed topic params**: `:roomId` in the topic becomes a required `params` field.
3. **Reusable templates**: `setPayload`, `setParams` and `setPayloadMapper` derive new emitters.

:::

---

## Send a payload

Pass the payload to `emit`, or set it first with `setPayload` and call `emit()` without arguments. A payload passed to
`emit` wins over one set before. Messages are sent in call order.

```ts title="send.ts"
sendChatMessage.emit({ payload: { text: "Hello" } });

const greeting = sendChatMessage.setPayload({ text: "Hello" });
greeting.emit();
```

---

## Address one resource with topic params

Params in the topic, such as `:roomId`, are required until you set them, either in `emit` or with `setParams`.

```ts title="rooms.ts"
export const sendRoomMessage = socket.createEmitter<{ text: string }>()({ topic: "rooms/:roomId" });

sendRoomMessage.emit({ params: { roomId: "general" }, payload: { text: "Hi room" } });
sendRoomMessage.setParams({ roomId: "general" }).setPayload({ text: "Hi room" }).emit();

// error-next-line
sendRoomMessage.emit({ payload: { text: "Hi room" } }); // params are missing
```

---

## Emit only while connected

`emit()` sends right away and returns nothing. There is no acknowledgement and no queue: when the socket is not
connected, the message is dropped and the error is reported through `socket.events.onEmitterError` and `onError`.

```ts title="send-when-connected.ts"
socket.events.onEmitterError(({ error, emitter }) => {
  console.warn(`Not sent to ${emitter.topic}:`, error.message);
});

if (socket.adapter.connected) {
  sendChatMessage.emit({ payload: { text: "Hello" } });
}
```

- In React, [`useEmitter`](/docs/react/sockets/use-emitter) returns `connected`, so you can disable the send button.
- When the server answers, model the answer as its own [listener](/docs/sockets/listener) topic with a correlation id.
- The Server-Sent Events adapter only receives. `emit()` on an SSE socket throws.

---

## Transform the payload before sending

`setPayloadMapper` runs right before the message goes out and can be async. It is kept on every clone.

```ts title="stamped.ts"
export const sendStamped = sendChatMessage.setPayloadMapper((payload) => ({ ...payload, sentAt: Date.now() }));
```

To change every emitted message of a socket, such as adding a client id, use `socket.onSend` on the
[Socket](/docs/sockets/socket#intercept-messages).

---

## Setters return clones

`setPayload`, `setParams`, `setOptions` and `setPayloadMapper` return a new emitter and leave the original unchanged.
Use the returned value.

```ts title="clones.ts"
// error-next-line
sendChatMessage.setPayload({ text: "Hello" }); // the result is discarded
// error-next-line
sendChatMessage.emit(); // type error: the payload is not set

sendChatMessage.setPayload({ text: "Hello" }).emit(); // OK
```

- `emit({ payload, params })` sends at once, without acknowledgement, and drops the message when disconnected.
- Use the clone that `setPayload`, `setParams` and `setPayloadMapper` return.
