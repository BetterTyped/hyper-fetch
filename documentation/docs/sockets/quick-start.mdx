# Quick start

<Lead>

**Send a typed chat message to a public echo server and receive it back through a listener.** You see both
directions working in under 20 lines.

</Lead>

---

## 1. Install

```bash npm2yarn2pnpm
npm install @hyper-fetch/core @hyper-fetch/sockets
```

`@hyper-fetch/core` is a peer dependency. Browsers, Node.js 22+, Bun and Deno have a global `WebSocket`. On older
Node.js versions, install `ws` and pass it with `adapterOptions: { WebSocket }`.

---

## 2. Create the socket

Create one socket per server and export it. It connects right away and reconnects on its own when the connection
drops.

```ts title="socket.ts"
import { createSocketClient } from "@hyper-fetch/sockets";

// highlight-next-line
export const socket = createSocketClient({ url: "wss://echo.websocket.org" });

socket
  .onConnected(() => console.log("connected"))
  .onDisconnected(() => console.log("disconnected"));
```

---

## 3. Define the topics

A topic is a channel of messages. A **listener** receives one topic with a typed `data`. An **emitter** sends to one
topic with a typed `payload`. Like requests, both are templates you define once.

```ts title="chat.ts"
import { socket } from "./socket";

type ChatMessage = { author: string; text: string };

// highlight-start
export const onChatMessage = socket.createListener<ChatMessage>()({
  topic: "chat",
});
export const sendChatMessage = socket.createEmitter<ChatMessage>()({
  topic: "chat",
});
// highlight-end
```

By default, messages travel as JSON in the shape `{ "topic": "chat", "data": { ... } }`. If your server uses another
format, map it with the adapter's `decode` and `encode` options.

---

## 4. Listen and send

```ts title="index.ts"
import { onChatMessage, sendChatMessage } from "./chat";

// highlight-next-line
const unlisten = onChatMessage.listen(({ data }) => {
  console.log(`${data.author}: ${data.text}`); // "Ann: Hello!"
});

// highlight-next-line
sendChatMessage.emit({ payload: { author: "Ann", text: "Hello!" } });

// Stop listening when you no longer need the messages
// unlisten();
```

The echo server returns your message on the same topic, so the listener logs it. With a real chat server, the
listener receives messages from other users the same way.

:::caution Emit only when connected

`emit()` does not queue messages. When the socket is disconnected, the message is dropped and reported through
`socket.events.onEmitterError`. In React, `useEmitter` returns `connected` so you can disable the send button.

:::

---

## 5. Topics with params

Put params in the topic string to address rooms, users or documents. They are typed, and required when you send.

```ts title="rooms.ts"
const onRoomMessage = socket.createListener<ChatMessage>()({
  topic: "rooms/:roomId",
});
const sendRoomMessage = socket.createEmitter<ChatMessage>()({
  topic: "rooms/:roomId",
});

onRoomMessage
  .setParams({ roomId: "general" })
  .listen(({ data }) => console.log(data.text));
sendRoomMessage.emit({
  params: { roomId: "general" },
  payload: { author: "Ann", text: "Hi room" },
});
```

---

## What just happened

- The [Socket](/docs/sockets/socket) opened one connection and will reconnect it with backoff when it drops.
- The [Listener](/docs/sockets/listener) typed `data` and filtered messages by topic.
- The [Emitter](/docs/sockets/emitter) checked the payload and params at compile time and sent them as one JSON frame.
