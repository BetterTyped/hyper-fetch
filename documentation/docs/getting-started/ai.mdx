# AI and LLMs

HyperFetch gives coding agents one pattern to follow for every API: a client, typed requests and `send()` or a hook. The
same shape works for REST, GraphQL, Firebase and realtime, and the types reject wrong params or payloads at compile time.
This page covers why that helps agents and how to install the HyperFetch agent skills.

```ts title="api/chat.ts"
import { createClient } from "@hyper-fetch/core";

export const client = createClient({ url: "https://api.example.com" });

export const postMessage = client.createRequest<{
  response: { id: string; message: string };
  payload: { prompt: string; context?: string[] };
}>()({ endpoint: "/chat", method: "POST" });

// Same call shape for every request in the app
const { data, error } = await postMessage.send({ payload: { prompt: "Hello" } });
```

---

## Why a single pattern helps agents

Every request is defined and sent the same way, whatever the transport:

1. **Configure a client** once with the base URL and adapter.
2. **Define a request** with its endpoint, method and types.
3. **Send it** with `send()`, or use `useFetch` and `useSubmit` in React.

For an agent this means fewer patterns to learn and fewer ways to get it wrong:

- **Errors show up at compile time.** A missing `:userId` param or a wrong payload shape fails `tsc`, so the agent sees
  the mistake before running anything.
- **No `try/catch` decisions.** `send()` always resolves with `{ data, error, status }`, so there is one way to handle
  failures.
- **Requests are data.** An agent can read a request's endpoint, method and options from one definition instead of
  tracing hooks and fetchers.

## Share an API as an SDK

Wrap your endpoints in an [SDK](/docs/core/sdk) and publish it as a package. Any developer or agent who knows HyperFetch
can use it right away, because every leaf is a regular request. If the API has an OpenAPI schema, the
[CLI](/docs/cli/overview) generates the SDK for you.

## Install the agent skills

HyperFetch ships agent skills: instructions that coding agents such as Claude Code, Cursor, Codex or OpenCode load when
a task touches a HyperFetch package. Each package has its own skill with the patterns, defaults, type-safety rules and
pitfalls, checked against the source and tests.

Install all of them with the [skills](https://skills.sh) CLI:

```bash
npx skills add BetterTyped/hyper-fetch/skills
```

Or pick the packages you use:

```bash
npx skills add BetterTyped/hyper-fetch/skills --skill hyper-fetch-core --skill hyper-fetch-react
```

:::secondary Summary

- **One pattern**: client, typed request, `send()` or a hook, for every transport.
- **Compile-time checks**: wrong params, payloads and query params fail the typecheck.
- **SDKs**: share an API as typed requests, or generate them from OpenAPI.
- **Agent skills**: `npx skills add BetterTyped/hyper-fetch/skills` installs one skill per package.
