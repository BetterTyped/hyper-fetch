# Development

A suggested layout for the API layer, and three ways to see what your requests are doing while you work. Adapt both to
your project.

---

## Structure the API layer

Keep the client and every request in one `api` folder, with one file per entity. Components, loaders and tests then
import the same request definitions.

```text title="Project structure"
src
├── api
│   ├── client.ts
│   ├── users
│   │   └── users.api.ts
│   └── products
│       └── products.api.ts
└── ...
```

```ts title="src/api/users/users.api.ts"
import { client } from "../client";

export type User = { id: number; name: string };

export const getUsers = client.createRequest<{ response: User[] }>()({ endpoint: "/users" });
export const getUser = client.createRequest<{ response: User }>()({ endpoint: "/users/:userId" });
```

- **One client per backend**, created once in `client.ts` and exported.
- **Requests at module level**, never inside components or handlers. Derive variants with `setParams` and the other
  setters, or pass values to `send()`.
- **Large APIs**: describe them as one [SDK](/docs/core/sdk) schema, or generate it with the [CLI](/docs/cli/overview).

## Debug with the logger

Turn on the built-in logger with `setDebug(true)`. It prints `"warning"` and `"error"` logs by default. Change the level
with `setLogLevel`, which takes `"debug"`, `"info"`, `"warning"` or `"error"`.

```ts title="src/api/client.ts"
import { createClient } from "@hyper-fetch/core";

export const client = createClient({ url: "https://api.example.com" })
  .setDebug(process.env.NODE_ENV === "development")
  .setLogLevel("debug");
```

## Build your own tooling

Every step of a request emits an event on the client's [managers](/docs/core/managers), and
[plugins](/docs/core/plugin) can observe the cache and the dispatchers too. Use them for custom logging, metrics or your
own devtools.

```ts title="src/api/logging.ts"
import { client } from "./client";

client.requestManager.events.onResponse(({ request, response }) => {
  console.log(request.method, request.endpoint, response.status);
});
```

See the [plugins example](/examples/request-control/plugins) for a logging and a metrics plugin.
