# Sockets

The **Sockets** page shows the realtime side of your app: whether each socket is connected, every message it receives
and sends, and its errors. It works with every adapter of [`@hyper-fetch/sockets`](/docs/sockets/overview.mdx), such as
WebSocket and Server-Sent Events.

## Add your sockets

HyperFlow shows the sockets you pass to the devtools plugin. Until you do, the page says **No sockets inspected**.

```ts title="api/client.ts"
import { createSocketClient } from "@hyper-fetch/sockets";
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";

export const socket = createSocketClient({ url: "wss://api.example.com/ws" });

client.addPlugin(
  DevtoolsPlugin({
    appName: "Acme Store",
    // highlight-next-line
    sockets: [socket],
  }),
);
```

---

## Socket cards

Each socket gets a card with its URL, adapter and status: **connecting**, **connected**, **reconnecting**,
**disconnected** or **failed**. The card counts messages and bytes received and sent, errors, failed sends,
reconnection attempts and topics.

Select a card to show only that socket's messages, and select it again to show all of them.

---

## Messages

The log lists the newest messages first and keeps the latest 1,000.

| Filter         | Shows                                                                   |
| -------------- | ----------------------------------------------------------------------- |
| **All**        | Everything below                                                        |
| **Received**   | Messages that arrived, with their topic and data                       |
| **Sent**       | Messages your emitters sent, and the ones that failed to send          |
| **Connection** | Connecting, connected, disconnected, reconnection attempts and errors  |

Search the log with **Search by topic or content**. **Clear messages** empties the log while the counters on the cards
keep going.

<Screenshot
  src="/img/hyper-flow/sockets-message.webp"

  caption="Select a message to see its full data and the adapter's details."
/>

Select a message to see its data or payload, the adapter's extra details, such as the raw `MessageEvent`, and any error
in full.

:::tip Debug a message that never arrives

If a listener never fires, look for the topic in **Received**. When the message is there under another topic, the
listener's topic or params differ from what the server sends. When it is missing, check the socket's status and
**Connection** events.

:::

When HyperFlow restarts, the plugin reports every socket and its current state again. Only messages sent while
HyperFlow was closed are missing.
