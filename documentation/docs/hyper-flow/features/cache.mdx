# Inspect and edit the cache in HyperFlow

Most data bugs are cache bugs: a stale entry, a key that differs by one param, a component that never re-renders.
HyperFlow lists the cache of a connected app, shows each entry's data and observers, and lets you change an entry while
the app runs to see how the UI reacts.

![Cache Management](@site/static/img/previews/cache.png)

---

## Cache Overview

The cache dashboard gives you a high-level view of your cache's state, including metrics on hit rates, memory usage, and
the number of stored items. This helps you understand how effectively your caching strategy is working.

![Cache Dashboard](@site/static/img/previews/dashboard-cache.png)

---

## Exploring Cached Data

You can browse a list of all items currently in the cache. Each entry shows the cache key, whether it is fresh or stale,
how many observers it has, and when it was last updated. This allows you to:

- Verify that data is being cached as expected.
- Identify and remove stale or unnecessary entries.
- Find entries no component reads anymore.
- Monitor the overall size and growth of your cache.

### Observers

Observers are the subscriptions of your application to the data of a cache key. Every mounted `useFetch`, `useSubmit`
and `useCache` reading the key counts as one, and so does every `cache.events.onDataByKey` listener. The DevTools plugin
reports the counts as components mount and unmount, and sends them all again each time HyperFlow connects.

## Inspecting Cache Entries

For deep debugging, you can drill down into individual cache entries. This detailed view shows you:

- The cached data itself.
- How many observers read the entry.
- Metadata such as timestamps and expiration details.
- The request that originally populated the cache entry.

Read [cache](../../core/cache.mdx) for how keys, `staleTime` and `cacheTime` work in the client.
