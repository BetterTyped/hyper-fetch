# Network

The **Network** page lists every request your client sends, newest first, as it happens. Select a request to see what
went out, what came back and how HyperFetch processed it. Beyond what a browser's Network tab shows, it lists requests
that waited in a stopped queue, requests that were canceled or removed before they finished, and the cache, query and
abort keys HyperFetch used.

## Find a request

Type in **Search by endpoint, method or key** to match the endpoint, the HTTP method, the query key, the cache key or the
abort key. The status filters narrow the list further and work together with the search.

| Filter          | Shows requests that                                                              |
| --------------- | -------------------------------------------------------------------------------- |
| **All**         | Were sent, in any state                                                          |
| **Success**     | Finished with a successful response                                              |
| **Failed**      | Finished with an error, such as a `4xx` or `5xx` status, a timeout or a network error |
| **In progress** | Are being sent or waiting for a response                                         |
| **Paused**      | Wait in a [stopped queue](/docs/hyper-flow/features/queues)                  |
| **Canceled**    | Were aborted, for example by `request.abort()` or a newer `cancelable` request   |
| **Removed**     | Were removed from a queue before they finished                                   |

Click the **Endpoint**, **Cache** or **Timestamp** column header to sort by it. Click again to reverse the order, and a
third time to go back to the default order.

<Screenshot
  src="/img/hyper-flow/network-failed.webp"
  alt="The Network page filtered to Failed requests, showing only requests that ended with an error."
  caption="The Failed filter keeps only requests that ended with an error."
/>

**Clear network** empties the list in HyperFlow and keeps your search and filter, so new requests are filtered the same
way. It does not change anything in your app, and the [dashboard](/docs/hyper-flow/features/dashboard) statistics
keep counting.

GraphQL requests are listed by their operation name instead of the whole document.

## Inspect a request

Select a row to open the details panel next to the list. Drag its edge to resize it, and close it with the **X** in its
toolbar.

<Screenshot
  src="/img/hyper-flow/network-details.webp"
  alt="The details panel of a failed GET /customers/7 request with status 404, showing its tabs Payload, Response, Processing Details and Request Details."
  caption="The details of a request that failed with a 404."
/>

The header shows the method and endpoint, with a **Retried Request** badge and the number of retries when HyperFetch
retried it, and a **Mocked** badge when the response came from `request.setMock()`. Under it you see the status, the
status code and when the response arrived.

| Tab                    | What it shows                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------- |
| **Payload**            | The payload, params, query params and headers that were sent                          |
| **Response**           | The response data, error, status and extra details such as response headers           |
| **Processing Details** | Timestamps of each step, retries and whether the request was canceled or offline       |
| **Request Details**    | The whole request configuration, including `cacheKey`, `queryKey`, `abortKey`, `staleTime` and `retry` |

**Response** and **Processing Details** stay empty until the response arrives. Every value has a copy button, so you
can paste a payload or response into a test.

**Actions** › **Remove** deletes the request from HyperFlow's list. Your app is not affected.

---

## History limit

HyperFlow keeps the latest 1,000 requests per app and drops the oldest as new ones arrive. Change the limit with
**Network History Limit** in the app's [settings](/docs/hyper-flow/features/settings#network-history-limit).
