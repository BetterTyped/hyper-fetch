# DB

The **DB** page shows what a [`@hyper-fetch/db`](/docs/db/overview) db holds: its collections, the subsets of rows
each loader fetched, every live query with its plan, and the writes waiting in the outbox. Use it to answer why a query
sent a request, why it did not, or why a row has not reached the server yet.

## Add your db

Pass the db to the devtools plugin. Until you do, the page says **No dbs inspected**.

```ts title="api/client.ts"
import { DevtoolsPlugin } from "@hyper-fetch/plugin-devtools";

import { db } from "./db";

client.addPlugin(
  DevtoolsPlugin({
    appName: "Acme Store",
    // highlight-next-line
    dbs: [db],
  }),
);
```

The plugin sends a snapshot whenever the db changes, at most once per tick, and one whenever HyperFlow connects. With
more than one db, a switcher at the top picks which one to show.

---

## Collections and subsets

The **Collections** table lists each collection with its rows, loaded subsets and pending writes. Select a collection
to open its **Subsets**: the sets of rows a loader fetched for one combination of conditions.

| Subset column | Meaning                                                                         |
| ------------- | ------------------------------------------------------------------------------- |
| **Loader**    | Which of the collection's loaders fetched the rows, by its position in the chain |
| **Rows**      | How many rows the subset holds                                                  |
| **State**     | `loading`, `live` when syncs keep it current, `fresh` or `stale`, or `error`    |
| **Queries**   | How many live queries read the subset                                           |

---

## Live queries

The **Live queries** table shows every query that has subscribers.

| Column          | Meaning                                                                 |
| --------------- | ----------------------------------------------------------------------- |
| **Status**      | `loading`, `ready` or `error`                                           |
| **Rows**        | How many rows the query returns                                         |
| **Plan**        | How the query is answered, such as `list · loader 0`, or `answered locally` from rows the db holds |
| **Sent**        | The conditions sent to the backend                                      |
| **Local**       | The conditions applied to the returned rows                             |
| **Syncs**       | The socket syncs that keep the query live                               |
| **Subscribers** | How many components or listeners read the query                         |

This is the same plan `query.explain()` returns in code.

---

## Outbox

With `offline` writes turned on, the **Outbox** lists writes waiting to reach the server in the order they will replay,
with their collection, key and whether they were sent. An empty outbox shows **The outbox is empty.**

The DB page is read-only. It updates every time the db changes.
